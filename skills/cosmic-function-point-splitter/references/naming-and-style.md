# 命名、写法与排序

这里分两类内容，**不要混用**：

- **COSMIC 事实**：功能用户、触发事件、兴趣对象、数据组与数据移动的判定，
  见 [拆分原则](splitting-rules.md)。
- **送审表惯例**：列的顺序、句式、命名、排序。它们让表更好读、更接近评审习惯，
  但**不改变规模**。工具对这些只给提示，`--strict` 时才阻塞。

## 功能用户（E 列）

- 写边界外的真实角色：操作员、审批人、管理员、外部系统、硬件设备。
- 持久存储不是功能用户；它在本软件边界内。
- 定时触发的采集/统计写「定时任务」，在规格 `user` 里如实写，并加入
  `measurement.functional_users`。
- 有的送审表要求两行：`发起者：<角色>` 换行 `接收者：<三级模块>`。
  用 `build --user-format dual` 生成，规格仍只维护纯角色名，避免两处写法漂移。

## 触发事件（F 列）

- 写真实触发：谁在什么条件下发起了什么。功能用户与触发事件应对得上。
- 不要与功能过程同名。同名只说明「有人触发了它」，没有信息量。
- 不要写成「发起」+过程名，也不要把前端交互步骤塞进来
  （「打开页面、点击查询、核对数据」不是触发事件）。
- 定时过程写「定时任务触发」或按实描述调度条件。

## 功能过程名（G 列）

- 结构是「业务对象 + 动作」，如「订单状态修改」「订阅数量统计」。
- 全表唯一。重名时加业务限定（实体名、指标名、场景），不加数字后缀。
- 不要从 URL 末段取名字：`/export` 的 `export` 是路由，不是业务对象。
- 不要把列表与详情强行并成一个「订单查询」；也不要仅凭字段多就拆两个过程。
  判据是是否存在独立触发与独立功能用户需求。
- 一级/二级/三级模块名只保留实体名。把「订单列表」「订单导出」当三级模块
  会让同一实体的过程散落在多个模块里。

## 子过程描述（H 列）

推荐简洁动宾式（作者没写时工具按此推导）：

| 移动 | 写法 | 例 |
| --- | --- | --- |
| E | 输入 + 对象 + 动作 + 请求 | 输入订单查询请求 |
| R | 读取 + 对象 + 信息 | 读取订单信息 |
| W | 保存/更新/删除 + 对象 + 信息 | 保存订单信息 |
| X | 返回 + 对象 + 动作 + 结果 | 返回订单查询结果 |

会被提示的旧模板句：`接收…请求并校验输入数据`、`从数据存储读取…`、
`将…数据写入数据存储`、`向用户返回…结果`。`normalize` 可以批量改写措辞，
但只改文字，不动对象、属性与移动类型。业务对象含「我的」时不要删「的」。

描述**不要求全表唯一**。两行文字相同只提示确认是否复制粘贴，不自动加前缀或数字。
真正要区分的是业务对象与数据组，不是文案。

## 数据组（J 列）

- 数据组是兴趣对象的一组属性，名称应说明这组数据是什么，如「订单资料」「审批意见」。
- 同一数据组可以在多个过程中复用（读、写、返回）。这不是重复计量。
- 有的项目要求「完整功能过程名 + 请求数据/信息/记录/结果」的后缀写法。
  这是**本地格式惯例**，可以照做，但它不构成数据组的语义判据；也不要求全表唯一。

## 数据属性（K 列）

- 只写真实字段：表字段、接口字段、页面可见字段。缺证据就标待核实，
  **不为了凑数量补「操作状态」「操作编码」**。
- 一个字段也可以是有效的数据组；不设「至少三个」的下限。
- 同一行内不允许重复字段；跨行、跨过程允许相同属性。
- 系统字段（主键编码、创建人、修改时间、分页参数）一般不进入业务数据组说明，
  但作为查询入参时按真实接口写。
- 英文残留按 [术语表](glossary-en-zh.md) 处理：行业缩写可保留，普通英文给改写建议；
  不改写 `addressID` 这类真实标识。

## 排序

默认按规格声明顺序，工具不猜。需要对齐送审惯例时用 `--order crud`：

`新增 → 修改 → 删除 → 查询 → 采集 → 统计 → 图表/报表 → 其他`

- 只移动整块（同一功能过程的 E/R/W/X 行不拆开），模块顺序不变，CFP 不变。
- 同类内保持原相对顺序（稳定排序）。
- 报表/看板模块没有 CRUD 时，按 `采集 → 统计 → 查看图表/报表查询`。
- 这是本地编排惯例，不影响计量；`audit` 对已有表只提示不重排。

## 明确拒绝的「规则」

以下做法会把规模做出来，但不是 COSMIC，也不进入本工具：

| 做法 | 为什么拒绝 |
| --- | --- |
| 每个操作名固定 CFP（新增 2、查询 3……） | 同一操作在不同需求下移动数不同；固定值会把分析变成套模板 |
| 每行强制 ≥3 个属性，不足就补通用字段 | 单字段数据组合法；补字段等于造数据属性 |
| F/G/H/J/K 五列全表唯一，冲突就加前缀或数字 | 唯一性不是标准规则；为凑唯一而改文案/属性会歪曲事实 |
| 为了达到目标行数补功能、拆采集统计、加导入导出 | 目标不参与计量；未证实的功能不能进入已确认规模 |
| 把「批量操作」「格式差异」「技术路线」拆成额外过程 | 同一次触发、同一兴趣对象不因实现差异重复计点 |
| 用「2025 年送审被打回」之类说法给句式背书 | 未独立核实的历史结论不作为规则来源；句式只作为本地偏好 |

需要送审表满足这些格式要求时，区分清楚：**格式可以照做，规模不能倒推**。
