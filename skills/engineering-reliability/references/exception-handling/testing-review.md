# 异常处理测试与评审

## 必测失败路径

至少测试：

- 请求解析和参数校验失败；
- 预期业务拒绝；
- 认证与授权失败；
- 资源不存在和状态冲突；
- 依赖不可用与依赖超时；
- 可重试与不可重试分类；
- 最大重试次数和总耗时；
- 取消传播；
- 事务回滚和资源释放；
- 清理失败时保留主异常；
- 未知异常兜底；
- 错误响应脱敏；
- 消息重试耗尽和死信转换。

时间相关测试使用确定性时钟、伪依赖或明确误差范围。

## 评审清单

- [ ] 没有空 `catch/except`。
- [ ] 未知失败不会转换为空值或成功结果。
- [ ] 每个捕获点承担恢复、转换、补偿、上下文、清理或最终处理责任。
- [ ] 包装异常保留原始 cause 和调用栈。
- [ ] 映射逻辑不检查异常消息字符串。
- [ ] 预期失败使用已登记错误码。
- [ ] HTTP 状态语义准确，失败不返回 HTTP 200。
- [ ] 未知失败返回安全的 `INTERNAL_ERROR`。
- [ ] 对外信息不包含堆栈、SQL、路径、地址、密钥或敏感标识。
- [ ] 每个外部操作都有超时或截止时间。
- [ ] 仅临时性失败会被重试。
- [ ] 被重试的写操作具备幂等保护。
- [ ] 退避、抖动、次数和总耗时均有上限。
- [ ] 永久性异步失败不会无限重新投递。

## 发布阻断条件

存在以下任一情况时不得发布：

- 失败路径无法诊断；
- 错误响应泄露内部或敏感信息；
- 错误码语义冲突或不稳定；
- 重试缺少硬上限；
- 非幂等操作可能被不安全重复执行；
- 事务或资源可能无法释放；
- 关键重试耗尽、死信增长或依赖故障缺少监控。
