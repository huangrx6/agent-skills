# 日志测试与评审

## 必测内容

至少验证：

- 关键事件在正确边界产生；
- 同一失败不会重复打印堆栈；
- 日志级别符合运行影响；
- 输出是合法 UTF-8 和合法 JSON Lines，或符合项目指定标准格式；
- 每条逻辑事件只生成一条可解析记录；
- 时间戳包含时区且排序语义正确；
- 必需结构化字段存在且类型稳定；
- trace、span 或 correlation 上下文能够传播；
- 未知异常包含内部诊断信息；
- 预期业务失败不滥用完整堆栈；
- 密码、令牌、Cookie、支付数据和个人信息不会出现；
- 用户输入无法注入换行或伪造字段；
- 单条记录超限时按策略截断并带有标记；
- 达到时间或大小阈值时正确滚动；
- 滚动后写入方继续写入新活动文件；
- 只压缩已关闭归档，不压缩活动文件；
- 保留天数、文件数和总容量上限均会触发清理；
- 清理最旧合格归档，不删除活动文件和法律保留文件；
- 磁盘高水位产生告警并执行有界降级；
- 采样和限频符合配置；
- 被限频或丢弃日志仍有数量指标；
- 审计事件不受普通采样和普通清理影响；
- 日志平台故障不会拖垮核心业务；
- 归档上传确认、保留和访问策略可验证；
- 人读流与机器读流的同一事件字段语义一致（文本流 key=value 与 JSON 字段对应）；
- 双流并存时级别阈值与上下文（trace/request 标识）一致；
- 上下文在入口注入、请求结束后清理，异步/线程池执行不串号；
- 动态调级生效、有效期回退生效，调级本身有审计记录；
- 审计通道故障时产生降级事件并告警，不静默丢审计；
- 删除权响应（匿名化/重写/删除）幂等且范围正确；
- 告警通知内容不含敏感日志内容。

## 代码评审清单

- [ ] 事件具有明确诊断、运营、安全或审计价值。
- [ ] 同一失败只在一个责任边界记录。
- [ ] ERROR 仅用于当前操作最终失败且需要关注的情况。
- [ ] 输出格式、编码、时间戳和单行要求明确。
- [ ] 关键上下文使用结构化字段。
- [ ] 字段命名、类型和单位与团队目录一致。
- [ ] 统计和告警不依赖自然语言消息解析。
- [ ] 高基数字段有明确索引和成本策略。
- [ ] 单条日志有大小上限和截断标记。
- [ ] 容器环境没有同时由应用和平台重复轮转同一日志流。
- [ ] 文件日志有时间或大小滚动条件。
- [ ] 文件数、保留天数或总容量存在硬上限。
- [ ] 归档仅在关闭后压缩。
- [ ] 清理策略最旧优先、幂等且不会删除活动文件。
- [ ] 磁盘水位、缓冲上限和丢弃优先级明确。
- [ ] 日志不包含禁止记录的数据。
- [ ] 用户可控文本已限制长度并处理控制字符。
- [ ] 请求和响应内容记录有明确允许列表和采样规则。
- [ ] 审计日志与诊断日志分离。
- [ ] 审计通道降级时产生可观测事件和告警，不静默丢审计。
- [ ] 生产动态调级有回退机制、有效期和审计记录。
- [ ] 人读流与机器读流字段语义一致，无重复采集同一形态。
- [ ] 日志量预算已定义并纳入容量规划。
- [ ] 告警规则基于事件名/错误码，通知内容已脱敏。
- [ ] 高频路径使用指标、聚合、采样或限频。
- [ ] 日志平台故障有有界缓冲和降级策略。

## 发布阻断条件

存在以下任一情况时不得发布：

- 日志格式无法稳定解析或字段类型发生未管理漂移；
- 日志泄露密钥、凭据、支付信息或不必要的个人信息；
- 同一错误在多个层级重复输出堆栈；
- 关键故障无法通过链路标识关联；
- 文件日志没有滚动、保留或总容量上限；
- 活动日志文件可能被压缩或清理；
- 日志目录可能无限增长直至磁盘耗尽；
- 应用和平台同时轮转同一日志流；
- 高频日志可能导致明显成本或容量风险；
- 审计事件会被普通采样、普通清理或静默丢弃；
- 日志平台故障可能导致核心服务不可用；
- 关键格式、脱敏、轮转和清理规则没有自动化验证。
