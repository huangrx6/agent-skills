# 韧性可观测性与运行手册

## 核心指标

每个依赖/资源池至少监控：

- **超时**：依赖调用超时次数、超时占比、P99 延迟。
- **重试**：retry rate（重试/原始请求比）、重试成功/失败、总 retry duration。
- **熔断**：熔断打开/关闭状态、半开探测次数、拒绝请求数。
- **限流**：被限流请求数、per-tenant 配额使用率。
- **负载**：CPU、memory、worker/连接池使用率、queue depth、event loop lag。
- **背压**：队列积压（depth、oldest age）、入队/消费速率、背压触发次数。
- **降级**：降级模式触发次数、降级期间成功率、恢复次数。
- **异步**：DLQ rate、poison message 数、消费延迟、重放次数。

## 告警阈值（示例，按容量验证调整）

| 指标 | 阈值示例 | 动作 |
| --- | --- | --- |
| retry rate | > 20% 持续 5min | 告警 + 考虑停重试/降级 |
| queue depth | > 80% 容量持续 5min | 告警 + 背压降级 |
| oldest age | > 10min | 告警 + 检查消费速率 |
| DLQ rate | 持续增长 | 告警 + 人工介入 |
| 依赖超时占比 | > 5% | 告警 + 检查熔断 |
| 降级期间错误率 | > 阈值 | 升级告警 |

## Runbook 结构

每个关键故障模式一份 runbook：

```text
## 症状
## 影响
## 诊断步骤（含命令/面板链接）
## 缓解动作（按顺序）
## 验证恢复
## 事后记录
```

## 常见 runbook

### 依赖慢/超时（熔断打开）

1. 确认熔断状态、超时占比、重试率。
2. 检查下游是否过载/故障（面板、日志）。
3. 若下游恢复，半开探测应自动恢复；若持续，考虑手动降级或限流。
4. 记录恢复时间和流量影响。

### 队列积压

1. 确认 queue depth、oldest age、消费速率、生产速率。
2. 检查消费者是否被慢依赖拖住（连接池/worker 耗尽）。
3. 逐步增加消费 concurrency（避免瞬间压垮下游）。
4. 若为瞬时峰值，等积压自然排空；若持续，检查下游容量。

### 过载/限流误伤

1. 确认 CPU/worker 使用率、限流命中率、被拒流量来源。
2. 区分"保护性拒绝"（实例饱和）vs"误伤"（配额过低）。
3. 保护性拒绝保持；误伤则调整配额并观察。

## 降级可观测

- 每次降级产生事件：`degradation.triggered`（组件、模式、原因、时间）。
- 降级期间必须能区分"降级响应"与"正常响应"（响应头/字段）。
- 恢复事件：`degradation.recovered`（时长、期间成功率）。
- 告警：降级持续超过预期时长应告警，防止静默降级长期运行。

## 验证

- 测试：降级触发/恢复事件产生、指标可查询、runbook 步骤可执行。
- 故障注入期间验证指标和告警确实反映注入的故障。
