# 边界与异常场景矩阵

主路径（Happy Path）通常只占真实产品问题的一小半；真正消耗研发返工与伤害用户信任的，几乎全部藏在空态、极值、长文本、切页复位、并发竞态、网络失败和存量兼容里。起草产品规格时，按本矩阵逐类扫查，把适用于当前需求的场景直接落进规格和编号 AC。

## 1. 标准边界与异常矩阵总模板

将下表复制到规格书的「边界与异常场景矩阵」章节，删去确实不适用的行（并注明原因），将适用行的「具体数值/文案/恢复动作」替换为本需求的真实约定：

```markdown
## 边界与异常场景矩阵

| 场景类别 | 具体触发条件 | 预期可见行为 | 恢复动作 / 数据保护 |
| --- | --- | --- | --- |
| 0 项空态 | 数据源为空（首次使用 / 全部删空） | 展示明确空态插图或图标 + 1 句说明 + 下一步主引导按钮；不展示空表头或无效工具栏 | 点击引导按钮可进入创建/安装主路径 |
| 搜索无结果 | 输入关键词或组合筛选后匹配 0 项 | 展示「未找到匹配『<关键词>』的项」提示；不清空已有勾选与表单草稿 | 提供「清空搜索/重置筛选」一键恢复完整列表 |
| 单条数据 | 列表恰好只有 1 项 | 正常展示单条内容；隐藏或禁用无意义的批量排序控件；删除该条后平滑过渡到 0 项空态 | 不出现复数语法错乱或除零/分页异常 |
| 高数量（20+ / 100+） | 列表 ≥ 20 项或 ≥ 100 项 | 列表区独立纵向滚动，顶部搜索栏与底部主操作栏粘性固定；滚动到底时末项不被底栏遮挡 | 支持关键词快速过滤；超大规模（>100）按约定分页或虚拟滚动，保持交互不卡顿 |
| 超长文本与特殊字符 | 名称 > 60 字符、无空格 URL、中英混排、Emoji/ZWJ、`<script>` 等转义字符 | 单行省略（或最多 2 行折行），悬停显示完整原文；右侧状态徽章与操作按钮宽度固定、永不被挤出容器；特殊字符按纯文本安全转义 | 界面无横向溢出、无 XSS 解释执行、无文字重叠 |
| 切页 / 关闭 / 重开复位 | 点遮罩、按 `Esc`、切 Tab、切工作区/项目后重新打开 | 临时态（搜索词、筛选、展开态、滚动条）复位到初始态；若有未保存的重要表单编辑则按约定触发离开确认或草稿暂存 | 关闭浮层后焦点回到原触发按钮；切项目不串写旧项目数据 |
| 快速连点与并发竞态 | 连续点击提交/开关、快速输入触发多次异步请求、请求未返回时关闭弹窗 | 提交期间按钮禁用并显示进行态；异步查询仅采纳最新一次请求结果，丢弃晚到的旧响应；弹窗关闭后忽略在途回调 | 不产生重复记录、不出现「新输入被旧结果覆盖」、关闭后不报未挂载错误 |
| 网络超时与 4xx / 5xx | 校验失败（400/422）、未登录/无权限（401/403）、冲突（409）、限流（429）、服务端错误（5xx）、离线或超时 | 就近展示可理解的原因说明，区别字段级错误与全局错误；不弹窗套弹窗，控制台无未捕获异常 | **铁律：完整保留用户已填内容**，提供「重试」「重新登录」或「刷新合并」动作 |
| 破坏性操作与存量兼容 | 删除/批量清空/重置配置；升级后首次读取旧版配置或缺省字段 | 破坏性操作具备分级护栏（可撤销 Toast / 二次确认 / 输入名称确认）；旧版数据自动补齐默认值并保留未识别字段 | 误操作有明确阻断或撤回手段；旧用户升级零报错、配置不丢失 |
```

## 2. 九大必查场景深度细则

### 2.1 0 项空态（Empty State）
不要把所有「空」混为一谈，必须区分三种成因并给出不同文案与动作：
- **首次空白（Onboarding Empty）**：用户还没创建或安装任何项 → 解释这项能力有什么用 + 1 个高辨识度主按钮（如「创建第一条规则」「浏览扩展」）。
- **全部清零（Cleared Empty）**：用户刚删掉最后一条 → 简洁说明「当前没有剩余项」+ 创建入口（若支持撤销，底部 Toast 仍保留撤回机会）。
- **权限或服务受限导致的空（Restricted Empty）**：并非真没数据，而是当前账号无权查看或本地服务未启动 → **严禁显示「暂无数据」误导用户**，必须如实展示「权限不足」或「服务未连接」及解决指引。

### 2.2 搜索与筛选无结果（Zero Search Results）
- 必须与「0 项空态」区分：此时真实数据还在，只是过滤条件太窄。
- **保留已有选择**：在多选选择器中，输入无匹配关键词绝不能把用户前面已勾选的项清掉。
- **回显关键词与一键复位**：明确显示「未找到与『`xxx`』相关的项」，并紧跟「清空搜索」或「重置全部筛选」按钮（键盘 `Esc` 优先清空搜索框或按约定关闭，必须在规格写死顺序）。
- **前后空格与大小写**：规格中明确是否默认忽略首尾空格（`trim`）与英文大小写不敏感。

### 2.3 单条数据（Single Item）
- 检查依赖「至少两条」才成立的交互：如拖拽排序手柄、上下移动按钮、「对比所选」按钮、分页器（仅 1 页时隐藏分页条）。
- 检查删除最后 1 条的跃迁：删除完成后视图平滑切换为 0 项空态，且原批量操作栏自动收起，不残留「已选 1 项」僵尸条。

### 2.4 高数量（20+ / 100+ 项）
高数量是 UI 规格最容易在开发完才翻车的地方，必须钉死四条线：
1. **搜索触发阈值**：如 `< 15 项` 隐藏搜索框保持紧凑、`≥ 15 项` 自动展示搜索框（或始终常驻，择一写死）。
2. **独立滚动区 + 粘性头尾**：限定列表容器最大高度（如相对视口留出上下安全边距），仅列表内容区滚动，顶部搜索/筛选栏与底部主操作栏（如「管理」「确认」）保持粘性可见。
3. **末项安全边距**：滚到底部时，最后一条记录必须完整露出，不能被底栏阴影或固定按钮盖住下半截。
4. **超大规模策略（100+ / 1000+）**：明确是否采用分组折叠、分页加载、后端检索或虚拟列表；若后端分页，写清「全选」是全选当前页还是全选所有匹配项。

### 2.5 超长中英混排 / URL / Emoji / 特殊字符
以下 5 种测试字符串必须在边界规格里明确排版与转义契约：
- **超长纯中文 / 中英混排**（如 60–120 字标题）：规定单行省略（`ellipsis`）或最多 2 行截断，且提供 `title` / Tooltip 展示完整原文。
- **连续无空格长串**（超长 URL、Hash、Token、文件路径）：禁止撑破容器引发横向滚动条，必须安全截断或断词折行（`break-all` / 中间省略保留头尾）。
- **右侧操作区保护**：名称再长，行尾的开关、状态标签、删除/更多按钮必须固定最小宽度、不换行、不被挤出视口。
- **Emoji、复合字符（ZWJ）与多字节字符**：字数上限按字符视觉长度或明确规则校验，截断时不产生乱码半截字符。
- **HTML / Markdown / 注入字符**（`<img src=x>`, `{{foo}}`, 引号, 反斜杠）：一律按纯文本转义渲染，搜索关键词高亮时只做安全文本切片，绝不直接拼接原始 HTML。

### 2.6 切页 / 关闭 / 重开状态复位
凡含弹层、抽屉、多 Tab、多工作区/项目切换的功能，必须逐一写死下表行为：

| 退出/切换动作 | 临时态（搜索/展开/滚动） | 未保存的表单编辑 | 焦点去向 |
| --- | --- | --- | --- |
| 点遮罩 / 点 `×` / 按 `Esc` | 重开后全部复位 | 无修改直接关；有修改按约定弹出「放弃修改？」确认（或自动存草稿并提示） | 焦点回到打开该弹层的触发按钮 |
| 切换 Tab / 路由页 | 离开即复位（或显式约定保留当前会话） | 离开前提醒未保存变更，防止静默丢失 | 焦点进入新页面主标题或首焦控件 |
| 切换工作区 / 项目 / 账号 | **必须强制清空并按新上下文重载** | 禁止将旧项目草稿带入或提交到新项目 | 重置到新上下文默认视图 |

### 2.7 快速连点与并发竞态
1. **写操作去重（Double-Submit Guard）**：点击「保存」「提交」「创建」「支付」后，立即进入禁用 + 进行态（Spinner / 文案变化），直至请求结束（成功或失败）才恢复；键盘连按 `Enter` 同理受控。
2. **异步读操作乱序覆盖（Stale Response Drop）**：用户快速输入 `a` → `ab` → `abc` 或快速切换列表项 A → B 时，若先发出的请求晚于后发出的请求返回，**必须按请求序号或取消令牌丢弃陈旧响应**，严禁让 A 的数据覆盖当前正在看的 B。
3. **关闭后在途回调（Unmount Safety）**：请求尚未返回时用户关闭弹窗或切换页面，请求随后成功或失败时，不得向已关闭界面弹出莫名其妙的旧错误框，也不得触发控制台未捕获异常；若为后台持久写操作，则按全局 Toast 明确告知归属对象（如「项目 A 配置已保存」）。

### 2.8 网络超时 / 权限不足 / 4xx / 5xx 错误保留输入与恢复
**总铁律：任何提交或校验失败，绝不允许清空用户已经填写的内容。**

| 异常类型 | 典型状态 / 场景 | 界面反馈要求 | 必须提供的恢复动作 |
| --- | --- | --- | --- |
| **前端/服务端字段校验失败** | 400 / 422（必填缺失、格式不符、超长） | 就近标红对应字段并给出可执行修正提示（如「名称不能超过 50 字」），焦点移至首个错误字段 | 用户原地修改后可直接再提交，其余已填字段原样保留 |
| **鉴权过期 / 权限不足** | 401 / 403 | 明确区分「登录已过期」与「当前账号无操作权限」，禁止只显示「请求失败」 | 401 提供重新登录/刷新凭证入口（保留草稿）；403 说明所需权限与联系途径 |
| **资源冲突 / 并发覆盖** | 409（已被他人修改或重名） | 明确告知冲突原因（如「名称已存在」或「该配置已被更新」） | 重名则就地聚焦名称框；版本冲突则提供「查看最新 / 强制覆盖 / 放弃」明确选择 |
| **频控限流** | 429 | 提示「操作过于频繁，请稍后重试」，有明确冷却时间时显示倒计时 | 冷却结束恢复按钮可点，已填内容保持不丢 |
| **服务端异常 / 离线 / 超时** | 500 / 502 / 503 / 离线 / 超时（如 >10s） | 展示顶部或区域内错误条（不覆盖表单），说明是网络或服务侧问题而非用户输入错误 | 提供「重试」按钮；本地只读内容继续可用，不把整个页面锁死成白屏 |

### 2.9 破坏性操作护栏与存量数据兼容

#### 破坏性操作三级护栏
按操作「可恢复性」与「影响面」选择对应护栏，不在低风险操作上滥用重弹窗，也不在高风险操作上裸删：

| 风险级别 | 典型操作 | 强制护栏设计 |
| --- | --- | --- |
| **低风险（可逆）** | 移除单条轻量标签、取消收藏、移除单条临时过滤 | 直接生效 + 底部 **5 秒可撤销（Undo）Toast** |
| **中风险（单对象不可逆）** | 删除单条规则、重置单个项目配置、丢弃未保存表单 | 二次确认弹窗：明确点出待删对象名称与后果；默认焦点在「取消」；支持 `Esc` 取消 |
| **高风险（批量/全局不可逆）** | 清空全部记录、删除整个工作区、覆盖全量数据 | 强确认弹窗：列出影响数量 + 要求输入目标名称或勾选风险确认框后才启用红色主按钮 |

#### 存量数据与升级兼容契约
凡涉及持久化结构调整、枚举增删或配置项更名，规格必须回答以下 4 问：
1. **缺省字段怎么读？** 老版本记录缺少新字段时，读取端按哪个明确默认值兜底？
2. **废弃字段/未知枚举怎么处理？** 首次加载是否静默兼容不崩溃？回写保存时是否无损保留未知扩展字段，避免降级回滚失败？
3. **自动迁移是否幂等？** 升级迁移中途失败或重复执行时，会不会把原数据改坏？
4. **旧行为是否保留？** 老用户升级后首次打开界面，是否会意外看到开关被重置、数据「看起来丢了」？

## 3. 键盘流、焦点管理与视口约束速查表

桌面端与 Web 效率工具常见漏测项，写入规格时按需勾取：

- **焦点进入**：打开弹窗/浮层/抽屉时，焦点进入首个主交互控件（如搜索框或首个输入框）；若为危险确认弹窗，默认焦点落在「取消」。
- **键盘导航**：`Tab` / `Shift+Tab` 仅在当前模态层内循环（焦点陷阱），不穿透到底层页面；列表支持 `↑/↓` 移动高亮、`Enter` 确认或切换。
- **退出与焦点回归**：`Esc` 按层级逐层关闭（先关内层下拉或清空搜索，再关外层弹窗），关闭后焦点准确归还给原触发按钮。
- **窄窗与边界贴合**：明确最小支持视口（如 `900×620` 或 `1280×720`）；浮层靠近窗口底边或右边时自动翻转展开方向，绝不截断在视口之外。

## 4. 边界场景漏测自查清单

在提交规格前，用 60 秒逐项核对：

- [ ] 是否明确区分了「首次 0 项空态」「搜索无结果」与「无权限/服务断开」？
- [ ] 高数量场景（20+ / 100+）是否钉死了搜索触发线、独立滚动区与粘性头尾？
- [ ] 是否验证了超长无空格字符串、中英混排和特殊字符不会挤走右侧操作按钮？
- [ ] 是否逐一写明了关闭弹窗、切换 Tab、切换项目/工作区后的状态复位与焦点回归？
- [ ] 写操作是否防连点、异步读操作是否防旧响应覆盖新状态？
- [ ] 所有 4xx / 5xx / 超时场景是否都承诺「保留用户输入」并提供恢复按钮？
- [ ] 破坏性操作护栏与风险级别匹配，且存量旧数据升级路径已写明兼容默认值？
