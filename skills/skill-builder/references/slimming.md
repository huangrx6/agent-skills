# 精简而不损失可执行性

先读完整入口，再按实际消费者检查 references、scripts 和 assets。行数下降只是结果，
目标是减少重复读取和错误指令，同时保留完成任务必需的信息。

## 处理顺序

1. **删除失效内容**：已经取消的步骤、过期状态快照、未经支持的能力、重复历史复盘。
2. **合并重复规范**：保留一个权威位置，其他地方给用途明确的引用。
3. **展开含混指令**：把“要完美”“必须高级”换成能检查的条件；必要时文字会变长。
4. **拆分条件细节**：后端专用参数、长 schema、少用的边界案例进入参考文件。
5. **核对消费者**：文件没有在文档提及不代表无用，还要看代码导入、动态加载、模板引用和打包入口。

有明确调用者的 helper、测试 fixture、字体或模板不因为“看起来多”就删除。
只有确认无用途或已由等价内容替代的文件才移除；忽略文件里的本机状态不是仓库垃圾。

## 迁移后的核对

- 入口是否仍说明触发条件、输入、必要步骤和验收方式？
- 引用目标是否存在，是否保留所声称的内容，安装后是否可访问？
- 命令能否在文档标明的目录运行，配置是否来自真实解析器？
- 取消某条确认或限制后，是否仍尊重用户授权和实际风险？
- 行为改变用对应场景回归；只改重复措辞不额外制造镜像测试。
