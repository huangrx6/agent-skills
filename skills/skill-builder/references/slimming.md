# 正文瘦身怎么搬（余量不足时）

## 什么时候搬

体检脚本会直接说：

```sh
python3 tools/skill_health.py          # 看「正文余量偏紧」那一行
python3 skills/skill-builder/scripts/validate_skill.py <skill>
#   ! 正文余量只剩 2 行：下次要往正文加规则前，先做 references 瘦身
```

门槛是 **余量 < 10 行**。不要等顶到 150 才搬 —— 那时你正要加的那条规则就只能先砍别的。

## 搬什么（判断只有一条）

**问自己：读者在"知道该做什么"之后，还需要立刻看到这段吗？**

| 搬出去 | 留在正文 |
| --- | --- |
| 为什么当初这么定（实测经过、踩过的坑、反例） | 规则本身（做什么 / 不做什么） |
| 长清单、完整决策树、参数表 | 判据（怎么知道做对了）、命令 |
| 具体案例的来龙去脉 | 索引（「这条的来历见 references/x.md」） |
| 跨 skill 共用的约定 | 触发场景与边界 |

判断的落点是**触发之后的第一步**：正文是"我现在该做什么"，references 是"为什么是这样"。

## 怎么搬（四条，都踩过）

1. **整段搬，不要搬半句。** 一次搬一类（比如整个「报告纪律」），而不是从两段各抽一句 ——
   半句搬走会让两边都不完整，读哪边都读不懂。
2. **目标文件要自带上下文。** references 的读者不是从 SKILL.md 一路读下来的，
   所以搬过去的段落开头要补一句它是什么、跟谁有关。
3. **正文留指针，并且指针要短。** 一行足够，例如：
   `（为什么这条防线没闭合，见 references/reporting.md）`。
4. **搬完必须核对目标真的接住了。** 「指针写对了」≠「内容搬过去了」——
   本仓库实测过：删掉 8 条风格规格改成指针，目标文件里一条都没落地。

   核对方式（机械的）：

   ```sh
   python3 skills/skill-builder/scripts/check_pointers.py   # 列出所有指针语句
   # 然后对每一条：在被指向的文件里 grep 一个特征短语
   grep -n "报告是自由文本" skills/skill-builder/references/reporting.md
   ```

   特征短语要选**只有那段才有**的词（比如上面那句），不要选通用词。

## 搬完的验收

```sh
python3 skills/skill-builder/scripts/validate_skill.py <skill>   # 余量回来了
python3 tools/skill_health.py | grep <skill>                     # 不再落在「余量偏紧」
python3 -m unittest discover -s tools/tests                      # 别把检查改坏
```

## 代价（所以不要过度搬）

- references 多一个文件，读者要多跳一次；**只在余量真的紧张时搬**。
- 搬错了（把规则搬走）会让 skill 在触发后不写该写的东西 —— 这比正文超行更难发现。
  所以**规则类的句子一律留在正文**：正文超行会被脚本挡住，规则搬走没人挡。

## 一个反例

不要为了"腾地方"把规则改写成更短的句子。那会让规则变得模糊（比如把三条硬规则压成一个表格，
丢掉了"什么算违规"的判据）—— 余量是回来了，但 skill 变弱了。
**搬的是"为什么"，不是"什么"。**
