# 内容质量：让人真的学会

这份文档约束“写什么”，[笔记深度规范](depth-standard.md) 约束“写多深、多少行、必须有哪些节”。
两份一起用。

## 一、覆盖必要概念，不覆盖所有 API

一条系列的范围要能一句话说清：

> 覆盖“入队 → 消费 → 落盘 → 恢复”的主链路；不覆盖分布式共识、多副本与运维。

判断是否足够，用承诺的产物反推：

- 前置概念补齐了吗？
- 核心对象都有定义吗？（消息、队列、ack、持久化、幂等）
- 机制链连得起来吗？（输入 → 处理 → 状态 → 输出 → 失败）
- 边界与失败模式讲了吗？
- 有验证方式吗？（练习、自测、可观察指标）
- 明确写了“不覆盖什么”吗？

## 二、每篇的内容合同

1. **是什么**：一句话定义；缩写第一次出现就展开。
2. **为什么重要**：解决什么问题，不解决什么问题。
3. **怎么工作**：输入、关键步骤、输出；有循环就写退出条件。
4. **完整例子**：代码、配置、消息轨迹；标 `tested / illustrative / pseudo`。
5. **常见误解**：一个错误直觉 + 正确说法。
6. **依据**：官方文档、源码、论文；正文先讲，链接放旁边。

正文不写成“先看这篇，再看那篇”。链接是依据，不是讲解。

## 三、清晰度

- 一篇只回答一个问题；标题就是这个问题或判断。
- 先给心智模型，再给源码细节；不要在读者没有地图时扔 2000 行代码。
- 代码块说明“这段在演示什么”，并标是否运行过。
- 例子最小化：能说明一个机制即可。
- 重要结论旁边放依据；关键限制不要藏到最后一段。
- 用“因为 → 所以”，不用“众所周知”“显然”。
- 读完一篇，读者应该能用自己的话复述，而不是只记住文件名。

## 四、自测与复习

- 每篇 1–3 道题；至少一道问“为什么/下一步会怎样”。
- 复习卡正面只放问题，背面放答案与依据。
- 答错要能回到对应段落，而不是只显示“错了”。

## 五、来源与不确定性

- 每篇至少一个可点的依据；整条系列有 `verified_at`。
- 视频只核验元数据时写明，不评价讲授质量。
- 代码没跑过就标 `illustrative` / `pseudo`。
- 版本敏感内容写清版本与日期；不确定写“截至某日”。
- 链接失效或 API 变化时，先修内容，再更新核验日期。

## 六、发布前自检

- [ ] 一个新手能从第一篇读到最后一篇，不需要外部搜索才能理解。
- [ ] 每篇有一个明确的“带走”。
- [ ] 每个核心结论有一个可点的依据。
- [ ] 每篇至少一次回忆或动手。
- [ ] 写清了范围与不覆盖的内容。
- [ ] 示例代码/配置的状态标注正确。
