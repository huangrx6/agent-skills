# 视频：找、核验、内嵌

视频是学习系列里最容易注水的一环：标题看起来对，点开是搬运；时长写着 10 分钟，实际是广告；或者只是“看起来相关”，讲的是三年前的 API。这份文档约束从搜索到上墙的全过程。

## 一、只从这些来源找

优先级从高到低：

1. 官方频道：项目/框架/语言/云厂商自己的频道，或官方课程的完整播放列表。
2. 会议频道：会议主办方上传的 talk（如各语言大会、PyCon、QCon、KubeCon）。
3. 作者本人：库的维护者、论文作者、规范作者的讲解。
4. 可信课程：有明确讲师、大纲、更新日期的付费或免费课程。
5. 高质量个人频道：有可核验的作品或维护记录，且视频不是纯搬运。

不选：搬运号、无出处的“10 分钟精通”、AI 配音拼接、封面与内容不符、评论区全是“求资料”的频道。

## 二、每个视频必须核验的字段

| 字段 | 说明 | 缺失时 |
| --- | --- | --- |
| `title` | 视频原标题 | 必填 |
| `url` | 可直接打开的链接 | 必填 |
| `channel` | 频道/作者 | 必填 |
| `duration` | 时长（`12:30`） | 建议必填；没有就写“未标注” |
| `lang` | 语言（`zh` / `en`） | 必填 |
| `why` | 一句话：它补哪一段，为什么是它 | 必填 |
| `verified_at` | 核验日期 | 必填 |
| `paid` | 是否付费/会员 | 有就写 `true` |
| `region` | 地区限制 | 有就写地区码 |

核验动作至少包括：打开链接确认可访问、确认标题与频道一致、确认时长与语言。**没有完整观看，就只能写“元数据核验”，不能评价讲得好不好，也不能写“强烈推荐”。**

## 三、能否内嵌

构建脚本支持三类平台，自动转换为播放器地址：

| 平台 | 接受的链接 | 转换后 |
| --- | --- | --- |
| YouTube | `youtube.com/watch?v=ID`、`youtu.be/ID`、`/shorts/ID` | `youtube-nocookie.com/embed/ID` |
| Bilibili | `bilibili.com/video/BV...` | `player.bilibili.com/player.html?bvid=BV...` |
| Vimeo | `vimeo.com/123456` | `player.vimeo.com/video/123456` |

其他平台不内嵌，只保留外链。内嵌用的是**点击后加载**：页面先显示按钮，点击才插入 iframe，避免一屏十几个播放器同时请求网络。

内嵌不代表离线可看。断网时播放器区域不可用，但笔记正文、目录、测验、复习卡仍然可用；这一点要在交付说明里写清楚。

## 四、数量和位置

- 每个阶段/每篇笔记 0–2 个视频。超过 2 个通常说明这篇该拆，或者视频在替代讲解。
- 视频不能是唯一讲解：每篇必须有文字解释、示例和自测；视频是补充视角，不是正文。
- 同一视频不要在多个阶段重复挂；确实需要复用时，在 `why` 里写清“复习用”。
- 长课程（>60 分钟）要给出分段建议（看哪几段、跳过哪几段），不能只写“看完”。

## 五、写进 plan.json

```json
{
  "videos": [
    {
      "title": "原视频标题",
      "url": "https://www.youtube.com/watch?v=XXXXXXXX",
      "channel": "频道名",
      "duration": "28:14",
      "lang": "en",
      "why": "补第 2 节的调度模型，前面 8 分钟是背景，可跳过。",
      "paid": false,
      "verified_at": "2026-10-23"
    }
  ]
}
```

字段写不全就不要放。一个核验不完整的视频，比没有视频更伤可信度。

## 六、交付前检查

- [ ] 每个视频链接都能打开，标题与频道对得上。
- [ ] 时长、语言、付费、地区限制都标了。
- [ ] 没有把“没看完”写成“讲得很好”。
- [ ] 内嵌平台在支持列表里；不支持的只给外链。
- [ ] 视频数量没有超过正文的讲解密度。
- [ ] 断网时正文仍可读，页面没有因为 iframe 卡住。
