# 成文规范：一篇知识笔记的骨架

这套骨架描述「一篇写完了的知识笔记长什么样」，是本 skill 的默认输出格式。
目标是**陌生读者不看别的文章也能读懂**，并且能顺着章节找到自己要的那一段。

下面的数字是经验区间，不是配额：内容需要时可以偏离，但要能说清为什么。
目标库已有自己的约定（目录、命名、frontmatter 键）时，**一律以目标库为准**，
本篇不覆盖用户已有格式。

## 一、参考区间

| 指标 | 常见值 | 什么时候该警惕 |
| --- | --- | --- |
| 全篇行数 | 150–300 | 低于 120 行常缺示例；超过 400 行考虑拆篇 |
| 二级标题 | 5–9 | 少于 4 个说明没分层；多于 12 个说明一节太碎 |
| 三级标题 | 0–8 | 只在二级下面确有两块以上内容时使用 |
| 表格行 | 10–40 | 对比、字段、故障矩阵主要靠表格 |
| 代码块 | 3–8 | 讲机制却不给可运行片段，多半没讲透 |
| 外部链接 | 5–15 | 无来源的断言读者无法核验 |
| 散文段落 | 40–120 字 | 超过 200 字拆段，或改成表格 |

这些数字来自「读得下去的技术长文」的共同形态，不是某个库的统计结果；
不同主题差异很大，按内容取舍。

## 二、frontmatter

知识笔记建议带一组稳定属性，方便检索、筛选和更新。常见键：

```yaml
---
type: resource
status: draft
area: <领域>
topic: <主题>
depth: L2
kind: concept
created: 2026-01-01
reviewed_at: 2026-01-01
tags:
  - <标签>
---
```

- `depth`：`L1` 名词级 / `L2` 能复述机制 / `L3` 能动手改，默认 `L2`。
- `kind`：`concept` / `mechanism` / `practice` / `source-review`，与骨架一一对应。
- `reviewed_at` 是核验落点：改写结论、补新版本时更新它，正文不必再单开一节「核验说明」。
- **已有属性不删不改名**；目标库的键与本表不同就沿用它的，不要把本表当模板强推。

## 三、章节：编号，并以参考资料收尾

```markdown
# 一个判断，不是名词

开头一段：具体场景，或一句与常识相反的判断。不要写「本文介绍……」。

## 1. 问题长什么样

## 2. 机制 / 分层

### 2.1 子问题

## 3. 对比与取舍

| 方案 | 什么时候选 | 代价 |

## 4. 失败模式与边界

## 5. 参考资料

- [标题](https://…)
```

约定：

1. **二级标题从 `1.` 连续编号到 `N.`**，最后一个是 `参考资料`。插入新节时重排编号，
   不留 `1. 2. 4.` 这种断号。
2. **`## N. 参考资料` 放在最后**，3–8 条，一行一条 `- [标题](URL)`。
   优先官方文档、原始论文、源码仓库；标题里带版本或编号更好。
3. 三级标题写 `2.1`、`2.2`；只在二级下面确实有两块以上内容时使用。

## 四、段落与句式

- 一段一个判断；连续三段都在铺垫，说明这一节该合并或改成表格。
- 常用句式：
  - 对照式：「A 把控制流写在代码里，B 把它交给模型」——先说清差在哪，再展开。
  - 判断式：「停止条件的作用，是把『什么时候交出控制权』从模型的语气里拿出来。」
  - 代价式：「这样做的收益是 …，代价是 …」——只讲收益的段落通常是没想完。
- 数字优先：写「平均 7.9 条外链」而不是「很多外链」；给版本、给日期、给行号。

## 五、表格与代码

- **表格承担对比**：方案 × 适用场景 × 代价；字段 × 默认值 × 什么时候改；
  症状 × 先查 × 原因 × 修法。表头写名词，单元格写判断，不要一格一句话。
- **代码块承担可运行事实**：完整片段优于伪代码；标 `tested` / `illustrative`。
  讲机制时给最小可跑版本，不贴整份工程。

## 六、收尾

正文最后一段做**桥接**：把本篇的结论接到相邻问题上
（例如「分类负责叫什么，追踪负责在哪一步」），然后直接进 `## N. 参考资料`。
不写「总结」「要点回顾」这类复述段——它们不增加信息。

## 七、反模式

| 写法 | 为什么不行 | 改成 |
| --- | --- | --- |
| 「本文介绍 X 的背景与用法」 | 读者要的是结论，不是目录 | 直接给场景或判断 |
| 「综上所述 / 总结一下」 | 复述不增加信息 | 删掉，末段写桥接 |
| 一节里塞三个话题 | 标题对不上内容 | 拆成三个编号节 |
| 无来源的绝对化断言 | 无法核验 | 给链接、版本或标注「推断」 |
| 只有概念没有取舍 | 读者不知道什么时候用 | 补一张对比表或「代价」段 |
| 用「详见另一篇」外包解释 | 笔记要能独立读 | 本篇讲清，或用一句背景补上 |
| 照抄目标库的栏目但填不满 | 空节比没有更糟 | 按本篇问题取舍，缺项说明原因 |

## 八、怎么用这份文档

- 写新笔记：先照「三、章节」搭编号骨架，再按 `kind` 补内容（见 [笔记骨架](note-templates.md)）。
- 吸收资料进已有笔记：先找到受影响的判断再改，保持原有编号语义，插入新节后重排序号，
  并在 frontmatter 的 `reviewed_at` 记本次复核日期。
- 自检：`python3 scripts/check_notes.py --plan plan.json` 会检查编号、参考资料节与开头禁语。
