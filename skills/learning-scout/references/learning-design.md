# 学习路线设计

一条好路线不是把课程目录抄一遍，而是让学习者**知道自己在哪、下一步做什么、什么时候算过关**。
页面应该像一次有节奏的远征：有入口、有转折、有停顿、有战利品。

## 从“资源清单”升级成“教学循环”

只给链接，学习者不知道从哪里看、看完什么算懂。一个能跟着学的页面要有六件事：

1. **起点**：`learner` 写清基础、目标、每天时间和偏好；不要假设所有人同一起跑线。
2. **一页一个概念**：`paged` 的每篇 `section` 只回答一个问题；先白话解释，再给最小例子/源码。
3. **依据**：每个概念至少一个可点的官方文档、论文或源码；正文先讲，链接放旁边，不反过来。
4. **动手**：`practice.steps` 用 `do / expect / check` 写操作、预期现象和过关标准；让学习者自己做。
5. **回忆**：`quiz` 在阶段末问“不看笔记还能不能说出来”；答错进入薄弱点，不停留在看完。
6. **间隔复习**：`review` 卡片按 1 / 3 / 7 天安排；记录在本机，刷新和下次打开还能继续。

再加一个最终产物（`capstone`）：不是“学完”，而是“做出一个能演示、能解释失败的东西”。
页面应支持继续上次、标记完成、导出学习记录；但不要把本机记录说成云同步。

## 不设固定五栏

阶段不是表单。不要为了凑齐“目标 / 资源 / 任务 / 检查点 / 时间”而写空话。
一个阶段至少要有以下之一：

- 一个要建立的判断或能力（`goal`）
- 一组值得看的资料（`resources`）
- 一个动手任务（`practice`）
- 一个自测问题（`checkpoint`）

时间、类比、绕路、能力清单都是“有则更好”的调味，不是每站必填。
但整条路线至少要有一个真正的动手任务；否则它只是收藏夹。

## 叙事节拍

按内容选择节拍，不必每站一样：

| 节拍 | 作用 | 例子 |
| --- | --- | --- |
| 入口 | 用一个问题或反差抓住注意力 | “先别碰向量数据库。” |
| 地图 | 给学习者一个可复述的心智模型 | “RAG 是一场开卷考试。” |
| 遭遇 | 用 1–3 个资源建立核心理解 | 论文 + 官方文档 + 5 分钟视频 |
| 动手 | 让理解变成一个可检查的产物 | 画流水线、跑 10 个问题 |
| 过关 | 用问题暴露“以为懂了” | “你能分清没召回和没用好吗？” |
| 绕路 | 给愿意深入的人一个入口 | 一个可选的实验或分支 |
| 过场 | 在阶段之间换气、抬视角 | 一句反直觉的话 |
| 收束 | 用一次小实验闭环 | before/after + 下一步 |

不是每个阶段都要“入口 + 地图 + 遭遇 + 动手 + 过关”。有时一站只做一次实验，
有时一站只读一篇论文。节奏比完整性重要。

## 让它有趣，但不幼稚

有效的手法：

- **具体类比**：把抽象系统映射到日常经验，但只用一个，不堆砌。
- **反差**：先说一个常见错误，再给出更好的判断。
- **约束**：给任务加一个现实限制，例如“只准改一个变量”。
- **可见产物**：一张图、一个脚本、一张对比表，比“看完”更有反馈。
- **小胜利**：每站都有一个 20–90 分钟能完成的小出口。
- **可选深坑**：把高级分支放进“学完再跳”，不打断主线。
- **诚实的时间**：不确定就写范围，不写“7 天精通”。

避免：

- 为了“有趣”加无关梗、徽章、积分和伪游戏化。
- 用“轻松学会”“一文搞懂”替代真实难度。
- 用大量 emoji 和感叹号制造热情。
- 把学习失败归因于自律，而不是路线设计或资料质量。

## 认知负荷

- 每站主资源 1–3 个；超过 4 个通常应该拆站。
- 一站只保留一个主任务；练习可以小，但必须可验证。
- 先给可运行的最小闭环，再给生产化细节。
- 对快速变化的主题，先给稳定概念，再给版本相关细节。
- 长课程不必线性看完；写清楚“先看哪几段”。

## 视觉方向

HTML 不是装饰，它是路线的一部分。先选版式，再选主题。渲染器提供四种结构不同的版式：

- `journey`：星图 + 纵向阶段，适合概念递进和完整叙事。
- `atlas`：目录式双栏，阶段标题在左、内容在右，适合资料多、需要快速定位。
- `studio`：海报式开场 + 卡片墙，适合源码、工程项目、多天集训。
- `paged`：一屏一页、滚动吸附、视差背景；适合系统笔记和从头读到尾的教程。

版式决定信息架构；不要用换颜色代替换版式。然后再选四种主题和四种背景 motif：

- `deep-field`：深色、荧光绿，适合 AI、研究、前沿技术。
- `paper-trail`：暖纸色、衬线，适合人文、写作、产品。
- `citrus`：明亮、橙色，适合设计、前端、创意。
- `blueprint`：深蓝、青色，适合系统、基础设施、工程。

选择依据是**内容的性格**，不是随机换色：

- 研究/实验型：深色 + orbit，像在观测信号。
- 工程/系统型：深蓝 + grid/waves，像一张蓝图。
- 人文/阅读型：纸色 + grid，像一本工作手册。
- 设计/创意型：亮色 + bloom，像一块情绪板。

主题只是起点。`accent` 可以换，`motif` 可以换；不要把四套主题当成四张死模板。
页面上的字号、留白、阶段节奏和资源密度，应该跟内容的难度与阅读场景匹配。
首屏不要把标题推得太低：标题、承诺和第一个动作应该尽快进入视野。

## 质量门禁

渲染前检查：

- 主题、承诺、阶段、核验日期是否存在。
- 每个阶段是否至少有一个资源/练习/检查点。
- 整条路线是否至少有一个动手任务。
- 资源是否写了“为什么是它”。
- 链接是否唯一、可打开、没有伪装成免费。
- 视频是否只做了元数据核验却写成“看过了”。

渲染后检查：

- 桌面和手机都能读；标题不被随机拆词。
- 阶段导航、资源筛选、进度勾选可用。
- `paged` 的测验、完成按钮、复习翻面、续读和导出都实际点过。
- 没有横向溢出、遮挡、不可点击的链接。
- 打印或保存 PDF 时，主要内容不丢。
- 页面能离线打开；不依赖远程字体、脚本或图片。

## 收尾

最后一站不要用“继续学习”收尾。给一个**可交付物**和**下一步实验**：

```text
我改了什么 → 哪个指标变了 → 哪个反例还在 → 下一轮只改什么
```

学习者离开页面时，应该已经知道今天要做的第一件小事。
