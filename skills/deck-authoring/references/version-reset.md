# 新版本从零开始：版本隔离

真实返工的样子：v2 在 v1 目录里打开 `source.html`，复制 `deck.css`，改标题、换封面图，
再加两页 —— 交出去被问"这不就是上一版吗"。问题不在能力，在**上一版就在手边**：
"重做"在文件层面没有边界，复制是最省力的路径，改到最后只剩配色不同。

这一页给边界和验收。版本目录契约见 [SKILL.md](../SKILL.md#项目与版本目录硬约束)。

## 什么时候适用

| 用户的实际表达 | 做法 |
| --- | --- |
| "再来一版""换个方向""重新设计""用最新 skill 重做" | 全新设计，走完本页 |
| "沿用上一版那个风格，只更新内容" | 不是重做：在当前版本内改，或新建版本但登记沿用范围 |
| 品牌 / 客户规范指定字体、色值、logo | 该维度可以沿用，但要登记（见"授权沿用"） |
| 换了主题或观众 | 这是新 deck：新主题目录，从 v1 开始 |

"用户没说要换风格"不是沿用理由。新版本默认重做；要沿用，用户得说出来。

## 开工前：把上一版留在门外

1. **新版本目录从空目录开始。** 先只建 `design.md`，写下本版命题和「与上一版的差异」。
2. **不复制、不改写上一版的实现。** 不从 v1 `cp -R` 一个文件，不在 v1 的文件上原地改，
   不把 v1 的 `source.html` / `deck.css` 当模板删字。
3. **设计期间不打开上一版的源。** `source.html`、`deck.css`、`design.md`、`image-plan.json`、
   `refs/` 里的参考截图，都不作为设计素材；"找找哪里还能保留"也算。
4. **会话里已经出现过的旧样式同样算污染。** 不要凭记忆重建上一版的栅格、组件名、
   装饰和封面动作 —— 记忆比文件更隐蔽。
5. **旧版本只留不改。** 不删、不改名、不搬素材；只有用户明确要求才清理。

知道"上一版是暖纸色双栏"并主动避开，和打开它的 CSS 抄一遍，是两件事：前者是判断，
后者是复用。允许前者。

## 必须重新长出来的东西

下面每一维都要在本版记录里写**"本版选什么"**，而不是"和上一版差不多"：

| 维度 | 本版要重新决定 |
| --- | --- |
| 参考 | 重新找；与上一版同一作者/同一系列的第二件作品容易复现同一套语法，宁可换来源 |
| 字体 | 一个承担全部文本的字族（字重、字距、中英混排随之定）；品牌强制才可沿用 |
| 配色 | 色彩角色、明暗关系、纸张或深色底、强调色的用法 |
| 栅格 | 栏数、边距、基线、页面比例、出血与越界的规则 |
| 组件 | 类名、卡片、编号、页眉页脚、图签；重新命名与拆分，不沿用旧组件 |
| 图案 | 视觉母题、背景纹理、装饰线、图标、内联 SVG 路径；重新选，不换色复用 |
| 封面 / 尾页 | 独立设计，不沿用上一版的构图与视觉动作 |
| 配图 | 按新母题重新规划 `image-plan.json`、角色与提示词；复用旧图必须 `source: provided` 并写理由 |
| 页序 | 按本轮问题重新拆页；不沿用上一版的页数、章节顺序与每页骨架 |

用户明确要求沿用的维度照做，但在记录里写明"这一维是用户指定延续"，其余维度仍然重做。

## 比对：定稿后验收，不作为设计参考

```bash
# 三张 hero pages 之后先跑一次，早发现早改
python3 scripts/version_guard.py /path/to/v2-2026-10-19-深色/
# 交付前再跑一次，结果留档
python3 scripts/version_guard.py /path/to/v2-.../ --json /path/to/v2-.../checks/version-guard.json
```

- 省略 `--against` 时自动比对同级与 `_archive/` 里编号更小的 `vN`。目录名必须符合 `vN-...`，否则发现不了。
- 它读 `source.html`（没有时读 `deck.html`）、项目 CSS、`design.md`、`image-plan.json`，
  按九维报重合：CSS 文件、组件类名、字族、彩色色板、背景 / 图案、内联图形、
  页面骨架顺序、图片 / 素材、版本差异记录。
- 结构化 spec 项目先 `render.py` 出 `deck.html` 再比对；只统计版本目录里的 CSS，
  目录外的共享样式不计入，交付前仍要按版本目录自带资源核对。
- **报告只说哪一维重合、重合多少，不打印上一版的具体值。** 这是有意的：把旧色号、
  旧字体重新塞回上下文，等于帮你接着抄。要改就回本版参考重选。
- 硬失败退出 1，提醒退出 0；`--strict` 把提醒也当失败（退出 2）。阈值是重合度上限，
  不是审美评分，见脚本头部注释。
- 它只证明"没有跨版本搬用"，**不证明这一版好看**。审美仍按
  [审美闸门](design-review.md) 看，两者不能互相替代。

失败后的顺序：先确认是不是**整维沿用了**（CSS 逐字相同、字族 100%、页序 80% 以上），
是就回参考重做这一维；再处理单点重合（一处渐变、一张图）。不要靠改色号、换配图
把重合度压下去 —— 那还是同一套设计。

## 授权沿用

只有用户明确说"还用那个字体 / 那个红 / 那个封面结构"时，才允许某一维重合：

```bash
python3 scripts/version_guard.py /path/to/v2-.../ \
    --allow fonts,palette --reason "用户原话：品牌字体和主色必须保留"
```

- `--allow` 的维度写进 `design.md` 的版本差异一节，并在交付说明里提一句。
- 理由写用户原话或品牌规范出处，不写"为了统一"。
- 授权只覆盖列出的维度，其余维度仍然按重做检查。
- 品牌规范指定的字体、色值用 `--allow fonts,palette --reason "品牌规范出处"`；
  这放行的是指定 token，不是整套配色 —— 色彩角色、明暗与构图仍按本版参考重做。
- `brands/` 与 `assets/brand*/` 下的 logo、品牌图本来应逐版一致，脚本不计入图片查重；
  放在别处的固定素材仍要在 `image-plan.json` 登记 `provided`，或对 `images` 单一维度授权。
- "只更新内容、不动设计"不是新版本：在当前版本内改；确需保留旧版交付快照才新建，
  并授权全部维度、在交付说明写明"本版仅更新内容"。

## 常见借口

| 说法 | 实际 |
| --- | --- |
| "内容一样，版式只能一样" | 版式由讲解任务决定，不由材料决定；同一材料可以重拆 |
| "只留了页脚、编号和一条线，不算抄" | 这些最容易成为上一版的签名；重画 |
| "先复制再改，快一点" | 复制会把上一版的判断一起带进来，改到最后只剩配色不同 |
| "用户没说要换风格" | 新版本默认重做；沿用需要用户明确说 |
| "字体是品牌的" | 品牌字体可以登记沿用，其余维度仍要重做 |
| "报告只有一项硬失败" | 一项也是失败；提醒也要能说出本版依据 |

## 交付前

- 两版缩略图并排看：轮廓、密度、封面是否一眼能分开；分不开就是没重做。
- `checks/version-guard.json` 留档，`design.md` 写清本版差异与沿用授权。
- 相似度检查是分钟级的，不能以"没时间"跳过；补做的成本比重做一版高。
- 贴图 PPTX / PDF 等导出按 [交付格式](delivery-formats.md) 另验，跨版本检查不替代它们。
