# 配图、背景与素材回填

先明确图片帮助观众理解什么或形成什么视觉感受，再决定来源与处理方式。图可以直接承载页面的主要内容，而非只作文字旁的配饰。
主视觉、解释图、真实截图和背景承担不同任务；HTML/SVG 的精确图解同样是视觉表达，不必为了叫作“配图”另生一张图片。
完整新稿必须规划配图并交 `image-brief.md`：位图由用户生成或提供，作者不代生图；只有用户明确要求纯文字或局部文字编辑才免除相应步骤。
可以组合授权照片、原始截图、图表、生成图及精确的 HTML/SVG 解释层，不把某次项目的风格或色板写成全局默认值。
**但具象角色（小人、机器人、动物、场景物件）只能有一套实现**：生成位图与手写 SVG 角色不能在同一套里并存，
边界见[一套 deck 只有一套形象](#一套-deck-只有一套形象先选媒介再画页面)。
用户明确的素材限制持续有效，禁止 SVG 的 HTML 项目使用 `--raster-only`。

## 从页面到图像，再回到页面

1. **页面提出需求。** 在正文排满页面前，逐页写清图像承担什么、替代哪些文字、使用页、图位及主体与文字的避让位置。默认让各内容页有可解释的视觉主体；流程、机制、架构、比较与证据页尤其如此。结论过渡或完整参考表可不额外配图，但不能因文字已占满而放弃图。图位可跨栏、出血、局部放大、嵌入节点或作为背景，不默认每页右侧矩形框。
2. **先写交接清单，不代生图。** 位图只有一条路：量图位 → 写 `image-plan.json` → 运行 `--brief` 交 `image-brief.md`。用户拿 brief 用自己的模型生成，或提供真实素材；作者不调用生图工具、不下载素材站图片。
   - **生成图**：`prompt` 写完整可执行提示词（本版媒介、光线、色板、构图、主体位置、文字安全区、负向约束），`target_px` 按实际图位量出，`source` 记 `generated`。brief 里的提示词要能整段复制给任意模型。
   - **真实素材**：截图、证据、授权照片、官方资产在计划里写 `source: "provided"` 与 `source_note`，说清用途、尺寸和来源要求，请用户提供；不代用户判断许可，也不代下载。
   - **交接**：`image-brief.md` 交出去后按文件名回填到 `assets/images/`；图未回填前不导出。
3. **回填并记录来源。** 用户生成图、真实截图、授权素材都按计划路径落盘，在 `image-plan.json` 写清来源。
   真实界面、数据、现场与实验结果不能用生成图冒充；截图另说明采集位置与需要展示的状态。
   找不到合适素材就留白并说明，不用来源不明的图硬凑。
4. **回填到原图位。** 核对路径，局部调整比例、焦点与背景层；不为了插图重写无关页面。新素材不覆盖仍需保留的原图。
5. **看实际页面。** 检查主体裁切、文字避让、背景衔接和素材瑕疵，再更新导出。文件合格与页面完成是不同状态。

已有素材先登记来源与用途，不为凑数重新生成；完整新稿仍需交付素材说明，说明哪些由用户生成、哪些是真实截图或授权素材。
已有结构化 spec 继续用自己的请求合同及 `image_source.py --brief`，不另维护第二份计划；该脚本只写契约与验收，不提供生图后端。
尚未有 HTML 时可先交 Markdown，但明确图位尚未接入。

## 文本为主还是图像为主

不是配额，是判断。先看材料要观众做什么，再决定图占多少：

| 材料 | 默认主导 | 图做什么 |
| --- | --- | --- |
| 活动、品牌、叙事、情绪、公众演示 | 图像主导 | 母题、场景、人物、氛围；可以连续多页都是图 |
| 机制、架构、流程、数据、评审 | 图形主导 | 图解、图表、剖面、标注、大数字；照片只做证据或气氛 |
| 合同、附录、密集参考、规范 | 文字主导 | 导航、证据、局部放大；不为了"有图"打断阅读 |

同一份材料可以两种都成立：以每页的问题、观看条件和证据要求判断，不以"应该有几张图"判断。
图像能承担解释或气氛就多用，不设上限；图只是重复文字或在凑数，就删掉。

## 素材来源与许可

**参考图不是素材。** 用户给的作品截图、海报、影片帧只放 `refs/`，用于提取画风关系，
**永不放进 `assets/images/`，也不在页面里当 `<img>` 引用**。把它剪进页面等于让用户以为
这就是成品画面；它没有登记来源、没有按本版图位重画，也不承担任何解释。
先有 `image-plan.json` 与本版提示词，再由用户按文件名生成或提供——顺序见
[风格证据](../references/style-evidence.md) 与 [阶段闸门](../references/stage-gates.md) 的 G4。

作者不代下载素材。需要真实照片或外部资产时，在 brief 里写清主题、用途、尺寸和许可要求，由用户自行取得；可以在 brief 里把下面这些来源列为候选，但“能下载”不等于“能用”：

| 来源 | 适合 | 注意 |
| --- | --- | --- |
| Unsplash / Pexels / Pixabay | 摄影、场景、人物氛围 | 免费但逐张看许可；不冒充真实产品、事件或实验结果；人物注意肖像权 |
| Wikimedia Commons / Openverse | 历史、地点、物件、CC 授权素材 | 逐张核对许可证与署名要求，保留作者与 URL |
| Met / Rijksmuseum / Smithsonian Open Access | 文物、艺术、时代图像 | 多为公共领域，仍核对单件声明与分辨率 |
| Poly Haven / Kenney | 3D 环境、HDRI、模型、贴图 | CC0；适合搭建场景与材质，不直接当产品证据 |
| 官方品牌资产 | logo、产品图、界面 | 用官方文件并遵守品牌规范；不重绘官方标志 |

用户提供素材后，作者在 `image-plan.json` 的 `source_note` 写作者、URL、许可证；截图写采集位置与状态。
生成图也要在计划里保留完整提示词，便于复核与重出。

## 先量图位，再写宽高

图位的像素尺寸在页面里量，不在提示词里猜。跳过这一步，常见的三个后果是：素材按模型的默认比例
（1:1 或 16:9）出来，塞进图位后被 `cover` 裁掉主体；`contain` 留出一圈对不上的底色；
图被附近的卡片或遮罩盖住一角，回填后才发现。

1. **量图位。** 图位尺寸在写 CSS 时就定下来（固定宽度 + `aspect-ratio`，或按栅格算），拿不准就在
   1600×900 下读实际渲染尺寸；再乘捕获倍率：PNG / 贴图 PPTX 默认按 3200×1800 捕获用 2×，
   只交 PDF 可用 1×，同时交多种格式按 2×。结果写成 `target_px`，比例由这组像素得出，不预设 16:9。
   同一素材用在多页时按最大图位定尺寸，`pages` 写全。
2. **让 brief 把尺寸放在提示词第一行。**「输出规格：1200 × 800 px（3:2）。按此比例原生生成，不裁切、不拉伸、不加白边。」
   生成工具没有“这个图位”的概念，只写“横向构图”它会自己挑比例。`image_handoff.py --brief` 会按
   `target_px` 自动补这一行，不要手写进 `prompt` 字段；用户自己执行时也能照抄首行。
3. **把构图换算成百分比。** 主体占哪块、哪一侧必须空出来给标题、边缘留多少安全距离，
   写成「主体在右侧 55% 宽度内，左侧 45% 保持低细节」这类可判断的约束，进 `prompt` 与 `negativeSpace`。
4. **回填后核对真实像素。** `image_handoff.py --check` 会报实际尺寸、需放大倍数和裁切比例；
   需要放大、或 `cover` 裁掉的比例超出设计时，请用户重出或改图位比例，不用 `object-fit` 把问题盖过去。
5. **功能图不靠裁切落地。** 流程、图表、剖面、截图这类要读内容的图，素材比例必须等于图位比例；
   确实要 `contain` 时，图位底色与图内底色必须一致。

多数生成工具只有几档预设比例（1:1、4:3、3:2、16:9…）。图位比例尽量落在预设上；
落不上时，要么改图位，要么在提示词里让主体收在中心安全区、接受小幅 `cover` 裁切——
功能图不在此列，比例不对就改图位。

尺寸、主体位置、空区和光向都要落成数字与方位。“留白一点”“高级感”生成不出可用的图位关系。

## 交接给用户时的做法

- **不在 skill 内出图。** 不调用宿主图像工具、MCP、HTTP API 或命令行生图程序，也不为出图临时写脚本；项目里不留生成服务密钥。
- **不复用旧出图脚本。** 目录里已有 `gen_images.py` 或类似调用生成服务的脚本时，不执行、不改造、不把它当成素材来源；本版配图仍从 brief 重新交接。
- 按计划的 `prompt`、`target_px`、`negativeSpace` 逐张写全；brief 是用户唯一的执行依据，文件名、目录、使用页都要能直接照做。
- 提示词里把 `target_px` 写成输出规格，主体位置、安全区、光向和负向约束都落成数字与方位。
- 系列一致靠同一段媒介/光线/色板描述、同一视角与裁切规则；需要参考图或种子时，在 brief 里注明让用户固定。
- 用户回填后逐张看：主体、文字安全区、裁切、伪文字、水印、肢体与边缘；不合格列出来请用户重出，不将就。
- 逐张核对实际像素与比例；尺寸不对先请用户重出，不靠 `object-fit` 掩盖。
- 真实界面、数据、现场与结果不能用生成图冒充；这些位置用截图、原始图表或明确标注的示意。
- 免费 HTML 计划用 `image_handoff.py --check` 验收；结构化 spec 用 `image_source.py --check`。

## 封面与尾页的图，单列出来

封面和尾页如果需要图，必须在 `image-plan.json` 里**单独成条**：`role` 写 `cover` 或 `finale`，
`purpose` 写清它承担的是氛围、材质还是主体。

- 不要把它混进正文图列表里——正文图讲证据，封面图定语气，两回事。
- 没有就明说"封面无图，由版式承担"，不要留一个空图位到最后。
- 这两处的图和正文图**同一批交给用户出**：风格、光线、色彩角色一致，否则头和尾会像两套 deck。
- 章节页和议程页的图也单列（`role` 写 `section` / `agenda`），复用同一母题；它们决定整套节奏，
  不是正文图的附赠。

## 提示词随视觉方向适配

配图不是独立风格：它和本版选定的参考同源。写提示词前，先从 `design.md` 抄出四个变量，再逐个翻译成**可执行的约束**。

| 从视觉命题里取 | 翻译成提示词里的东西 |
| --- | --- |
| 媒介 / 材质 | 摄影、扫描、手绘、版画、3D；颗粒、网点、纸纹、墨边、反光 |
| 明暗关系 | 高调还是低调、对比度强弱、光源方向、是否单色 |
| 色彩角色 | 只留几个色、强调色出现在哪、哪块必须留给文字 |
| 构图与出血 | 主体位置、裁切方式、留白区、是否需要透明底 |

写法要求：

- **用可判断的约束，不用形容词**。"黑白高对比、硬光自左上、纸边锐利"能执行；"高级感、科技感、克制"不能。
- **负向提示也来自方向**：手绘方向排除照片质感与渐变；排印方向排除插画与 3D；深色工程方向排除白底截图。
- 同一套图要并排看出同族：媒介、光源、色彩角色一致，**主体与构图随页面变化**。
- **换版本就重写**。上一版的提示词属于上一版的方向，不能拿来就用（见[素材也按版本走](refined-workflow.md#素材也按版本走)）。
- `purpose` 写本页要解释的问题，不写风格词；风格由提示词承担。

自检：把这句提示词换到另一个方向的项目里——如果仍然成立，说明它太泛，没有承担方向；如果换页就不成立，说明它只够做一张图，也不合格。

## 什么时候把段落变成图

先判断这段文字在做什么，再决定要不要画：

| 文字在做的事 | 处理 |
| --- | --- |
| 陈述判断、理由、风险、边界条件 | 留在文字 |
| 描述**对象之间的关系**：顺序、包含、依赖、对照、阈值 | 变成图，文字只留判断与条件 |
| 枚举 3 个以上并列项且要比较 | 变成矩阵或条带，不要写成三段并列文字 |
| 讲"在哪一层、在哪一段、谁写给谁、什么时候切" | 变成剖面或流向 |
| 精确参数、契约条款、需要逐字检索的内容 | 留在文字或表格 |

做法：把段落改写成一句「**谁 → 对谁 → 什么关系**」。三个成分都能指认，就画；只能得到一句判断，就别画。

验收两个方向：

1. **遮住文字**，图能不能回答本页的问题？
2. **遮住图**，文字是否只剩判断与条件，而不是在复述图？

常见该画没画：三个真源的"应该 / 实际 / 物化"、完成声明的证明链、拒答的三种原因、fail-closed 的四条边界。
常见不该画却画了：只有一句判断的封面、把一个表格拆成一排等宽卡片。

## 让配图承担解释，让背景参与构图

在现有 `design.md` 的页序中简记“视觉要解释什么 / 图片与 HTML 各负责什么 / 正文保留什么 / 背景怎么配合”。
这份记录覆盖封面与所有内页，不要求新增固定风格字段或另建一本设计手册。

- **封面**有专门设计的主视觉与背景关系：可以是排印海报、图形构成、场景、摄影或其组合，按参考安排焦点和安静区；不要求额外的大幅插画，也不固定标题与图片的左右位置。
- **内容页**围绕具体对象设计：过程展示对象如何变换及分支；机制展示剖面、状态或输入输出；比较让同一尺度下的差异可见；证据可用真实图像的局部放大与对应注解。选择服从内容，不是页型套餐。
- **背景层**要支持当前焦点和阅读路径：可用场景延伸、材质、图像局部、色域、渐变或空间层次。密集区域可以保持安静纯色，整体仍须有设计过的前后层次；不靠把一张壁纸铺遍全套交差。
- **文字与图分工**：图承担了位置、关系或变化后，正文留下判断、解释缺口及重要条件；完整参数、代码或清单可移入可读的附录。信息图可以包含标题、标签、图例与短注，甚至占据整页；问题是重复和负担，不是图里能不能有文字。把原段落截图再贴回页面，没有改善表达。

比较能力可以用共同维度的矩阵，符号区分支持、受限与不支持，条件紧邻对应单元；流程可以直接呈现分支和状态，
不必另用长表复述。先核实具体模型/版本/条件，参考图只用于学习表达，不能将其中的旧结论直接作为新项目事实。
精确标签与频繁更新的数据优先放在 HTML/SVG 层；用户需要完整位图信息图时可一体生成，逐项复核文字、符号与关系，
保留可更新的内容来源。矢量、位图与图中嵌字按清晰度、编辑需求和实际工具选择；这里的“混合”指图层，不是在同一套里换角色画法。不设全局“图片禁字”。

功能图提示词需写清必须出现的对象、方向、顺序/并行、状态、边界与省略内容。可将对象插图嵌入流程节点，
或在整体图像上就近叠加精确技术名、数值、条件和箭头；它们共同构成一张解释图。
需要标签的位置和连接端点在图位设计时确定，避免出图后再挤入旁边的长表。
生成层不画文字不等于页面不能在图中标注；“无字隐喻图 + 另一栏完整说明”若没有减少解释负担，应重新构图。
图上节点已能辨认时，不再给每个节点添加重复图标；装饰用于识别对象和建立节奏，不虚构额外模块或连接。
检查解释图时暂时忽略旁边的说明：观众能否从图读出本页核心关系？若仍要逐段读正文才能理解，重做图的表达，不能仅增加图数或扩大图框。
需要生成器绘制关系时逐项复核，不能让模型自由补造架构。装饰图不能顶替功能图验收。

每页有视觉表达不等于每页新生一张大图。同一组对象素材可以复用、局部放大或逐步展开；复用项的 `pages` 写全实际使用页。
一页使用多个节点素材时各自登记路径和图位，提示词约定一致视角与尺寸感。按需交接素材，避免为图片数量制造无用文件。

同一项目的图片沿用已确定的媒介、质感、色彩与构图关系；每张再根据本页任务调整主体、视角和裁切。
把这些决定写进提示词或选图条件，不能只写“符合整套风格”。可用参考图时在 brief 里注明让用户传入并记录用途，
仅有文字描述时不声称模型看过参考。用户回填后若关键质感或主体不符合方向，请用户改素材或调整构图再验证，
不要用统一滤镜掩盖不匹配。系列一致不要求同一主体、相同比例或每页同一位置。

## 一套 deck 只有一套形象（先选媒介，再画页面）

同一套演示里，**具象角色只能来自一种实现**：全部是生成位图，或全部是手写矢量，或全部是照片/实拍。
不能封面用生成的黏土小人、内页又用 SVG 描一个同款小人；也不能背景位图里已经有角色，前景再叠一个 SVG 角色。
观众会读成两个 IP、两套画风，配色再接近也救不回来。

先分清两层，再决定能不能混：

| 层 | 内容 | 能否跨媒介 |
| --- | --- | --- |
| 形象层 | 有身份的小人、机器人、动物、手、场景、物件插画 | **不能**。一套只用一种实现；同一角色在不同页保持同一造型 |
| 图形层 | 图表、流程框、节点、连线、箭头、标注、边框、图标、纹理、遮罩 | 可以。它们不承担“角色”，与位图同页不构成第二套形象 |

判断方法：把整套缩略图并排，遮住文字，逐个指认“有脸 / 有身体 / 有固定造型”的对象。
如果同一个对象出现两种画法，或不同页的小人明显不是同一套，就是硬伤；纯结构框线不算。

- 文件格式（PNG / WebP / JPG）可以混，**媒介不能混**。需要矢量精确时，画抽象结构（框、线、节点、剖面），
  不要用 SVG 重画位图里的角色；整套走矢量角色时，也不要再用生成位图补同一个角色。
- 媒介在样页阶段定下来，写进 `design.md` 的视觉命题和 `image-plan.json` 的 `styleDirection`
  （“形象来源：生成位图 / 手写矢量 / 照片”）；之后新增页面只能沿用。
- 封面背景图已经含角色时，前景只放文字、标签和细线，不再叠同类角色——这是最常见的“配图互相覆盖”。
- 一页最多一套角色。两个不同来源的角色同框，比没有角色更糟。
- 已经混了怎么收口：先定哪一套是主形象（通常是有提示词、可重出的生成位图），把另一套角色从页面删除或替换成同一套的图；
  不能靠统一配色、描边或滤镜把两种画法拉近。

## 让图像组成一个世界，而不是一页一张插图

有冲击力的成套演示，靠的通常不是“每页配一张图”，而是**同一个视觉母题反复出现并变形**：
秋日花园的蘑菇与藤蔓、定价方案的价签、项目启动的倒计时轨道。母题同时充当封面主视觉、
章节标记、内容页的结构和数据的框；观众缩小看一眼也能认出是同一套。

先定三件事，再写 `image-brief.md`：

1. **母题**：一个可放大、可缩小、可裁切、可重复的对象/形状/材质/照片处理。
   它要能解释主题，而不是通用装饰——蘑菇解释秋日花园，价签解释定价，倒计时解释上线。
2. **出现方式**：至少三种角色——封面（整幅或出血）、章节/议程（标记、框景或容器）、
   内容页（主体、容器、标注或数据背景）。同一母题重复 3–6 次，每次换尺度、位置和角色，
   不换素材气质；不要每页复制同一张图。
3. **图文关系**：图可以出血、嵌套、遮挡文字区、被文字压住边缘或低细节区（不压主体）、做成容器或标注；
   不要把图统一缩成右侧小方块。每页先决定“图占多少、文字退到哪里”，再排字。

母题不一定是一张生成图，常见五类形态：

| 形态 | 适合 | 例子 |
| --- | --- | --- |
| 插画对象 | 活动、教育、主题化演示 | 蘑菇、香草、人物、场景小物 |
| 图形装置 | 商务、技术、数据 | 价签、倒计时轨道、框架、编号牌、刻度尺 |
| 照片处理 | 品牌、团队、现场 | 统一拱形/圆形裁切、双色调、局部拼贴 |
| 3D 场景 / 渲染 | 技术、产品、空间 | 等距房间、产品爆炸图、抽象几何、材质球 |
| 材质 / 表面 | 排印、编辑、档案 | 纸纹、墨边、网格、金属、扫描质感 |

**母题不是 signature move。** 母题是这套 deck 的素材系统（蘑菇与藤蔓），
signature move 是它在页面上的固定动作（“蘑菇从卡片顶部溢出来”“数字放在花环里”）。
先定母题，再定 2–3 个动作；动作重复 2–5 次，别每页发明一个新动作。

母题从内容里长出来，不从装饰库挑：

- 找材料里反复出现的对象、动作或单位：花园 → 蘑菇；定价 → 价签；上线 → 倒计时。
- 把它压成一个可缩放、可裁切、可重复的形状，而不是一张只能用一次的完整插画。
- 规定它在封面、章节、内容三种角色里的形态，再交给提示词或 SVG。

按内容选默认路线：活动、品牌、营销与公众演示走**图像主导**；技术、数据与评审走**图形主导**
（图形装置 + 图解 + 大数字，不必生成插画）；纯文字只留给确实需要密集阅读的附录型材料。
不确定时看缩略图——如果观众只能靠读字理解，就是还没选对路线。

**先画视觉分镜，再写页面。** 6–10 行的表，逐页写视觉载体与母题角色；连续三页同一载体就换：

| 页 | 本页要回答的问题 | 视觉载体 | 母题角色 | 图文关系 | 图位 / 文件 |
| --- | --- | --- | --- | --- | --- |
| 1 封面 | 这是什么活动 | 整幅插画 + 大字 | 主视觉 | 图压底部，标题占左上空区 | `cover.png` |
| 4 章节 | 进入第二部分 | 暗底满幅 + 大号数字 | 二次大尺度 | 数字在花环里，标题压图 | `section-02.png` |
| 7 课程 | 三个工作坊 | 三个种子袋形状 | 容器 | 插图从卡片顶部长出来 | `cards.png` |

分镜表放在 `design.md` 或单独的 `visual-storyboard.md`，先于 HTML；它防止“先排字、后补图”。
分镜里如果一半页面写不出视觉载体，说明母题还没选对，回参考重新找。

照片处理也要成系统：统一裁切形状、色调、边框或蒙版；不要一张圆角、一张拱形、一张全幅。
人物与现场照片是活动、品牌、团队演示的有效载体，但技术材料里不能拿人物照替代事实与分解图。

图像/图形主导的材料里，**封面、章节页和议程由主视觉承担主体，内容页让图参与解释而不是只做插图**；
文字主导的合同/附录可以以文字为主，但封面与章节仍要有视觉角色。数量由内容决定，不设上限：一页可以只有一张主视觉，也可以整页是图；图集、步骤、前后对比
可以连续多页。判断标准是每页的图是否承担了解释或气氛、构图与角色是否在变，而不是张数。
材料确实需要密集文字时说明理由，但封面与章节页仍要有主视觉。

自检：把整套缩略图缩小到看不清字，仍能认出同一个世界、同一套叙事节奏吗？
如果缩小后只剩一排排文字块和右侧小图，说明这一版还是文字优先，回参考重做图像系统，
不要靠加大标题或换字体补救。

成套主题站适合观察这种母题如何贯穿封面、议程、章节与内容页，例如
[PPT-Design 主题](https://ppt-design.com/zh/themes)；取它的图像系统与节奏，不复制版式与主题符号。

## 配图与背景的设计边界

| 图像任务 | 内容依据 | 页面处理 |
| --- | --- | --- |
| 概念或情境主图 | 材料中的主体与含义 | 可以摄影、插画、3D 或其他媒介；不要默认居中或占满单栏 |
| 架构、流程与数据 | 核实的节点、关系、数值 | 优先保留可编辑标签；生成图同样要逐项复核事实 |
| 界面与现场证据 | 真实文件或授权素材 | 保全必要标注与上下文，不为了色板重绘证据 |
| 整页或局部背景 | 阅读路径与文字位置 | 决定图像、保护层与文字层的关系；不要求底栏或固定遮罩比例 |
| 透明主体 | 需要跨越色块或露出底层 | 请求真实 alpha，保留透明通道，检查边缘和底色融合 |

背景可以是纯色、图片、渐变或组合。文字覆盖图片时，先找低细节区域；必要时再调图片位置、局部遮罩或底板。
遮罩应解决实际对比问题，不统一铺黑。标题、正文与需要精确编辑的数据通常留在 HTML 层。

文字和图只有两种合法关系，先选一种再排：

| 关系 | 做法 | 常见错法 |
| --- | --- | --- |
| 文字在图外（默认） | 图位与文字各占各的区域，图注放图位外的正常流 | 文本框飘到图上“补空”，看上去像没排完 |
| 文字压图 | 图里预留安静区（写进 `negativeSpace`），需要时加局部 scrim 或底板，回填后按实际画面复测对比 | 正文压在高细节区，靠一层半透明黑盖满整张图 |

压图是重点页的动作（封面、章节、证据页很常见），不要每个内容页都靠它收场；
每页都要能指认“文字落在图上哪块空地”。每次都要加大遮罩才读得清，说明这张图不该承担这个位置：
换图或把字挪出去，调 z-index 解决不了这个问题。

按最终图位及导出倍率确定目标像素。`cover` 填满图位会裁切，`contain` 保全原图会留边。
主体位置、文字安全区与透明需求写入提示词，实际 CSS 再落实 `object-fit` / `object-position`；
这些值不会因写进计划就自动改变页面。相同比例不证明主体没被切掉，文件尺寸充足也不证明标签清楚。

## 图层、裁切与格式

**图层顺序**：背景 → 装饰 → 内容图 → 遮罩/叠层 → 文字/标签。用一组明确的 z-index 层级（例如 0/10/20/30），
不要让后写的卡片靠 DOM 顺序无意盖住图。绝对定位的图先确认父容器高度、`overflow` 和最终画面；
被压掉一角、被卡片切掉一半，都算没做完，除非是设计特意需要的遮挡。

图被盖住先按三种原因查，别急着换图：后写的卡片或标签没有定层；父容器 `overflow` 切掉一角（这是尺寸错了）；
动画包裹层在播放期间临时成了独立图层。参与叠压的元素各自显式定层，顺序才不会随动画起落变化，
见[落定后层级不能变](animation.md#落定后层级不能变)。

**裁切**：`object-fit: cover` 是图内部的裁切，安全；父容器 `overflow: hidden` 把图切掉一部分，
通常是尺寸或容器高度错了。需要艺术裁切时，把主体放进安全区，并在元素或容器上写
`data-web-check-allow="media-clipped" data-web-check-reason="有意裁切，主体完整"`。
`web_check.py --check` 会报 `media-clipped`（被容器裁掉）和 `media-occluded`（被不透明元素盖住），
两者是 review；不要靠隐藏、缩小或换图绕过。相同元素还可以用同样的方式豁免 `media-occluded`。
SVG 自身也要看：`viewBox` 是否包含全部图形、`preserveAspectRatio` 是否把内容切掉；
容器没裁，图自己也可能露不全。

**格式**：按内容、透明、交付格式和文件大小选，不按"哪个更高级"选。

| 格式 | 用在哪 | 注意 |
| --- | --- | --- |
| SVG | 图表、示意图、图标、需要清晰缩放的几何图形；文字标签留在 HTML | 生图模型很少输出真矢量，伪 SVG 常是位图包一层；原生 PPTX 支持有限 |
| PNG | 透明主体、截图、需要精确像素的插画 | 文件大；照片不用 PNG |
| WebP | 照片、带透明的插画、Web 交付 | 体积小；部分工具/宿主不支持，PPTX 导出前转 PNG |
| JPG | 不透明照片、背景 | 无透明；反复编辑掉质量 |
| AVIF | 现代 Web 照片 | 兼容性差；不用于 PPTX/PDF 交付 |

生成能力：多数生图模型输出 PNG / WebP / JPG，不输出真 SVG；需要矢量精确时用代码或手写 SVG，
或生成后描摹。有些工具能输出真 SVG，先打开看是路径/文本还是嵌入位图，不能只看扩展名。透明图用 PNG/WebP；PDF/PPTX 导出前确认 SVG 是否被栅格化、是否仍清晰。
同一套图混用**文件格式**（PNG / WebP / JPG）可以，但要统一视觉处理（裁切形状、色调、边框），
不要一张圆角、一张拱形、一张全幅；**文件格式统一也不等于形象统一**，具象角色的媒介不能混（见[一套 deck 只有一套形象](#一套-deck-只有一套形象先选媒介再画页面)）。

## 自由 HTML 的图片计划

`image_handoff.py` 不生图、不改 HTML。它把本版配图整理成一份**可执行清单**：占位图位、目标路径、尺寸比例、用途与提示词。
全部配图默认先占位，用户生成后按文件名放进 `assets/images/` 即生效。

### 占位是空白框，不是贴在图上的说明

图位从一开始就指向最终文件路径。缺图时只显示一个**空白占位框**（虚线、淡底或斜纹任选），
图放进去刷新就是真图——不改 HTML、不跑接入步骤、没有 pending 状态。

**占位框里不放任何文字**：不写“待配图”、文件名、尺寸、编号、alt 文案，也不用 `position:absolute`
把说明压进图像区域。缺哪张图看 `image-brief.md` 和 `image_handoff.py --check` 的输出，不靠页面自述。
回填后更不能残留占位文案——图与说明同框，就是观众看到的“字盖在图上”。

```html
<figure class="img-slot" data-image-id="scan-vs-digital">
  <img src="assets/images/scan-vs-digital.png" alt="左右并置：左侧数字版，右侧扫描件"
       data-placeholder onerror="this.setAttribute('data-missing','');">
</figure>
```

```css
.img-slot { position: relative; background: #eceae5; border: 1px dashed #c9c5bc; overflow: hidden; }
.img-slot > img { display: block; width: 100%; height: 100%; object-fit: cover; object-position: 50% 50%; }
.img-slot > img[data-missing] { visibility: hidden; }   /* 保留空框，不显示破图 */
```

- `data-placeholder` 是**声明**，不依赖 `onerror` 时序：导出遇到它缺失时跳过该图，不判失败。
- 缺图与有图都只呈现图本身；占位阶段照常检查容量、裁切与文字避让，不靠标签辨认缺哪张。
- 需要图注时，把 `<figcaption>` 放在图位**下方正常流**，写图的解释而不是文件名/尺寸；
  图注不得绝对定位到图上，也不得在回填后保留“待配图”字样。
- 命名约定：`assets/images/<id>.<png|jpg|webp>`，与计划里的 `id` 一致。
- 背景图同样用绝对定位的 `<img data-placeholder>` 配合叠层 CSS，保留明确资源路径。

### 文字与图的安全区

先定图的主体与焦点，再排文字：标题、正文、标签、页码都不能压在图的主体上。
整页背景图上的文字放在主体之外的空区，或加可读遮罩；遮罩也不能盖住主体。
生成提示里写清 `negativeSpace`（文字安全区），回填后按实际画面复测，不按提示词假设。
压图页回填后看三件事：主体有没有被字盖住、对比够不够、第一眼还认不认得出图的焦点；
三项有一项不成立，就把字挪出去，而不是继续加遮罩。
图上的标注、引线、区域框是设计层，可以叠；占位说明、文件名、尺寸不是设计层，回填后必须消失。

### 计划文件

计划使用 `schemaVersion: 1`，顶层包含 `project` 与非空 `images` 数组。
建议写一句 `styleDirection`（本版的媒介/明暗/色彩/构图关系，以及贯穿画面的母题），其中写明具象角色的实现媒介（生成位图 / 手写矢量 / 照片），让后续改图的人按本版方向
重写提示词，而不是沿用上一版；同一套图的 `purpose` 要能看出它们属于同一个视觉世界。

| 字段 | 含义 |
| --- | --- |
| id / pages / file | 稳定标识（与文件名同）、实际使用页数组、项目内相对路径 |
| role / purpose | 图像职责与本页要解释的问题 |
| target_px / fit / focal | 目标像素 `[宽, 高]`（量自实际图位 × 导出倍率，不用默认比例）、cover 或 contain、焦点 `[横向%, 纵向%]` |
| alt | 图像内容的替代描述 |
| prompt | 完整生成提示，按本项目对象、关系、媒介与构图编写；输出尺寸由 `target_px` 补，不写进这段 |
| source / source_note | 默认 generated；已有素材用 provided 并记录来源 |
| negative / negativeSpace / transparent | 排除项数组、文字安全区描述（写方位与百分比）、透明背景布尔值 |

`role` 用同一套词，整套覆盖才检查得出来：

| role | 用途 | 计划里怎么记 |
| --- | --- | --- |
| `cover` | 封面主视觉 | 单列一条 |
| `section` | 章节页（长稿每章一次） | 每章一条，或共用一条母题素材 |
| `agenda` | 议程/导航页 | 单列一条，可复用母题 |
| `subject` | 内容页的主体对象 | 每个主体一条，`pages` 写全 |
| `evidence` | 真实照片、截图、现场证据 | 每张一条，保留来源 |
| `background` | 整页或局部背景/材质 | 可多页复用 |
| `motif` | 可重复的透明底母题素材 | 一条，`pages` 写所有出现页 |
| `finale` | 尾页 | 单列一条 |

15 页以上的长稿默认有章节页与议程页；章节页是整套的呼吸点，也是母题第二次大尺度出现的地方，
不是多出来的一页。短稿可以没有议程，但封面、内容与尾页仍要有视觉上的接续。

完整新稿的计划至少覆盖：`cover` 1 条、有章节页时每章 1 条 `section`、`agenda` 1 条；
内容页按视觉分镜接图，不设数量上限。连封面、章节和议程都没有视觉角色，通常是页面已经按文字排完了，
图只是补进去的——回视觉分镜重排，不要用“图可以后补”解释。

不提供固定色板、材质或主体的默认提示词；这些决定来自本轮视觉方案。

`pages` 写真实使用页；比例从 `target_px` 推导，也可显式写一致的 `aspect`。
`source: "provided"` 的复用项省略 `prompt`，其余图位字段保留。
透明图必须 PNG / WebP；这不证明抠图边缘合格。
复用素材按最大图位检查，并在所有使用页目检；不同比例的图位必要时采用不同素材。

```bash
# 交接清单：逐图提示词 + 目标路径 + 尺寸，附占位片段
python3 scripts/image_handoff.py --brief /project/image-plan.json --html /project/source.html
# 编译：缺图只提醒，不阻塞
python3 scripts/web_deck.py /project/source.html -o /project/deck.html --image-plan /project/image-plan.json
# 图放齐后确认文件与图位（导出闸门；退出 1 就停）
python3 scripts/image_handoff.py --check /project/image-plan.json --html /project/source.html
```

`--brief` 创建 `image-brief.md`：逐图给出文件名、目标路径、尺寸比例、用途、完整提示词与负面约束
（提示词首行是输出像素规格，整段复制即可交给用户自己的生成工具），
外加可直接粘贴的占位片段。不覆盖人工修改；新版本用 `--out briefs/v2.md`，交付时链接当前有效版本。
`--check` 验文件是否就位；带 `--html` 时同时扫描页面里残留的可见占位文字。图还没回填时不必跑它。

**交完 `image-brief.md` 就停在这里**：告诉用户逐图提示词、目标路径和回填方式，等他生成；不代生图，也不因等待把图位删掉或改成纯文字。
再按 [导出前的两个问题](delivery-formats.md#导出前的两个问题) 处理。图没回填前不导出 PDF / PPTX；
`--check` 退出 1 就报待补文件并继续等，退出 0 才进入格式选择。

缺图阶段按占位外观检查版式：不挪走图位、不写假成品图、不用错误的后备图永久替换目标路径。
图放齐后刷新预览、重新截图并导出，已有 PDF/PPTX 不会自动更新；补图后要重导，
不能把旧文件说成已包含新图。
静态检查不认证 CSS 背景、`picture/srcset` 或脚本换图，这些需浏览器另核对。

## 结构化 spec 的兼容接口

`visual.kind` 使用 `none`、`data`、`evidence_image`，图位比例用 `visual.ratio`。
可选 `visual.imageBrief` 保存本图用途与提示词意图：`purpose`、`subject`、`style`、`composition`、
`negativeSpace` 为文本，`focal` 为 0–100 的 `[水平百分比, 垂直百分比]`，`transparent` 为布尔值，
`avoid` 为文本数组；全部按需填写，字段与校验以 `validate_spec.py` 为准。
不填时工具不代选摄影风格、色板、主体位置或透明需求。旧 hero 渲染器的真实标题遮挡仍须避让。

```bash
python3 scripts/image_source.py --brief deck.spec.json
python3 scripts/image_source.py --check deck.spec.json
```

`--brief` 生成 `image-brief.md` 与 `assets/requests/<槽位id>.json`，临时测量图不会成为交付素材。
请求 schemaVersion 2 兼容旧 v1：`target_px`、`aspect` 与 `requirements` 来自实际图位；
每个 requirement 保存 page / width / height / fit，复用图片按所有图位验收。
用户出图时读取已填写的合同，不用模板覆盖提示词。未完成的占位提示词不得交付给用户执行。

`image_source.py` 只提供 `--brief` 与 `--check`，不带任何生图后端，也不读取生图密钥。
用户用 brief 里的提示词出图后放回 spec 同目录（或 `--dir` 指定目录），再由 `--check` 验收；
用户所用模型的默认尺寸不一定匹配图位，回填后仍检查有效采样、裁切和透明通道。

直接路径相对 spec；使用 `assets/manifest.json` 时，`image` 写 assetId，manifest 中 `file` 相对 `assets/`：

```json
{"schemaVersion":1,"assets":{"overview":{"file":"overview.png","source":"provided","note":"真实产品界面"}}}
```

spec 的图片 fit 与焦点在项目皮肤定义，默认仍是 cover。`--check` 临时渲染并量取每个实际槽位，
按 cover / contain 检查有效像素。原生 PPTX 会读取实测 fit / position，但复杂背景和效果仍须回读验证。

## 回填后的叠加层校准（必做）

只要页面上有按百分比定位的 HTML 标注（区域框、取景框、引线、编号），回填后**必须按图像实际内容重测一次**；
同时复测文字安全区与主体位置，确认标题、正文、标签都没有压在图的主体上，且占位文字已全部消失。
有动效的页面要在播放落定后再测一次：静态回填检查看不出播放期间的临时成层，
落定后的图文层序才和导出静帧一致（见[落定后层级不能变](animation.md#落定后层级不能变)）。
生成图不会遵守你设想的版式：示例里"公式在底部"，实际可能画在图表右侧。

做法：先量出图像里各区域的像素边界，再换算成百分比写回 CSS/内联样式。

```python
from PIL import Image
im = Image.open("assets/images/example.png").convert("L")
w, h = im.size
px = im.load()
# 行方向：找有内容/无内容的区间，得到每个区域的 top/bottom
rows = [min(px[x, y] for x in range(0, w, 4)) for y in range(h)]

```

- 标注框以**图像内容**为准，不以容器为准；框住的是"这段文字/这张表/这个图表"，不是"这块画布"。
- 图注要说明哪些区域被框、哪些没有，避免观众以为漏标。
- 宽高比与计划不一致时，先改 `target_px` 或裁切，再校坐标；`object-fit` 会改变实际可见区域。
