# 图片：契约、提示词、验收

图从哪来。这条流水线里，**图不由脚本生成**（下面说为什么），分工是：

> **脚本写契约与提示词 → 人出图 → 脚本再验一遍。**

## 为什么不是"脚本调生图模型"

不是因为难，是因为**分工反了**：

- 脚本真正知道的是——每张图**放进版面的哪个槽位**、那个槽位**实测多少像素**、
  **该风格的色板是什么**（提示词的色彩栏就来自它）。这些模型不会自己知道。
- "出一张好看的图"这件事，人拿自己顺手的模型做得比脚本去调一个陌生 API 好；
  而且没有一层 API key / 配额 / 供应商变更要维护。

所以默认路径是**交接**，不是生成。`--brief` 把契约与提示词写到一份文档里，
人拿它去出图，出完 `--check` 验一遍。

```bash
python3 scripts/image_source.py --brief your.spec.json      # → image-brief.md + 占位图
# …… 拿着 prompt 去出图，按文件名存到产物同目录 ……
python3 scripts/image_source.py --check your.spec.json      # 验尺寸 / 比例 / 在不在
# --brief 加 --json：把机读 brief 额外打到 stdout（给脚本消费）
```

`--brief` 会**顺便放一张占位图**：出图要时间，而流水线不该因此停住 —— 先跑通整条链，
图回来再替换。

### 资产清单（manifest，§12 统一 Asset Pipeline 的入口 · v1）

spec 同目录放 `assets/manifest.json` 时，图文页的 `image` 写的是 **assetId**
（语义引用），编译（`deck.py::compile_spec`）按 §14 的优先级链把它解析成 `assets/<file>`（manifest 即
选择；generated / provided 的区分由 `source` 记录），Decision Trace 留痕，页对象
携带最终路径 —— 渲染器不见 assetId。没有 manifest 时 `image` 走旧的相对路径
语义（demo/stress 全兼容）。清单 schema 封闭，违规即 ERROR：

```json
{"schemaVersion": 1,
 "assets": {"cover-photo": {"file": "generated/cover.png",
                            "source": "generated", "note": "主视觉"}}}
```

两条铁律的落点：**缺文件由 check 的「图片加载」门实测拦**（不猜存在性）；
**联网找图与静默造占位都禁止** —— content-image 缺 `image` 被 `validate_spec.py`
直接拦，文件缺失 / 太小 / 比例不对由 `image_source.py --check` 与 `check.py` 的阻断
拦。会往产物目录写图的只有 `--brief` 的**显式占位**（先跑通整条链用，图回来再替换），
它不叫"静默"。

### 资产请求（requests，manifest 的上游合同）

`--brief` 除了人读的 `image-brief.md`，还在 spec 同目录给每个图槽位写机读的
`assets/requests/<槽位id>.json`（槽位 id 即 spec 里的 `image` 值，也用作 assetId）。
schema 封闭 v1：`{schemaVersion, slide, role, aspect, focal, negative_space, prompt,
required, note}`（`aspect` 是实测槽位宽高比，`prompt` 即契约里的中文提示词）。
先有请求、再出图：图回来后把选中的文件登记进 `manifest.json`，assetId 就用这个
槽位 id —— 请求说"要什么"，manifest 说"有什么"，管线闭环。

**该要就要，别嫌麻烦少要，多了也没事。** 这条在这里的含义是：`--brief` 不该因为
"图少"而显得多余 —— 一份 spec 有多少图位，就出多少份契约，逐张写全。反过来，遇到
**一张图都没有**的 spec，`--brief` 也不会甩一句"没有要出图的地方"就完事：它按版式
指出哪几页最可能该加图（纯文字页 ≥3 条的那种），由内容定要不要加。一页在讲
"某个东西长什么样 / 现场 / 对比"，就该有图；讲"三条结论"，就不必有。

另两条路仍然在，按需用：

| 路径 | 给谁 | 说明 |
| --- | --- | --- |
| `--brief` / `--check` | **默认** | 人出图；脚本给契约、给提示词、验交付 |
| `--provider-cmd` | 有 API 的人 | 用 `{prompt}` 与 `{out}` 占位的命令模板；**不过 shell** |
| 几何色块拼贴 | 先跑起来看看 | 确定性生成，且过色板三角检查 —— 是版画式拼贴，不是灰占位图 |

## 契约里有什么

| 项 | 从哪来 |
| --- | --- |
| 文件名 | spec 里的 `image` 字段（同一个文件名用在多页时**合并成一条**） |
| 尺寸 | **实测槽位 × 2**（槽位宽由布局定：`.imgwrap{width:640px}` → 1280px） |
| 比例 | 3:2。选它的理由：旁边是 820px 文字栏，太宽像背景条；1:1 的 640px 高会顶到页脚 |
| 透明通道 | 内容图**不需要**（整张不透明照片）；logo 那套另有路径 |
| 会被怎么处理 | **按原样使用**（v4：制版后处理已退役）；色彩与构图约束由提示词的对应栏承担 |
| 内容 | **留空给人填**（主体 / 场景 / 细节）。见下 |
| 提示词 | 中文 + English，两份都按同一套字段顺序给 |

### 三件容易做错的事（都踩过）

1. **同一张图用在多页时要合并**。第一版按页列，于是压测 deck 里那张图出现三遍 ——
   人会出三张、互相覆盖。
2. **不能说"给文字留压字空间"**。我们的版式里文字是**独立一栏**（左文右图；
   唯一例外是 hero 变体 —— 满幅图 + 底部**实心**标题条，条用 --text/--paper
   反转色对，对比度与正文同一个 token 保证，所以出图时**不需要**给标题留白区，
   标题条压在图上任意位置都成立），
   不是压在图上。写错了模型会交一张主体偏到一边、空掉半张的图。
3. **工具不许自己编主体**。第一版把该页标题拼成"内容草稿"塞进了提示词 ——
   那是**擅自补充事实**：条目往往在讲这份 deck 的叙事（"把现场图处理成两色…"），
   不是在讲画面里该有什么。现在「主体 / 场景 / 细节」三栏**留空**（写作 `〈…〉`），
   工具只把标题与条目列成**参考材料**放在提示词外面 —— 它读不到你脑子里的画面，
   就不该假装读得到。

## 提示词怎么组织：字段顺序就是优先级

每条提示词按**固定顺序**给十个字段：

```text
主体 → 场景 → 构图 → 镜头 → 光线 → 色彩 → 风格 → 细节 → 文字 → 限制
```

顺序本身就是信息：先让模型明白**画什么**（主体 / 场景），再明白**怎么画**
（构图 / 镜头 / 光线 / 色彩 / 风格），最后是**绝对不能错**（文字 / 限制）。
堆成一段的写法会让"不要细密纹理"这种约束把"主体是什么"淹掉 —— 而主体最优先。

每一栏只讲它该讲的事，不混着写：**构图不谈光线，光线不谈风格**。这是顺序能成立的
前提；混着写的话顺序就名存实亡了。所以风格那一栏给的是**可执行的视觉语言**
（"纪实摄影；克制平静、画面干净不杂"），不是风格文献的名字（写 Massimo Vignelli
对模型是噪音），也不夹规则说明。

冲突时按这个优先级裁决（左边赢）：

```text
你的明确要求 > 主体准确 > 文字与品牌准确 > 构图 > 场景 > 光线 > 风格 > 装饰细节
```

这条在本流水线里**真的会撞**：风格的强色相属于低优先级，不允许破坏构图与细节
（主体位置、负空间、形体是否清楚）—— 所以风格栏里明写"靠大块明暗和强形状立住"，
让它别压过构图。低优先级的不许破坏高优先级的。

### 谁知道哪些字段

| 字段 | 谁填 |
| --- | --- |
| 主体 / 场景 / 细节 | **人**（工具留空，写作 `〈…〉`） |
| 构图 / 光线 / 色彩 / 风格 / 限制 | 脚本。构图来自**实测槽位与版式**（图独立成栏、文字在旁边），色彩来自**该风格的色板**，光线与风格来自风格的**气质**档，限制来自**这条管线的约束**（与风格色板 / 构图冲突的观感项） |
| 镜头 | **默认不出现这一栏**：镜头参数只有能明显改善画面时才该加，而工具判断不了你这张图需不需要它 —— 给了"安全默认值"就等于**每次都加**，正好违反规则。要加就自己插一行，位置在【构图】与【光线】之间；契约里给了几个可抄的例子 |
| 文字 | 脚本。答案在**版面**上：画面里不要出现任何文字，说明文字由版面另排 |

**API 已经有的参数不要写进提示词**：尺寸、比例、数量、质量、seed 都单列在每张图的
「参数」栏里 —— prompt 里再写一遍只会在两者冲突时给出随机结果。第一版就把
`3:2` 与 `1280x853px` 写进了正文，这是错的。

**限制项只列与这条管线相关的**：细线 / 细密网格或织物纹理 / 柔和渐变 / 低对比平光
（这四样与"按风格色板出图、主体清晰"冲突）、多个并列或重复主体、结构变形 / 过曝 / 裁切主体。
不堆"不要水印 / 不要额外人物 / 不要畸形手指"这类通用负面词 —— 与本任务无关的
负面词是噪音，还会挤掉真正重要的约束。

### 提示词里那条**管线特有**的约束

v4 起**不再有制版后处理**（`plate.py` 的双色调 + 半调网点整文件退役）——图按
**原样使用**。所以约束不再来自"会被压成两墨"，而来自**提示词的色彩与构图栏**：

- 色彩栏钉住**该风格的色板**（主色 / 副色 / 纸色），让图与版面同源；
- 构图栏给**实测槽位与版式**（图独立成栏、文字在旁边、主体偏哪侧、哪侧留负空间）；
- 风格栏给**可执行的视觉语言**（"靠大块明暗和强形状立住"），不是风格文献的名字
  （写 Massimo Vignelli 对模型是噪音）。

这几条不写进去，模型会交一张很漂亮、却与版面不同源的图 —— 而**只有这条流水线的人
知道**该风格的色板与版式，通用提示词里不会有。

## 验收：`--check`

在**渲染之前**对着契约验，所以能在跑完整条流水线之前就告诉你"这张图你出小了"：

- 文件在不在（不在就说"还没出图"）
- 宽度够不够（契约是 1280px；小了这个尺寸的图放进版面**一定糊**）
- 比例对不对（版面按宽度缩放，比例差太多会撑高，撑高会撞页脚）

`check.py` 那条放大检查是**渲染之后**看产物的（它只知道有没有被放大）；
两者互补，不是重复。

> ⚠️ **`--check` 不许自己造图。** 第一版它先调了会写占位图的那个函数，于是把图删掉
> 之后照样报"符合契约"—— 检查把它该验的东西自己造了出来，永远验不出"还没出图"。
> 现在它只读 spec 与文件，不渲染任何东西。
