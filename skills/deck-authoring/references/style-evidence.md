# 风格选择：让用户看见「这一风格在页面上长什么样」

风格名不是选择依据。「3D 动画电影」「极简」「暗色科技」「高级感应」这类词，
在用户脑子里和在作者手里的意思是两件事：用户以为会得到角色与场景，作者给了一张深色排版
加一个琥珀色强调——两边都没说谎，但交付必然作废。这个失败不需要用户懂设计才能避免，
只需要**在用户选择之前，先让他看见页面本身**。

本篇管「选择时给什么证据」；给不出证据时该不该开工见 [阶段闸门](stage-gates.md) 的 G2。
配色与排印的具体判断见 [配色](color.md)、[排印与空间](typography-and-space.md)。

## 三条证据，只有前两条算数

| 等级 | 证据形态 | 什么时候用 | 算不算完成选择 |
| --- | --- | --- | --- |
| **A · 同媒介实现案例** | 用户能打开的**页面本身**：同类题材的 deck、可播放的 HTML、模板站的具体模板页（能看见整页骨架与密度） | 有现成作品时首选 | 算 |
| **B · 可比拟样张** | 作者用**本项目真实内容**先做 1–2 页，给用户看实际渲染 | 没有现成案例，或参考来自别的媒介 | 算（且是媒介型风格的唯一合法路径） |
| **C · 只有名字或海报** | 作品名、风格词、影视截图、设计站缩略图 | 只能用来启发作者，不能拿给用户当选项 | **不算** |

风格词从哪里来、四个模板站怎么取样，见 [风格来源](style-sources.md)：
Canva 与 Miricanvas 编的是成品模板，Envato 偏用途，Dribbble 是视觉语言；取它们的原词，不自己命名。

**参考媒介 ≠ 交付媒介。** 影片、游戏、海报、摄影、品牌广告提供的是**气质与关系**，
不是页面形态：它们没有标题层级、没有页脚、没有 16:9 的内容带、没有「一页要回答一个问题」。
拿影片当参考必须多走一步——先做 B 档样张，再把「取哪几个关系」写清楚。
找不到同媒介案例不是跳过选择的理由：**B 档样张是默认兜底**，成本只有 1–2 页，
比铺完全套再返工便宜两个量级。

典型误读（出现过就要警惕）：

| 用户说 | 错误落地 | 正确落地 |
| --- | --- | --- |
| 「3D 动画电影风格」 | 深色底 + 暖色强调 + 大字号，页面里没有 3D 画面 | 每页一张 3D 渲染剧照当主体，文字压安静区；角色与材质来自同一套设定 |
| 「电影感」 | 换成深色 + 黑边 + 衬线体 | 说清是「一个焦点 + 明暗对比 + 景深」还是「宽银幕比例 + 字幕位」 |
| 「高级」「极简」 | 留白变多、字号变小、颜色变少 | 给出尺度关系、留白位置、字号跳级的具体页面 |
| 「像苹果发布页」 | 白底 + 大字 + 圆角卡片 | 先找同媒介页面，指出取的是产品图占比还是页间节奏 |

## 选择前必须回答的五个问题

把这五条写成用户能判断的话，不要写形容词。回答不了其中任何一条，说明方向还没成形，
这时去开工就是拿用户的等待换返工。

1. **页面主体是什么**：一页第一眼落在图、文字、数字还是图表上；图占多大面积。
2. **一页长什么样**：标题在哪、图位什么形状、密度多少、有没有页脚带。
3. **色彩与明暗关系**：几个色、谁当主角、明暗怎么分、强调色出现在哪。
4. **素材从哪来**：生成位图 / 手写矢量 / 截图 / 摄影；用户需要做什么（生成、提供或授权）。
5. **动效是什么**：有没有镜头推近、光扫、逐条揭示；导出静帧长什么样。

再补一条**反例**：这次明确不要什么。反例比正例更能拦住误读——
「不要深色科技排版，不要每页文字块加小图」比「要高级」有用得多。

## 提问怎么写

一次问一个能直接回答的问题；给 2–4 个**具体方向**，每个方向写清「会得到什么」，
而不是让用户在风格名之间挑。合格的一问：

> 这套要图像主导还是图文并重？图像主导＝每页一张大剧照、文字压安静区；
> 图文并重＝图占半边、文字另半边。两种我都能先给你 1 页样张再定。

不合格的一问：

> 你想要什么风格？（极简 / 科技 / 商务 / 高级感）

用户已经给了形容词（「要电影感」「要 3D 动画」）时，**不要用形容词回问**，
用 B 档样张把形容词变成画面；用户明确说「风格你定」才由作者决定，且仍要做样张自查。

## 参考图与画面素材是两件事

- 参考截图只放 `refs/`，**永不放进 `assets/images/`**，也不在页面里当 `<img>` 引用。
  它证明的是「作者看过什么」，不是「本 deck 画了什么」；把它放进交付目录，等于让用户以为
  这就是成品画面。
- 参考里的角色、场景、图形不能直接剪下来复用；要复用必须由用户在 `image-plan.json` 里
  登记 `source: "provided"` 并说明许可与理由。
- 用户提供的参考图同样遵守这条：先问「能否作为素材」，不要默认可用。

## 记录：用户看到了什么

`design.md` 的「参考拆解」只记作者取的关系；另外必须有一行**用户依据**：

```md
- 用户依据：refs/ref-a.png（同媒介页面截图）· 用户原话「要这种大图压字的感觉」· 2026-10-20
```

只写「用户选了 A 方案」不够——没有说明他怎么看到的，就没有办法判断这次选择是否成立。

## 自检

- [ ] 用户看到的是**页面**，不是作品名、海报或风格缩略图。
- [ ] 至少一条证据属于 A 档或 B 档；媒介型风格必须是 B 档。
- [ ] 五个问题都答得出，且写进了 `design.md`。
- [ ] 有一条反例，能区分「这次不要什么」。
- [ ] `refs/` 与 `assets/images/` 没有混用。
