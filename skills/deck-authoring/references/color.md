# 配色：角色、对比度与视觉方向

色值放在风格 `style.json` 的 `colorSets`，内容 spec 只写具名的 `deck.colorSet`。
品牌可以合并或覆盖同名色板，最终采用 `deck.resolve_theme()` 解析出的主题。

## 颜色角色

| 角色 | 用途 |
| --- | --- |
| `background` | 页面底色 |
| `primary` | 主色、图形与装饰 |
| `secondary` | 次色、对照与装饰 |
| `text` | 显式文字色；省略时才用 primary × secondary 的乘色结果 |

`colorStructure` 是可选的作者备注，可描述色相关系、明度、饱和度与冷暖；脚本不把它当成
自动推色模型，也不检查作者的审美描述。不要声称这些字段能自动保证配色新颖。

叠印适用于需要这种效果的风格。现代简约、深色演讲或品牌风格可以直接声明 `text`。
浅底深字与深底浅字都合法。主色也并非天然不能当文字色，实际背景与对比度决定是否可读。
旧 spec 的 `color:"overprint"` 仅是兼容标记；内容层不接受 HEX。

## 两层验收

```bash
python3 scripts/ink.py styles/<风格>/style.json
python3 scripts/check.py deck.spec.json deck.html
```

`ink.py` 检查声明色板中的文字/背景组合；它无法知道任意皮肤里的实际背景与透明度。
`check.py` 另读真实 DOM，合成祖先 opacity 与背景后检查文字。目前普通文字统一采用
4.5:1 的保守门槛；`minLarge` 尚未用于按实际字号放宽。不要降低阈值掩盖对比度问题。
图片、渐变等复杂背景上的文字会提示人工确认，需打开截图观察。

品牌合并后的主题与风格原色板可能不同。原风格通过 `ink.py` 不等于品牌组合也通过，
最终以实际产物检查为准。标题反白、透明页脚、图片上的字幕都应单独看。

图表多系列颜色由渲染器生成；肉眼检查相邻颜色能否分辨，避免只依赖颜色传递结论。
数值与类别标签应清楚，不能用装饰色低对比度地隐藏证据。

## 如何设计方向

未确定方向时，把配色与字体、构图、密度一起做三版代表页；已有选择就沿用。
不要在风格选择之后强制再跑一轮三色板确认。

1. 先确定阅读场景和情绪：现场演讲需要远距离识别，异步阅读需要长时间阅读舒适。
2. 选一个清楚的主次关系，再给需要强调的事实分配强调色。
3. 借鉴参考的颜色关系，结合品牌、图片与内容调整；可用 OKLCH 辅助控制明度和彩度。
4. 在密集正文、图表和真实素材上试用，不只看色块或封面。

蓝白、黑金或低饱和色本身不是错误；是否合适取决于内容与品牌。
新颖不能压过可读性，也不需要为了“与众不同”强行旋转参考色的色相。

全套 deck 共用一个 `colorSet`；页面强调可以通过皮肤与布局变化表达。
皮肤可自行画渐变等 CSS 效果，但没有通用渐变 token 或自动质量验收，导出也可能不同。
