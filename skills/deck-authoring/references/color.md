# 配色：从实际参考到图文页面

新建或重做视觉方向时，先读本篇；沿用已确认方向的局部修改无需重新选色。
配色必须与功能图、背景、排印一起落实，不能凭题材标签选择惯用组合。

## 先找到可观察的依据

用户给了参考网站、作品或截图，先查看其中适合本次任务的具体画面。没有指定品牌或色板时，
从这些参考出发选择，不能跳过检索直接回到此前惯用色。已否决的整体组合不再作为候选；
一张旧图的颜色配置不等于品牌要求。网站不可访问时使用已有截图或其他可访问参考，并如实记录范围。

| 参考入口 | 用来判断什么 |
| --- | --- |
| [Oh My PPT 画廊](https://www.ohmyppt.cc/style-showcase)及用户截图 | 背景、图像、标题和留白怎样共同形成一张演示画面；进入具体作品，不按风格名套模板 |
| [Happy Hues](https://www.happyhues.co/) | 颜色在真实页面中如何分配给背景、标题、正文、强调和插图，而非只看一排色块 |
| [Adobe Color](https://color.adobe.com/) | 从参考图提取颜色、探索组合与调整色彩关系；选出的色板仍需在本项目试排 |
| [中国色](https://zhongguose.com/) | 发现单色及其冷暖、明度；单个色名不构成完整方案或题材约束 |

按当前需要使用，不必逐站打卡。保存采用的具体链接或截图，以及借鉴的颜色关系、调整和原因，
写入已有 design.md 即可。只有网站名称、链接清单或“高级、克制”等词不算选色依据。

## 把颜色分配给画面

在项目 CSS 和配图提示词中使用同一套决定：

- **画布与背景**：决定明暗、冷暖和表面层次。封面可让主视觉或大色域主导；内页让颜色组织信息空间，密集区域保持阅读稳定。
- **文字**：主文字、次要说明和反白文字分别校准；必要条件不能灰到难读。字号、字重和位置也参与主次，勿靠满页彩字强调。
- **主色与强调**：明确主色在哪里真正可见、哪一处需要更强反差。强调只落在焦点，避免编号、边框、标签、数字同时抢眼。
- **配图与局部表面**：依据图像的明暗、主体和边缘处理图文衔接；生成提示词要具体写出这些决定。真实截图保留证据色，通过周边背景协调。
- **语义色**：状态与数据有独立含义；成功、失败和类别跨页保持一致，并配标签或形状，不能只靠红绿区分。

不规定主题专属色、固定色数或面积比例。大面积底色、细线和小字使用同一色值时，实际作用与可读性不同。
渐变、纹理、透明表面和图像叠层可以使用，但要检查合成后的颜色；深底重新搭配文字和局部表面，不机械反相。

## 在当前内容上淘汰不合适的组合

先在能暴露问题的真实页面中看颜色与图位，覆盖当前需要的明暗、信息密度和图文组合，
不另换容易漂亮的主题，不默认制作多套完整样张。图片尚缺时只能确认色彩方向，回填后重审。

| 实际问题 | 优先调整 |
| --- | --- |
| 整页发灰、发闷，焦点只剩几条彩线 | 检查大面积中性色是否吞没主色，重分明度、彩度与视觉重量；不要继续往同一灰底上加小色块 |
| 字色清楚，整体却像模板 | 检查参考中的图像、背景层次和色域关系是否落实；不要只复制色值或深浅交替 |
| 大色块喧闹、元素互相抢眼 | 集中强调，拉开主色、辅助色和安静区的作用；避免所有模块等量着色 |
| 图片像贴上去，底色与素材打架 | 调整图位、边缘、局部背景与照明处理，必要时重做生成素材；不统一染色真实证据 |
| 深浅页面各自好看，连起来断裂 | 延续主体和语义色的身份，调整面积与表面关系；不要每页重抽一套色板 |

与采用的参考并看，用具体差异决定修订。对比度通过只说明可读性的一部分，不能作为颜色好看的证明。

## 数据、对比度与工具边界

无序类别采用可辨识的类别色；连续量按大小映射；有真实中点的偏差可用发散关系。图例、标签与形状辅助辨认，
保留真实零点、单位和范围。可参考 [Carbon 数据色](https://carbondesignsystem.com/data-visualization/color-palettes/)。

文字按实际前景/背景检查：[WCAG](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 的普通文字 4.5:1、大字 3:1
可作基准；缩放、细字、投影与图像背景仍需目检。透明度先合成，渐变与图片检查文字实际覆盖区域。
自由 HTML 的 web_check.py 不全面计算对比度，也不评价配色。结构化项目用 ink.py 查声明色板、check.py 查实测 DOM，均不能代替视觉审阅。

结构化路线的 colorSets 包含 background、primary、secondary 和可选 text；未写 text 时渲染器采用既有乘色逻辑，
项目应显式指定实际文字色。brand 可合并或覆盖同名色板，复杂背景由 skin 实现；没有通用渐变 token。
自由 HTML 在项目 CSS 定义颜色角色，不受这些兼容字段限制。新方向的方法见 [视觉语言](visual-language.md)。
