# 视觉审稿：根据画面修订

几何检查发现资源、边界和部分遮挡问题；视觉审稿判断重点、构图与观看体验。
检查通过不代表画面成立。构图方法见 [构图推导](composition-principles.md)，字号与中文实测见
[排印与空间](typography-and-space.md)。本篇用于看实际渲染、定位问题和验证修订；
完整新稿的扩展条件、hero pages 与两轮证据见 [审美闸门](design-review.md)。

## 先看全套，再读每页

**整套缩略图**看主角、轮廓与疏密。封面之后，标题是否总在同一位置，内容是否总是一排等重栏，
图片是否总占同样大小？先判断各页任务是否需要这些重复；连续步骤或比较可以保持方位，帮助观众识别变化。
需要改善节奏时改变信息展开、主角与尺度，不能只轮换背景色、挪页码或增加动画。

**目标观看尺寸**看逐页阅读，不能靠高分辨率放大后的清楚程度判断。带着具体内容做以下观察：

| 观察 | 需要回答的问题 |
| --- | --- |
| 第一眼 | 实际先看见什么？它是否正是本页要说明的对象、判断或证据？多个同样重的小标题是否抢走主角？ |
| 大形与路径 | 暂时忽略文字细节，大小、明暗与位置是否组织出主次？视线能否顺着关系找到解释与条件？ |
| 空间 | 哪一片区域是有意保持安静？相关内容是否靠近？空白是否只剩在底部，正文却挤在窄带里？ |
| 排印 | 中文断行、标点、中英混排、字重是否自然？核心说明是否被当作图注缩小？辅助字是否过于抢眼？ |
| 素材与证据 | 图片是否属于本主题，裁切是否保全关键内容，解释是否靠近对应证据？生成瑕疵和来源是否处理？ |
| 风格是否落地 | 与所选参考并看，关键形象、表面、排印与空间关系实际出现了吗？还是只剩相似颜色与工整文字？内容页能否延续这种表达？ |
| 语义与完整性 | 版面是否暗示了不存在的先后、因果或数量关系？限定、单位与不同事实是否完整？ |
| 作者性 | 这套 deck 有没有一个可识别的 signature move？它是否重复得刚好，而不是每页都出现？ |

完整新稿先看三张 hero pages：封面、最难讲的内容页和 signature page。三张连续看，
检查尺度、图文比例、密度和阅读路径是否共享亲缘；不要只用封面或局部放大证明整套。

安静区应帮助组织信息，不能仅因为“空”就填充；内容多也不自动表示设计差。
画面单薄时，检查是否仍是一组过小、等重的元素，或视觉想法和该展开的证据还没有进入画面。
不要把删除装饰本身当成改进：主题图形、笔触与材质可以建立身份和气氛，按它们在实际构图中的作用判断去留。
留白、精简与可读性不能靠删除必要内容、隐藏末行或把文字改成低对比度实现。

**实际交付格式**需要独立回读。打开或渲染 PDF/PPTX，核对页数、文字与数据、字体替换、图片裁切和图表系列。
HTML 正确不能证明 PPTX 正确；贴图 PPTX 不可当作逐字可编辑版本。
有动效还需实际播放入场、切页与完成态，见 [播放与动效](animation.md)。

## 先修最影响结果的问题

先排除丢内容、错证据、读不清、遮挡等实质问题，再处理画面的视觉主次。
优先顺序通常是：焦点与信息关系、构图与空间、排印与素材、局部细节；不要在主角仍不清楚时反复微调圆角。
每次处理当前最明显的少量问题，修后看新图，按实际结果决定是否继续。
完整新稿按 [审美闸门](design-review.md) 至少回看两轮 hero pages；不设审美分数，
轮次不是目标，major 清零和可定位的证据才是。

| 画面中的具体问题 | 优先尝试的改变 |
| --- | --- |
| 标题大、清单齐，但每页轮廓相同 | 重新确定本页主角；移动标题，把证据放大或分段展开，改变对应解释的位置。保留共同阅读坐标即可。 |
| 一页同时解释输入、过程、契约和使用场景 | 按观众的问题拆成连续页；流程与分支用带标签的节点图，完整映射留在可读参考页，不因旧稿页数而压缩。 |
| 长文旁边放一张无字隐喻图，文字几乎没减少 | 将图改成能直接读出本页核心关系的主体，标签与条件放在作用位置；删去复述。暂时忽略旁边正文仍应能读懂图要表达什么。 |
| 主体勉强放下，底部说明挤进页脚 | 将说明、图注和所有间距计入正文预算，拆页或重组；检查最终版本，不靠裁切、缩整页或隐藏末行消除溢出。 |
| 框去掉了，仍像等宽组件清单 | 重分视觉重量与列宽，按职责、因果或比较关系组织；不要只减边框再扩大空白。 |
| 中间一条小字带，上下大片空地 | 调整主体尺度和阅读宽度，把空间放到组间或焦点周围；不要一起放大所有文字或拉高空盒子。 |
| 内容四处漂浮，只有“非对称”的感觉 | 找回共同对齐轴与语义邻近关系，减少无意义的错位；偏心需要秩序支撑。 |
| 图片漂亮，换个主题仍完全适用 | 换用材料中的对象、局部证据或实际场景，重新考虑图片任务；不靠统一调色掩盖内容脱节。 |
| 同一角色一页生成位图、一页 SVG，或背景图含角色又叠 SVG 角色 | 先定形象媒介，一套只一种；SVG 只承担图表、连线、标注、图标等图形层，不重画角色。 |
| 占位标签压在图中央，回填后还留着 | 占位只用空白框，图位内不放“待配图 / 文件名 / 尺寸”；回填后删净占位文案，文字避让主体。 |
| 动画落定后图文换位，或文字突然被图压住 | 先查层序与动画包裹层：参与叠压的元素各自定层，reveal 只包原子元素，落定不留层；对比入场中与 `?scroll` 完成态。 |
| 文字压在图的高细节区，纹理和边缘透上来 | 文字退回图外，或换到图里预留的安静区并加局部遮罩；不用盖满整张图的半透明黑去蒙。 |
| 图位比例和素材对不上，功能图被裁 | 按图位 `target_px` 请用户重出素材；功能图不用 `cover` 凑，`contain` 要统一图位与图内底色。 |
| 图表和关键界面都缩成装饰图 | 保留关键比例与标注，必要时局部放大或拆页；原图、放大区和结论保持可追踪关系。 |
| 条目、标题、编号和结论只是换词重复 | 合并重复表达，让判断、证据与条件各自承担工作；保留有目的的教学复述或连续对照。 |
| 技术词全是高亮 chip，正文像注脚 | 用正常连续排印恢复解释，只强调需要辨别的内容；核心英文名、用途与失败条件不能统一缩小。 |
| 表格文字贴线或行内重心不稳 | 按真实换行调整列宽和内距；短行可垂直居中，长段可顶齐，整表位置另行判断。 |

镜头式放大、裁切、对照或沿路径展开应帮助解释，不能虚构截图细节、图表比例或技术关系。
拆页时保留条件与来源去向；必要时将补充细节放入后续页、讲稿或附录。
缺少主视觉时可以审结构和文字，但图文关系仍待素材回填，不能据占位图宣布审美完成。
交待配图稿时，运行 `image_handoff.py --handoff` 并打开实际 `image-brief.md` 核对使用页、提示词及保存路径。
完整新稿还要逐页核对：封面是否按参考设计焦点与背景关系（排印或图形也可成为主视觉）；解释页是否用功能图承担关系而非堆文字卡；内页背景是否服务焦点；
图已表达的内容是否仍重复写成长段。只有装饰封面或背景壁纸不能算功能配图完成。
只有配图建议或计划 JSON、没有 Markdown 文件，属于交接未完成。文档检查、几何通过都不能替代这些视觉判断。

## 留下可追踪的审稿结果

在项目已有记录中简记“页与版本 / 画面中的问题 / 已做的改变 / 回看结果或仍缺什么”。
例如“第 4 页截面太小，解释先于证据被看到；放大截面并将条件贴近右侧注释，普通窗口复看可读”。
“更精致”“符合某风格”“测试通过”都不能替代可定位的发现。

生成全部 PNG 不等于看过全部页，看缩略图不等于逐页实际尺寸审阅。只声明实际看过的范围和格式。
如果当前环境无法看图，就明确视觉审稿未完成；颜色像素占比、几何结果和源码检查不能替代目检结论。
改共享 CSS 后回看受影响页面，换素材后重看裁切与图文关系；局部修复重看该页。
检查编译版时不声称已回读内嵌版；未落实的修订仍列为未完成，不能凭几何通过补写目检结果。

若 token 与实际字号不一致、选择器未匹配、字体回退或动画尚未落定，先修实现再评价设计。
`small-text` 按页和角色聚合，一条警告可能包含很多段文字；看 `count`、字号分布和正文样本，
不能用警告数量代表小字数量，也不能靠改角色标记规避核心文字检查。
检查器无法穷尽像素遮挡与互动状态，`passed` 只说明该次测量范围内的结果。

## 结构化项目的复核边界

HTML 可自由构图，下面的结构仅供既有 spec 项目映射，不是所有页面的版式菜单：

| 信息关系 | 当前可用结构 | 需要保全 |
| --- | --- | --- |
| 一个结果及意义 | `content-text`、`role:metric` 或 `title` | 数字、基准、解释分层，完整条件不能一并放成展示字 |
| 两方案比较、前后变化 | `two-column`、`content-image` 或 `chart` | 统一维度、可比尺度、变化点与原始证据 |
| 阶段推进 | `timeline` | 真实时间关系、阶段输出和下一步 |
| 判断与依据 | `content-text`、`content-image` 或 `chart` | 判断、证据与解释之间的对应关系 |

当前没有原生表格、架构或指标卡页型；复杂关系可用适合的素材、自由 HTML，或明确扩展后再用。
不能填写未实现的 schema 字段。结构化 fit/focal 目前通过 skin 的 `object-fit` / `object-position` 表达，
不是独立 spec 字段；证据通常先保全全貌，是否裁切仍取决于必要内容。

spec 可用 `deck.delivery` 表明场景：`live` 按投影阅读，`async` 按普通窗口自读，`printable` 按目标纸张看 PDF。
1600×900 下，`check.py` 对 live 正文 28px / 图表标签 22px、async 正文 20px / 标签 14px 提醒偏小；
这不是远读保证。未声明 delivery 时不猜场景或自动改字号。自由 HTML 的提醒机制见 [排印与空间](typography-and-space.md)。
`render --repair` 只尝试未声明的字号档；`--candidates` 只比较几何候选，均不能决定叙事和审美。

审稿方法借鉴 taste-skill 的截图观察与按可见问题修订，独立适配为演示流程；不采用其评分和风格门槛。
