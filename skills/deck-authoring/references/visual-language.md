# 从参考形成项目视觉语言

用于建立新方向、转译用户参考，或修正“清楚但普通”的页面。风格来自当前材料、视觉偏好与观看条件，
可以跨类别组合；现成风格名有助于交流，但不决定可用的构图。制作推进见 [项目记录](refined-workflow.md)。

## 先看用户在意什么

有图片、网站或已有演示时，实际查看画面，辨认用户喜欢的是整体气质，还是排印、色彩、材质、图像或空间关系。
用户只认可其中一部分，就只继承该部分；已有品牌与明确选择是当前设计的依据。
品牌须有用户确认或真实品牌规范作为依据。仓库中一张架构图的颜色文件、旧截图、此前 AI 写的设计记录，
只是对应作品的局部决定；不能因为文件还在就继承为整套演示规范。读取技术事实不意味着接受其呈现样式。
读文字说明可以了解意图，但截图不能证明动画，源码也不能代替看最终效果。

新方向先查看用户给出的具体作品或画廊，再按内容、受众与表达目的寻找适合的设计关系。
可参考演示、出版物、海报、展览、摄影或网页，不限定行业 PPT 模板。探索页面序列时看作品系列与内容页，不能只收集封面。
选色按 [配色流程](color.md) 查看实际应用，保存采用的具体页面或截图及转译决定。参考不可访问时如实说明，用已有截图或可访问作品继续；不能虚构已查看。

参考数量取决于信息是否足够。不同作品中的相容特征可以组合；品牌、表达目的或素材处理冲突时需要取舍，
不能把喜欢的元素全部堆到一页。检索结果用于启发判断，不按“行业 → 风格名 → 模板”自动套用。

## 新稿的参考选择入口

何时提问、等待及继续，以 [制作入口](../SKILL.md#开始制作前先判断是否需要交互) 为准。本节提供选参考的方法，
不能把“作者发现了一个合适参考”解释为不再需要用户选择。不要把找参考全部推给用户。

**给用户的证据必须是「页面」，不是作品名。** 同媒介的实现案例优先（用户能打开的 deck 或 HTML）；
参考来自影片、海报、摄影、游戏时，先做 1–2 页可比拟样张再让用户选，并把「取哪几个关系」写清楚。
三条证据的等级、选择前必答的五个问题与常见媒介误读见 [风格证据](style-evidence.md)。
只给风格缩略图或影视截图，等于让用户用想象补全页面——「3D 动画电影风格」被做成深色排版加暖色强调，
就是这么发生的。参考截图只放 `refs/`，不进 `assets/images/`。

第一次询问应能直接回答，例如：

> 这次重做还没有确定视觉方向。你可以在 [Oh My PPT](https://www.ohmyppt.cc/style-showcase) 看封面气质，
> 或在 [Pitch](https://pitch.com/templates) 看整套内容页，发我喜欢的作品链接或截图。
> 你想自己挑参考、让我先找具体作品供你选，还是把风格交给我直接完成？
> 也可以直接说这次要图像主导（插画、摄影或图形装置）还是文字主导；不确定就让我按内容判断。

措辞随项目调整，不要求用户学习设计术语。用户选择让作者找参考时，展示可见作品及适用特点，等其选择；
不要返回一串“极简 / 科技 / 商务”名称。用户给出作品后，只确认尚不清楚且影响制作的偏好，随后用真实内容做样页。

| 来源分组 | 看什么 | 在哪 |
| --- | --- | --- |
| **成品模板** | 整页版式、页数、真实排版：Canva / Miricanvas / Slidesgo / PresentationGO / Envato / Pitch | [风格来源](style-sources.md) 的注册表 |
| **成套主题** | 同一母题如何贯穿封面 / 议程 / 章节 / 内容页：PPT-Design / Oh My PPT | 同上 |
| **视觉语言** | 画风、光色、材质：Dribbble 的 tag | 同上 |

站点清单只有**一份**：`assets/style-sources.json`，文档与 `style_probe.py` 都从这里读，
`python3 scripts/style_probe.py --list-sites` 直接打印。新增站点改那张表，不要在别处再列一遍。

这些是浏览入口，不是必须使用的平台或付费依赖；不能访问时说明限制，不用反复抓取拖延首次提问。
截图足以说明偏好时，不要求注册或下载模板。

成套主题值得看母题如何贯穿，而不是看单页配色。典型例子：
[女巫花园](https://ppt-design.com/zh/themes/witch-s-garden-autumn-garden-theme-531) 的蘑菇与藤蔓、
[Pricing Strategy](https://ppt-design.com/zh/themes/pricing-strategy-good-better-best-pricing-theme-687) 的价签、
[Project Kickoff](https://ppt-design.com/zh/themes/project-kickoff-kickoff-meeting-presentation-theme-680) 的倒计时轨道——
同一母题在封面、章节、数据页以不同尺度和角色反复出现，图像因此承担结构，而不是装饰。
取其图像系统与节奏，不复制具体版式、主题符号或页面顺序。

模板站适合让用户快速表达偏好，但不是视觉研究的天花板。确定方向或需要提高上限时，
另看编辑设计、年报、海报档案、博物馆图录、数据新闻和字体样张；按
[视觉 craft 的参考来源](visual-craft.md#10-参考来源提高天花板不抄主题) 记 move，
不把“极简/科技/商务”或某个模板主题名当成设计方向。
选中作品后，记下喜欢和不喜欢的具体关系，例如“保留红色斜切海报与大留白，正文不要手写体”，而非只记风格名。
只有封面参考时，继续找到或设计能承载本项目真实内容的页面；不用漂亮短口号替代密集内容试排。

封面可以由文字海报、色块、图形符号、摄影、信息图或场景构成；字体也可以是主视觉，不强制左标题右图片。
内页背景可保持安静，不必复制封面的装饰。不要把参考作品的每种特征同时塞进全套。

## 提取设计关系，而非主题符号

从采用的参考中提取真正影响画面的关系：什么占主导、文字怎样与图像相遇、明暗面积怎样分配、
边缘与表面呈现什么质感、画面哪里紧张或安静，以及连续页面如何保持亲缘关系。
按当前任务记下必要观察和转译方式即可，不维护打分表或一份包罗万象的风格词库。

可以借鉴作品的尺度与空间关系而不复用其物件；也可以沿用品牌设计语言承载完全不同的主题。
风格不必来自内容的字面隐喻，技术材料不自动需要科技符号，所有项目也不必设计一个贯穿的装饰图案。
主题中的真实对象、排印、摄影或抽象形式都可以成为表达来源；题材联想只是候选，不足以决定风格。

## 写下能指导实现的项目决定

在已有 brief 中用一小段话说明想让画面呈现什么感受、靠哪些具体关系实现，再记录确实影响制作的决定：

- **整套延续的特征**：字体分工、色彩角色、图像处理和对齐关系。只选本项目需要的一致性，不固定清单或数量。
- **页面可以变化的部分**：主体尺度、位置、密度、明暗与图文关系，随讲解任务变化；稳定不等于每页同一布局。
- **落实方式**：项目 CSS 与真实字体、需要的图像及其取得方式、背景与文字如何分层。说明应能指向实际页面或素材。

整体描述与数值各有作用：描述说明意图，色值、字形与实现说明让它落地。采用参考中的关键特征，
就应在页面中看到对应关系；必要素材尚未取得时先处理素材，不把文字占位当成该方向已实现。

色彩与字形的具体判断见 [配色](color.md)、[排印与空间](typography-and-space.md)；局部阅读关系见 [构图](composition-principles.md)。
不用填一份固定 JSON，也不把一次项目选定的颜色、字体或禁忌升级为 skill 的全局默认值。

## 选择能实现效果的媒介

CSS 适合表面、渐变与规则几何；SVG 适合精确轮廓、线条与关系图；摄影、手绘媒介、材料细节和复杂主体
可使用真实素材或生成图。按目标效果、事实用途和交付条件选，不为了省事把所有视觉都做成几何拼图。
图片任务与回填见 [素材流程](images.md)。正文、数字和需要精确修改的标签尽量与图像分层维护。

装饰可以承担气氛、身份和停顿，不必各自证明一条数据。大胆的字形、裁切、笔触、纹理与叠层都可以使用，
只需在当前画面中处理好主次、可读性和事实关系。排印可以主导个别页面，完整新稿仍需履行功能配图与背景设计，
不能将“排印路线”写成全套无图的豁免理由。
HTML 中可修改的 SVG、滤镜或渐变，不代表目标 PPTX 会保留为原生对象；按 [交付格式](delivery-formats.md) 验证。

## 用真实内容检验，再回应反馈

用本项目能暴露难点的内容落实方向，检查它能否从开场延续到解释、比较、证据或收束等实际任务。
具体页数和结构由材料决定。比较方向时保留必要事实，不另换一个容易做漂亮的主题；
封面与密集内容页承担不同工作，不能只用短口号证明内容承载改善。

与参考并看，定位用户在意的特征哪里丢了：素材不对、尺度太接近、背景没有层次，还是读法与内容冲突？
改产生问题的设计决定，再回看受影响页面。不要把“更有设计感”自动翻译成换颜色、增加装饰或持续动画。
反馈若只针对某页或某个维度，保留其他已认可决定；若改变整体方向，更新 brief、共享 CSS 和受影响素材。

试排交付要能直接看到真实画面、实际中英文字形和内容图解；纯风格说明、色值表或空白图框不能代替这一步。
用户尚未回填生成图时，可用准确绘制的内容图解展示真实阅读关系，并注明待图范围；依赖主视觉的页面仍待素材验证，
不能声称整套图像风格已验收。按入口判断是否等待样页反馈，不能先铺满全稿，再把最后截图称为“样页”。
保存实际样页、项目 CSS、素材与必要说明即可。确有复用需求再整理项目风格包；
它仍是可修改的项目资产，不是通用 skill 的必选菜单，外部风格包也不自动兼容本工具。

方法参考 [style-generate-skill](https://github.com/arcsin1/style-generate-skill/tree/02c17be466979a2f9cb018c9a695e3eaa3d2108f)
的具象描述与预览分工，并结合演示内容独立改写；不继承固定分类、配图禁令或外部文件契约。
