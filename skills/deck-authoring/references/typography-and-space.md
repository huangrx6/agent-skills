# 排印与空间：让层级在实际字形中成立

字号变大、留白变多不自动构成好设计。先让标题、证据和解释获得不同的视觉权重，
再用少量稳定的对齐轴，把这些内容组织成可读的整体。

## 先确定排印语法

依据 [项目设计记录](refined-workflow.md) 的方向，用本项目实际文字试排字体。
[Typewolf](https://www.typewolf.com/) 可研究网页字体搭配，
[Google Fonts](https://fonts.google.com/) 可查看字形与字体资料；具体字体以发行方的覆盖与许可为准。
英文参考不能证明中文效果。样张至少覆盖本项目实际用到的文字类型，核对汉字、标点、数字和字重确实生效。
需要单独比较字体时固定内容、颜色与大体构图；也可在代表内容页中整体判断。
用户要求选字时展示实际样张，已有选择不重复问。根据主题与观看场景，考虑以下关系：

- **字体与字重分工**：用实际汉字、数字和标点判断字感，结合参考选**一个能同时承担标题与正文的字族**；层级用字重、字号和行高拉开，不靠第二族。第二文本字族只在用户或品牌明确要求时使用。
  大字可以轻，正文也可以有足够重量；按实际笔画与背景判断，不给某类主题固定字体或字重配方。
- **尺度关系**：主角、解释与辅助信息获得可辨的重量。主角可以是图像或文字，
  也可以由接近尺度的连续排印形成阅读；不要求每页经过同一套标题层级。
- **阅读宽度与断行**：用实际段落找合适行长，长标题按语义与构图安排。中英混排、字形、
  内容长度和观看距离共同决定列宽，不先把正文锁进固定字数或模板栏。
- **空间骨架**：外边距、主对齐轴、栏间距与组内间距共同组织关系。参考中的尺度与空白
  需要与本项目内容一起试排，不能只取它的字号与色值。

字号与间距由实际画面确定，不把一张通用尺寸表作为所有风格的起点。
以下数字仅说明工具目前怎样提示可读性，选择器与变量可按项目调整：

新 `.deck-page` 在 1600×900 画布上默认正文 26px、标题 64px、组内小标题 32px、图注 18px、页脚 16px，分别可调；
`cover` 用 112px 展示档，`statement` 用 52px。这是演示尺度起点，不是所有主题的字号表；
密集阅读页可下调，海报页可上调。标题不必又大又粗；靠字重、位置和间距也能建立层级。
用户要求精致、利落时优先收敛标题与重复小标题的重量，正文在看得清的前提下可适当调小，腾出的空间不再填字。
面向远距投影时应按现场阅读条件调整，不能把屏幕字号当作投影保证；展示大字仍可用于确有需要的焦点页。
`data-viewing="screen"`（缺省）以 24px、`room` 以 28px 提醒正文可能偏小；这是普通阅读建议，
不是默认阻塞条件。必要时按实际观看场景设项目自己的显式要求，并据真实渲染判断。
有效分区里，小字提醒对图注/小标签和页脚分别以 16px、14px 为起点；显式 `--min-font` 则统一覆盖。
`.deck-kicker` 属于辅助标签，不承担正文解释；不要用它替代说明或把正文缩成标签。
小字号警告用于检查阅读条件，不应把正常图注、页脚推到正文的视觉重量。
这些值用于提醒检查可读性，不是字号下限，也不应让辅助字与正文争夺注意力。
阅读困难时考虑内容量、构图和比例，而非只缩字。标题、正文与页脚的实际可用尺寸见
[布局计算与章节拆页](layout-technology.md)，不能按固定字数或画布总高估算正文能否放下。

不要把高分辨率截图当作可读性证明。1600 px 设计画布缩到 1000 px 窗口时，24 px 正文
只相当于约 15 px 屏幕字；远距离演示更需要减少信息或拆页。

## 标题与证据的相对重量

标题可以是短判断，也可以是有节奏的长句或主题索引；其视觉重量由页面任务决定。
原因、条件和实现细节按与主旨的关系组织，不必一律缩成副标题。
若限定影响结论，须留在标题或紧邻说明中，不能按固定字数裁切而改变含义。
大字不一定属于页头：图像是主角时，标题可以在旁边或下方以较小字号帮助辨认；
一句判断承担全页时，它可以进入主体区域。不要因为已有标题样式就自动占据每页相同的高度和位置。

中英混排尤其要核对实际宽度。不要将长解释仅改成浅色，却继续沿用标题字号；视觉面积并没有减少。
标题需要两行时按语义断行，并让正文自然让位。若标题与大段副标题共同占满页头，重新提炼信息层级，
而不是持续压缩正文或收紧字距。

## 中文不能套用英文字距

**这一节是硬错误，不是风格选项。** 下面的情况在评审里直接算 defect：

1. 中文句子/标题被加了 ≥0.05em 的字距（`kicker`、栏目标签、表头、竖排边注最容易中招）。
2. 竖排中文用 `text-orientation: mixed`，导致数字和拉丁字母侧躺。
3. 页码引用、序号、"→ p12–13"这类短引用被换行劈开（行尾只剩箭头，或下一页只剩 `13`）。
4. 中文语境里混用半角/全角括号与斜杠。
5. 中文正文与等宽标识符用同一字号，标识符看起来像脚注。

- 中文从 `letter-spacing: 0` 开始，按实际字形微调。不要把英文展示字常用的负 tracking
  整段套到中文；尤其不要普遍设为 `-.06em` 或更紧来“挤出高级感”。
- 正文行高通常从 1.5–1.75 试，标题从 1.15–1.35 试。宋体、高对比字形和短标题要单独看，
  不能只按数字判断拥挤。拉丁展示字可有不同的行高。
- 逗号、句号、括号与引号要目检；不要把孤立标点留在新行。手工 `<br>` 只用于已知画布
  的语义断行，文案改变后重新检查，不锁死整段正文宽度来凑原稿。
- 拉丁字、版本号和数字观察基线与视觉大小，不能仅因为 CSS 字号相同就认为协调。
  表格使用 `font-variant-numeric: tabular-nums`；必要的单位与数值保持相邻。

## 确认浏览器实际使用的字体

声明 `font-family` 不等于已加载。`document.fonts.check()` 也不足以证明目标字族真的承担了汉字：
系统回退可能让检查仍返回成功。

1. 核对目标机器字体文件或已授权的本地 webfont；格式、字重和 CJK 覆盖一起确认。
2. 等 `document.fonts.ready` 后，查看浏览器实际渲染字体（例如 CDP `CSS.getPlatformFontsForNode`）。
   检查含汉字的标题、正文和含拉丁/数字的节点，而不只检查英文 logo。
3. 截图比较轻/常规/半粗字重是否确实不同；不依赖缺字重时的浏览器合成。
4. 交付其他机器时带上获许可的字体，或明确列出系统字体依赖并回读。不得将系统商业字体
   复制进公开 skill；嵌字方法与许可检查见 [fonts.md](fonts.md)。

## 用间距把关系表达出来

同一组的标题、解释与图注靠近；不同组之间留更大的间距。间距须让归属一眼可辨，
不用固定倍数代替实际判断。外边距、文字轴和图表基线应有清楚关系，视觉中心可按字形与图像重心微调。

整页安静区的安排见 [构图推导](composition-principles.md)；这里同时检查组间分隔与行间呼吸。
底部空着 200px 仍可能很挤：若五段长行横跨全页，先缩短阅读路径、拆解解释，把空间留到内容旁边和组间。
不要按“空白占比达标”打分，也不要把网格剩余空间视为必须填完的额度。

信息量按阅读任务安排：五个短标签和五段完整说明的负担不同，需要时展开讲解。
默认 `.deck-copy` 用 820px 作为试排列宽，可按字体和构图覆盖；长行需要检查阅读是否吃力，
短标签、表格与海报也不受同一列宽约束。强调色、字重和横线应帮助识别层级与分组，避免处处抢眼。

外边距与栏间距按主角尺度和阅读关系调整。满版图、海报或出版物式细边距均可采用，
按实际构图与可读性判断。

## 容器与表格中的空间

内容只有几行而边框一直延伸到页脚时，先检查是有意构图还是自动拉伸。画布的可用高度与内容块的
可见边界分开设计；不要仅为了填满被拉高的容器而增加文字、放大字号或全部垂直居中。内容带需要整体放大时
按 [构图原则](composition-principles.md#页面利用率内容带要有意) 处理主体尺度。等高比较或稳定图像比例可以保留，
但内部重心应与之相配。Grid / Flex、高度和表格的具体排查与 CSS 示例见 [布局计算](layout-technology.md#容器跟内容合身空间留给构图)。

紧凑比较表中，名称、数值与短说明通常垂直居中更平衡，上下内距相称；长段说明可以顶齐，保持共同阅读起点。
行高随内容与内距确定，不为铺满画布拉长每行。整张表在页面的位置与单元格中的垂直对齐分别检查。
实际看多行单元格、首尾行和缩放后的文字；写了 middle 不等于视觉中心一定正确。
目标场景中读不清时调整列宽、排印与信息组织；需要拆页时保留必要比较关系与所有说明。

排印完成后在实际观看尺寸读一遍，查看真实字形、断行、图注和最密页面；整套审稿方法统一见
[视觉审稿](visual-quality.md)，不重复维护另一份检查表。

排印方法参考 [IBM Carbon Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview)：
按阅读目的区分信息型与展示型层级，并将字族、字重、字号和行高作为整体校准。
本文件的演示尺寸与中文建议是试排起点，不是 Carbon 的规定；仍须按本项目实际文字与观看条件验证。
