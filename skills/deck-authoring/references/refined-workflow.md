# 项目设计记录与制作推进

## 一份记录贯穿制作

沿用当前有效的 brief；跨页或跨轮需要保持决定时，在 design.md 简记观众、目标、观看条件、事实来源、
采用的参考及设计决定、素材计划与待验事项。区分用户确认与作者选择，局部编辑不补造整套档案。
设计记录指向实际 CSS、字体与素材，已有配图计划直接链接，避免多处重复维护。
记录当前推进位置（待选参考、待看样页或制作中）、用户实际选择/委托的原话或消息依据、样页路径与反馈。
只记真实发生的决定，不以作者搜索、计划中的任务或旧稿文件代替用户回复；不需要新增状态 JSON。

完整新稿在正文铺满页面前完成 [功能配图和背景规划](images.md)，交付 Markdown 并接好图位。
逐页明确本页问题、图像分担什么、保留的短文与细节去向；信息过多先拆讲，再安排配图和背景。
用户出图期间继续完成文字与图位的实测，不能等回填才第一次检查容量。

## 风格选择要有理由和取舍

先按 [制作入口](../SKILL.md#开始制作前先判断是否需要交互) 判断选择是否已经发生，再按 [参考选择入口](visual-language.md#新稿的参考选择入口)
取得具体视觉依据，按 [配色](color.md) 在真实图文关系中选色。已确认品牌、参考与选择持续有效；
旧作品的局部样式不能自动成为新稿约束。等待用户时，不进入依赖选择的制作。

## 从代表内容到整套

先处理影响整体的未知项：关键图像、复杂内容、字体或导出限制。用能暴露该问题的真实页面验证，
不固定样页数量与页型。样页需同时暴露开场气质和真实内容的承载问题，并使用实际标题、正文与图标签字体；
有动效要求时提供可播放的对应样页。观察目标观看尺寸后修订，按入口约定取得反馈或自主继续，再扩展；
内容变化时可以重组构图，不能让全套迁就第一张样页。
统一字体与颜色角色、图像处理及阅读坐标，各页按任务改变主体、密度与位置。
网页参考转成讲解序列，互动信息保留静态可读状态；参考图不冒充项目证据。

## 修改与交付

反馈落实到内容、整体方向、素材或局部阅读关系，更新相关源文件与决定。共享 CSS 或素材变化后回看受影响页面。
按 [视觉审稿](visual-quality.md) 简记具体问题、处理及回看结果。配图交接与资源/几何/格式检查分别报告，
缺图只能交待配图稿；保留可修改源、素材与需要的格式。通过技术检查不等于设计完成。

## 重新制作与资料边界

用户要求完全重做、不看历史时，排除旧 deck、截图、配色、字体、隐喻与旧选型记录；
文件放在 diagrams 或 assets 中也不改变这一边界。仅核实当前技术事实与有效品牌要求，引用路径需实际存在。
用户要求清理时移除指定旧素材并修复引用；重做本身不等于删除授权。局部修订保留已认可的其他决定。
