# 项目设计记录与制作推进

## 一份记录贯穿制作

沿用当前有效的 brief；跨页或跨轮需要保持决定时，在 design.md 简记观众、目标、观看条件、事实来源、
采用的参考及设计决定、素材计划与待验事项。区分用户确认与作者选择，局部编辑不补造整套档案。
设计记录指向实际 CSS、字体与素材，已有配图计划直接链接，避免多处重复维护。
记录当前推进位置（待选参考、待看样页或制作中）、用户实际选择/委托的原话或消息依据、样页路径与反馈。
完整新稿另记一句视觉命题（观众与场景、2–3 个参考 move、字体/颜色/网格/图像/材质、signature、反目标）
和至少三张 hero pages；可从 [设计记录模板](../assets/design-record.md) 复制。
扩展前按 [审美闸门](design-review.md) 留下两轮 before/after。
只记真实发生的决定，不以作者搜索、计划中的任务或旧稿文件代替用户回复；不需要新增状态 JSON——
**阶段状态用 `design.md` 的 `## 阶段闸门` 表记录**，由 `gate_check.py` 核验顺序与产物，见 [阶段闸门](stage-gates.md)。

完整新稿在正文铺满页面前完成 [配图和背景规划](images.md)，接好图位，并交 `image-brief.md` 由用户生成或提供；
不代生图。逐页明确本页问题、图像分担什么、保留的短文与细节去向；
信息过多先拆讲，再安排配图和背景。取图期间继续完成文字与图位的实测，不能等素材齐了才第一次检查容量。

## 风格选择要有理由和取舍

先按 [制作入口](../SKILL.md#开始制作前先判断是否需要交互) 判断选择是否已经发生，再按 [参考选择入口](visual-language.md#新稿的参考选择入口)
取得具体视觉依据，按 [配色](color.md) 在真实图文关系中选色。已确认品牌、参考与选择持续有效；
旧作品的局部样式不能自动成为新稿约束。等待用户时，不进入依赖选择的制作。

## 从代表内容到整套

先处理影响整体的未知项：关键图像、复杂内容、字体或导出限制。用能暴露该问题的真实页面验证，
不固定样页数量与页型。样页需同时暴露开场气质和真实内容的承载问题，并使用实际标题、正文与图标签字体；
有动效要求时提供可播放的对应样页。观察目标观看尺寸后修订，按入口约定取得反馈或自主继续，再扩展；
内容变化时可以重组构图，不能让全套迁就第一张样页。
统一字体与颜色角色、图像处理及阅读坐标，各页按任务改变主体、密度与位置。
网页参考转成讲解序列，互动信息保留静态可读状态；参考图不冒充项目证据。

## 修改与交付

反馈落实到内容、整体方向、素材或局部阅读关系，更新相关源文件与决定。共享 CSS 或素材变化后回看受影响页面。
按 [视觉审稿](visual-quality.md) 简记具体问题、处理及回看结果。配图交接与资源/几何/格式检查分别报告，
缺图只能交待配图稿；保留可修改源、素材与需要的格式。通过技术检查不等于设计完成。

HTML 生成并检查完成后先问两件事：**配图还要不要、导出哪种格式**，见
[导出前的两个问题](delivery-formats.md#导出前的两个问题)。缺图回填前不导出 PDF / PPTX；
用户明确说不配图才进入格式选择；用户要求先导一版时标明草稿与待补文件。补图后重导，
不能把旧导出说成已包含新图。导出不是 HTML 完成后的默认动作。

## 重新制作与资料边界

用户要求完全重做、不看历史时，排除旧 deck、截图、配色、字体、隐喻与旧选型记录；
文件放在 diagrams 或 assets 中也不改变这一边界。仅核实当前技术事实与有效品牌要求，引用路径需实际存在。
用户要求清理时移除指定旧素材并修复引用；重做本身不等于删除授权。局部修订保留已认可的其他决定。

**开新版本不需要用户先声明"不看历史"**：新版本默认全新设计，设计期间不读上一版源文件，
也不凭记忆重建它的栅格与组件。边界、必须重做的维度、授权沿用与常见借口见
[版本隔离](version-reset.md)。

## 版本轮换：重做不等于改稿

- **重做 = 新版本目录**（见 SKILL.md 的目录契约）。旧版本不覆盖、不搬素材、不就地改风格。
- **新目录从空开始**：不 `cp -R` 上一版，不在旧 `source.html` / `deck.css` 上删字改版。
  复制会把上一版的判断一起带进新稿，改到最后往往只剩配色不同。
- 重做时**内容可以复用，结构必须重推**：按问题重新拆页，不得直接沿用上一版的页序与组件。
- 在 `design.md` 写 `## 与上一版的差异`，至少覆盖参考、字体、配色、构图、图案、封面 / 尾页；
  写"本版选什么"，不写"和上一版差不多"。`version_guard.py` 会核对这一节存在且有内容。
- 同一套组件只在版本内复用；跨版本复制 class 与版式，等于把上一版的审美决定偷偷带进新稿。
- 三张 hero pages 之后与交付前各跑一次 `version_guard.py`：它比对同级更早的 `vN`，
  报告只给哪一维重合、重合多少，不回显上一版的具体值。硬失败按 [版本隔离](version-reset.md) 处理，
  不靠改色号或换配图把重合度压下去。
- 交付前把这一版与上一版**并排看缩略图**：若轮廓几乎相同，说明只换了颜色，不是重做。

## 素材也按版本走

配图、参考截图、字体都属于某一版的视觉决定，不属于项目：

- 新版本**默认重新规划配图**（`image-plan.json` 与 `assets/images/` 一起重做），参考图重新找。
- 复用旧版图片必须在计划里写成 `source: "provided"`，并说明它为什么在新方向下仍然成立；
  只因为"文件还在"就沿用，等于把上一版的视觉语言偷偷带进新稿。
  `version_guard.py` 按文件哈希查重，未登记的复用会判硬失败。
- 字体同理：换风格常换字族，旧字体留在旧版本目录里，不要挂到新版本上。
- 用户明确要求沿用某一维时，用 `version_guard.py --allow <维度> --reason "用户原话"` 放行，
  并在 `design.md` 记下授权范围；未列出的维度仍按重做检查。
