# 六项机械校验的口径

`scripts/check.py` 跑的是**六项机械校验** —— 只查能机械判定的东西，不承诺审美。
全过退出 0，任一不过退出 1。这份文档是每一条的"判据"，让你看到报错就知道
该改哪。

> 校验和调参循环都在同一个文件里 —— 调参**完全由校验结果驱动**，
> "哪项失败动哪个参数"是一张表的两半。

## ① 对比度

**判据**：每页文字（标题 / 条目 / 时间点 / 图表值 / 图表标签）相对纸色的对比度
必须达到 `contrast.minBody`（4.5）或 `contrast.minLarge`（3.0，按 ≥ 32px 分档）。

**为什么是叠印墨**：

主 / 副色单独当文字色对比度天生不达标（vivid 实测 2.35 / 2.68 ✗）。
它们的语义是**墨层 / 色块 / 装饰**，不是**承载文字**。
文字色是 `overprint(primary, secondary)` 派生出来的（vivid 实测 9.55 ✓）。

**会报的情况**：

- `第 N 页 X 对比度 R < floor` —— 叠印墨在该色板下不达标。换色板，不要改 `minBody`。
- `第 N 页 X 声明 color='<hex>'` —— spec 里写了 `color` 字段且不是 `"overprint"`。
  主 / 副色不允许直接当文字色。

**反例**：`style.json` 里 `colorSets` 新加的"两墨都亮"组合会在 `ink.py` 那一关就过不去，
不该出现在 deck-spec.json 里。

## ② 文字溢出

**判据**：按字宽估算表算文本盒宽度，超出版式上限就报。
CJK / 全角按 1em，ASCII 按 0.55em。**这是估算**，不是度量表 —— 精确断行靠浏览器，
估算只为挡住"明显放不下"。

**每种版式的上限不一样**（不是统一宽度）：

| 版式 | 可用宽度 |
| --- | --- |
| `title` / `content-text` / `end` / `chart` | 1432px（内容区满宽） |
| `content-image` | 820px（左栏） |
| `two-column` | 660px（每栏） |
| `timeline` | 1320px（多栏拼成） |

用同一个宽度判，必然一边误报一边漏报 —— 用错版式上限是**常见踩坑**。

**累计高也算溢出**：条目堆叠超过内容区高度也算。
这里没有按字符精确折行，但能给"条目太多塞不下"一个机械判据。

**反例**：把图左页的条目按全文页宽度判，会报"溢出"；
实际渲出来根本放得下 —— 不要因此去改条目字号。

## ③ 错位区间

**判据**：从**产物 HTML** 里读实际写进去的 `--dx` / `--dy` / `--rot`，
比对 `token.misregistration` 的区间。

**为什么不只看 spec**：错位量是脚本**派生**出来的，spec 里也没有对应字段。
只看 spec 拿不到真值；只看 token 会被脚本自己内部越界漏过去。

**会报的情况**：读到的 `dx/dy/rot` 不在 token 区间内 → 内部不一致，报告里写明
"这是脚本内部不一致"而不是"这是内容问题"。

## ④ 装饰不压文字 + 图表成比例 + 图表区无错位

**判据 A（装饰不压文字）**：墨块（`data-zone="tr|br|tl|bl"`）必须落在
**安全区**（SLIDE_W / SLIDE_H 的右下两个角的"溢出"位置），
与文字栏（`(84, 132, 1000, 770)`）不相交。

为什么不放四象限：左栏是文字栏 ✗ —— 实测有标题被墨块压上。
`render.py` 现在只生成 `tr` / `br`（右侧两角），所以 `tl` / `bl` 一旦出现就是
脚本或 spec 错乱。

**判据 B（图表柱高成比例）**：柱高两两之间必须与数据成比例，**且基准取数据
最大那一条**。

为什么不按图形最高那根当基准：被篡改的那根一旦成为最高，它自己就被跳过、
而无辜的柱子被报 —— 实测过 ✗。

为什么不用对峰值归一：一旦有一根被改高，峰值基准就跟着错，六根全报
—— 那种输出等于没说清是谁错了。两两比例与基准无关，只会指向真的那一根。

**判据 C（图表区无错位）**：图表容器（`<div class="chartwrap">`）
内不许出现错位叠印元素。riso 只允许做容器与背景 —— 错位会毁掉柱与刻度的可读性。

## 不是校验但值得提的"内在不变量"

> **#1 元素间隙** 和 **#3 文字溢出-精细版** 在今天的坐标推导下**构造上不可能失败**。
> 它们一旦报，报的是**脚本内部不一致**（推导与实际落笔不符），不是你的内容有问题。
> 留着是因为以后换掉坐标推导方式时它们会立刻变成真实的门。
> **别把"它从来不报"当成"它没用"** —— 但也不要因为它在就以为间隙真的被量过了。

## ink.py 的门禁（不进 check.py 但同源）

`python3 scripts/ink.py styles/risograph/style.json` 是色板门禁 —— 任何一套色板
不达标退出 1。它和 `check.py` 第 ① 条共用同一份 token，但视角不同：

- ink.py 看的是**色板本身**（叠印墨相对纸色是否达标）
- check.py 第 ① 条看的是**产物里实际写进去的文字色**（产物里所有文字都是
  overprint 色，所以一旦 ink.py 过，check.py 第 ① 条在该色板下不会失败）

两者**不是冗余** —— ink.py 早一步挡住坏色板，免得用户渲到一半才发现。
