# 校验的口径

`scripts/check.py` 跑的是**一组机械校验** —— 只查能机械判定的东西，不承诺审美。
全过退出 0，任一不过退出 1。这份文档是每一条的"判据"，让你看到报错就知道该改哪。

分两类（这个区分很重要）：

- **阻塞**：能确定性判定的。判错就是真错 —— 包括从真浏览器**实测**出来的版面数据。
- **提示**（`advisories()`）：启发式的。字体回退就属于这类 —— 它可能误报，
  拿它挡交付会把人逼到忽略整个检查。

> 校验和调参循环都在同一个文件里 —— 调参**完全由校验结果驱动**，
> "哪项失败动哪个参数"是一张表的两半。
>
> 输入层门（`validate_spec.py`）与几条跨工件验收（风格的 `layouts` 词表）
> 不在 `check.py` 里，一并记在 §⑥。

## ① 对比度

**判据**：只有一条 —— 叠印墨（`overprint` 派生的文字色）× 纸色的对比度
必须达到 `contrast.minBody`（4.5），整副一刀、不分页不分角色（check.py ①）。
`contrast.minLarge`（3.0，按 ≥ 32px 分大字档）**只是 token 里备着的数，判据未接**
—— 按字号分档的对比度检查在路线图上。

**为什么文字色不让你自己填**：

主 / 副色单独当文字色对比度天生不达标（vivid 实测 2.35 / 2.68 ✗）。
它们的语义是**墨层 / 色块 / 装饰**，不是**承载文字**。
文字色是 `overprint(primary, secondary)` 派生出来的（vivid 实测 9.55 ✓）。

**会报的情况**：

- `叠印墨对比度 R < 4.5（文字色不达标）` —— 色板派生的叠印墨不达标（整副
  一条，不带页号）。换色板，不要改 `minBody`。
- `第 N 页 声明 color='<hex>'` —— spec 里写了 `color` 字段且不是 `"overprint"`。
  主 / 副色不允许直接当文字色。

**反例**：`style.json` 里 `colorSets` 新加的"两墨都亮"组合会在 `ink.py` 那一关就过不去，
不该出现在 deck-spec.json 里。

## ② 版面越界 / 容器裁切（**实测**，不估算）

**判据**：用 `measure.py` 从真浏览器读每个元素的**真实盒子**，再判两件事：

- **甲・越出版面**：元素盒子和**它所在那一页**的盒子比。`.slide` 是 `overflow:hidden`，
  出去就是被裁。
- **乙・容器内裁切**：元素**自己会裁**（`overflow` 不是 `visible`）且 `scrollW/H > clientW/H`。

**为什么删掉了估算**：原来用 `text_width()` 按 CJK 1em / ASCII 0.55em 估宽。
实测同一行 12 个汉字标题（`end` 页，真实字号 180px）：

| | 值 |
| --- | --- |
| 估算 | 12 × 86 = **1032px** |
| 实测 | 文字 **2124px**，盒子右缘 **2212px** |
| 后果 | 越出版面 **612px**，被裁 —— 而估算判的是「✓ 全过」 |

**低估 2 倍多**，而且这个偏差不是常数：随字体、字距、折行、`white-space` 变。
故估算永远修不准，只能量。

**两条注意事项（都是实测踩出来的）**：

- 比的是**该元素所在那一页**的盒子，不是全局 1600×900 —— 产物是竖向堆叠的多页，
  第 2 页的元素 y 本来就在 900 以下，拿全局边界比会把后面每一页都误报。
- 容器裁切只在**元素自己会裁**时才算。`.foot` 那种 `overflow:visible` 的，
  `scrollHeight` 比 `clientHeight` 大 2px 是行高与字面度的正常差，报它就是误报。

**装饰墨块不会误报**：它们故意溢出到版面外（`right:-60px`），但没有 `data-m`、
不进测量清单。

## ③ 产物健康（同样实测）

两条阻塞检查（最容易被忽略，因为失败是静默的）：

- **图片没加载**（`img.naturalWidth == 0`）。相对路径的产物挪个目录就会全员裂图 ——
  交付前要么同目录交付，要么 base64 内嵌。
- **产物里的脚本报错**（`error` / `unhandledrejection` / `console.error`）。

还有一条**不阻塞**的提示：**字体回退**。它是启发式（拿一个一定不存在的族当基准比宽度，
衬线撞衬线时会误报），所以拆到 `advisories()` 里只提示 —— 拿启发式挡交付会把人逼到
忽略整个检查。已经排除了 `serif` / `monospace` 这类**通用族**（它们不是字体而是回退目标）。

### 契约没过期（导出 PPTX 前跑）

```bash
python3 scripts/check.py deck.spec.json out.html --resolved resolved.deck.json
```

契约（`render.py … --resolved`）把**当时的**几何烤了进去，导出 PPTX 走的就是那一份。
而契约会过期：改两行字、换一次风格、换台机器（字体不同 → 行高不同），HTML 重渲一遍
版面就动了，契约还停在原地 —— 那时导出的 PPTX 与 HTML **不一样**，而两边各自都
"成功"了，没人会知道。所以传了 `--resolved` 就等于说"我要从这份契约导"，那道门
就当场对账（元素缺在任一侧 / 盒子差 >1px / 页数不同 → 阻塞）。

**1px 这个阈值有实测依据**：同一份 HTML 量两次、以及"契约 vs 现测同一份 HTML"，
逐元素差都是 **0px**（管线是确定性的）—— 所以任何超过 1px 的差都是真漂移，
不是测量噪声。

### 本机路径（一半是可移植性，一半是隐私）

`check._check_local_paths` 扫产物文本，分两类：

- **图片的绝对路径 —— 阻塞**。`src="/Users/…/x.png"` 在**这台机器**上看着正常，
  而产物是要被拷到别人机器、会议现场、归档目录里的 —— 换一处就裂图，而且裂得
  很晚（那时人已经走了）。“图片没加载”那道门只会在这台机器上也读不到时才响，
  所以它拦不住这一种。顺带：绝对路径里往往带着用户名 / 项目名 / 客户名。
- **`file://` —— 阻塞**。交付物不该指向本机文件系统，没有任何合法场景。
- **字体的绝对路径 —— 提示**。字体住在 deck 项目之外是**设计**（见 `fonts.py`），
  所以不阻塞；但拿去别的机器会回退 —— 要真正自包含单文件就 `fonts.py --embed`。

### 素材复用（提示）

`check._reuse_notes`：同一张图被多页当主视觉时开口。它是“每页都真的决定过它要
什么”的反面证据（而**合理复用**是决定：贯穿动机、同一组系列图 —— 那就要在 `notes`
里写一句为什么）。两页的**槽位比例不同**时一并说：同一张图进两个比例的槽位会被
裁成两种构图，那是两种用法，不是复用。

## ③b 对齐提示（网格吸附 · 右缘 · 同级一致）

三条**提示级**的对齐体检（挂在网格对齐那组，`check._check_grid_alignment`）：

- **左缘吸附**：锚点元素（title / subtitle / image / chart）的左缘应当在边距或
  某个列起点上；风格有意的偏移（悬挂缩进 / 出血）可忽略 —— 提示里写明了。
- **右缘在栅格缘**：视觉容器（chart / image）的右缘必须落在内容右界（1516）
  或某列起点减一档 gutter（span 的右端）。它看得见「左缘吸得完美、右缘冲出
  内容界 48px」那种宽度数学错（实测：图表盒 content-box 下 width+padding
  会宽出 48px，皮肤不留横向 padding 时恰好被掩盖）。
- **同级左缘一致**：`s{N}.title` 与 `s{N}.subtitle` 的左缘差 >1px 即提示
  （按 **id** 配对，不按 role —— 栏题与时间线节点标签的 role 也是 subtitle，
  但它们不是标题块的副标题）。实测抓到过 2px 漂移：标题块内缩 6+24=30、
  副标题用了 32 的档 —— 单看每行都「差不多」，并排才露馅。

## ④ 错位区间

**判据**：从**产物 HTML** 里读实际写进去的 `--dx` / `--dy` / `--rot`，
比对 `token.misregistration` 的区间。

**为什么不只看 spec**：错位量是脚本**派生**出来的，spec 里也没有对应字段。
只看 spec 拿不到真值；只看 token 会被脚本自己内部越界漏过去。

**会报的情况**：读到的 `dx/dy/rot` 不在 token 区间内 → 内部不一致，报告里写明
"这是脚本内部不一致"而不是"这是内容问题"。

## ⑤ 装饰不压文字 + 图表就绪/数据形状 + 图表区无错位

**判据 A（装饰不压文字）**：墨块（`data-zone="tr|br|tl|bl"`）必须落在
**安全区**（SLIDE_W / SLIDE_H 的右下两个角的"溢出"位置），
与文字栏（`(84, 132, 1084, 770)`，右缘 = PAD_X+1000 —— check.py 的 TEXT_BAND）不相交。

为什么不放四象限：左栏是文字栏 ✗ —— 实测有标题被墨块压上。
`render.py` 现在只生成 `tr` / `br`（右侧两角），所以 `tl` / `bl` 一旦出现就是
脚本或 spec 错乱。

**判据 B（图表就绪 + 数据形状）**：不查"柱高与数据成比例"——几何由 AntV G2
的编码算，脚本再量它的像素等于用手去量尺子。查的两件事：

- **G2 真渲染出来了**（只能实测）：`measure.py` 给图表容器多记一个 `chartReady`
  字段（`ready` / `pending` / `error:<原因>`，measure.py:170）。产物静态 HTML 里
  只有容器与 spec，判断不出来 —— 所以这条必须真浏览器量。`check.py` 的 ④
  （check.py:603 起）拿它判：`error` 即阻塞（G2 缺失或渲染失败，那一页是空的）。
- **数据形状对**：`label` 非空（空标签 → 轴上缺一个标签）、`value` 是数字。
  数据本身错才是真错。

**判据 C（图表区无错位）**：图表容器（`<div class="chartwrap">`）
内不许出现错位叠印元素。错位叠印效果只允许做容器与背景 ——
错位会毁掉柱与刻度的可读性。

## ⑥ 输入层与布局词表门

审美决策由作者声明，脚本是验收器：下面这几道门是"作者声明"那一侧的守门人 ——
声明缺了、写错、写了不认识的值，都在这里当场拦。

**输入层（`validate_spec.py`，渲染之前）：**

- **colorSet 必填具名**：`deck.colorSet` 缺失或写 `"auto"` → `MISSING_COLOR_SET`；
  名字不在该风格 token 的 `colorSets` 里 → `BAD_COLOR_SET`。v3 的配色方向不再由
  语义（`mood`）推导，直接写色板名。（`render.resolve_color_set` 同样拦：缺失 /
  `auto` 直接 SystemExit —— `deck.compile_spec` / render 两道入口都进不去。）
- **图表类型必填且封闭**：chart 页缺 `chart` → `MISSING_CHART_TYPE`；不在八类
  （bar/bar-horizontal/line/area/bar-stacked/donut/scatter/combo）→
  `UNKNOWN_CHART_TYPE`（`render.chart_declared_type`（render.py:785）同样
  SystemExit，再交给 `render.chart_g2_spec` 出 G2 spec —— 见 `charts.md`）。
- **layout 是自由值，但 `auto` 拦**：`layout` 必须是非空字符串（非字符串/空 →
  `BAD_LAYOUT`）；写 `"auto"` → `BAD_LAYOUT`（布局必须显式声明）。自造布局名
  合法 —— 渲染套缺省结构 + `data-layout` 钩子，由 skin.css 排。
- **`variant` 字段不存在**：slide 级写 `variant` → `UNKNOWN_FIELD`，HINTS 里
  指路 `layout`（字段已改名，不再是变体）。

**跨工件（`check.py`，产物 + 词表）：**

- **风格 `layouts` 词表验收**（`check._layout_vocab_problems`，**阻塞**）：风格在
  `style.json` 声明 `layouts`（字符串数组）时，`spec.layout` 必须落在"词表 ∪ 结构
  布局（`IMAGE_LAYOUTS` / `TWO_COL_LAYOUTS`）"里；不在 → 阻塞 problem（自造名写错
  一个字母，skin 里那条规则就永远不生效 —— 最难查的静默）。风格没声明 `layouts`
  → 不验（没有词表就没有拼写基准）。
- **档位提示**（`check._tier_notes`，提示）：content-text 页条目 **> 5 且未声明
  `bulletTier`** 时提示"缺省档下会偏挤，先拆页/收短，确实要小字就显式写
  `bulletTier`"。v3 **没有按条数自动升降档** —— 档位是作者声明（`slide.bulletTier`
  / 风格 `bulletDefault`）。
- **布局轮换提示**（`check._layout_rotation_notes`）：同 type + 同 layout 连排
  ≥2 页提示换布局（阈值与函数名见 `layout-system.md` §41）。
- **字号体检**（`check._check_type_size`，提示，**四条线**）：判据全来自实测的
  `fontSize`（不是风格里声明的意图值）——
  内页标题 ≥72px（封面尺度用在了非封面/封底页）／一页 ≥4 条却用 >30px 的宣言档／
  正文中位数 >28px（整体偏大）或 <20px（总体偏小，一臂之内看不清）。
  中位数按**条目**加权（不是按页取最大值再中位）—— 少数宣言页不会把总体结论顶偏。
  提示里点名是哪一档（`type.compact` 之类），修法可执行。阈值与缘由见
  `style-architecture.md` 的「字号怎么定」。
- **下半页空着**（`_check_deck_shape`，提示，**两层**）：一页内容底只到正文带
  （132→824）的 `SPARSE_NOTE`=50% 以下就汇总报一条；低于 `DEAD_SPACE_NOTE`=28%
  则是逐页报（“只有标题没条目通常是漏了”）。这条跟字号是同一个问题的两面：
  **大字在填满正文带**，所以“字太大”常常同时意味着“内容不够”—— 一份
  3~5 条的内容页在合理字号下占带 45~60%；只有 33~46% 时下半页整块是死的。

## ⑦ 安全盒碰撞（`layout/` 包）

**判据**：`measure.py` 实测元素盒 + `layout/collision.py` 的安全距离表 ——
不同视觉组、同页、**安全盒**（四向外扩）相交 → 阻塞。只查真实边界看不见
「没撞但只剩 3px」的挤；「图表本体没撞、标签撞了」「图片没撞、caption 撞了」
只有安全盒能看见。

报告带**需要 / 实际**两个数（修法：拉开父容器 gap 档，或这页该拆）：

```text
第 9 页 s9.chart 与 s9.caption 太近（visual×caption：需要 ≥44px，实际 24px）
```

豁免四条（政策与距离表全文见 `layout-system.md` §11b）：同组、caption 被
visual 包含、同页 visual×caption、`layout == "hero"` 的标题条压图（intentional
必须显式声明 —— 不让 QA 猜「这是 bug 还是设计」）。

## 这一层不覆盖什么

- **字段集 / 必填声明**：那是**输入层**的事，由 `validate_spec.py` 管（见
  `style-architecture.md` 的 schema 一节，以及本文件 §⑥ 列的新门）。`check.py`
  仍不做字段集校验；它读 spec 只做三件跨工件的事：布局词表验收（**阻塞**）、
  档位提示与布局轮换提示（**提示**）—— 由它主动拦的**字段**只有 `color`
  （只接受 `"overprint"`）。
- **② 是实测，不是估算**：但它量的是**当前这份产物**在当前字体下的样子。
  换了机器（字体不同）或换了浏览器版本，同一个 spec 量出来可能不同 —— 所以
  `measure.py` 会在字体回退时给提示。
- **审美不承诺**：配色好不好看、版式舒不舒服，这些校验一律不管（`check.py` 的
  docstring 第一句就是这个意思）。字号体检也只是“报出明显不搭的组合”（内页用封面
  尺度、密集页用宣言档），“大字很有气质”的正确场景它一律放过 —— 只测它会报、
  不测它不误报的闸门，会把作者逼到永远不敢用大字。

## ink.py 的门禁（不进 check.py 但同源）

`python3 scripts/ink.py styles/<你的风格>/style.json`（deck 项目里跑）是色板门禁 —— 任何一套色板
不达标退出 1。它和 `check.py` 第 ① 条共用同一份 token，但视角不同：

- ink.py 看的是**色板本身**（声明的文字色相对纸色是否达标）
- check.py 第 ① 条看的是**产物里实际写进去的文字色**（产物里所有文字都是
  overprint 色，所以一旦 ink.py 过，check.py 第 ① 条在该色板下不会失败）

两者**不是冗余** —— ink.py 早一步挡住坏色板，免得用户渲到一半才发现。
