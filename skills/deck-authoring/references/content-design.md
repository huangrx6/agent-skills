# 内容设计

工具能算坐标、字号、对比度，算不了"这一页该说什么"。这份文档说的是**后者**——
但只写能落到具体动作上的部分：每条规矩都接一个可执行的检查或工具，不写"要用心"。

## 一页一个观点

**判据：标题需要"和 / 与 / 及 / ，"才能说清，那就是两个观点。**

- ✗「留存提升和成本下降」→ 拆成两页（或一页讲留存、成本放到证据页）
- ✓「留存提升 23%」→ 成本那件事另起一页

为什么较真：观众在一页上只建立一次印象。一页塞两个观点，记住的是零个。
`check.py` 的越界检查量不出这件事，但**排版会告诉你**：挤两个观点的页，条目一定是
满到最小字号那一档（见下）。

## 容量估算：先问 fit.py，别猜

写 spec 时最容易撞的墙是"这页装得下吗"。**别猜，量**：

```bash
python3 scripts/fit.py --from-spec deck.spec.json --slide 3   # 试排现有一页
python3 scripts/fit.py --json '{"title":"结论","bullets":["…","…"]}'
```

它把候选版式和各条目数档位摆进同一份产物渲一次、开一次真浏览器量一次，报出来的是
真实几何。下面这些数字都是**实跑出来的**（swiss-grid，中文条目 20~30 字）：

| 内容 | 结果 |
| --- | --- |
| 2 条 | 占正文带 46%（**偏稀**） |
| 3 条 | 占 57%（合适） |
| 6 条 | 占 61%（合适） |
| 10 条长句 | 占 85%（很满） |
| 16 条 | `content-text` **撞出 152px**；`two-column` 装得下，占 87% |
| 30 条 | 两种版式都撞；**单页最多 12 条**，得拆 3 页 |

两个反直觉的地方，都是量出来才知道的：

1. **字号按条数分档，所以"合并两页"有时反而更满**。≤3 条用大档（46px），4 条起换中档
   （32px），6 条起换小档（26px）。于是 4 条可能比 3 条还矮 —— 「越少越矮」是错的。
2. **微信/投影上的"看不清"有个具体门槛**：小档 26px 在一页 6~12 条时启用。
   900px 高的页面投到会议室，后排看到的约等于 26 × (投影高 / 900) —— 3 米外基本读不了。
   所以**一页超过 6 条时，先想"这一页是不是该拆"，再想字号**。

## 版式选择：看条目之间是什么关系

不是审美题，是关系题：

| 条目之间是… | 用什么 | 为什么 |
| --- | --- | --- |
| 并列、没有内在顺序 | `content-text` | 读者只需要"有几条" |
| **有先后 / 有过程** | `timeline` | 时间线把顺序画出来，正文列表把顺序丢掉 |
| **两方对比 / 两个立场** | `two-column` | 左右分栏本身就是"对立"这个意思 |
| **数字比大小 / 趋势** | `chart` | 柱高是量的对比，文字做不到 |
| 一条结论 + 一张实拍 | `content-image` | 图是证据，文字是判断 |
| 只要一句话 | `content-text` 拆到 1~2 条，或 `end` | 别为半句话占一整页 |

关系判错的典型症状：把"Q1→Q2→Q3→Q4"写成普通条目列表 —— 读者能读，但
**顺序感没了**，而那正是你要讲的东西。

## 叙事骨架

一份 deck 不是"内容的容器"，是一条**有落差的线**。最小可用骨架：

```text
封面（是谁 / 什么时候 / 讲什么）
  ↓
结论先行（一句话说清最重要的判断 —— 不要留到最后揭晓）
  ↓
证据（每一页支撑同一个结论；不同结论就该是不同的 deck）
  ↓
收尾
```

两个**可查**的偏离：

- **没有封面**：`check.py` 会提示（`type=title` 一页都没有）。第一页直接进正文时，
  观众还在调整状态，你已经讲到第二点了。
- **全是同一种版式**：`check.py` 会提示（3 页以上全是 `content-text`）。
  视线没有落点变化，观众的注意力会滑走 —— 这也正是前端 slides 模板库
  列为"不可妥协的反模式"的那条（no centered-only layouts with no compositional
  variety）。

倒数第二页放什么，取决于场合：**要被讨论的**放进"待决事项"，**要被记住的**放进收尾页
（`end` 的大字档就是给这个用的）。

## 观众距离：它决定字号、密度和**交付形式**

同一个内容，三种距离：

| 场合 | 距离 | 密度 | 交付 |
| --- | --- | --- | --- |
| 会议室站着讲 | 3~8 米 | 一页 ≤5 条，字号大档 | `out.html?present` 或 MP4 |
| 发群里 / 邮件里 | 手机屏，自己划 | 无所谓密度，但**必须能缩放** | 视频（GIF 最省事） |
| 打印 / 归档 / 反复翻阅 | 30 厘米 | 可以密，但要有页码与页脚 | PDF |
| 对方要改字 | 他在 PowerPoint 里 | 版式会被他改乱 | 可编辑 PPTX |

**这一栏会反过来改版面**：给 8 米外看的 deck 不该有 12 条一页 —— 那不是"内容多"，
是交付形式选错了（应该给 PDF 让他自己读）。所以先说清场合，再写内容。

## 该要就要：图别省

**图片该要就要。别因为嫌麻烦就少要 —— 多了也没事。**

这条得写成规则，因为"少要图"几乎总是**成本**造成的，不是内容造成的：出图要有人动手、
要写提示词、要等文件回来。这些都不该决定一页该不该有图。

一条判据：**如果这一页你要说"看这个"，就该有图。**

| 该有图 | 不必有图 |
| --- | --- |
| 讲**某个东西长什么样**（产品 / 现场 / 界面 / 人物） | 讲三条结论 |
| 讲**对比**（改造前后、竞品、两个方案） | 讲一个流程的步骤（`timeline` 更合适） |
| 讲**空间**（场地、动线、布局） | 讲一组数字（`chart` 更合适） |
| 需要**情绪**（封面主视觉、章节分隔） | 一页只有一句宣言（`billboard` 更合适） |

右列不是"不该做图"，是**这个版式已经承担了视觉功能**：时间线本身就是图形，
柱状图本身就是图 —— 再塞一张照片是重复。真正要提防的是**纯文字页**：
三四条长条目挤在一页、没有任何视觉落点，读的人是靠意志力在读。

### 这条准则在流水线里怎么落地

- **输入门（阻塞）**：`content-image` 版式**必须**有 `image`。缺了不是"少一张图"，
  是渲染器会直接崩 —— 这一页的全部内容就是那张图，它不该是可省的。
  这一页不需要图就换成 `content-text`（`validate_spec.py` 会拦）。
- **产物提示（不阻塞）**：全篇**一张图都没有**时 `check.py` 会开口，并点名条目最多的
  那几页纯文字页（最多三页）。为什么只是提示："这份 deck 该有几张图"取决于内容，
  像素判不出来 —— 但**不能不说话**，沉默就是默认，默认就是少要。
- **出图这条路要走得通**：`image_source.py --brief` 一次把每张图的契约与提示词写全
  （见 `references/images.md`），就是为了让"多加一张图"的成本降到"多填一行 spec"。

## 图不承载信息

上面说"该要就要"，这一条说**要来的图能装什么**：**一页的信息永远由版面用真文字排。**

图在版面上只有两种角色：

| 角色 | 是什么 | 在本流水线里 |
| --- | --- | --- |
| **配图** | 占一栏，和文字并排 | `content-image` 的图栏（实测占整页 **17%**） |
| **点缀** | 更小的装饰元素 | 更小的图、纹样、角上的元素 |

**背景**是唯一允许大的一张 —— 但它也不承载这一页的信息（它是场景 / 质感，不是标题、
不是数字）。

### 禁止：一张图盖住整页

**不要把这一页的所有东西生成到一张图上、再让那张图覆盖整页。**

这不是审美问题，是**功能**问题。一页的信息烘进图里之后，同时失去四件事：

| 失去 | 后果 |
| --- | --- |
| **可编辑** | 改一个字要重新出图、重新制版 |
| **可搜索** | PDF 里搜"毛利率"搜不到 |
| **可翻译** | 双语版本等于重做 |
| **可被读屏器读** | 无障碍直接归零 |

而"对方要改字"正是这个 skill 能出**原生 PPTX** 的理由 —— 一份内容全在图里的 PPTX
**是个假的可编辑文件**。

### 这条在流水线里的落点

- **`check.py` 阻塞**：任一张图（`role` 是 `image` / `logo`）的实测面积 ≥ 整页
  **60%** 就报错。阈值离真实情况很远 —— 唯一带图的版式实测是 17%，所以不会误伤；
  取 60% 是给"背景那种大图"留的余量，同时把"整页一张图"挡住。
  （今天没有整页图的版式，所以它是**给已声明的禁止留的守卫**：哪天有人加了个全幅版式、
  或手改 skin，这条禁止不会静默失效。）
- **`--brief` 的提示词**：「构图」栏明写这张图只占一栏、不是整页背景；「文字」栏明写
  **不要把这一页的信息画进去**（标题 / 条目 / 数字 / 流程示意 / 界面截图都不算画面内容）
  —— 信息由版面用真文字排，图只负责观感。

### 那贴图版 PPTX 算不算违规

不算，但要知道代价。`make_pptx.py`（观感 100% 那版）确实把每页渲成一张 PNG 贴上去，
可那是从**真版面**渲出来的：HTML 里的标题和条目本来就是真文字，不是画出来的。
它的问题是**导出之后**字不能在 PPT 里改 —— 所以要改字就用 `pptx_native.py`。
两条路的取舍见 `references/delivery-formats.md`。

区别在于**信息第一次被写下来的时候**是不是文字。版面写的是文字，导出贴图只是投影；
让生图模型直接把整页画出来，信息从一出生就是像素。

## 反 AI-slop（只留能验证的）

社区模板库里那些"不要"，一部分确实是可验证的：

- **不要 `linear` / `ease` 缓动**：动画层有一条静态检查专盯这个 —— 匀速运动没有
  重量感，是"这页是机器生成的"最直白的信号。（想改运动去改风格的 `motion`。）
- **不要用"通用默认字体"当 display**：没有字距/字重功夫的 Arial/Roboto 是 slop；
  但 Helvetica Neue 是瑞士学派的**本源**，不是 slop —— 区别在有没有拿它做功。
  判据不是字体名，是 `style.json` 里有没有为它定字距与级数。
- **不要使用紫色渐变 / `#6366f1` 那一类"AI 紫"**：不是审美洁癖，是**用滥到读者认得出**
  —— 认出来的那一刻，内容就退到背景了。`ink.py` 的色板门禁会把它挡在对比度那一关。
- **不要装饰压文字**：`check.py` 第 ⑤ 条有牙。

其余那些（"要高级"、"要有呼吸感"）不写进来 —— 它们没有判据，写了只会变成噪音。

## 什么时候**不该**听这些

规则是默认值，不是法律。以下都是合法的例外，但**要说得出来为什么**：

- **一页只有一句话**：如果那句话是结论，就该独占一页。这不是"内容太少"。
- **故意密集的一页**：附录、数据表、参考文献 —— 它本来就不是给人"看"的，是给人查的。
- **没有封面**：如果是插在一段对话里的补充材料，第一页就是要点，是对的。
- **留白很多**：留白若是**构图**（有视觉锚点、视线有落点），它就是内容的一部分。
  安静派风格（`swiss-grid`）全靠这个。但留白若是"内容缺席"，那就是没做完 ——
  区别在于画面里有没有锚点，**像素密度算不出来**，得看。

## 一条元规则

**先决定说什么，再决定怎么放。** 反过来的顺序（先把页面摆满，再想说什么）产出的
是"排版很好但没人记得住"的 deck —— 这也是为什么这份文档放在 `references/` 而不是
塞进 `SKILL.md`：它是写内容时读的，不是渲染时用的。
