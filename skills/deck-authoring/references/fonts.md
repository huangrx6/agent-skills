# 字体选择、加载与交付

字体方案同时包含角色、实际文件、字重和文字覆盖；只写一个字体名字没有完成接入。
自由 HTML 在项目 CSS 接入，分区辅助用 `--deck-display-font` / `--deck-body-font`；
结构化风格才使用 `fonts.display` / `fonts.body`。先表达本次排印意图，
再确认字体实际存在、中文字形完整和目标格式可用。系统 UI 字体也是合法选择，
不因为“来自系统”就需要替换；装饰字更要检查长标题和正文的阅读负担。
与用户讨论字体时先做 [实际文字样张](typography-and-space.md#先确定排印语法)；本篇负责加载与交付。

## 从角色到真实字体

在项目记录中写清本版用**哪一个字族承担全部文本**，以及字重、字号关系、中英混排和代码是否需要等宽。
一套覆盖完整、字重适合的字族就能成立；标题、正文、数字、图注、表格、页脚都用它。
第二文本字族是例外，只有用户或品牌规范明确要求时才用，比较实际基线、字面大小、笔画和标点，
并在记录里写清授权来源；不能为了"层次感"自行配展示体 + 正文体，也不将长段技术说明全部设为等宽字来营造技术感。

根据参考选择可用字体后，将获准分发的文件放入项目 `assets/fonts/`，逐字重声明 `@font-face`，明确真实的 normal/italic。
可变字体声明其真实支持范围；CJK 分片字体保留完整的 `unicode-range` 和所需文件，不只拷贝拉丁分片。
系统字体方案写明环境依赖；自包含交付使用本地 webfont 或嵌入，不依赖打开时临时访问 Google Fonts。
没有所需字体时先取得文件，或明确替代并重排；不要悄悄回退后继续宣称原风格已经实现。

用实际长标题、两行正文、中文标点、数字单位和图标签组成小样，等待加载完成，再检查实际渲染字体，方法见
[字体核验](typography-and-space.md#确认浏览器实际使用的字体)。样张与代表内容页用同一份 CSS，避免样张好看、正文又回到系统默认。
更换字族后重新测量行宽与版面，不能把它当作只影响外观的最后一步。

## 按交付格式判断

| 格式 | 字体影响 |
| --- | --- |
| HTML | 本地文件或系统字体换机器可能失效；可内嵌获准使用的字体文件 |
| PDF | 成功嵌入字体/字形时可保留外观，仍需检查缺字与实际导出 |
| PNG / 贴图 PPTX / MP4 / GIF | 字形已经栅格化，接收者无需安装字体，但文字不可直接编辑 |
| 原生 PPTX | 写字体名字与东亚字族，不嵌字体文件；目标宿主缺字体会替换 |

可编辑性与字体可移植性是两件事。需要接收者编辑时，确认对方可用字体；
不满足时说明限制并提供保真预览，不能把贴图版叫作可编辑文字版。

## 清单与缓存

仓库的 fonts/catalog.json 和 fonts/mapping.json 是清单与字感映射，
字体二进制不随 skill 分发。清单数量和可下载范围以命令输出为准：

```sh
python3 scripts/fonts.py --list --urls
python3 scripts/fonts.py --map --a-only
python3 scripts/fonts.py --installed
python3 scripts/fonts.py --where
```

下载目录由 `DECK_FONT_DIR` 指定，默认 `~/.config/deck-authoring/fonts/`；
`--temp` 可临时下载。旧 fonts/ttf 目录如果存在仍作为读取兜底，新下载不写入 skill。

```sh
python3 scripts/fonts.py --fetch
python3 scripts/fonts.py --fetch --only '霞鹜文楷'
python3 scripts/fonts.py --fetch --temp
```

fetch 只处理已有可验证下载实现的字体；其余按 `--list --urls` 查看来源。
找不到直链时明确报告，不把“清单中存在”当成“工具能自动安装”。
下载会联网；仅做本地检查时不必下载全部字体。

## 许可与来源

清单的 A/B/C 是筛选信息，不是法律结论或永久授权。默认 fetch 与
`--list --license A` 使用严格 A；A/B 不被当作 A。`--map --a-only` 给出严格 A 的候选。
正式使用按实际字体文件、来源和当前许可核对允许的用途，尤其是安装、嵌入与再分发。
已有用户提供的有效授权按其范围处理，不需要为了清单分级强行换字。

需要随产物分发字体时保留来源和适用许可信息；工具不会替作者完成许可判断。
不要从一次字体/PDF测试推导所有文件格式、字体或浏览器版本都适用的结论。

## 加载与回退

结构化 `render.py` 可按清单识别本地已就位的字体并注入 @font-face；自由 HTML 的 `web_deck.py` 不替作者下载或注入字体，
需要作者在源文件或项目 CSS 中接入。没有文件时仍会按 CSS 栈回退，部分检查只有启发式提示；
“没有裂图”不代表首选字体已经生效。核对实际字形、中文覆盖、数字与标点的节奏。

fonts.py 用字体内部名称及受约束的匹配记号识别文件；不要只改文件名就声称字体可用。
同一字族存在多格式时工具有选择顺序，但单次 TTF/OTF 实测不能保证所有字体都相同。
浏览器加载、PDF 嵌入和 PowerPoint 替换需分别验证。

## HTML 字体内嵌

```sh
python3 scripts/fonts.py --embed deck.html -o portable.html
```

命令将现有 @font-face 的本地 URL 替换为数据，保留字重与样式，支持相对路径和 file:// URL，
并检查整个生成 HTML 的体积。超过限制会拒绝，不应删掉必要字形来凑体积。

它只处理字体，不打包图片或所有外部资源，也不自动保证许可与跨浏览器一致。
交付前把文件放到另一目录、确认资源可解析，再检查实际页面；
PDF 还应检查嵌入结果，原生 PPTX 仍需目标宿主回读。

## 借鉴 Oh My PPT 的范围

核对版本 [56bc56d4](https://github.com/arcsin1/oh-my-ppt/blob/56bc56d41e6065bbb7fa21f2b3ea407575cb3aae/src/main/presentation/fonts/font-registry.ts)：
字体注册记录用途、拉丁/CJK 覆盖、分类与文件；标题/正文选择通过资源层生成本地 `@font-face` 与 CSS 变量。
借鉴的是“选择—文件—实际渲染”一致，而非固定使用它的 14 款字库或只复制字体名。
其 [PPTX 字体收集实现](https://github.com/arcsin1/oh-my-ppt/blob/56bc56d41e6065bbb7fa21f2b3ea407575cb3aae/src/main/io/html-pptx/font-collect.ts)
按实际文本收集字体、合并所需分片并处理嵌入；缺文件、限制位、转换失败或体积限制仍会跳过。本 skill 的原生 PPTX 尚无这套嵌字实现，不能因借鉴文档就承诺相同能力。

`fonts.py --embed` 只读 HTML 自身的 `@font-face`。字体声明放在外链 CSS 里（推荐做法）时它会找不到，
需要先把 CSS 内联进 `<style>`，或改在 HTML 里声明后再内联。把它当作可移植化的最后一步，而不是默认步骤。

## 一个字体承担全部文本

**选定一个字族，标题、正文、数字、图注、表格、页脚都用它。** 等宽只留给机器标识（路径、代码、ID、变量名），
并在 `design.md` 里写明这个例外清单——除此之外再出现第二个文本字族，就是没适配。

为什么：多族混排在中英混排里最先露馅。英文一套、中文一套时，字面高度、重心、字重对比全都对不齐；
读者说不出哪里怪，只会觉得"不像一个人做的"。标题展示体与正文体分开，还会让翻页时像换了作者。

- 优先选**中英同族**的字体：一个文件里同时有中英文字形（得意黑、思源黑体、霞鹜文楷都是），全稿只声明一次。
- 第二文本字族只在用户或品牌规范明确要求时使用，必须在样页里并排验证字面比例，并在 `design.md` 记下授权来源；
  作者不能为了"标题有气质"自行配第二族。授权后仍要限制用途，正文一律回到主字族。
- 等宽栈也要补中文兜底：`"Mono","中文字体",monospace`。否则代码块、图注、页脚里的中文会掉到系统苹方。

**落版后和交付前各核一次**：

```bash
python3 scripts/type_audit.py /path/to/vN-... --json /path/to/checks/type-audit.json
pdffonts deck.pdf
```

`type_audit.py` 按选择器判断字族用在哪：`pre` / `code` / `.mono` 等代码语境可以用等宽，
`.icon` 等图标选择器可以用图标字体，其它选择器上出现第二个文本字族就退出 1。只有用户或品牌明确要求时才 `--allow "字族名" --reason "原话"`。

`pdffonts` 只应看到声明过的字族。出现 `PingFang`、`Menlo`、`Helvetica`、`Arial`、`Noto Sans` 这类系统字体，
说明有文字没适配——常见漏点：等宽栈里的中文、SVG 图注、页脚、图表标签、代码块里的单位。

## 字体要有性格

"干净、中性、现代"不是选型理由——系统默认无衬线也满足这三个词，而那正是"看起来没设计"的来源。

对照参考问三件事：

| 看什么 | 怎么落到选型 |
| --- | --- |
| 字重对比 | 标题 800–900 对正文 400，还是 600 对 400？对比不足会显得平 |
| 字形细节 | 转角是直角还是圆角、收笔有没有斜切、字腔开不开——这些决定"性格" |
| 数字造型 | 等宽还是比例数字？有没有衬线？直接决定数据页的气质 |

需要"有动感"的标题时，优先看：几何无衬线（Space Grotesk、得意黑）、可变字重、带斜切或锐角端点的展示体。

## 不建议使用的字体

| 不要用 | 原因 |
| --- | --- |
| 系统默认栈（PingFang / Menlo / Helvetica / Arial） | 不可控、不可嵌入、换机器就变；也是"没设计感"的主因 |
| 只覆盖常用字的艺术字 | 标题缺字会断行，正文缺字变方框（先用 `--coverage` 验） |
| 单字重字体 | 建不起层级，只能靠字号硬撑 |
| 授权不明的"免费"字体 | 先看仓库的授权说明，再决定能否商用 |

## 从开放字体仓库找字

清单只有 126 款、且多数没有可验证直链。缺字时先去这三个仓库，用脚本查，不要靠记忆或搜索结果碰运气：

```bash
python3 scripts/font_repos.py --index                 # 抓一次文件树，写入本地索引（约 3 秒）
python3 scripts/font_repos.py --search 思源            # 中英文一起查，结果标 [zh]/[en]
python3 scripts/font_repos.py --search serif --lang en # 需要哪类就筛哪类
python3 scripts/font_repos.py --get "dengcao/free-fonts:路径/字体.ttf" -o assets/fonts/
```

| 仓库 | 体量 | 适合 |
| --- | --- | --- |
| `jaywcjlove/free-font` | 约 1000 个字体文件，按厂商/风格分目录 | 按风格找中文艺术字；目录里有来源与授权说明 |
| `dengcao/free-fonts` | 约 2300 个（中文约 348 款） | 一次铺开挑选；**多字重的成套字库常在这里**（如阿里巴巴普惠体 Light/Regular/Medium/Bold/Heavy） |
| `zispace/hanzi-fonts` | 约 190 个 | 完整中文字库（思源黑体/宋体、MiSans、HarmonyOS Sans、OPPO Sans 等） |

用法要点：

- **装字体前先查覆盖**：

  ```bash
  python3 scripts/font_repos.py --coverage assets/fonts/某字体.ttf --html source.html
  ```

  它按稿子实际用到的字符逐字核对，缺字会直接列出来（缺字会回落成别族或变方框）。
  标题字体尤其要查：艺术字/手写体常只有几千字，正文常用字就缺，"哪些""证明"这种词直接断字。
- **不要默认只看中文**：拉丁展示字同样是选题的一部分（英文衬线、几何无衬线、手写体都有专门的目录）。
  先不带筛选地看结果里的 `[zh]/[en]` 标注，确定方向后再用 `--lang` 收窄。
- **不要手打中文路径**。索引里的路径含全角括号、逗号和空格，重敲一次就会 404。先用 `--search` 拿到脚本打印的 `--get` 命令，再原样执行。
- 体积 8–10MB 的单个文件通常是**完整字库**，2–4MB 的多半是子集或单字重；封面大字要 Black/Heavy 时别拿子集凑。
- 一个项目优先选**同一家族的 3–4 个字重**（400/500/700/900），不要混搭两个家族冒充字重。
- 仓库只做收集和分类，**不构成授权判断**；商用前回到字体发行方核对。
- 索引缓存默认在 `~/.config/deck-authoring/font-index.json`，换机器或有新字体入库时重新 `--index`。

## 中文 webfont：要单文件分片，不要百片 CSS

Google Fonts / fontsource 对 CJK 会把一个字重切成上百个 `unicode-range` 分片；本地演示不需要这种拆法。
取**按语种合并的单文件**（fontsource 的 `chinese-simplified` 分片，约 1.1MB/字重），一个 `@font-face` 一行，四五个字重约 5MB：

```css
@font-face{font-family:"Noto Sans SC";font-weight:400;font-display:block;
  src:url("fonts/noto-sans-sc-chinese-simplified-400-normal.woff2") format("woff2")}
```

- 拉丁与中文分属两族（仅在授权双族时）字体栈里**拉丁在前、中文在后**，否则中文分片里的拉丁会顶掉展示字。
- 字体栈要设在整张 slide 上，不能只设在内容容器：容器外的边注、页码、角标会继承 `body` 的系统字。

## 导出 PDF 后核对字体

```bash
pdffonts deck.pdf | head
```

出现苹方 / 微软雅黑 / PingFang / Microsoft YaHei 等**系统字体**时，先分清两种成因：

- **整段回落**：对象数少、但覆盖面大。说明有元素没继承项目字体栈（最常见是 `.deck-page` 之外的边注、页码、角标）。修字体栈后重新导出。
- **字形回落**：对象数接近页数（每页一个子集），通常来自中文子集没收录的符号与标点（`∧ ≥ → ①②③ 「」`）。这类可接受，但要在交付说明里写清；想彻底消除，就换覆盖更全的中文字库或把这些符号改成 ASCII / SVG。

系统字体会被嵌进 PDF：既可能超出系统字体许可，也会在别人机器上缺字。修完字体栈再导一次并复读。
