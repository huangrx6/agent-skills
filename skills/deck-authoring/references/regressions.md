# 返工清单：这些错已经犯过，别再犯

每条都是真实返工过的。交付前逐条过一遍，比事后改十轮便宜。

## 一、版本与目录

| 现象 | 规则 |
| --- | --- |
| 开 v2 时直接沿用 v1 的风格 | 新版本第一件事是**重新选参考**，旧风格不自动继承 |
| 复制 v1 的 `deck.css` / `source.html` 改几个字 | 新目录从空文件写；`version_guard.py` 会把逐字相同的 CSS 判硬失败 |
| 封面构图、页脚、编号或背景纹理沿用上一版 | 这些是最容易被认出的签名；重画，不靠换色或换图遮住 |
| 字体、色板"看着顺眼就留着" | 没有用户原话就重选；`version_guard.py --allow` 只放行用户指定的维度 |
| v2 只换了配图和标题 | 图片查重与背景声明会命中；重做的是整套视觉关系，不是素材 |
| 换主题却接着叫 v2 | **vN 是同一份 deck 的第 N 版**；换主题 = 新 deck，新建主题目录从 v1 起 |
| 在产物上做字符串手术改版面 | 改**生成器/模板**再重出；手工修补 HTML 会破坏嵌套，编译器"修复"后内容对不上 |

## 二、字体

| 现象 | 规则 |
| --- | --- |
| 部分文字不是声明字体（混进 PingFang/Menlo） | 交付前 `pdffonts` 核对，只应出现声明过的字族。常见漏点：等宽栈里的中文、SVG 图注、页脚、表格单位 |
| 标题断字、出现方框 | 落版前 `font_repos.py --coverage` 跑一遍，缺字改成中文或代码写法 |
| 标题一套、正文一套、数字再一套 | 默认**一个字族承担全部文本**（等宽只给机器标识）；第二族只限用户或品牌明确要求，并用 `type_audit.py` 登记 |
| 表格用展示体排 16px，糊成一团 | 展示体只做标题/声明/图内标签；正文与表格要么用正文字族，要么把字号压到正文级、去掉伪粗体 |

## 三、版面

| 现象 | 规则 |
| --- | --- |
| 每页底部都是"三块 + 颜色条" | 底部至少四种：三块 / 一行三段 / 一句判断 / 两栏文字；`rhythm_check.py` 会数出来 |
| 页面骨架千篇一律 | 非图像骨架不超过全书 45%；图像页不设上限但要换构图，不连续三页同一非图像主角（`rhythm_check.py`；相邻两页同构只在比较时允许） |
| 文字页左上一坨、下方大片空白 | 文字页要按版面填满：编号清单、分栏对照、垂直居中；不要默认左上角堆文字 |
| 表格列对不齐 | `table-layout: fixed` + `<colgroup>` 定宽，表头与正文才会同列 |
| 尾页直接放一页内容 | 每套 deck 都要有**设计过的封面与尾页**；尾页是收束，不是最后一个知识点 |
| 插画被卡片或容器裁掉一角 | 先查父容器 `overflow` 与图尺寸；有意裁切要 `data-web-check-allow` 并保证主体完整 |
| 封面 PNG 小人、内页 SVG 小人，或背景图含角色又叠 SVG 角色 | 一套 deck 的具象角色只用一种实现；SVG 只画图表、连线、标注、图标等图形层。换页先换构图，不换画法 |
| 图位写着“待配图 · 文件名 · 尺寸”，回填后还压在图中央 | 占位只用空白框；缺图看 `image-brief.md` / `--check`，图位内不放任何文字；回填后清零占位文案 |
| 文字压在图的主体上或高细节区，回填后才看出来 | 先定图的主体与文字安全区再排字；文字要么在图外，要么落在图里预留的安静区并加局部 scrim；不靠盖满整张图的半透明黑 |
| 后画的卡片、标签或遮罩盖住图 | 显式 z-index 层级（背景 0 / 装饰 10 / 图 20 / 遮罩 25 / 文字 30）；不靠 DOM 顺序；有意遮挡写 `data-web-check-allow` 与理由 |
| 图按模型默认比例出来，塞进图位后被裁或被拉 | 先量图位得 `target_px`；提示词首行写输出宽高与“按此比例、不裁不留边”；功能图比例必须等于图位，不靠 `object-fit` 硬撑 |
| 动效一结束，文字和图换了上下位置 | 参与叠压的元素各自定层；reveal 只包原子元素；落定回到 `transform: none` / `opacity: 1`，不常驻 `will-change`；对比 `?scroll` 完成态 |
| SVG 被压扁、拉伸或自己裁掉内容 | `viewBox` 覆盖全部图形并与容器比例一致；用 `preserveAspectRatio` 或 `object-fit`，不硬塞宽高；SVG 内文字不超所属形状与 viewBox（逐叶子形状与 text 扫描渲染边界） |
| 内容堆在上半页，底部空一半 | 先定内容带：放大字号/主体或加视觉锚点，也可有意居中；不要只把内容顶在上半 |
| 三列卡片用 14–16px 正文塞满 | 正文从 22–26px、行高 1.5–1.7、内边距 28–32px 起；放不下减列或拆页，不缩字 |
| 全高竖线/边栏配半页内容 | 装饰与内容带对齐；不要用贯穿全页的线强调底部的空 |

## 四、过程

| 现象 | 规则 |
| --- | --- |
| 用户指出改底部，却顺手改了字体和结构 | 改动范围 = 用户指出的范围；其它问题列出来，不擅自改 |
| 源码改了、截图/PDF 没变 | 每次构建后跑 `build_verify.py` 比对源码与产物的页签名，不一致就停下修结构 |
| 只看缩略图就说"改好了" | 改完必须看那一页的**单页截图**，缩略图看不出列错位、字糊、缺字 |
| HTML 一生成就顺手导 PDF | 先问配图、再问格式；缺图回填前不导出，用户明确说不用图才导 |
| 缺图导出后说"已完成" | 缺图导出只能叫草稿，列待补文件；补图后重导 |
| 用户说"先导一版看看"就跳过提问 | 仍要说明是草稿、列出仍缺的图，不能当成品交付 |
| 跳过 brief 直接调生图模型、API、MCP，或临时写/复用 gen_images.py | 配图一律先交 image-brief.md，由用户生成；skill 内不调用任何生图服务 |
| 用户说“你直接生成”“我有 key”就照做 | 仍只交 brief 并说明由用户生成；分工不因口头授权或环境里有密钥而改变 |
| 为了"稳妥"把配图删成纯文字 | 图片是设计的一部分；只有用户明确要求纯文字才免除，不能自己降级 |
| 图多就劝用户少放 | 数量由内容决定，不设上限；管构图、裁切和角色，不管张数 |
