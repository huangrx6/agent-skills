# 风格来源：从模板站取真实的风格信息，而不是由作者命名

用户说「给我几个风格选项」时，最容易出现的失败是作者编名字：极简、科技、高级、3D 动画——
用户看到的是词，拿到的是另一回事。模板站其实已经把风格编码在**分类、筛选器和标题命名**里，
取这些真实字段比自己想形容词可靠得多。

本篇管「去哪取、怎么取、怎么给用户看」；取不到时该不该继续见
[风格证据](style-evidence.md) 的证据等级表，闸门位置见 [阶段闸门](stage-gates.md) 的 G2。

## 一份注册表，三个分组

站点清单只有一份：**`assets/style-sources.json`**。文档、脚本都从这里读，`--list-sites` 直接打印；
要加站点只改那张表，不要在别的文档里再列一遍（重复清单一定会漂移）。

| 分组 | 站点 | 站点给的轴 | 取数 | 能回答什么 |
| --- | --- | --- | --- | --- |
| **成品模板**（看整页版式） | Canva | 用途分类 + 标题里的「颜色 + 风格 + 行业」 | 渲染 | 这套像什么、多少页、什么气质 |
| | Miricanvas | **Style**（Cute / Sentimental / Professional / Traditional / Fun）× Color × 免费/付费 | 接口 | 情绪风格 + 配色 + 成本 |
| | Slidesgo | 主题 / 学科分类 | 静态 | 教学与主题化演示怎么排 |
| | PresentationGO | 图表 / 流程 / 关系图分类 | 静态 | 长段落怎么变成图解 |
| | Envato Elements | 用途 / 行业 + 软件兼容 | 渲染（条目常被 consent 挡住） | 商业模板里这类内容怎么排 |
| | Pitch | 整套演示的接续 | 只给入口 | 封面 → 图文 → 数据 → 结尾的节奏 |
| **成套主题**（看母题贯穿） | PPT-Design | 中文题材 / 风格 / 节日分类 | 静态 | 同一母题如何在封面、议程、内容页复用 |
| | Oh My PPT 风格画廊 | **中文风格名**（国风治愈、经营图谱…），按气质成组 | 渲染 | 中文风格词从哪来 |
| **视觉语言**（看画风） | Dribbble | 视觉 tag：3d / gradient / dark-mode / glassmorphism / isometric | 渲染 | 画风、光色、材质；**不给页结构** |

**不要只用一个站。** 九个站编的是三种东西：成品模板给版式，成套主题给母题，视觉语言给画风。
只用一个站等于只借了那一站的审美；候选要求**跨分组**，至少来自两个分组。

## 三轴模型：别把用途当风格

站点分类混着三种不同的东西，取回来先分开，再给用户看：

| 轴 | 例子（站点原词） | 回答的问题 |
| --- | --- | --- |
| **用途轴** | business / pitch deck / education / technology / medical / company profile / visual charts | 这套讲什么场景 |
| **视觉轴** | minimalist / bold / vintage / watercolor / cute / gradient / 3d / 国风治愈 | 这套长什么样 |
| **交付轴** | PowerPoint / Keynote / 16:9 / 页数 / 免费 vs 付费 / 是否带动画 | 能不能直接用、要不要买 |

用户说「科技感」其实只给了半个用途轴；「高级」是情绪词，没有视觉轴。**风格选择必须落到视觉轴**，
否则做出来仍然是他不想要的「科技蓝 + 线条」。

## 取数协议

```bash
python3 scripts/style_probe.py --list-sites        # 注册表：分组、轴、取数方式
python3 scripts/style_probe.py --terms             # 归一化词表（风格词必须来自站点）
python3 scripts/style_probe.py --probe "3D 动画"    # 默认查 8 个站
python3 scripts/style_probe.py --probe "国风" --sites ohmyppt,ppt-design
python3 scripts/style_probe.py --probe "极简 商务" --limit 6 --json checks/style-probe.json
```

脚本做三件事：把中文意图翻成站点能搜的词 → 逐站取真实条目 → 把标题里的
**颜色词 / 风格词 / 用途词**抽出来。拿不到就如实降级并给入口链接，**不编内容**。

取数分四级，报告里要说明用的是哪一级：

| 级 | 方式 | 站点 |
| --- | --- | --- |
| L1 | 结构化接口 | Miricanvas |
| L2 | 无头 Chrome 渲染后取 DOM | Canva / Dribbble / Oh My PPT |
| L3 | 静态页面 | Slidesgo / PresentationGO / PPT-Design |
| L0 | 只给入口 | Pitch；被 consent / 付费墙挡住的 Envato |

已知限制（写进交付说明，不要假装拿到了）：

- Canva / Envato 有 consent 与反爬；Envato 条目常取不到，只保留分类入口。
- Miricanvas 的关键词搜索较宽，返回结果要按视觉轴再筛一遍。
- Dribbble 作品是视觉参照，没有可直接套用的页结构。
- 中文站（Oh My PPT / PPT-Design）用中文词检索才命中；英文词容易空手。
- 站点改版会让解析失效；报告里的抓取时间就是它的有效期。

**只做人工级别的浏览取样**：不批量爬取、不绕登录和付费墙、不下载素材站图片。
缩略图只记 URL，用来让用户看见方向；真正进页面的图仍由用户按本项目的 `image-plan.json` 生成。

## 给用户看什么

候选不是一串链接。每一条都要能让用户判断「这是不是我要的感觉」：

```md
| # | 来源 | 这套像什么 | 适合 | 不适合 | 看整页 |
| --- | --- | --- | --- | --- | --- |
| 1 | Canva · Pink and White Minimalist Skincare | 白底、细字重、大留白，几乎没有图 | 数据少、要显干净的报告 | 信息密度高的技术评审 | [打开](<URL>) |
| 2 | Miricanvas · Beige Minimalist Business Contact | 米色纸感 + 单一强调色，页数少 | 对外提案 | 需要图表页的场景 | [打开](<URL>) |
| 3 | Oh My PPT · 青莲碧蓝 · 梦幻国风 | 中文国风配色，手写字体倾向 | 文化类题材 | 技术评审 | [打开](<URL>) |
| 4 | Dribbble · #3d | 立体渲染、强光、饱和调色 | 想让画面当主角 | 逐字核对细节的评审页 | [打开](<URL>) |
```

规矩：

1. **至少两个分组的候选**，3–5 个，不要全是同一站的审美。
2. 每条写「像什么 / 适合 / 不适合」，用页面上能看见的特征（底、字重、留白、图占比、页数），不写形容词。
3. 每条都要能点开看**整页**；只有缩略图不算。
4. 风格词必须能在站点页面上找到出处（标题、筛选器或 tag），报告里保留原词，不要改写成同义词。
5. 附抓取时间与取数级别，用户知道这条信息的时效与可靠度。

## 覆盖度不足时：说明这个方向不是模板

注册表里都取不到匹配的风格，是一个**有用的结论**，不是失败。典型的「3D 动画电影」「手绘绘本」
「电影海报」在模板站里几乎没有对应分类——说明它不能靠挑模板得到，必须：

1. 告诉用户：这个方向模板站覆盖很低，我们不会硬套某个模板；
2. 转 [风格证据](style-evidence.md) 的 **B 档**：用本项目真实内容做 1–2 页样页；
3. Dribbble / 影片 / 摄影可以继续当**画风来源**，但要写清取的是哪几个关系（造型、光位、调色、景深）。

脚本在这种情况下会直接给出「覆盖度不足」的提示——不要忽略它去凑一个模板。

## 用户选中之后

选择不是终点，要落成可执行的记录：

1. 把该模板页**截图存进 `refs/`**（不是 `assets/images/`）；
2. 在 `design.md` 的「风格选择：用户看到了什么」写：候选编号、来源链接、原词、用户原话、抓取时间；
3. 用五个问题把模板翻译成本项目的决定（主体 / 一页长相 / 色彩明暗 / 素材来源 / 动效）；
4. 记下**不沿用**的部分：模板的页脚、品牌色、图标、版式都不进本 deck——我们只借视觉关系；
5. 该模板的配色与字体只作参考，本版仍按 [配色](color.md)、[字体接入](fonts.md) 重新确定。

## 加一个新站点

只改 `assets/style-sources.json`：

1. 选 `group`（template / theme / visual）——它决定这个站能回答哪类问题；
2. 写 `access`（api / render / static / entry）与对应字段（`api`、`category`、`link`、`tag`）；
3. 写 `parse`：已有解析器直接复用（canva / miri / slidesgo / presentationgo / pptdesign /
   ohmyppt / dribbble / envato / entry），新结构才新增一个解析函数；
4. 填 `axes` 与 `note`，写清这个站**编的是哪种轴**，别把用途写成风格；
5. 跑一次 `--list-sites` 与 `--probe` 确认能取到，再更新本篇的表格。

## 自检

- [ ] 候选来自 ≥2 个分组，3–5 个，每条可点开整页。
- [ ] 风格词有站点出处，没有作者自造的新词。
- [ ] 用途轴与视觉轴分开写，没说「科技感」就当成风格。
- [ ] 覆盖度不足时明确说了，并转入 B 档样张。
- [ ] 缩略图只记 URL；`refs/` 与 `assets/images/` 没混用。
- [ ] 抓取时间与取数级别写进报告。
- [ ] 站点清单只在 `assets/style-sources.json` 里维护，别处没有第二份。
