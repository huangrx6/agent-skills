# 审美校准基准

测一个产品问题：**这套 skill 能否把真实材料做成有设计判断的演示，而不是只有检查通过的页面？**

这是一道校准门，不是模型排行榜，也不产出“最佳风格”。它不提供可复制的样张：
样张一旦成为默认答案，所有 deck 会长得一样。基准只给真实 brief、证据要求和审稿规则。

## 四个案例

见 [manifest.json](manifest.json)：技术机制、编辑/博物馆、产品复盘、主题活动（图像主导）。
每个案例声明观众、观看条件、必须保留的事实、反目标和三张 hero pages。
案例是**内容任务**，不是版式或风格模板；实现可以完全不同。

## 跑法

- 使用同一份 skill 提交、同一模型/agent、同一时限、干净的项目目录。
- 一次完整调用 = 第一版；第一版结束即冻结，记录时间与页数。
- 允许两轮修订，每轮必须留 before/after；修订不是重开主题。
- 记录模型名、工具面、实际观看尺寸；不完整的矩阵不能当结论。
- 人审只按 [审美闸门](../../references/design-review.md) 的八轴和 severity，
  不设 1–10 分；`passed` 只表示没有 blocker/major，不表示“最好看”。

## 必须留下的证据

```
run/
  source.html              # 作者源文件
  deck.html                # 编译产物
  design.md                # 视觉命题、参考 move、signature、反目标
  review.md                # 至少两轮：页/版本、问题、改动、回看
  design-signals.json      # design_signals.py --json
  shots/
    cover.png              # 1600×900
    content.png            # 最难讲的内容页
    signature.png          # signature page
    target-size.png        # 实际观看尺寸
    contact-sheet.png      # 全套缩略图
```

另需实际回读最终交付格式（PDF/PPTX），在 `review.md` 记录字体、图片、图表和页数。
图位未回填时只能评结构，不能声称图文完成。

## 审稿记录

直接使用 [design-review.md 的模板](../../references/design-review.md#审稿记录模板)。
必须能定位到具体页和具体关系，例如“p4 第一眼是右侧截图，但本页要讲左侧三个阶段”，
不能只写“更精致”“更有设计感”。

## 不发布什么

- 没有真实运行、没有截图、没有人审的“模型审美得分”。
- 把某一次好看的产出当成默认风格或新模板。
- 用 `design_signals.json` 全绿代替目检；信号不是分数。
- 用封面或 4K 局部截图证明整套完成。
- 只改颜色、圆角、阴影或动画，就声称审美提升。

## 怎么读结果

不要问“哪个模型分数最高”，先问：

1. 三张 hero pages 是否各自成立，连看是否有亲缘？
2. 最难内容页是否真的被重新组织，而不是缩字或加卡片？
3. 有没有一个可识别的 signature move，而不是每页换装饰？
4. 修订轮是否解决了第一轮指出的问题，还是只换了表面？
5. 最终 PDF/PPTX 是否保住了字体、图像、数据和页数？

这些问题的答案比任何总分更能说明 skill 是否真的提升了审美。
