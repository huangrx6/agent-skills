## 三种记忆

必须区分：

### 项目规则

例如：

```text
所有数据库迁移必须支持滚动发布。
```

属于仓库。

### 个人跨项目偏好

例如：

```text
我默认使用 pnpm。
我更喜欢中文工程文档。
```

属于用户级 Agent 配置，不应默认提交团队仓库。

OpenAI Codex 支持用户级 `~/.codex/AGENTS.md`，但修改用户级配置前必须得到用户明确同意。

### 一次性任务偏好

例如：

```text
这次只改后端。
```

只存在当前会话，不持久化。

## 项目工作约定

适合写入：

`docs/working-agreements.md`

内容包括：

- 开发流程；
- 团队选择；
- 非工具可自动判断的规则；
- 例外审批；
- AI Coding 约定。

当某条规则必须被 Agent 每次执行时，在 `AGENTS.md` 中只保留精简执行版本，并链接详细说明。

## 个人跨项目偏好

不要写入共享仓库。

适合写入：

- 用户自己的 Agent 全局配置；
- 个人 dotfiles；
- 私有个人知识库。

只有用户明确要求时才修改。

## 一次性要求

不要因为一次对话出现：

```text
先不要重构
这次别加测试
临时使用 JSON
```

就升级为长期规则。

## 从对话提炼

### 可自动沉淀

用户明确表达长期作用域：

```text
以后这个项目统一……
团队约定……
从现在起这个仓库……
```

并且不涉及敏感个人信息时，可以更新项目约定。

### 需要确认

Agent 通过多次对话推断：

```text
用户似乎总喜欢……
可能更偏好……
```

只能作为候选，不能自动提交。

### 不应记录

- 健康；
- 身份敏感信息；
- 私人关系；
- 私人账号；
- 密钥；
- 无关个人习惯；
- 情绪性表达。

## 安全与隐私

项目文档只能记录完成工程任务必要的信息。

不要为了让 AI “更懂用户”建立个人画像。

工作约定应该描述：

```text
这个项目如何工作
```

而不是：

```text
这个人是什么样的人
```

## 避免记忆膨胀

每条 Working Agreement 应能回答：

- 哪些任务会用到它？
- 如果删除会导致什么重复错误？
- 是否能通过代码/CI 自动实现？
- 是否已被其他规范覆盖？

能自动化的规则优先进入工具配置，而不是不断增加自然语言记忆。
