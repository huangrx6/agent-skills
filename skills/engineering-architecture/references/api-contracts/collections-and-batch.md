## 集合响应

集合响应应有稳定结构，例如：

```json
{
  "items": [],
  "page": {
    "nextCursor": "opaque-token",
    "hasMore": false
  }
}
```

规则：

- 同一 API 的集合包装结构保持一致。
- 不在有时返回数组、有时返回对象之间切换。
- 空集合返回空数组，不返回 `null`。
- 是否返回总数、链接和聚合值必须明确。
- 资源表示和分页元数据分离。

## 分页

### 游标分页

适用于：

- 大数据量；
- 数据持续变化；
- 需要稳定顺序；
- 顺序扫描或无限滚动。

要求：

- 游标不透明；
- 游标与过滤、排序、租户和权限上下文绑定；
- 使用稳定排序和唯一决胜字段；
- 明确过期、篡改和无效游标错误；
- 不承诺可跳转任意页；
- 变更数据下明确重复和遗漏语义。

### 偏移分页

适用于：

- 数据量有限；
- 结果相对稳定；
- 需要跳页；
- 查询成本可控。

要求：

- 设置最大 `limit`；
- 明确偏移上限；
- 排序稳定；
- 不承诺大偏移高性能；
- 需要精确总数时评估成本。

### 通用规则

- 默认页大小和最大页大小必须写入契约。
- 客户端提供超限页大小时应截断还是拒绝，必须统一。
- 下一页信息优先使用 token 或链接，不要求客户端拼接内部状态。
- 不把敏感查询信息直接编码为可读游标。
- 总数昂贵时允许省略或提供估算，但必须标记语义。

## 过滤

- 使用允许字段和操作符白名单。
- 定义相等、范围、集合、存在性和组合逻辑的编码方式。
- 同一参数重复出现、逗号分隔或 JSON 编码只能选择一种主方式。
- 明确大小写、时区、精度和空值语义。
- 未知过滤字段应返回明确错误，不应静默忽略。
- 不直接暴露数据库查询语言或任意表达式执行能力。
- 过滤语义必须在权限过滤之后执行，防止侧信道泄露。

## 排序

- 使用明确的排序字段白名单。
- 定义升序、降序和多字段编码。
- 所有分页查询必须有稳定排序。
- 非唯一排序字段必须追加稳定决胜字段。
- 未指定排序时提供文档化默认值。
- 不允许客户端按敏感、昂贵或无索引字段任意排序。
- `null` 排序位置和字符串排序规则需要时应明确。

示例：

```text
GET /orders?sort=-createdAt,id
```

## 搜索与字段选择

- 全文搜索和精确过滤使用不同参数。
- 搜索应声明语言、分词、匹配范围和排序语义。
- 字段选择只允许白名单字段，且不得绕过授权或数据最小化策略。
- 展开关联资源应设置深度、数量和复杂度上限。
- 复杂查询可使用查询资源或 POST 搜索端点，但必须保持只读语义和可缓存考虑。

## 批量读取

- 请求数量必须有上限。
- 明确结果是否保持输入顺序。
- 重复 ID 的处理必须明确。
- 不存在和无权限资源的可见性策略必须一致。
- 大批量读取优先异步导出，而非单次返回超大响应。
- 不允许批量接口绕过单资源授权。

## 批量写入

批量写入必须明确：

- 整批原子还是逐项独立；
- 最大项目数和载荷大小；
- 幂等键作用于整批还是单项；
- 校验顺序；
- 并发和版本检查；
- 重试后如何避免重复副作用；
- 是否支持异步处理。

不要使用“批量”隐藏不受限的任意脚本执行。

## 部分成功

当允许部分成功时，返回每项结果：

```json
{
  "results": [
    {"clientItemId": "a1", "status": "SUCCEEDED", "resourceId": "ord_1"},
    {"clientItemId": "a2", "status": "FAILED", "errorCode": "INVALID_ARGUMENT"}
  ],
  "summary": {
    "succeeded": 1,
    "failed": 1
  }
}
```

要求：

- HTTP 状态表达批次请求级结果；
- 项目级结果使用稳定状态和错误码；
- 每项有稳定关联键；
- 明确可重试项；
- 不因一个项目失败就隐瞒其他项目结果；
- 需要原子性时不得返回部分成功。

HTTP 207（Multi-Status，源自 WebDAV）可表达批次多项结果，但语义依赖客户端正确解析；多数 REST 生态对 207 支持薄弱。推荐在 200/202 响应体中用上述逐项结果结构，而非依赖 207 状态码，除非组织明确采用其语义并验证客户端兼容。

## 查询安全与性能

- 对页大小、过滤条件数、排序字段数、展开深度和批量大小设硬上限。
- 对昂贵查询实施成本预算、超时和限流。
- 防止通过计数、排序时间或错误差异推断无权访问数据。
- 记录高成本查询指标，不在普通响应中暴露内部执行计划。
- 查询能力变更需评估索引、缓存和容量。
