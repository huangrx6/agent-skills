## Schema 作为契约

- 每个请求和响应正文必须有机器可读 Schema。
- Schema 必须定义类型、格式、长度、范围、模式、必填、可空和附加字段策略。
- 复用只用于相同语义，不因字段外观相同就强行共享模型。
- 请求模型、响应模型、存储模型和领域模型可以不同。
- 不直接把数据库实体或 ORM 对象暴露为外部契约。
- Schema 约束必须与运行时校验一致。
- 当前工具链允许时使用 JSON Schema 2020-12 语义。

## 字段命名

- JSON 默认使用 `lowerCamelCase`，除非现有生态明确采用其他约定。
- 同一 API 不混用多种命名风格。
- 名称表达领域语义，不泄露数据库列名。
- 布尔字段使用 `is`、`has`、`can` 等可判断命题，或团队统一语义。
- 集合使用复数。
- 单位和时区无法由类型明确时写入名称，例如 `timeoutMs`、`createdAtUtc`。
- 不使用 `data1`、`flag`、`value` 等缺乏上下文的名称。

## 标识符

- 对外标识符定义为字符串，即使当前内部使用整数。
- 标识符应稳定、唯一且不可被客户端推断内部拓扑。
- 不要求客户端按长度、前缀或数值区间解析 ID。
- 需要不同类型标识时使用不同字段名或类型前缀，但前缀语义必须稳定。
- 资源 ID 与幂等键、请求 ID、Trace ID 不得混用。

## 必填、可空与缺省

必须区分：

- 字段缺失；
- 字段存在且为 `null`；
- 字段存在且为空字符串、零或空集合；
- 服务端应用默认值。

规则：

- 新增必填请求字段通常是破坏性变更。
- 响应中新增可选字段通常兼容，但客户端必须容忍未知字段。
- `null` 只在业务上有独立含义时允许。
- 可选字段不得靠特殊空值表达多个状态。
- 默认值必须写入契约，并说明由客户端还是服务端应用。
- PATCH 中缺失和 `null` 的语义必须明确。

## 时间与日期

- 时间点使用 RFC 3339 格式并包含时区，服务间交换优先 UTC。
- 仅日期使用完整日期格式，不附加虚假午夜时间。
- 持续时间使用明确单位或标准 duration 表达。
- 不使用本地化日期字符串。
- 明确精度，例如秒、毫秒或微秒。
- 不把持续时间和绝对时间混为同一字段。
- 需要时区规则时使用 IANA 时区标识，而不仅是固定偏移。

示例：

```json
{
  "createdAt": "2026-08-07T03:59:00Z",
  "businessDate": "2026-08-07",
  "timeZone": "Asia/Shanghai"
}
```

## 金额、单位与精度

- 金额不得使用二进制浮点数表达。
- 选择以下一种并全局一致：
  - 最小货币单位整数 + ISO 货币代码；
  - 十进制字符串 + ISO 货币代码。
- 比例、税率和百分比必须明确是 0–1 还是 0–100。
- 长度、容量、速度和温度必须明确单位。
- 舍入模式和精度在涉及结算时必须写入契约。

示例：

```json
{
  "amountMinor": 1299,
  "currency": "CNY"
}
```

## 枚举与状态

- 枚举值使用稳定机器标识，不使用会本地化的展示文本。
- 保留未知值处理策略。
- 客户端不得假设枚举集合永不扩展，除非契约明确封闭。
- 新增枚举值可能破坏穷举分支，应纳入兼容性评估。
- 删除、重命名或改变含义属于破坏性变更。
- 状态枚举与动作、错误码不得混在同一集合。
- Protobuf 枚举必须保留零值并遵循其兼容规则。

## 对象与数组

- 对象职责应清晰，避免万能 `metadata` 承载未定义业务字段。
- 扩展字段必须有命名空间、类型和生命周期策略。
- 数组必须定义是否允许重复、是否有序和最大长度。
- 大集合必须分页，不返回无上限数组。
- Map 的键格式、大小和未知键策略必须明确。
- 对象深度和载荷大小应有上限，防止资源消耗攻击。

## 读写方向

应标明：

- 只读字段，例如 `id`、`createdAt`；
- 只写字段，例如明文密码；
- 服务端计算字段；
- 客户端可修改字段；
- 创建时可写但更新时不可写字段。

不要依赖文档文字隐含这些规则，应在 Schema 或不同模型中表达。

## 文件与大载荷

- 文件上传应声明媒体类型、最大大小、文件名处理和恶意内容检查。
- 大文件优先使用分片、预签名 URL 或对象存储直传，而非把二进制嵌入 JSON。
- 下载应声明 `Content-Type`、长度、文件名和 Range 支持策略。
- 流式接口必须定义背压、断线重连、消息边界和完整性。
- Base64 会增加载荷，应仅在确有需求时使用。

## 示例

- 每个主要操作至少提供成功示例。
- 复杂校验、分页、异步和错误应提供边界示例。
- 示例必须通过 Schema 校验。
- 示例使用虚构、脱敏数据。
- 不在示例中放生产域名、令牌或真实个人信息。
