## 资源建模

- 先定义领域资源、集合、子资源和状态转换，再决定 URI。
- 资源名使用调用方理解的领域名词，不暴露表名、ORM 类型或内部服务名。
- 操作可自然表达为资源创建、替换、局部更新或删除时，优先使用标准方法。
- 无法自然映射为 CRUD 的领域动作，可建模为命令资源或明确动作端点，例如：
  - `POST /orders/{id}/cancellations`
  - `POST /reports/{id}:generate`
- 一个 API 风格只选择一种动作表达方式并保持一致。
- 状态机必须明确合法转换、重复请求和最终状态。

## URI 设计

推荐默认规则：

- 使用 HTTPS。
- 路径使用名词；集合通常使用复数。
- 使用小写和连字符，避免空格、下划线和文件扩展名。
- 层级只表达真实归属，避免超过必要深度。
- 查询参数表达过滤、排序、分页、字段选择和视图，不用于隐藏副作用。
- URI 应稳定；显示名称、可变业务状态和敏感信息不应成为资源主标识。
- 标识符按不透明字符串处理，客户端不得解析其中业务含义。
- 不在 URI 中放令牌、密码、证件号或其他敏感数据。
- 尾斜杠策略、大小写策略和 URL 编码策略必须统一。

示例：

```text
GET /v1/orders/{orderId}
GET /v1/customers/{customerId}/orders
```

版本位置属于组织决策。选择路径、主机或媒体类型后保持一致。

## HTTP 方法

| 方法 | 语义 | 安全 | 幂等 |
| --- | --- | --- | --- |
| GET | 获取资源表示 | 是 | 是 |
| HEAD | 获取与 GET 相同的元数据，不返回正文 | 是 | 是 |
| POST | 提交处理、创建服务器分配标识的资源或执行非幂等动作 | 否 | 默认否 |
| PUT | 在已知 URI 完整创建或替换资源 | 否 | 是 |
| PATCH | 对资源进行部分修改 | 否 | 取决于补丁格式和操作 |
| DELETE | 删除或使资源不可用 | 否 | 是 |
| OPTIONS | 获取通信选项 | 是 | 是 |

要求：

- GET、HEAD 不得产生调用方可见的业务副作用。
- PUT 的重复执行应得到相同目标状态。
- DELETE 重复调用不得产生新的副作用；后续返回 204 或 404 由契约明确。
- PATCH 必须声明媒体类型和补丁语义，例如 JSON Merge Patch 或 JSON Patch。
- 不使用 GET 执行删除、支付、发送通知等写操作。
- 不自定义与标准方法相冲突的方法语义。

## 成功状态码

| 场景 | 推荐状态 |
| --- | ---: |
| 成功读取 | 200 |
| 创建资源并立即完成 | 201 |
| 请求已接受但尚未完成 | 202 |
| 成功且无响应正文 | 204 |
| 条件 GET 未修改 | 304 |

要求：

- 201 应返回新资源 URI，通常通过 `Location`。
- 202 必须提供后续查询状态的方式。
- 204 不得返回消息正文。
- 更新操作返回 200 还是 204 必须在同类接口中一致。
- 重定向只在客户端和中间件能正确处理时使用。

## 失败状态码衔接

HTTP 状态码表达通用协议语义；稳定业务错误码表达具体原因。

详细错误结构、错误码目录和全局异常映射属异常处理层职责。

本规范要求：

- 不用 200 包装失败；
- 不把程序缺陷伪装为 4xx；
- 不把所有业务失败统一返回 400；
- 401 与 403 语义准确；
- 409 用于当前状态或版本冲突；
- 412 用于条件请求失败；
- 422 用于内容结构正确但语义无法处理；
- 429 返回限流语义，并按需提供 `Retry-After`；
- 5xx 不暴露内部实现。

## 请求头与响应头

- 只定义真正跨资源或跨表示的元数据为 Header。
- 业务核心字段优先放正文，避免自定义 Header 泛滥。
- 自定义 Header 名称不使用已废弃的 `X-` 规则作为强制前缀。
- Header 大小、重复值、大小写和代理行为必须考虑。
- 链路标识可回传，但不得承载敏感业务信息。
- 需要资源关系时可使用 `Link` Header 或正文链接。
- 可选处理偏好可使用标准 `Prefer` 机制，服务端应说明是否应用。

## 缓存与条件请求

对每个 GET/HEAD 明确：

- 是否允许共享缓存；
- `Cache-Control` 策略；
- 是否返回 `ETag` 或 `Last-Modified`；
- 是否包含用户或租户私有数据；
- 哪些请求头影响表示，并正确设置 `Vary`。

要求：

- 私有或敏感响应不得被公共缓存错误复用。
- 可缓存资源应支持条件 GET，减少带宽和计算。
- 更新时可使用 `If-Match` + ETag 防止丢失更新。
- 不依赖查询参数中随机值绕过缓存，除非有明确兼容原因。
- 缓存键必须包含会改变表示的身份、租户、语言和版本维度。

## 内容协商与媒体类型

- 请求必须声明正确 `Content-Type`。
- 客户端可用 `Accept` 声明可接受表示，服务端按契约返回或拒绝。
- 字符编码优先 UTF-8。
- JSON 响应使用正确媒体类型；错误使用 `application/problem+json` 时与 RFC 9457 对齐。
- 文件上传、下载、流式响应和压缩必须声明媒体类型、大小限制和完整性策略。
- 不通过文件扩展名代替媒体类型。
