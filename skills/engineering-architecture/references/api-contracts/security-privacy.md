## 信任边界

- 所有外部和跨服务输入都按不可信处理。
- API 网关验证不能替代服务端资源级授权。
- 内部网络不等于可信身份。
- 多租户系统必须在查询、缓存、日志和异步任务中保持租户隔离。
- Schema 校验、业务校验和授权是不同步骤，不得互相替代。

## 认证

- 使用组织批准的标准认证机制。
- 明确 Token 的颁发者、受众、作用域、有效期和轮换。
- 不在 URL 查询参数中放长期凭据。
- 不在响应、示例或错误中回显凭据。
- API Key 仅作为凭据时必须配合传输加密、权限范围和轮换。
- 机器身份与用户身份同时存在时，明确代表关系和审计主体。
- 认证失败不泄露账号、租户或凭据存在性。

## 授权

每个操作必须定义：

- 所需角色、权限或 scope；
- 资源级所有权检查；
- 字段级可见性；
- 批量接口逐项授权；
- 管理员越权边界；
- 委托和代操作语义；
- 失败时资源存在性是否隐藏。

禁止只在列表入口授权，而在单项、导出或批量端点遗漏检查。

## 数据最小化

- 响应只返回调用方当前用途所需字段。
- 敏感字段默认不返回，不能只依赖客户端隐藏。
- 字段选择和展开不得绕过权限。
- 对个人信息、支付数据、健康数据和密钥材料标记分类。
- 缓存、错误、Webhook 和事件同样遵守最小化。
- 导出接口必须有更严格权限、审计、大小和有效期控制。
- 测试和示例使用虚构数据。

## 输入与资源限制

必须限制：

- 请求正文大小；
- 字段长度；
- 数组和 Map 大小；
- 对象嵌套深度；
- 文件大小和类型；
- 页大小；
- 批量项目数；
- 过滤条件复杂度；
- 展开深度；
- 同时请求和异步任务数。

输入通过 Schema 后仍需进行业务和权限验证。

## 浏览器与跨域

浏览器可调用 API 应明确：

- CORS 允许来源、方法和 Header；
- 是否允许凭据；
- CSRF 防护；
- Cookie 的 Secure、HttpOnly、SameSite；
- 重定向和预检行为；
- Content-Type 和下载安全 Header。

不得使用 `Access-Control-Allow-Origin: *` 与凭据组合。

## Webhook 与回调

- 使用 TLS。
- 对目标进行验证，防止 SSRF。
- 签名覆盖正文和关键元数据。
- 时间戳与 nonce 防止重放。
- 密钥可轮换并支持重叠期。
- 不接受任意内网、回环或云元数据地址。
- 回调响应不得泄露内部错误。
- 投递日志和审计遵循日志规范。

## 滥用与限流

- 按身份、租户、IP、操作成本或业务资源设置限额。
- 返回 429 和必要的重试提示。
- 配额、突发和恢复策略必须文档化。
- 高成本搜索、导出和批量操作使用独立限额。
- 防止通过并发、分页或多账号绕过限制。
- 限流不能替代权限和容量保护。

## 安全文档与测试

契约中明确：

- 安全方案；
- scopes；
- 敏感字段；
- 限额；
- 认证和授权错误；
- Webhook 签名；
- 文件限制；
- 数据保留或删除语义。

测试至少覆盖：

- 未认证；
- 权限不足；
- 跨租户访问；
- 批量越权；
- 字段级越权；
- ID 枚举；
- 超大载荷；
- 注入和恶意文件；
- 重放和重复请求；
- CORS/CSRF；
- 限流；
- 错误信息泄露。
