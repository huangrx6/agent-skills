## 访问控制

- 应用、迁移、只读分析和 DBA 使用不同角色。
- 最小权限；应用运行账号通常不拥有 DDL 权限。
- 生产管理员使用个人/短期凭据，不共享永久 root/superuser 密码。
- 凭据不写入代码、迁移脚本或镜像。
- 网络层限制数据库暴露范围，并要求加密连接。
- 临时授权有到期时间和审计。

## 敏感数据

- 建表时标记敏感分类和 Owner。
- 不存储业务不需要的敏感信息。
- 密码只存经过批准的 password hash，不可逆“加密密码”。
- 需要加密字段时明确 key management、轮换、搜索能力和备份恢复。
- 测试/开发环境不得直接复制未脱敏生产数据。
- 导出、备份和 CDC 同样属于敏感数据范围。

## 审计

数据库审计与应用业务审计职责分离。

记录适用场景：

- DDL；
- 权限变化；
- 高权限读取；
- 数据导出；
- 敏感表修改；
- 备份恢复。

不要默认记录每条业务 SQL 的完整参数，避免敏感数据和成本失控。

## 保留与归档

每个大表/高增长表必须定义：

- 数据 Owner；
- 在线保留时间；
- 归档时间；
- 物理删除时间；
- 法律保留例外；
- 查询历史数据的方式；
- 归档完整性校验；
- 容量预算。

定期清理必须分批、限速并观察复制延迟。

## 删除

- 业务软删除与合规物理删除是不同需求。
- 物理删除必须覆盖主库、副本、搜索索引、缓存、归档和合法范围内的备份生命周期。
- 大量过期数据不要一次性 DELETE。
- 分区表可通过 drop/detach partition 高效淘汰，但必须验证引用和备份策略。

## 备份

备份方案必须回答：

- full/incremental/logical/physical；
- 周期；
- 加密；
- 异地副本；
- 保留；
- 不可变/防勒索；
- 备份失败告警；
- 恢复依赖的软件和密钥。

“备份任务成功”不等于可恢复。

## PITR 与恢复

- 定义 RPO 和 RTO。
- 需要时启用 WAL/binlog/日志归档以支持 point-in-time recovery。
- 定期在隔离环境恢复，并校验应用能连接、Schema 正确、数据完整。
- 记录恢复 runbook 和负责人。
- 备份加密密钥本身也必须可灾难恢复。
- 定期测试误删表、误更新、整库故障和区域故障等场景。

## 高可用与容灾

明确：

- failover 自动或人工；
- 数据丢失窗口；
- 连接切换；
- split-brain 防护；
- 读副本提升；
- DNS/代理 TTL；
- 客户端重连和事务失败；
- failback；
- 跨区域成本和一致性。

高可用不能替代备份；副本会复制误删除和逻辑错误。
