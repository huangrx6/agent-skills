## 表设计评审

检查：

- 业务不变量是否明确；
- 主键与业务唯一键；
- NOT NULL/UNIQUE/FK/CHECK；
- 时间、金额、单位；
- 字符集和 collation；
- JSON 是否被滥用；
- 查询模式是否支持；
- 生命周期和删除；
- 数据 Owner 和敏感级别。

## SQL 与事务测试

至少覆盖：

- 并发创建唯一业务键；
- 乐观锁冲突；
- 悲观锁等待；
- deadlock/serialization retry；
- rollback；
- 超时；
- 批量边界；
- 分页数据同时新增/删除；
- 读副本延迟（如果使用）。

不要只在空数据库上验证 SQL。

## 迁移测试

迁移必须在接近生产 Schema 和代表性数据量上测试：

- fresh install；
- 从当前生产版本升级；
- 重复执行/幂等性（适用时）；
- 执行时间；
- lock wait；
- 表重写和临时空间；
- 新旧应用并存；
- 应用回滚；
- 副本延迟；
- migration 失败后恢复。

## 回填测试

- checkpoint 可恢复；
- 重复处理不会破坏数据；
- 单行异常不会使整体不可恢复；
- 限速生效；
- 中断后继续；
- 校验查询能发现漏行和错值；
- 处理新写入与历史回填的竞态。

## 性能测试

关键查询使用代表性：

- 行数；
- 数据倾斜；
- 热 key；
- 高基数/低基数；
- 峰值并发；
- 缓存冷/热场景。

记录执行计划、P95/P99、锁等待和资源使用。

## 恢复测试

定期演练：

- 恢复完整备份；
- PITR 到指定时间；
- 单表误删；
- 错误批量 UPDATE；
- 主库故障切换；
- 区域恢复（若承诺）；
- 加密备份密钥恢复。

恢复后不仅检查数据库启动，还要运行应用 smoke test 和数据一致性校验。

## 发布门禁

存在以下任一情况不得发布：

- migration 假设应用与数据库原子发布；
- 大表 DDL 未确认实际锁/重写行为；
- 回填不可暂停或不可恢复；
- 破坏性变更无调用方迁移证据；
- 新唯一约束存在历史冲突；
- 无复制延迟和锁等待监控；
- DROP 前没有满足恢复目标的备份/PITR；
- 关键查询无执行计划/容量验证；
- 数据删除和保留无 Owner；
- 迁移失败后没有明确 stop/cleanup/forward-fix 路径。
