# 英文残留与术语

面向中文送审表时，普通英文通常要换成中文；行业共识缩写与文件格式可以保留。
这份字典是**提示与可选改写的依据**，不是评分表：字段名、真实标识、产品名不因
「看起来像英文」而被替换。

内置数据在 `scripts/glossary.json`，`--glossary FILE` 可合并自定义词条
（`map` 为映射，`keep` 为保留词，`system_attributes` 为系统字段）。

## 保留词（不替换）

| 保留 | 说明 |
| --- | --- |
| API | 接口类通用缩写 |
| Token | 访问凭证 |
| AI | 人工智能 |
| KPI | 关键指标 |
| IP | 网络地址 |
| URL | 链接地址 |
| SDK | 开发工具包 |
| OAuth | 身份认证 |
| CSV / PDF / Excel | 文件格式或产品名 |
| OA | 国内通用系统叫法 |
| Key | 仅限连写（API Key / Token Key）；单独出现或作字段前缀时仍写「密钥」 |

大小写变体一视同仁（API/api/Api）。保留是「可用」而非「必用」；同一术语在全表内
应前后一致。不得以「行业共识」为名保留整串英文短语（`Model List` 不是缩写）。

## 替换映射（节选）

| 英文 | 中文 |
| --- | --- |
| Download / Upload / Import / Export | 下载 / 上传 / 导入 / 导出 |
| Login / Auth / Token 以外的凭证词 | 登录 / 认证 / … |
| Dashboard | 工作台 |
| Webhook / WebHook | 网络钩子 |
| Notification(s) | 通知 |
| Department(s) / Dept(s) | 部门 |
| Category / Tag(s) | 分类 / 标签 |
| Model(s) / Agent(s) | 模型 / 智能体 |
| Todo(s) / Approval(s) | 待办 / 审批 |
| Detail(s) / List | 详情 / 明细 / 列表 |
| ID / Id | 编码（`{实体名}编码`，不写「ID」） |

完整映射以 `scripts/glossary.json` 为准，新增词条直接改该文件或用 `--glossary` 合并。

## 替换的安全边界

1. **整词匹配**：`用户ID` → `用户编码`；`addressID` 整体不是字典词，保持原样，
   不会被拆成 `address编码`。
2. **只改显示文字**：`normalize --glossary` 改写子过程描述、数据组与数据属性，
   不动兴趣对象、移动类型、过程编号与来源。
3. **每次改写留回执**：工具打印行号、列名、原文与新文，方便逐项复核。
4. **产品名、协议名、真实字段名不硬替换**：字典只是提示；确认是字段标识就保留。
5. **不一致比残留更糟**：同一概念一半写「下载」一半写「Download」时，
   先统一，再考虑是否保留英文。

## 系统字段

下列字段通常不进入业务数据组说明（作为真实接口入参时仍可写）：

主键编码、创建人、创建时间、修改人、修改时间、删除标记、删除时间、页码、
每页条数、当前页、排序字段、排序方向、返回格式、关键词。

剔除它们是为了让数据组描述业务含义，不是为了凑数量；需要时按来源如实保留。
