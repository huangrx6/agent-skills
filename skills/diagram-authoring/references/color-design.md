# 按当前图设计配色

配色不是从固定 profiles 中挑一个名字。先判断画布、阅读文字、重点、分类和状态分别需要什么，
再选择具体颜色与面积。旧 visual / scheme 是兼容起点，不是允许颜色的白名单。
先按 [逐步确认](decision-gates.md) 完成内容确认，再提交配色提案并等待回复；不能以“自主设计”跳过确认。
没有行业固定色、固定色数或禁用色系；用户已有品牌或选择优先，不为追求多样性随机换色。

## 单张图先克制用色

默认用中性画布、文字和普通节点，只为关键节点引入重点色。色板里有很多颜色，不代表都要放进图里。
`by_kind / by_node` 默认留空，候选伴随色不会自动用于节点；不要因为有四种 kind 就分配四种颜色。
只有区分类别、状态或不同路径能减少理解负担时才增加辅助色，并保持跨图含义一致。
这不是硬性限制色数；复杂分类可以用更多颜色，但每种颜色都应有明确作用。
用户说“太花/杂乱”时，先减少无意义的彩色节点、边和背景，再调整饱和度；不只是替换色板名字。
节点重点色与分区底色承担不同任务。用户需要分层识别时，允许相邻区域使用不同的低饱和浅底色，
区内普通节点仍可用白底；同一区域跨视图保持同色。不必每层发明一种颜色，也不要把“少用色”执行成所有区域同底色。
连线密集的图优先试实心浅底色，大面积斜线纹理容易与连接线混淆；仍需看实际输出决定。

## 从哪里开始

- 有网站、参考图或品牌材料：实际查看颜色和应用方式，提取需要的 HEX，记录具体链接或本地来源。
  图片取色后还要分配角色，不能把照片中的所有颜色平均铺进节点；不要声称脚本已自动抓取网站或图片。
- 有一个主色：可用 `color_design.py --seed` 生成候选伴随色，色相偏移可自由指定。
  色轮关系只帮助探索，不能证明好看；作者仍需调整背景、明度、彩度、填充面积与角色。
- 没有参考：根据观看环境和表达重点准备推荐，说明具体颜色及角色分配，等用户确认后应用。
  需要比较时做少量有明确差异的候选；不是固定主题菜单，也不以随机轮换冒充个性化。

可按需要访问 [Adobe Color](https://color.adobe.com/) 的色轮/取色工具、
[Happy Hues](https://www.happyhues.co/) 的实际应用页、[中国色](https://zhongguose.com/) 的单色资料，
或 [Huemint](https://huemint.com/about/) 的按用途生成配色方法。
这些是发现入口，不是强制依赖。引用具体色板时查看具体页面，记录采用和调整了什么；
网站不可访问就使用已有材料或自主设计，不虚构取色结果。

## 项目文件与结构分离

把具体设计保存在用户项目的 `*.colors.json`，与 `*.diagram.json` 一起交付。
同一文件可用于 Excalidraw 和 draw.io；换颜色不改变标签、关系、字号或布局。
文件由 `--colors` 显式传入，不扫描用户目录，不改安装目录里的配色，不自动访问 source URL。
重新生成时也要传入；未传入的旧调用保持兼容行为。

```json
{
  "version": 1,
  "name": "本项目的紫色与绿色",
  "source": "品牌材料或实际查看过的色板 URL",
  "rationale": "紫色标记本次重点，绿色区分入口和数据；保留形状和文字帮助识别。",
  "canvas": "#FCFAFF",
  "ink": "#292436",
  "accent": "#7255B8",
  "critical": "#C44343",
  "swatches": {"sage": "#67A88D", "amber": "#B89346"},
  "by_kind": {},
  "by_node": {},
  "strength": {"normal": 0.15, "primary": 0.32, "critical": 0.18, "surface": 0.035}
}
```

`canvas / ink / accent / critical` 必填，使用 `#RRGGBB`。
`swatches` 可自由命名和增加颜色，不能重定义保留名 accent / critical。
`by_kind` 将已有节点角色分配给色名；`by_node` 用真实节点 ID 覆盖角色分配，适用于同类服务需要区分的情况。
未分配的普通节点保持中性，primary 默认用 accent；已分配的 primary 加强其所属色。
muted 回到中性，critical 保持警示编码，不被分类色覆盖。不要靠红绿或任何颜色单独传递意义。

`strength` 是源色混入画布的比例，0 为画布色，1 为原色；四项均可在 0–1 调整。
省略时默认 normal=.12、primary=.30、critical=.18、surface=.035；这些是起点，可以改变。
只有显式分配颜色的普通节点才用 normal 混色；未分配的普通节点仍保持中性。
surface 是普通分组/说明卡片混入墨色的比例，默认保持中性；其边框也用中性线色。
普通分组不继承 accent，避免一个重点色扩散到所有背景框。确需强调某个分组时显式设置 group.level=accent。
需要区分区域时，在颜色文件增加 `by_group`，例如：

```json
"by_group": {
  "processing": {"color": "sage", "strength": 0.22},
  "storage": {"color": "amber", "strength": 0.18}
}
```

键必须是源规格中的真实分组 ID；color 引用 swatches 或 accent / critical，strength 省略时沿用 normal。
它只改变对应区域的填充/标题文字色，边框保持中性，不改变区内节点配色。显式分配优先于 neutral/tint/accent，
但不覆盖 critical 的警示含义。色值检查包含这些背景上的文字与连线；三后端的流程图分区均支持。
在结构规格的分组 `style.fill=solid` 可只将背景改为实心，也可以全图选实心画法。
未指定的分组及说明卡片保持既有行为。见 [分区实例](../examples/regions/README.md)。
字体和线条画法仍由原 visual / scheme / style 控制。自定义配色优先覆盖其颜色；
draw.io 的 `--seed` 与 `--colors` 同时出现会报错，请在一个项目文件内修改，避免优先级含混。

## 实际执行

以下应用配色和生成命令在用户确认方案后使用；候选提案阶段不要覆盖项目已有配色。

```sh
# 从任意主色探索；偏移角度不限定在几种和谐模式中
python3 scripts/color_design.py --seed '#7255B8' --offsets=135,205 -o project.colors.json
# 随后按内容编辑 by_kind / by_node、伴随色和 strength；也可直接创建文件
python3 scripts/color_design.py project.colors.json -o color-check.json
python3 scripts/emit_excalidraw.py system.diagram.json --colors project.colors.json --quality showcase
python3 scripts/emit_drawio.py system.diagram.json --scheme classic --colors project.colors.json --quality showcase
```

网站选色无需转换成脚本认识的主题名，只要写入项目配色文件即可。
如果用户要的是很具体的色板，优先原色和用途，再调整派生填充/边线，不用算法替换其审美选择。
反白文字配合实心填充；稀疏纹理会露出画布，必须同时检查文字对填充和画布。

## 检查与审稿

程序保留原始 swatches，通过混色产生填充，并按需要派生边线颜色；所有边线调整记在回执 adjustments。
文字优先用 ink，强填充需要时采用黑字/白字。画布与 ink 不足 4.5:1 时明确失败，不悄悄改品牌原色。
解析时检查派生纯色组合：文字 4.5:1，关键边界/连线 3:1；不能满足时调整设计，不降低门槛。
这只是色值检查，**不是实际像素、色觉缺陷模拟或完整无障碍认证**；透明、纹理、图标、
嵌套强调区域和编辑后的颜色仍需单独审查。现有 palette 使用串行调用状态，已测连续生成互不污染，
尚未成为线程安全上下文；并发生成使用独立进程。

官方导出后按最终尺寸看：重点是否突出、分组是否抢眼、分类是否必要、深浅底文字是否完整、
细线是否可辨。只比较颜色时保留同一结构/字体/尺寸；实际图有效才保留方案。
颜色不合适时调整角色与面积，不能只换一个名字反复套模板。

它们是可编辑输入示例，不是新增的三套固定 profiles。
