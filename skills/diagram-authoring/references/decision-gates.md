# 内容、配色与图标的逐步确认

这是图的制作流程，不是笼统问一句“有什么偏好”。AI 先把选择整理成用户能判断的方案，
每次只提交当前节点；明确等到用户回复后，才进入下一节点。默认顺序：内容 → 配色 → 图标 → 生成。
适用于所有图型；Excalidraw、draw.io、Mermaid 都确认内容和配色，图标节点按后端能力处理。

## 1. 内容确认

先查材料和已有图，整理具体内容草案。此时允许只读调查、核对事实、在临时位置准备草案，
不写最终成品、不覆盖项目已有规格或配色、不启动正式出图和导出。

交给用户判断的内容至少包括：

- 图回答什么问题、给谁看、采用什么图型/后端、放在哪里看、分层图用 `LR` 还是 `TB`。
- 要画的层/分组及节点；简单图列全，复杂图按分组列节点并给出总量。
- 主链路、分支/回路与重要跨层关系；复杂图的其余关系要可展开查看，不能用一条概述冒充全量确认。
- 方向建议及依据：横向流水线、阶段推进、分支并排或 16:9 幻灯片优先 `LR`；纵向步骤、窄栏文档或移动端优先 `TB`。
  图型默认方向只是起手值；用户已明确说“横着/竖着”时直接采用，不再追问。方向不改变节点和边的语义事实。
- 需要同画布横竖混排时，说明拆成哪几个独立面板、各自方向和跨面板关系；这是面板式组合，
  不是单图复合布局，跨面板连线不会自动生成。
- 保留到什么细节程度，哪些信息放图外；是否一张总览或多张细节图；来源不确定的内容单列。

给出推荐及理由，然后提出一个明确问题，例如“按这份范围和关系继续，还是先调整内容？”并停止。
用户的内容选择不能把未核实的技术事实变成已证实事实；不确定项继续保留标记或核查。
用户修改内容时先修订当前草案；“增加 X”不是对修订后全部内容的自动确认。

## 2. 配色确认

内容确认后，结合用户已有条件准备配色提案。不要让用户填写 HEX 表，也不要只问喜欢哪种颜色。

- 有品牌/网站/参考图：先查看实际材料，提出怎样用到这张图；注明引用与调整。
- 没有偏好：给一个推荐方向，必要时再给一两个有意义的替代；允许自由改色，不是固定 profiles 菜单。
- 说明画布、文字/连线、普通节点、重点节点分别用什么颜色；分区是否有不同浅底色，具体对应哪些层。
- 说明填充与留白的大致比例、纹理或实心的选择；避免“色板好看，实际铺满后太花”。

可以在聊天里展示颜色角色表，附便于辨识的色名和 HEX；已有可用参考图直接引用。
用户确需视觉对比时才制作小范围示意或可编辑样稿，不把确认机制变成默认生成多份 PNG/SVG。
明确问“采用这组颜色及分配方式吗？”并停止。收到确认才将其落实到项目配色。
“颜色跟品牌走”提供了条件；如果具体分配尚不明确，仍应提交方案确认。

## 3. 图标确认

Excalidraw 不强制需要外部图标素材；不用图标、内置语义图标、外部通用素材、真实品牌图标均可提出。
先基于内容和已确认配色准备可执行的图标方案，再让用户决定，不默认加满或全部省略。

提案必须说明：

- **来源与样式**：无图标/内置/外部库；通用还是品牌，线性还是实心，同风格或有理由的混用。
  选外部素材时给出可用来源、实际项名及必要的可见参考；不能让用户确认尚未找到的图标。
- **覆盖范围**：列出哪些节点配什么图标、哪些不用；给出数量和占业务节点总数的比例。
  例如“28 个节点中 6 个使用图标，约 21%，仅客户端、队列、存储和推理入口”。这只是示例，不是默认比例。
- **视觉占比**：图标是小角标还是主要识别元素，位置与文字的大小关系；覆盖率与图内面积占比不能混称。
  当前脚本没有任意图标面积百分比参数，不能承诺精确 20% 面积；需要时用局部样稿说明可实现效果。
- **颜色处理**：统一墨色还是保留素材色；`auto/ink/native` 的实际效果和品牌原貌限制见 [图标](icons.md)。

明确问“按这个素材、覆盖范围和视觉比例使用图标吗？”并停止；收到确认后再把 icon 写入规格并生成。
用户已经明确“不要图标”即确认了无图标方案，不再追问种类与比例。

draw.io/Mermaid 生成器目前不支持图标：说明此限制，默认将图标节点记为不适用，不伪造选项。
若用户要求图标，先解决后端选择；不能未经同意改后端、删图标或拿文本符号冒充素材。

## 等待、恢复与变更

- 每次只问当前节点。回复“确认/采用 A/按该方案继续”只确认当前已展示的具体方案，不同时确认未来节点。
- 用户提前明确给出某一节点的完整选择，例如“配色沿用这张参考的角色分配，确认；不要图标”，
  记录为该节点已确认，抵达时简短复述即可，不重复索取相同确认。
- “你看着来/你推荐一个”默认授权准备提案，不撤销这里的逐步确认。
  用户明确说“本次跳过配色确认，由你直接决定”或“所有节点免确认直接生成”时，按其明确范围执行并记下授权；
  不从沉默、等待超时、工具默认选项、AI 自己写的记录或旧文件存在推断确认。
- 等待期间可以继续不依赖该选择的只读调查；不得继续下一节点设计、正式生成或同步已有图片。
  必须等待的节点不能用超时后默认选第一项代替；需要时以一个清晰问题结束当前轮次。
- 在对话中维护简短状态：当前节点、已确认选择、待确认内容、用户回复依据。长任务需要跨轮持久化时，
  可写入已有制作记录；确有需要才使用该图 `.source/decisions.md`，不例行新增顶层确认文件。
  记录只帮助恢复，不能替代真实用户回复；脚本生成的 `approved: true` 不构成授权。
- 三个适用节点确认后才正式生成、检查及同步已有导出。不再为已批准范围内的实现细节逐次请求许可。
- 修订已有图时沿用已确认且未变化的选择；首次接管且没有确认依据，展示“沿用当前内容/配色/图标”的具体方案逐项确认。
  纯导出、纯格式转换或已明确要求不改变设计的机械修复不重新启动设计确认。
- 内容范围、分组、重点或后端有实质变化，重新确认受影响的节点；配色小修不让用户从头确认内容。
  不静默换色、换图标、删边、改变单图/多图方案；若技术限制迫使改变已确认选择，解释限制并回到对应节点。

## 可执行边界

确认由使用 skill 的代理在对话中执行。低层生成脚本是非交互 CLI，不具备读取用户回复的能力；
不要声称它们能阻止一切绕过流程的手动调用，也不要添加一个谁都能自行填写的确认开关来冒充流程保障。
示例命令是确认完成后的实施入口；本 skill 的脚本开发、单元测试、临时回归夹具不逐张索取设计确认。
用户要求修改 skill 时先完成规则修改，不误把它变成对某张业务图的重画授权。
