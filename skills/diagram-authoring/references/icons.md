# 图标：让图更丰富，而且**不用手拖**

图标有两个来源，**内置 sigil 优先**：

| 来源 | 什么时候用 | 依赖 |
| --- | --- | --- |
| **内置 sigil**（`scripts/sigils.py`） | 常见语义角标：用户/括号/圆柱/队列/盾牌/云/外部/方块 | **零依赖** —— 不碰素材库 |
| 素材库（`.excalidrawlib`） | 品牌logo、更丰富的图形 | 本机路径可配，不入仓库 |

内置 sigil：每个语义角色一个小小的 16px 图形，
由脚本自绘、随当前画布墨色上色。宽度进尺寸链的方式与素材库图标**完全一致**
（同一个 `intrinsic_size` / `fit_scale` / `place` 管道），所以下面关于尺寸链的
讨论对两者同样成立。两源同名时永远取内置 —— 静默挑另一个等于"我写了 A 出来的是 B"。

```bash
python3 scripts/sigils.py                # 内置目录：user / api / database / queue / shield / cloud / external / plain + 别名
python3 scripts/sigils.py --name database
```

内置名的好处：**不配素材库也能用**，而且不存在"自带文字缩成噪点"的问题
（sigil 本来就只有图形）。注意：内置 sigil 目前只在 Excalidraw 后端渲染；
drawio 后端遇到任何 icon 仍然报错（见下）。

## 你（agent）该怎么做

### 0. 先去**官方素材库目录**里找（200+ 个库、几千个图形）

内置 sigil 只有十来个图形，只够“图能看”；语义一多就不够用了。
Excalidraw 官方维护着一个社区素材库目录（`libraries.excalidraw.com`），
`icons_fetch.py` 把那个目录变成可搜、可取的东西：

```bash
python3 scripts/icons_fetch.py --list                 # 官方有哪些库（名字 + 项数 + 作者）
python3 scripts/icons_fetch.py --list 监控             # 按库名/图形名过滤（中文也认，见下）
python3 scripts/icons_fetch.py --search 队列           # 哪些库里有“队列”类图形
python3 scripts/icons_fetch.py --get "IT icons"       # 取到本地缓存
```

- **中文能搜英文项名**：官方库里项名全是英文，工具内置一张常用词对照表
  （`数据库→database`、`队列→queue/message`、`防火墙→firewall`、`定时→timer` …）。
- 取下来后 `--library it-icons`（缓存里的库名）或全路径都能用；
  库文件**不入仓库**（第三方作品，体积与许可都不适合），只落在
  `~/.cache/diagram-authoring/libraries/`，旁边`.meta.json`记着作者与官方来源。
- 这个工具**需要联网**，是可选的 —— 不联网就用内置 sigil 或本机已有的库。

**选型优先顺序：** 内置 sigil（快、零依赖、与主题同色）→ 官方目录里的通用图标集
（`IT icons` 48 个语义图形，覆盖数据库/服务器/防火墙/用户/云/定时器…）→ 云厂商/品牌库
（AWS / GCP / K8s / Azure，只在图确实是那个环境时才用，否则会把普通架构图画成厂商图）。

**不要反复用同几个图标去覆盖不同语义**（用户原话："为什么每次都是这几个icon，
官方素材库不是一堆吗"）—— 先用 `--search` 确认真的没有合适的，再用相近的。

### 1. 再看本机库里有什么

**不要凭印象猜图标名字。** 名字对不上就是硬报错，不是"大概给我一个"。

```bash
python3 scripts/icons.py --grep database      # 按关键词找
python3 scripts/icons.py --size Router        # 看某一项多大、放进节点会缩到多高
python3 scripts/icons.py                      # 全列出来（超过 200 项会截断）
```

素材库路径的优先级：`--library` > 环境变量 `EXCALIDRAW_LIBRARY` > `~/.config/excalidraw-library-path`。
`--library` 也接受**缓存里的库名**（`icons_fetch.py --get` 下来的那些）。
**素材库不入仓库**（几 MB 的第三方文件，体积与许可都不合适），所以它是可配的本机路径。

### 2. 按语义选，不按"好看"选

图标的作用是让**读者更快认出一个节点是什么**。所以：

| 节点的语义 | 选什么图标 |
| --- | --- |
| 数据库 / 存储 | 圆柱、数据库、磁盘类 |
| 用户 / 角色 | 人物类 |
| 消息 / 队列 | 信封、队列、流 |
| 安全 / 鉴权 | 盾、锁、钥匙 |
| 外部系统 | 云、第三方厂商 logo |
| 网络设备 | 路由、交换机、防火墙 |

**同一个角色用同一个图标**，不要同一张图里数据库一会儿圆柱一会儿磁盘。
**不要给每个节点都配图标** —— 图标多了就变成噪声，反而看不出重点（与颜色那节同一条道理）。

### 3. 写进规格，出图

```json
{ "id": "db", "kind": "data", "label": "订单库", "icon": "Database" }
```

```bash
python3 scripts/emit_excalidraw.py spec.diagram.json -o out.excalidraw --library ~/素材库.excalidrawlib
```

- **图标风格由脚本统一，素材原风格不保留**（2026-09-16，用户反馈"图标风格不一致啊"）：
  描边粗细一律 `icons.ICON_STROKE_WIDTH`、颜色一律用**所属节点自己的描边色**（所以
  图标与它所在的框同色）、粗糙度统一、填充只保留"实心/空心"的设计但换成同一个墨色。
  素材库是不同作者做的，同一个库里都能出现 `strokeWidth: 1` 与 `: 4` 混用 ——
  照抄进同一张图就成了"粗黑图标 + 细线图标"混排。
- **实心也统一**：大块实心（面积 > 图标包围盒的 25%）一律转成空心 —— 素材里
  "整块填黑"的图形和细线图形放一起就是两套语言；**小面积实心保留**（点、箭头头部，
  比如内置 `queue` 的三个点），但颜色同样换成那个墨色。阈值是
  `icons.ICON_SOLID_MAX_SHARE = 0.25`。
- **颜色分两种待遇**（`style.icons`，默认 `auto`）：
  - **多色素材**（品牌 logo、彩色图标）= 作品 → **保留配色**；但每个颜色都要在画布上
    读得出来（对比度 ≥ 3:1，WCAG 对非文本图形的要求），不够就**保留色相往墨色压**
    （实测某云厂商的橙在浅画布上只有 2.04 → 压到 3.37，还是橙的，但看得清了）；
  - **单色素材** = 线描图形 → 一律换成**所属节点的墨色**（与它所在的框同色）；
  - 要严格单色（蓝图风）写 `"style": {"icons": "ink"}`；要原样保留（不管对比度）
    写 `"native"`。
- 描边粗细**不按缩放比例改**（曾经的实现会乘 `scale`）：那会让 22px 的小图标与 44px 的
  大图标粗细不同，又回到不一致。所有图标视觉重量一致才是一套。
- 图标高度按节点自身高度算（`icons.height_for`），所以同图里不同大小的节点图标也不会
  "小的挤大的" —— 实测同图四个图标墨迹高都恰好等于目标高（36px）。
- 图标与文字**作为一个整体在节点里居中**：文字不是绑定文字（`containerId: None`），
  位置由脚本算，所以"图标 + 间隔 + 文字"的重心正好落在节点中心
  （绑定文字会被 Excalidraw 拉回容器中心，整组会偏左 —— 见
  `references/excalidraw-backend.md` 第四节）
- **图标不会越出节点边框**，包括"图标 + 长说明"这种最容易溢出的组合。
  机制是**框自动适配内容宽度**：布局阶段保证
  `框宽 ≥ 内边距×2 + 图标宽 + 间隔 + 可见文字宽`，所以图标算出来总在框内。
  另一条同源规矩："可见文字宽度"按**每桶自己的字号**算（标题 16px、说明 12px）——
  拿标题字号去乘说明行会高估 33%，把图标推到框外（实测越界 30px，已修）。
  **不要用钳位去救**：钳位会把图标推到文字底下，看起来像"图标没了"（用户原话：
  "你这相当于溢出的直接不给icon了"）
- 图标缩放到固定高度（`icons.ICON_HEIGHT`），宽度随素材本身的宽高比
- 形状 / 图标 / 标签**同挂一个 groupId**：解绑之后靠分组，在 Excalidraw 里
  拖动、缩放仍然是一体（代价：改标签不会自动重排）
- 名字不存在 → **硬报错并列出可用的名字**，不 fallback（静默换一个图标，看图的人
  根本不知道原本想要的是什么）

## ⚠ 图标是**第一个外部尺寸来源**

前面所有步骤（文字测量、形状包围盒）都是本 skill 自己算的。图标的宽高来自那个
`.excalidrawlib` 文件 —— **不是我们量的**。

所以：

1. **节点盒子会为图标加宽**（`layout.boxes_from_spec` 的 `icon_sizes` 参数），
   否则图标会盖住文字或溢出节点。
2. `references/validation.md` 第六节里"尺寸只有一个来源"那条前提**从这一版起不再成立**，
   而且 **#1「元素间隙」开始可能真的报出来** —— 盒子被撑大之后同层节点可能挤在一起。
   那不是 bug，是这个断言第一次真的在干活。
3. 那三个新常量（图标高度、与文字的空隙、拿不到尺寸时的占位）目前都是
   **待验证**值，没有真实数据校准过。信任状态见 `diagram-spec.md` 的总表。

## ⚠ 实测：素材库通常是"示例图"，不是"图标集"

拿真实的素材库（429 项）跑了一遍，图上看得出的问题：

| 图标高度 | 自带文字缩到 | 可读性提示 | 最宽节点 |
| --- | --- | --- | --- |
| 22px（默认） | 3.2 ~ 5.7px | **6 / 6 条** | 304px |
| 40px | 4.6 ~ 10px | 4 条 | 322px |
| **65px** | ≥ 9px | **0 条** | **348px** |
| 90px | ≥ 12px | 0 条 | 373px |

结论很直接：那批素材是**厂商示意图**（图形 + 自带的标签文字），
不是单图形图标。要让它们自带的字看得清，图标得高到 65px —— 而那时节点已经
变成 348px 宽的卡片了。

**所以**：

- 当**节点角标**用 → 挑**单图形、不带文字**的项。带文字的项一律会被报出来
  （`check: icon` 那条），提示里会给出具体字号，不用你去猜。
- 当**独立图示**用 → 完全可以，把图标高度调大就行；那种情况下节点本来也该大。
- 不要为了消掉提示就把整张图的图标调得很大 —— 先想想那个素材该不该当角标。

这条检查是**软的（不阻塞出图）**：它说的是"素材选得不好"，不是"图错了"。

## 给用户：怎么把素材库装进 Excalidraw

官方入口（不需要任何脚本）：

```text
https://excalidraw.com/#addLibrary=<URL 编码的 .excalidrawlib 地址>
```

也可以在 Excalidraw 里点侧栏的 Library → 打开文件。装好之后在画布上可以手动拖用 ——
但**本 skill 生成图不需要这一步**：它直接把元素写进文件。
装库是为了用户自己在 Excalidraw 里继续编辑时手边有素材。

## 格式

两种都支持（官方从 v1 换到 v2 时没有保留兼容层）：

| 版本 | 顶层结构 | 项有没有名字 |
| --- | --- | --- |
| v1 | `{"version": 1, "library": [[元素...], ...]}` | **没有** —— 只能用 `#序号` 索引 |
| v2 | `{"version": 2, "libraryItems": [{"id", "name", "elements"}]}` | 有 |

v1 的项没有名字是**事实**，所以 `icons.py` 直接说"这个库没有名字"，
而不是造一个看起来像名字的东西出来。
