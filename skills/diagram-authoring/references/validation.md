# 校验与修复

先用 `validate_spec.py` 查结构输入，再用 emit 生成。emit 内部调用 `check_layout.py`
进行布局检查与有限调参，通过后原子写入。有阻塞项时不会用失败结果覆盖现有成品。

## 诊断层次

| 层 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 规格校验 | 字段、类型、枚举、节点/分组引用完整 | 关系符合代码或业务事实 |
| 布局校验 | 计算模型里的间隙、路由、容器与颜色规则 | 外部编辑器按真实字体重排后的结果 |
| 自研 preview | 近似的疏密、颜色与位置 | Excalidraw/draw.io 真实渲染一致 |
| 官方导出/应用打开 | 对应渲染器实际产生的图 | 叙事清楚、焦点正确、视觉美观 |

只有真正看过渲染结果，才可以报告完成目视审查；没有看图时不要将脚本通过称为视觉通过。

## 布局检查与质量档

下表概括 `scripts/check_layout.py` 的当前检查；阈值以脚本为准。

| 检查 | standard 行为 |
| --- | --- |
| 元素包围盒间隙、过短连线段 | 阻塞；尝试增加布局间距 |
| 文字溢出、颜色/角色越界 | 阻塞；区分输入错误与内部尺寸不一致 |
| 边交叉数过多 | 警告；尝试调整分层排序 |
| 连线穿节点（包括不正确地穿过端点内部） | 阻塞；尝试调整路由空间 |
| 区域部分重叠、包含非成员 | 阻塞；修分组或层级 |
| 共线重合、分层图的斜段 | 警告；尝试调整空间 |
| 区域标题溢出、压成员或超过两行 | 阻塞；前两种需查尺寸链，过长标题可缩写 |
| 折点过多、实际线段相交 | 警告；不能靠反复加间距保证解决 |
| 桌面缩放后的字过小、图标自身文字过小 | 提示；关注最终观看尺寸 |

`--quality standard` 是默认值。`--quality showcase` 在自动调参后将结构类软项
（交叉、重合、斜段、折点、相交等）升级为阻塞；可读性和图标提示不因此消失。
showcase 也不是“无一处问题”的证明：它只检查列出的性质。

## 读回执

```sh
python3 scripts/check_layout.py system.diagram.json --quality showcase --json
python3 scripts/check_drawio.py system.drawio
```

`check_layout.py` 退出码：0 无阻塞项，1 有阻塞项，2 规格读取失败。
`validate_spec.py` 退出码：0 合法，1 内容错误，2 读取或 JSON 解析失败。
JSON 诊断含 `code`、`severity`、`message`、`subject`、`evidence`、`suggestedFixes`。
先看受影响主体与证据，再选择保留事实的修复；建议不是事实判断的替代品。

## 修复顺序

1. 修错误引用、重复 ID、缺失标签和未知字段；不改脚本去放行拼错的 spec。
2. 用短标签、节点 detail 或 cards 减少图内阅读量；不得删必须展示的信息。
3. 调整有依据的分组、rank 或 pin。不要把像素坐标或内部调参参数写进 spec。
4. 复杂关系拆成总览与细节图，或多个 `.drawio` 页，保留对应 ID/术语。
5. 若诊断显示内部尺寸或路由错误，保留最小复现并修实现，不能要求用户改事实配合 bug。

自动调参是有限搜索，不能保证任何图都能无交叉排下。两轮内容修复仍无进展时停止盲试，
报告未解决的主体与原因。确需 standard 交付时披露保留的警告，不声称 showcase 已通过。

## 真实渲染复核

Excalidraw 绑定文字可能重新折行；带图标/说明的自由文字则不会自动适应后续手工改字。
draw.io 的文字、边标签位置与 Excalidraw 不完全一致。官方导出后检查：

- 每个节点、关系、说明、图标都出现；箭头方向和线型无误。
- 标签没有截断、遮盖、歧义；最终展示尺寸下能读，不能只看放大的局部。
- 区域边界没有制造错误归属，强调色对应真实重点。
- 全图疏密与阅读顺序合理；参见 [视觉审查](visual-design.md)。

`benchmarks/first-pass/` 中的历史结果仅是当时版本的证据；不能代替当前产物验收。
