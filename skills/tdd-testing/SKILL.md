# TDD 与高质量自动化测试

让每一条自动化测试都真正拦截生产缺陷，而不是凑覆盖率、测试 Mock 本身、靠 `sleep` 碰运气或留下脏状态。
**如果你没亲眼看到测试失败，就无法证明它测对了东西；违背规则的字面，就是违背规则的精神。**

## 1. 四条铁律

1. **没有先看到失败测试，绝不写对应生产代码**：新功能、缺陷修复、重构一律先红后绿。若生产代码已先写完，**彻底删除重来**——不留作参考、不边看边适配补测。唯一例外（一次性抛弃原型、生成器代码、纯静态配置）须经人类协作者明确批准。
2. **每条测试必须说得出它拦截什么生产故障**：预期值必须独立手写字面量或人工核对夹具，严禁用被测代码或其内部 helper 算预期（镜像断言）；测外部可观察行为，不写源码文本 grep、不写仅在有意改动时才响的常量/文案探测器、不替框架测它的公开机制。
3. **每条测试尽量运行真实代码，谨慎分层使用 Mock**：严禁断言 Mock 自身存在；Mock 只隔离底层慢速或外部不可控边界（网络、远端进程、外部服务），且返回完整镜像真实结构的载荷；严禁往生产类塞入仅测试调用的清理方法。
4. **没有新鲜验证证据，绝不宣称完成或通过**：最后一次改动后必须真实运行目标与项目**全量**测试命令并完整阅读输出与退出码；**严禁**弱化断言、删旧测试或加 `.skip` 掩盖失败。

## 2. 红-绿-重构门控表

上一关的退出证据未拿到，绝不进入下一关；正反代码例、卡壳应对、12 条借口反驳与 13 条红旗停手信号见 [红-绿-重构纪律与反合理化](references/tdd-cycle-and-discipline.md)。

| 阶段 | 核心动作 | 必须拿到的退出证据 | 越界红线（命中即返工） |
| --- | --- | --- | --- |
| **RED** | 为单一清晰行为写最小测试（按改动类型先选层级） | 仅刻画一个行为、清晰命名、执行真实代码 | 测试名带“和/and”、一上来先搭庞大 Mock |
| **Verify-RED** | 运行新测试并核对失败输出 | 确认为**断言失败**（非语法/导入报错），错因是目标功能缺失或原 Bug | 新测试一跑就绿、看不懂失败原因、跳过不跑 |
| **GREEN** | 编写刚好让该测试通过的最小生产代码 | 仅覆盖当前测试所需逻辑，无多余参数或预判分支 | 顺手重构别处、提前加未经测试的扩展选项 |
| **Verify-GREEN** | 跑目标文件 + **项目全量测试套件** | 新旧测试全绿、退出码 `0`、输出无报错无告警 | 只跑单文件就交差、无视全量中的红灯不汇报 |
| **REFACTOR** | 在全绿保护下消重、改名、提取 helper | 每次小步整理后复跑保持全绿，无新增未测行为 | 重构期间顺手加新功能、带红灯继续重构 |

- **缺陷修复闭环**：先写一条稳定复现原缺陷的失败测试 → `Verify-RED` 确认错因吻合 → 最小修复 → `Verify-GREEN` 确认新旧全绿。绝不在没有复现测试的情况下修 Bug。
- **全量红灯零隐瞒**：范围说明限定的是代码改动边界，从不限定验证边界。全量套件里滚过的任何失败——哪怕不是你引入的——都必须在汇报中点名列出。
- **即刻停手红旗**：一旦发现「代码先于测试落地」「新测试一跑就绿」「说不清失败原因」「打算留着旧代码作参考」「念头里冒出“只破例这一次 / 已经手工测过了 / 后补测试一样”」，立刻停止并删除未受测试保护的生产代码，按红-绿-重构重来。

## 3. 按改动类型选测试层级

先定层级再动笔，避免把数据层 Mock 成假单测，也避免为纯函数起整套服务；TS/Python 可复用骨架见 [按改动类型分层测试策略与模板](references/test-strategy-by-layer.md)。

| 改动类型 | 测试层级 | 真实组件 vs 替身 | 必测风险与边界 |
| --- | --- | --- | --- |
| 纯算法、解析、格式化、权限判定 | **L1 纯函数单测** | 100% 真实代码，零 Mock | 空值、零值、极值、非法编码、重复键 |
| 路由/IPC/CLI 入口、协议适配 | **L2 边界契约与错误分支** | 真实校验层 + 仅替掉慢速外部 I/O | 缺字段、类型错、未授权、超时/5xx、错误码 |
| SQLite/文件持久化、Schema 迁移 | **L3 临时目录真实集成测试** | 独占临时目录 + 真实 DB/FS | 首次初始化、多版升级幂等、旧数据保留、重启读回 |
| 并发锁、队列、异步取消与停机 | **L4 并发幂等与清理测试** | 真实并发原语 + `waitFor` | 竞态保护、重复投递幂等、中途取消、零句柄残留 |

## 4. 好测试两条铁律速查

编写、修改测试或引入替身前，过以下两道门控；完整代码正反例与 11 条警报信号见 [好测试设计与突变自检](references/writing-good-tests.md)。

| 原则 | 动手前门控提问 | 典型反模式（严禁） | 正确替代 |
| --- | --- | --- | --- |
| **一、说出拦截的故障** | 哪个生产 Bug 会让本测试挂？预期值是否脱离被测代码独立算出？ | 镜像断言、锁死常量/文案、grep 源码、测框架路由机制 | 表驱动手写字面量、断言依赖常量的真实行为、跑脚本测输出与退出码、只测己方边界契约 |
| **二、运行真实代码** | 真实方法有哪些副作用？替身是否镜像完整结构？是否只有测试调用？ | 断言 `*-mock`、高层 Mock 吞掉写配置副作用、局部字段 Mock、生产类放 `destroy()` | 撤掉 Mock 测真组件、Mock 下沉到慢速外部边界、补全所有文档字段、清理放测试工具 |

**收尾前必做 5 类心智突变自检**（每类突变改坏生产代码后，至少应有一条测试必然失败）：
1. 改错常量或关键参数（如重试次数、分页上限）；
2. 反转 `if` 条件或调换分支处理；
3. 删掉关键状态变更、写盘或事件副作用；
4. 直接返回空值或默认值（`null` / `[]` / `0`）；
5. 删掉空串、零值、`null`/`None`、未授权或畸形输入校验。

**写测试卡壳时的信号翻译**（把测试痛点当设计反馈，而非跳过测试的借口）：
- **不知从哪写起**：先按理想调用方式把断言写出来反推签名，仍模糊就先和人类协作者对齐契约；
- **测试写起来极复杂 / 准备夹具过长**：生产接口职责过重，先简化或拆分接口再测；
- **必须把一切都 Mock 才能跑**：模块耦合过紧，用依赖注入把慢速外部边界抽离出来。

## 5. 条件等待、严格隔离与污染排查入口

- **禁止硬编码 `sleep` 猜耗时**：异步测试一律用带超时与清晰描述的条件轮询等待（10–25ms 间隔、循环内重读最新状态）。仅验证真实时间窗口行为（防抖/节流/周期 tick）时，必须先条件等待起点事件、按已知周期等待并写注释解释 `WHY`。完整 `waitFor` 与 `waitForEvent` / `waitForEventCount` / `waitForEventMatch` 实现见 [条件等待与异步稳定性](references/condition-based-waiting.md)。
- **零污染与 5 步逆序清理**：每用例独占临时根目录，不碰 `$HOME`/主库/工作树，监听端口用 `0`，严格按「取消定时与后台任务 → 停止服务与子进程 → 关闭 DB 与文件流 → 恢复环境变量与 `cwd` → 删除临时目录」释放，保证单跑/乱序/并行结果一致。

当套件一起跑冒出脏文件或残留目录时，先清理现存产物，再用附带脚本 `scripts/find_polluter.py` 定位首个污染文件（从目标仓库根目录执行）：

```sh
python3 <S>/find_polluter.py \
  --artifact <不该出现的相对或绝对路径> \
  --cmd "node --test {file}" \
  --cwd /path/to/target-repo \
  spec/case-a.spec.mjs spec/case-b.spec.mjs
```

| 参数 / 退出码 | 含义 |
| --- | --- |
| `<S>` 与 `--cmd` | `<S>` 为本 skill 目录下 `scripts/` 绝对路径；`--cmd` 须含 `{file}` 占位符，可选 `--timeout <秒>`、`--json` |
| 退出码 `0` / `1` / `2` | `0` 全程无污染；`1` 找到**首个**污染源并早停；`2` 参数错误、超时或开始前产物已存在 |

若逐个单跑全干净（退出码 `0`）但整套合跑仍污染，按 [测试隔离、资源清理与污染排查](references/isolation-and-polluters.md) 执行固定受害者二分分组或并发共享路径排查。

## 6. 完成前验证门控红线

在说出“通过 / 已修复 / 完成 / 搞定 / 没问题”或任何暗示成功的措辞之前，或提交/提 PR/验收子代理产出之前，必须走完五步门控（完整对照表与 10 条伪完成借口反驳见 [完成前验证门控](references/verification-gate.md)）：

1. **IDENTIFY**：确定直接证明该声明的完整命令（测试、构建、类型检查、Linter 互不替代）。
2. **RUN**：在**最后一次编辑之后**新鲜、完整执行命令，绝不复用旧结果。
3. **READ**：逐字阅读完整输出，核对退出码、通过数、失败数与跳过数。
4. **VERIFY**：确认输出无歧义证实声明；补漏回归测试必须经过红-绿反证（回退修复必红、恢复必绿）。
5. **ONLY THEN**：附带真实命令与关键输出数据陈述结论；任何残留失败或未执行项必须点名披露。

| 你想作出的声明 | 必须具备的新鲜证据 | 不算证据（严禁以此交差） |
| --- | --- | --- |
| 测试通过 | 全量测试命令新鲜输出：退出码 `0`、0 失败、0 未预期跳过 | 改前跑过、“应该能过”、只跑单个文件 |
| 构建 / Lint 干净 | 对应构建或 Linter 完整命令退出码 `0` | Linter 通过推论构建成功、肉眼检查 |
| Bug 已修复 / 回归有效 | 原症状复现测试经红-绿反证后新鲜通过 | 改完代码逻辑上“看起来修了” |
| 子代理产出已完成 | 亲自核查 VCS diff 并独立复跑验证命令 | 直接转述子代理的“全部成功”汇报 |

**三条绝对禁令**：
- 禁止为凑绿灯把精确断言弱化成空洞判断（如改 `toBeTruthy()`）；
- 禁止删除失败旧用例或在未查明原因时盲目更新快照；
- 禁止给失败测试加 `.skip` / `xit` / `@unittest.skip` 绕过失败。

**遇到既有测试失败时的合规处理**：先判定是新改动引入的**真实回归**（修生产代码）还是需求明确要求的**契约变更**（确认依据后把旧测试更新为同等精确的新契约断言，并在交付中显式说明）。

## 8. 最终交付检查清单

- [ ] 新增功能与修复的缺陷均已有先失败后转绿的真实行为测试，且通过 5 类心智突变自检。
- [ ] 无镜像断言、无改动探测器、无断言 Mock 本身、无生产类测试专用清理方法。
- [ ] 所有测试严格隔离于临时目录且按序释放资源，无硬编码 `sleep` 猜耗时、无工作区残留脏文件。
- [ ] 最后一次改动后已新鲜运行受影响测试与项目全量套件，逐字核对退出码与输出并如实汇报。
