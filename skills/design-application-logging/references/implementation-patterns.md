# 落地实现模式

规范只回答"应该怎样"，本文件回答"从哪下手、常见形态长什么样"。所有模式都是语言无关的通用形态，落地到具体技术栈时保持字段契约不变。

## 从零开始的最小闭环

1. 确定日志用途与输出链路（工作流 1-3 步），选定"人读流 + 机器读流"形态；
2. 用 `assets/log-format-schema.csv` 登记公共字段；模板给出了完整字段集，落地时先确保 6 个必填公共字段（timestamp/level/event.name/message/service.name/deployment.environment）齐全，其余按需启用；
3. 定义 5-10 个关键事件进 `assets/log-event-catalog.csv`（启动、请求失败、依赖重试耗尽、认证失败、权限变更），引用字段必须在格式目录或事件字段目录有登记；
4. 配置输出（JSON 流）与滚动/保留（参考 `assets/log-storage-policy.csv`）；
5. 实现三个最小机制：入口上下文注入、统一业务事件记录、统一错误出口；
6. 写 3 条断言测试：JSON 可解析、必填字段齐全、敏感字段不出现；
7. 运行 `scripts/validate_logging_catalog.py` 通过全部校验后，才算目录完成。

## 入口上下文注入

HTTP/RPC 入口（中间件或过滤器）、消息消费者、定时任务入口统一处理：

- 接收或生成 trace/request 标识，写入日志上下文；
- 入口日志（请求开始/结束）与业务日志共用同一标识；
- 请求结束清理上下文，异步任务显式传递（协程/线程上下文传播）；
- 注入的标识随结构化输出平铺为顶层字段，随人读输出出现在固定位置（如 `[traceId]` 前缀）。

```text
入口中间件：
  生成 trace_id → 写入日志上下文 → 处理请求 → 记录 request.failed 或完成日志 → 清理上下文
```

## 统一业务事件记录

对需要观察的"业务操作"（写操作、状态变更、外部依赖调用）用统一拦截点记录，而不是在每个业务函数手写日志：

- 声明式标记操作名、模块、风险等级（注解/装饰器/配置表）；
- 统一记录：操作名、模块、结果（成功/失败）、耗时；
- 高风险操作（密码变更、凭据签发/吊销、权限变更、账户状态变更）额外投递审计通道；
- 异常透传，不在拦截点吞异常或重复打印——最终失败日志由统一错误出口输出；
- 拦截点自身失败必须可观测（如审计通道未装配时降级并告警），但不阻断业务。

好处：事件命名一致、字段一致、耗时统一统计、审计入口集中，业务代码零散日志最少化。

## 统一错误出口

所有未预期异常最终在总出口记录一次：

- 业务失败（预期）：WARN + 错误码/短码，不记堆栈，业务细节进结构化字段；
- 意外异常：ERROR + 完整堆栈（深度受限），只进日志不外泄；
- 对外响应与日志内容分离：对外错误消息复用错误码模板，不直接使用内部异常消息；
- 中间层（库、服务、切面）只补充上下文后透传，不逐层打印。

## 双流输出实现要点

- 人读流：文本格式化器输出一行式记录；生产禁用 ANSI；可带 `[模块] key=value` 前缀；
- 机器读流：结构化编码器输出 JSON/OTLP；上下文字段平铺为顶层字段；
- 两流共用同一个日志上下文和级别过滤，避免排查时两处不一致；
- 高吞吐时机器读流可走异步队列（有界队列 + 满时降级不阻塞业务线程），人读流保持同步或同队列。

## 异步输出与背压

- 日志写入通过有界队列异步化，队列满时按优先级丢弃（先丢 DEBUG/TRACE，不丢 ERROR，审计另行保证）；
- 丢弃必须计数并暴露为指标，禁止静默；
- 日志平台故障时本地缓冲有上限，达到上限丢弃并告警，不无限堆积。

## 动态调级

- 运行时级别配置化（配置中心/管理接口），支持按服务、按模块调整；
- 每次调整记审计（操作者、目标、级别、有效期）；
- 设默认回退：重启恢复、有效期到期自动恢复；
- 调低到 DEBUG 时联动采样与容量保护。

## 事件名与字段常量化

- `event.name`、`operation`、`error.code` 等集中定义为常量/枚举，代码引用常量；
- 事件目录与代码常量建立对照（测试断言目录中的事件名在代码中存在，防止目录与实现漂移）；
- 新事件先登记目录再写代码，改目录语义视为破坏性变更。

## 常见反面模式

- 每个 catch 都打印堆栈（违反单点记录）；
- 循环体内逐条 INFO（高频路径没有指标化）；
- 把用户输入直接拼进 message（日志注入）；
- 生产 DEBUG 硬编码（容量与安全风险）；
- 文本日志里塞 JSON、JSON 流里混文本（采集器解析失败）；
- 应用与平台同时轮转同一文件（重复归档或丢失）。
