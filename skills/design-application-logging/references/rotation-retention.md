## 唯一责任方

每个日志流必须只有一个明确的轮转责任方：

- 应用日志框架；
- 操作系统的日志轮转工具；
- 容器运行时或 kubelet；
- 日志 Agent 或托管平台。

不得由应用、操作系统和平台同时轮转同一活动文件，否则可能发生重复归档、句柄失效、丢失或重复采集。

## 滚动触发条件

文件日志必须至少设置一种滚动条件，并通常同时设置时间和大小条件：

- 按时间：每小时、每天、每周或明确周期；
- 按大小：活动文件达到上限；
- 组合：任一条件先满足即滚动。

必须同时设置至少一种最终容量约束：

- 最大归档文件数；
- 最大保留天数；
- 最大本地总占用。

高流量场景不得只按天滚动，否则单个活动文件可能过大。低流量场景不得只按大小滚动，否则旧数据可能长期留在活动文件中而无法归档和清理。

## 轮转方式

优先使用平台或日志框架支持的原子轮转方式：关闭/重命名活动文件并创建新文件，或使用平台原生句柄重开机制。

外部轮转工具改名活动文件时，应用必须能够通过信号、事件或定期检测重新打开文件句柄。

`copytruncate` 可能在复制与截断之间产生竞争窗口，只能在进程无法重新打开日志文件且已接受潜在数据丢失或重复风险时使用。

轮转操作必须幂等，并避免多个实例同时处理同一文件。

## 归档命名与压缩

归档文件名应包含足够的排序和唯一信息，例如：

```text
application.log.2026-08-06T09-00-00Z.001.gz
```

文件名不得包含令牌、用户姓名、订单号等敏感或高基数数据。

多实例部署时，活动文件与归档文件名应携带实例唯一标识，避免多个实例争写、争滚同一文件。

压缩要求：

- 只压缩已经关闭的归档文件；
- 不压缩当前活动文件；
- 写入方可能仍持有旧句柄时，应延迟压缩；
- 压缩失败不得删除原文件；
- 压缩算法和级别应在 CPU、存储和恢复速度之间权衡；
- 重要归档可记录校验和或完整性元数据。

## 保留与自动清理

保留策略必须按日志用途、数据分类和合规要求分别定义，禁止无限期保留。

清理策略必须：

- 定期执行；
- 可重复执行且结果一致；
- 从最旧的合格归档开始删除；
- 同时考虑年龄、文件数和总容量上限；
- 永不删除当前活动文件；
- 跳过仍在上传、压缩、查询锁定或法律保留中的文件；
- 记录清理失败并提供告警指标；
- 不把普通诊断日志策略用于审计或合规归档。

当多个条件同时存在时，任一硬性上限被突破都应触发清理，但必须遵守法律保留和最低保留要求。

## 远程归档

将集中平台或对象存储作为长期留存位置时，必须定义：

- 上传批次与重试策略；
- 上传完成的确认条件；
- 加密、访问控制与租户隔离；
- 完整性校验；
- 本地副本删除条件；
- 远程生命周期与最终销毁规则。

在远程平台作为唯一可信副本时，本地文件只能在收到明确成功确认后删除。

## 磁盘水位保护

必须为本地日志目录设置：

- 预警水位；
- 严重水位；
- 硬容量上限；
- 检查周期；
- 清理和降级顺序；
- 告警责任人。

达到高水位时，应优先：

1. 清理已超过保留期的最旧归档；
2. 清理可安全删除的低优先级诊断归档；
3. 降低 DEBUG 或采样型日志量；
4. 触发告警并暴露丢弃计数。

不得通过无限阻塞业务线程保护日志完整性。审计日志需要更高可靠性时，应使用独立存储、预留容量或同步到可靠远端，而不是与普通诊断日志争抢同一无限缓冲区。

## 容器与 Kubernetes

容器化应用通常应写 stdout/stderr，由容器运行时和节点日志系统负责文件轮转与采集。

要求：

- 应用不要再对同一 stdout/stderr 日志执行文件轮转；
- 平台必须配置单文件大小、保留文件数和节点磁盘保护；
- 工作负载日志量较大时，应调整平台的轮转并发和检查周期；
- 日志 Agent 必须处理轮转后的文件并避免重复或遗漏；
- 不应把容器本地日志文件当作长期归档。

核对具体实现时以平台文档为准，常见机制锚点（用于验证配置是否到位）：

- 容器运行时的容器日志文件轮转参数（如 containerd 的 max_size/max_file、
  旧 Docker 的 json-file log-opt）；
- 节点 kubelet 的容器日志文件轮转与容量参数（kubelet config 中的
  containerLogMaxSize / containerLogMaxFiles）；
- 节点日志目录（如 /var/log/pods）下的容器日志软链接与元数据布局；
- 采集器（如 Fluent Bit / Filebeat / Promtail）的 multiline 解析、JSON
  parse 失败处理与轮转跟踪。

Serverless 环境没有本地文件轮转概念，滚动、保留与清理全部由平台负责，
详见 [format-output.md](format-output.md) 的 Serverless 环境章节。

## 监控与告警

至少监控：

- 活动日志文件大小；
- 本地日志目录总占用；
- 归档文件数量与最老文件年龄；
- 轮转成功与失败次数；
- 压缩成功与失败次数；
- 清理成功、失败和删除字节数；
- 上传积压与失败；
- 因限频、缓冲溢出或磁盘保护而丢弃的日志数。

## 验证要求

至少测试：

- 达到大小阈值时滚动；
- 到达时间边界时滚动；
- 滚动后继续写入新活动文件；
- 归档关闭后才压缩；
- 超过文件数、年龄或容量上限时删除最旧合格归档；
- 当前活动文件和法律保留文件不会被删除；
- 压缩或上传失败时原文件仍可恢复；
- 并发轮转不会重复处理；
- 磁盘高水位触发告警和有界降级；
- 日志平台恢复后缓冲能够有界排空。
