# 异步任务、消息与批处理失败

## 任务与消息消费者

每个任务或消费者必须明确：

- 确认时点；
- 处理或可见性超时；
- 可重试错误集合；
- 最大投递次数；
- 幂等策略；
- 死信目标；
- 人工恢复路径；
- 链路与关联上下文传播。

永久性业务失败不得无限重新投递。

## 重试耗尽

重试耗尽后至少保留：

- 消息或任务标识；
- 首次和最后失败时间；
- 尝试次数；
- 最终归一化原因；
- 安全诊断上下文；
- 后续处理状态。

失败必须进入死信队列、失败表或明确的人工处理流程，不得静默丢弃。

## 幂等消费

消费者应使用业务唯一键、去重记录、条件写入、版本控制或 inbox 模式防止重复副作用。

消息确认必须与业务提交语义一致。业务状态未可靠提交前，不得提前确认；已成功提交后应避免因确认失败重复执行副作用。

## 批处理

必须明确批次是原子提交还是允许部分成功。

允许部分成功时，应返回或持久化：

- 成功项；
- 失败项；
- 可重试项；
- 不可重试项；
- 补偿或对账状态。

禁止把混合结果压缩为无法定位的笼统失败。
