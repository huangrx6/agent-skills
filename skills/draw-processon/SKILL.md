# ProcessOn 统一路由器

这是 ProcessOn 的唯一入口。先进行路由，然后仅加载所选分支所需的参考文件。

## 路由优先级

1. 尊重明确请求的图表类型。
2. 技术/系统关系、运行时交互、业务流程、模式、架构、依赖、部署拓扑或重绘任务 → **DIAGRAM**。
3. 文档/附件/网页/长文本加上总结、提取、组织或“将其转换为思维导图” → **DOCUMENT_MINDMAP**。
4. 层次化知识组织、头脑风暴、学习结构、大纲、任务分解、根因分析、分类法或通用思维导图请求 → **MINDMAP**。
5. 如果用户只说“画个图 / visualize this”且关系类型仍然真正模糊，则询问一个关于所需类型的简洁问题。

默认情况下不要加载所有分支。

## 路由：DIAGRAM

适用于：

- 流程图 / 业务流程 / 泳道图
- 时序图 / 运行时调用流程
- 系统、软件、服务、云或部署架构
- ER / 数据库关系图
- 组件/服务依赖
- 数据/控制/状态流
- 以关系为导向的组织结构图
- 时间线、路线图、信息图、金字塔图
- 草图/图像重绘为可编辑的结构化图表

阅读 `references/diagram.md`，然后按照其中的说明操作。

## 路由：DOCUMENT_MINDMAP

当输入是文件、附件、网页、图像文本、会议记录、报告、论文、书籍章节、长 Markdown 或长篇散文，且目标是将其总结或组织成思维导图时使用。

阅读 `references/document-mindmap.md`，然后阅读 `references/mindmap.md`。

## 路由：MINDMAP

适用于：

- 思维导图 / 知识图谱
- 头脑风暴
- 项目/任务分解
- 学习或学习路径
- 大纲 / 框架
- 根因 / 鱼骨图分析
- 层次结构 / 分类法 / 树状图
- 无需源文档预处理的结构化总结

阅读 `references/mindmap.md`，然后按照其中的说明操作。

## 通用规则

- 除非另有要求，否则使用用户的语言生成内容。
- 不要捏造仓库事实。如果图表依赖于代码/项目结构，请先检查仓库。
- 对于架构请求，建模关系、边界、依赖、调用路径和数据流；不要将文件夹树变成架构图。
- 如果返回了 ProcessOn URL，请在最终响应中保留原始的预览/编辑 URL。
- 不要暴露认证令牌或本地令牌文件。
- 如果当前代理处于计划/审批门控工作流中，请尊重该工作流。ProcessOn 云文档是外部副作用，除非用户的任务本身就是明确创建图表。
