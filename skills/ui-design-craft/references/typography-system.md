# 排版系统与文字排印规范

排版同时承担信息结构、阅读节奏与产品声部。优化既有界面时，在既定视觉世界内精进字族用法；除非用户明确要求重塑品牌，否则不私自替换已确立的字体体系。

---

## 一、先按访问模式定排版策略

- **Operate + Read**：稳定性、扫描效率与舒适行宽排在第一位。通常**单一调校精良的字族 + 固定角色尺度**就是最优解；等宽字体仅留给代码、参数与精确数值，不让字号随视口剧烈漂移破坏空间记忆。
- **Persuade + Experience**：展示标题可以承担鲜明声部，善用明确的字号/字重对比与 `clamp()` 响应尺度，把文字排布本身当作主动的视觉构图元素。

动手调整前，先写明 5 项决策：界面需要哪些语义角色、相邻角色的对比靠什么拉开、正文行宽与信息密度目标、哪些已有字族/字重必须保留、以及本地化/缩放/性能约束。

---

## 二、字族节制与角色尺度体系

### 1. 字族数量与角色分工

- **1–2 个文本字族封顶**：单族靠字重、字号、字距与色彩即可建立极强秩序；若引入第二族（如展示衬线 + 正文无衬线），两者必须气质泾渭分明且各自拥有不可替代的职责。
- **语义化 Token 命名**：按用途命名（`--text-display`、`--text-title`、`--text-body`、`--text-label`、`--text-caption`、`--text-mono`），不按像素值堆砌零散变量。
- **多维度拉开层级**：不要只靠“大 2px”区分角色——联合字号、字重、颜色深度（主/次/弱）与上下留白，让人不读内容也能一眼分出主标题、副标题、正文与元数据。

### 2. 基准尺度与安全红线

| 角色 | Web 建议尺度 | 行高（无单位） | 字距（Letter-spacing） | 关键约束 |
| --- | --- | --- | --- | --- |
| **展示标题（Display）** | `2.25rem–6rem`（上限 `6rem`） | `1.05–1.18` | `-0.02em` ~ `-0.03em`（底线 `-0.04em`） | `text-wrap: balance`；禁用单字变色/斜体噱头 |
| **区块标题（Heading）** | `1.25rem–1.875rem` | `1.2–1.35` | `-0.01em` ~ `-0.02em` | 上方留白必须大于下方留白 |
| **正文（Body）** | **底线 `1rem / 16px`** | `1.5–1.65`（衬线略高，中文 `1.6–1.75`） | `0`（中文不随意拉负字距） | 移动端输入框 `<16px` 会触发 iOS Safari 强制放大 |
| **密集界面 / 辅助文案** | `0.8125rem–0.875rem`（13–14px） | `1.4–1.5` | `0` ~ `0.01em` | 仅用于确认合理的次级信息与高频工作台表格 |
| **元数据 / 数值（Mono）** | `0.75rem–0.875rem` | `1.35–1.45` | `0` | 必设 `font-variant-numeric: tabular-nums` |

> 反模式警示：禁止标题内给单个词套斜体/强调色、禁止把普通界面标签全写成 `ALL CAPS`、禁止在标题上方塞无意义眉标。

## 三、行宽、段落节奏与暗底亮字三轴补偿

### 1. 行宽（Measure）与行高联动

- **舒适行宽：`45–75ch`**（长篇阅读与文档推荐 `60–75ch`，中文约 28–42 个汉字）。过长导致扫行回行迷路，过短导致视线频繁折返破碎。
- **行高随行宽微调**：同一字族下，行宽越宽，行高应相应增加；衬线体行高通常略大于无衬线体。
- **段落边界只标记一次**：使用**段间距（`margin-block-end`）**或**首行缩进（`text-indent`）**二选一；两者同时使用属于双重冗余标记（Web 界面默认采用段间距）。

### 2. 暗底亮字三轴补偿

由于人眼的光渗效应（Halation），白色或浅色文字在深色背景上会显得比浅色背景上更粗、更挤、更刺眼。在暗色主题中应对浅色正文执行**三轴同步补偿**：

```css
/* 亮色默认 */
.prose {
  max-width: 66ch;
  font-size: 1rem;
  font-weight: 400;
  line-height: 1.6;
  letter-spacing: 0;
  color: var(--ink-primary);
}

/* 暗底亮字：1) 微增行高 2) 微松字距 3) 视字族微调字重/微降纯白亮度 */
[data-theme="dark"] .prose {
  line-height: 1.68;
  letter-spacing: 0.01em;
  /* 若字族提供可变字重，可降半档抗光渗；或当极细字在暗底发虚时升一档 */
  font-weight: 420;
  /* 避免 #FFFFFF 刺眼眩光，采用柔和高对比浅色（确保仍 ≥ 4.5:1） */
  color: oklch(0.92 0.008 255);
}
```

## 四、断行控制与防寡字

现代 CSS 断行属性具备天然渐进增强特性（不支持的浏览器静默回退默认断行）：

```css
h1, h2, h3, .hero-subtitle, .centered-callout {
  text-wrap: balance; /* 标题与短居中块：均衡各行宽度，杜绝末行孤词 */
}

p, li, dd, .description {
  text-wrap: pretty;  /* 正文段落：温和避免末行落单孤词，允许两词收尾 */
}
```

- **窄栏不靠断行硬救**：当容器过窄以致 `balance`/`pretty` 失效时，应精简文案或放宽栏宽。
- **谨慎手写 `<br>`**：仅在完整短语边界处手动换行，且必须在移动端到桌面端全断点验证；手机端落在行中的硬换行比默认换行糟糕得多。
- **有意为之的视觉断行**：海报主标或引文若刻意让末尾落在一个强力单词上，应显式用可控断行声明并保持极低频次。

## 五、光学对齐与 `text-box` 精准居中

字体在行框内天生携带上下行距留白与基线不对称（大写字母顶部与基线之间才是视觉重心，而非含降部的完整 em 框），常导致按钮文字或徽章看起来偏上或偏下。

### 1. `text-box: trim-both cap alphabetic` 的正确用法

- **常见踩坑**：直接把 `text-box` 写在 `display: inline-flex` 的 `<button>` 上会**失效**，因为按钮里的文本节点是匿名 Flex 子项，裁剪无法穿透到文本。
- **正确写法**：用内部 `<span>` 包裹文案并设为 `display: block`，再对 `<span>` 施加 `text-box`：

```html
<button class="btn">
  <svg aria-hidden="true" width="16" height="16">...</svg>
  <span class="btn-label">保存更改</span>
</button>
```

```css
.btn {
  display: inline-flex;
  align-items: center;
  gap: 0.5rem;
  padding-inline: 1rem;
  min-height: 2.5rem;
}

.btn-label {
  display: block;
  text-box: trim-both cap alphabetic;
}
```

### 2. 回退字体度量对齐与目视复核

- 使用 `text-box` 裁剪时，回退字体的 `@font-face` 应按「Web 字体 cap-height ÷ 回退字体 cap-height」计算 `size-adjust`（`ascent-override`/`descent-override`/`line-gap-override` 只影响被 trim 掉的区域）。
- **最后一定肉眼复核**：全大写居中不等于混合大小写居中——英文混合大小写的主体落在 `x-height` 内，视觉中心低于 `cap-height` 中心，裁剪后在部分字号下仍可能略显偏低，须在每个实际发货尺寸上目检微调。

## 六、标点、数值与微排印细节

直接决定界面“精致感”与扫描准确度的高频细节（全站统一执行）：

| 项目 | 反例（禁止） | 正例（规范） | 原因 |
| --- | --- | --- | --- |
| **省略号** | `加载中...` / `Loading...` | `加载中…` / `Loading…` | 使用单字符真省略号 `U+2026`，加载态文案统一以 `…` 结尾 |
| **引号** | `"已完成"` | `“已完成”` / `「已完成」` | 界面展示文案使用弯引号或规范中文引号，代码框内除外 |
| **不换行空格** | `10 MB`、`⌘ K`（换行折断） | `10&nbsp;MB`、`⌘&nbsp;K` | 防止数值与单位、快捷键修饰符与键名、品牌词组被拆成两行 |
| **动态/表格数值** | 默认比例数字（倒计时/金额左右跳） | `font-variant-numeric: tabular-nums;` | 数字等宽对齐，表格小数点垂直成列、实时跳数不晃眼 |
| **小数与货币** | 手拼 `$` + `toFixed(2)` | `Intl.NumberFormat` | 自动适配千分位、小数分隔符与货币符号位置 |

## 七、字体加载、防闪烁与无障碍缩放

1. **按需加载与子集化**：只加载界面真实用到的字重（通常 2–3 档足够），利用 `unicode-range` 拆分拉丁/扩展字符集，避免一次性拖下数 MB 全量字体。
2. **关键字体预加载与防隐形文字（FOIT）**：

```html
<link rel="preconnect" href="https://fonts.example.com" crossorigin>
<link rel="preload" href="/fonts/ui-sans-var.woff2" as="font" type="font/woff2" crossorigin>
```

```css
@font-face {
  font-family: "ProductSans";
  src: url("/fonts/ui-sans-var.woff2") format("woff2");
  font-weight: 400 700;
  font-display: swap; /* 立即显示度量对齐的回退字体，避免白屏隐字 */
}
```

3. **保留用户缩放权**：字号与行高优先使用 `rem` / 无单位数值，禁止锁死根 `html { font-size: 10px }` 覆盖用户浏览器默认字号设置；在浏览器缩放至 `200%` 及系统放大字体下验证不重叠、不截断、不丢失功能。

## 八、排版验收自查表

- [ ] 不看文字内容，仅凭字号、字重、颜色与留白就能分辨主标题、副标题、正文与元数据。
- [ ] 正文行宽稳定在 `45–75ch`，移动端输入框字体 ≥ `16px`。
- [ ] 暗色模式下浅色正文完成了行高、字距、字重/亮度的三轴微调，无刺眼眩光。
- [ ] 标题已启用 `text-wrap: balance`，正文启用 `text-wrap: pretty`，数字列启用 `tabular-nums`。
- [ ] 字体加载无明显布局跳动（CLS），200% 缩放与超长本地化文案下结构不塌陷。
