# 文案清晰度、去噪精简、引导与分寸微愉悦

界面的文字、信息密度、首次引导、局部强弱与微交互共同决定“好用还是累人”。本规范覆盖 6 类高频内容与体验打磨动作：**清晰化（Clarify）、做减法（Distill）、首值引导（Onboard）、局部放大（Bolder）、降噪克制（Quieter）与有分寸的微愉悦（Delight）**。

---

## 一、界面文案清晰度（Clarify）

文字在界面里只有一个工作：**让用户立刻明白发生了什么、哪件事要紧、下一步怎么做**。绝不把文案当排版填充物。

### 1. 每处状态先定 4 层信息顺序

1. **此刻最需要的一个事实**；
2. **下一步可执行动作**；
3. **确实会改变决策的补充上下文**；
4. **匹配当下风险与情绪的语气**。

> 铁律：**同一件事只说一遍**。如果标题已经说明状态，下方副文案必须补充新信息（影响、后果或办法），否则直接删掉。

### 2. 按界面部位精准改写

| 场景 | 写作准则 | 反例 | 正例 |
| --- | --- | --- | --- |
| **按钮与导航** | 主动语态 + 具体「动词 + 宾语」；全链路词汇一致（按钮叫“发布”，成功提示就叫“已发布”）；数字用阿拉伯数字 | “提交”、“继续”、“确定”、“八个项目” | “保存 API 密钥”、“发布工作流”、“8 个项目” |
| **高危/破坏性操作** | 优先提供「撤销（Undo）」而非弹窗拦截；必须确认时，标题与按钮均写明对象和后果，禁用“是 / 否 / OK” | “确定要执行此操作吗？[取消] [确定]” | “永久删除「生产环境」密钥？相关集成将立即失效。[保留密钥] [删除密钥]” |
| **表单与校验** | 标签永久可见；占位符只放格式示例且以 `…` 结尾；格式规则提前说清；校验指出具体修改法且不责怪用户 | 占位符当标签；报错“输入无效” | 标签“工作邮箱”，占位 `name@company.com…`；报错“邮箱缺少 @ 符号，请补充完整地址” |
| **错误与权限** | 三要素：**失败了什么 + 已知原因 + 恢复/替代路径**；不拿内部错误码当主文案；不空口道歉、严肃场景（扣费/删数/隐私/阻断）绝不开玩笑 | “哎呀出错了 (ERR_502)，请稍后重试 😅” | “无法保存更改：网络连接已中断。你的草稿已保留在本地，联网后点击「重新保存」。” |
| **加载与成功** | 加载态说明真实动作并以 `…` 结尾；有真实进度才展示确定进度，绝不伪造进度条；常规成功简短确认即可 | “请稍候...” | “正在校验扩展清单…” / “已保存” |
| **帮助与链接** | 辅助文案回答用户隐含疑问而不复述控件名；链接脱离上下文仍能看懂（禁“点击这里”）；纯图标控件必配无障碍名 | “点击这里了解更多” | “查看密钥轮换策略” |

### 3. 声调、术语与可翻译性

- **第二人称、说人话**：按用户心智命名（“通知设置”而非“Webhook 配置”），不过度把专业受众真正懂的领域术语强行幼稚化；同一概念全产品只用一个词，不为文学修辞换同义词。
- **可本地化整句**：不要用代码拼接半截句子（不同语序无法翻译），变量按占位参数结构化传入，并预留 30–40% 翻译膨胀空间。

## 二、删繁就简与渐进披露（Distill）

极简不是阉割功能，而是**清除用户与目标之间的一切障碍**，让留下的每个像素都有存在理由。

### 六维去噪清单

1. **信息架构**：每屏只保留**一个主目标与一个主动作**、1–2 个次级动作，其余收进菜单或渐进披露（折叠、分步、按需面板）；删除在别处已重复说明的信息。
2. **视觉降噪**：收敛到 1–2 个品牌色 + 中性色 + 语义色；收敛到 1 个字族、3–4 档字号、2–3 档字重；拆除不承担层级职责的边框、阴影与装饰底色；拍平嵌套，绝不卡片套卡片。
3. **布局简化**：能用清晰纵向流表达就不硬切复杂多栏；去掉低频侧边栏；对齐轴统一（左对齐或居中择一坚持）；用留白代替分割线。
4. **交互减选**：减少同屏并列选项（遵循工作记忆 ≤ 4 项原则）；提供智能默认值；能行内编辑就不弹模态框；砍掉多余确认步骤。
5. **文案削冗余**：删去营销废话、铺垫客套和复述标题的导语。
6. **代码瘦身**：清除死样式、废弃组件与多余变体（如果 3 个变体能覆盖 90% 场景，就不要维护 12 个变体）。

> 红线边界：简化不得删掉决策必需信息，不得牺牲标签与 ARIA 可访问性，更不能简到让用户“猜谜”。

## 三、空态与首次价值引导（Onboard）

引导的职责不是教完整个产品，而是**以最短路径把用户带到证明产品价值的“Aha 时刻”**。

### 1. 五项引导铁律

- **展示而非说教**：用真实可交互样例和预置模板代替纯文字说教，不做脱离真实产品的封闭教程模式。
- **永远可跳过**：老手可直接点击“跳过 / 自行探索”，绝不锁死界面强迫看完长导览。
- **情境优先于仪式感**：在用户真正遇到某功能的那一刻再给轻量提示或引导气泡，而不是首登弹窗连环轰炸。
- **漫游克制**：确需分步导览时，严格控制在 **3–7 步**、围绕任务流（“创建首个工作区”而非“这是创建按钮”）、支持随时跳过且可在帮助菜单重播。
- **按账号与版本隔离已读状态**：防止共用浏览器下串号隐藏引导。

```js
// ✅ 按账号 ID 与引导版本做命名空间隔离，尊重用户关闭决定
const key = `onboarding-completed:v1:${userId}`;
localStorage.setItem(key, "true");
```

### 2. 五类空态精准区分（禁止千篇一律“暂无数据”）

| 空态类型 | 必备要素 | 示例写法 |
| --- | --- | --- |
| **1. 首次使用（First Use）** | **完整 5 要素**：①这里将出现什么 ②为何有价值 ③主 CTA / 模板入口 ④克制视觉锚点 ⑤轻量情境帮助 | 标题：“还没有项目”<br>说明：“项目用于隔离工作区配置与成员权限。”<br>操作：`[新建第一个项目]` `[从模板导入]` |
| **2. 用户主动清空** | 轻盈简洁，易于重新创建，不长篇说教 | “收件箱已清空。需要时随时按 `C` 新建任务。” |
| **3. 搜索/筛选无结果** | 明确点出当前关键词/筛选条件，提供一键重置或建议放宽条件 | “未找到匹配“权限”且状态为“已归档”的记录。” `[清除全部筛选]` |
| **4. 无权限访问** | 诚实说明受限原因，告知谁能授权或如何申请 | “仅工作区管理员可查看计费凭据。可联系团队管理员申请权限。” |
| **5. 加载失败空态** | 说明加载失败原因（如网络中断），提供直接重试按钮 | “项目列表加载失败，服务暂时不可达。” `[重新加载]` |

## 四、局部放大（Bolder）与降噪克制（Quieter）

既有页面出现“显得平淡”或“过于喧闹”时，均须在**现有设计系统内部**完成调节，不引入第二套风格。

### 1. 局部放大（Bolder）：作用域至上

- **严守边界**：只动指定区块，不动相邻模块，**不未经确认私自新增色值、字族、圆角或阴影原语**。
- **先诊断为何显得平**：平淡往往不是缺特效，而是该区块偷偷放弃了系统已有的最强手段（主标题尺度、结构化视觉母题、节奏留白）。把已有系统语言拉到满格，比叠加新特效更有力量。
- **承诺一处，静音其余**：决定一个核心视觉动作并彻底做透，同时弱化周围配角；如果所有元素一起变大变响，整体反而更平。
- **骨架测试（Skeleton Test）**：把文字全部抽空，只看线框与结构设备——如果离开大字就看不出这个区块的重要性，说明只是字大，不是设计强。

### 2. 降噪克制（Quieter）：有主见的安静

安静不等于“全灰白 + 均匀字重 + 相同卡片”的平庸。按 5 个旋钮精细降温，保留产品观点：

- **色彩**：高饱和色回调至 70%–85% 饱和度，扩大微染中性色占比，只在关键焦点留高对比；有色底面次级字仍用同色系深/浅派生，不改通用灰。
- **字重与尺度**：重字重降档（`900 → 600`、`700 → 500`），缩小极端字号跳变，更多靠留白和位置而非粗黑强调。
- **表面与线条**：删装饰性渐变、多重阴影、多余模糊；细边框降对比或改用间距分隔。
- **动效**：缩短位移距离（`40px → 10–20px`），改用平滑 `ease-out-quart`，删掉纯装饰动效与任何弹跳曲线。
- **对齐归位**：把游离元素收回到统一网格与空间节拍上。

## 五、有分寸的微愉悦（Delight）

微愉悦不是廉价彩纸和卖萌表情，而是**在值得的时刻，通过有用的交互、有人情味的反馈或考究的物理细节流露出产品性格**。

### 1. 先写一句话 Delight 命题

动手前写清：“在这一刻，用户应感受到什么？为什么这种感觉只属于本产品？”再选取最小实现系统：一次有辨识度的状态确认、贴合语境的精准文案、有材料质感的转场，或让老用户会心一笑的实用彩蛋。

### 2. 按情绪时刻施力与 6 条红线

- **按份量配比**：重大里程碑（首次发布、清零任务）可稍作展开；日常高频保存只需干脆利落的确定感——**必须经得起第 100 次使用而不令人厌烦**。
- **六条硬保护**：
  1. 绝不延迟、阻塞或遮挡主任务；
  2. 绝不为了秀动效人为拖慢完成速度或伪造等待进度；
  3. 绝不未经许可自动发声或无视静音设置；
  4. 绝不做成强制不可跳过的过场；
  5. 绝不破坏无障碍、键盘导航与 `prefers-reduced-motion`；
  6. 绝不为了一个局部点缀引入不成比例的第三方库体积。
