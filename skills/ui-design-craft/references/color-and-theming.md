# 色彩系统、语义 Token 与主题编排

色彩承担四项职责：**确立层次、传达语义、界定空间边界、塑造氛围**。在既有系统中做色彩优化时，必须尊重已确认的品牌色与领域语义；若需要全面更换品牌身份，应走完整视觉方向设定流程，而不借“加点颜色”偷换视觉世界。

---

## 一、按访问模式定色彩剂量

- **Persuade / Experience**：色彩可以大面积主导画面情绪与记忆点（如整幅着色画布、鲜明对比色块），剂量由品牌气质与视觉命题决定，不套死板的机械百分比。
- **Operate / Read**：色彩主要编码**主动作、选中态、语义状态、寻路与层级**。强调色的稀缺性决定了它的抓眼力度——如果全屏到处都是主强调色，真正的主按钮就会消失在噪音里；同时，工作台壳层（微染画布、带底色侧轨、数据系列）也要有明确的色彩秩序，避免退化为毫无生气的默认灰框。

---

## 二、角色化 Token 架构（拒绝零散色卡）

不要直接往组件里写十六进制硬编码色值，始终分两层管理：**原始色阶（Primitives）**与**语义角色（Semantics）**。切换明暗或品牌主题时，只需重映射语义层，业务组件样式零改动。

### 六类必备语义角色

1. **画布与表面（Surfaces）**：页面底色、内容容器面、抬升浮层（弹层/下拉）、嵌入式凹槽面（输入框/代码块）。
2. **文字层级（Ink / Text）**：主文本、次级说明文本、弱提示/占位符、反色文本（落在主按钮/深底色上的文字）。
3. **动作与焦点（Interactive）**：主动作填充与悬停/按压态、次级按钮面、选中高亮底色、焦点环。
4. **边界与分隔（Borders）**：默认细边框、悬停/激活强化边框、结构细分割线。
5. **语义状态（Status）**：成功（Success）、警告（Warning）、错误/危险（Danger）、信息（Info）——每组均包含**文字/图标色 + 极淡底色 + 可选细边色**。
6. **数据可视化（Data Series）**：彼此在明度、色相与彩度上清晰可辨的分类色板或连续色带。

### OKLCH 工程范本（双主题完整语义映射）

新建 Web 色板优先采用 `oklch(L C H)`：感知明度 `L` 与彩度 `C` 解耦，可精确控制对比度与同明度不同色相的视觉均衡。**关键细节：在接近纯白（`L > 0.92`）或接近纯黑（`L < 0.2`）时主动降低彩度 `C`**，防止高光刺眼或暗部发浑发脏。

```css
:root {
  color-scheme: light;
  /* 1. 微染中性表面（仅微弱带入品牌色相 255，保持冷静凝聚） */
  --bg-canvas:   oklch(0.985 0.004 255);
  --bg-surface:  oklch(1.000 0.000 0);
  --bg-subtle:   oklch(0.955 0.008 255);
  --bg-elevated: oklch(1.000 0.000 0);

  /* 2. 文字层级（主 ≥ 12:1，次 ≥ 5.5:1，弱/占位 ≥ 4.5:1） */
  --ink-primary:   oklch(0.20 0.015 255);
  --ink-secondary: oklch(0.42 0.014 255);
  --ink-muted:     oklch(0.51 0.012 255);

  /* 3. 主动作与边界 */
  --accent-solid:  oklch(0.52 0.19 255);
  --accent-hover:  oklch(0.46 0.20 255);
  --accent-soft:   oklch(0.93 0.04 255);
  --accent-ink:    oklch(0.99 0.005 255);
  --border-subtle: oklch(0.89 0.010 255);
  --border-strong: oklch(0.76 0.015 255);

  /* 4. 语义状态（高对比文字 + 同色系浅底 + 同色系浅边） */
  --status-danger-ink: oklch(0.48 0.20 25);
  --status-danger-bg:  oklch(0.96 0.03 25);
  --status-danger-bd:  oklch(0.84 0.08 25);
}

[data-theme="dark"] {
  color-scheme: dark;
  /* 暗色模式不是机械反色：画布偏深灰蓝，抬升表面逐级变亮 */
  --bg-canvas:   oklch(0.16 0.012 255);
  --bg-surface:  oklch(0.20 0.014 255);
  --bg-subtle:   oklch(0.24 0.015 255);
  --bg-elevated: oklch(0.27 0.016 255);

  /* 暗底浅字略降纯白亮度抗眩光，同时确保对比度富裕 */
  --ink-primary:   oklch(0.93 0.008 255);
  --ink-secondary: oklch(0.76 0.012 255);
  --ink-muted:     oklch(0.67 0.012 255);

  /* 暗色下主强调色提高明度、略收彩度，避免荧光炸眼 */
  --accent-solid:  oklch(0.68 0.16 255);
  --accent-hover:  oklch(0.74 0.15 255);
  --accent-soft:   oklch(0.29 0.06 255);
  --accent-ink:    oklch(0.15 0.015 255);
  --border-subtle: oklch(0.30 0.015 255);
  --border-strong: oklch(0.44 0.018 255);

  --status-danger-ink: oklch(0.80 0.14 25);
  --status-danger-bg:  oklch(0.25 0.06 25);
  --status-danger-bd:  oklch(0.40 0.11 25);
}
```

## 三、有色底面与中性色使用纪律

### 1. 有色底面上绝不使用中性灰文字

当文字落在品牌色块、语义提示条或着色侧栏上时，使用纯灰（如 `#737373`）或低透明黑会显得发脏发灰，且透明度会让对比度随底层色变化而失控。**必须从该底面色相或前景色派生显式实色**：

```css
/* ❌ 反例：有色底面放中性灰次级文字 */
.banner-info {
  background: oklch(0.93 0.04 240);
  color: #111827;
}
.banner-info .meta {
  color: #6b7280; /* 灰暗浑浊，与蓝色底脱节 */
}

/* ✅ 正例：从底面色相派生高对比深蓝次级文字 */
.banner-info {
  background: oklch(0.93 0.04 240);
  color: oklch(0.24 0.06 240);
}
.banner-info .meta {
  color: oklch(0.38 0.07 240); /* 同色相通透且对比度 ≥ 6:1 */
}
```

### 2. 中性色微染原则与透明叠加慎用

- 仅当品牌色相确实能增强整体凝聚力时，给中性灰加入极轻微彩度（`C = 0.004–0.016`）；当视觉世界本身需要冷静无色中性灰时，纯中性灰完全合法。
- **优先显式实色，少用多层 `rgba()`/`oklch(... / alpha)` 叠加**：多层半透明叠在一起会导致对比度高度依赖背景内容，难以在双主题下稳定保证 WCAG 合规。

### 3. 主强调色集中火力

让最强的主强调色专注服务于**唯一主操作、当前选中项与关键引导**；不要把它稀释在装饰图标、无关徽章、边框与渐变背景上。

## 四、暗色主题独立编排清单

暗色主题不是把亮色主题的 `L` 用 `1 - L` 机械翻转，必须单独设计以下 5 点：

1. **表面高度靠明度阶跃表达**：亮色模式靠柔和阴影区分弹层高度，暗色模式阴影几乎不可见，必须让**越靠近用户的浮层表面越亮**（画布 < 卡片面 < 悬浮菜单/弹窗），配合克制的浅色细边框（1px）勾勒边缘。
2. **避免纯黑与纯白硬撞**：纯黑 `#000` 配纯白 `#FFF` 在 OLED 与暗室下容易产生光渗重影；画布优先深炭/微染暗灰（`L = 0.14–0.18`），主文字优先柔白（`L = 0.90–0.94`）。
3. **强调色降彩提亮**：亮色下稳重的深蓝/深红在暗底上会沉没发闷，暗色下需提高明度并略降彩度，确保按钮底色与文字对比度双双达标。
4. **原生控件与浏览器壳层同步**：在 `<html>` 设 `color-scheme: dark`，同步 `<meta name="theme-color">`，为原生 `<select>` 和 `<option>` 显式指定 `background-color` 与 `color`（修复 Windows 下拉列表白底白字故障）。
5. **图片与插画暗化保护**：大面积纯白底色的图表或截图在暗色页中像探照灯，必要时提供暗色版本或给亮图加微弱边缘框/柔和暗化。

## 五、对比度底线与色觉无障碍

### 1. WCAG AA 最低对比度（必须实测计算值，不可靠肉眼猜）

| 元素类型 | WCAG AA 最低值 | 说明与延伸核查 |
| --- | --- | --- |
| **常规正文与表单占位符** | **`4.5:1`** | 含默认态、悬停态、只读态、错误提示与压图文字（压图须配局部 scrim 暗/亮衬底） |
| **大号文本** | **`3.0:1`** | ≥ 18pt（24px）常规字重，或 ≥ 14pt（18.67px）粗体 |
| **UI 控件边界、关键图标、焦点环** | **`3.0:1`** | 输入框描边、复选框边界、开关轨道、图标按钮图形、`:focus-visible` 焦点环 |
| **交互态对比度递进** | **高于静息态** | `hover`、`active`、`focus` 状态必须比静息态更具对比度或清晰视觉反馈 |

### 2. 绝不单靠颜色传递信息

模拟常见红绿色弱（Deuteranopia / Protanopia）与蓝黄色弱（Tritanopia）核验：
- **状态提示**：错误/警告/成功除颜色外，必须同时携带**明确文字或独立形状图标**（如叉号圆、感叹三角、对勾圆）；
- **表单校验**：报错不能只把边框变红，必须显示错误文案与图标；
- **数据图表**：不同数据系列除了色相，还要在**明度阶梯、线型（实/虚/点）、标记形状（圆/方/三角）或直接数据标签**上形成双重区分；
- **行业语义尊重**：遵从领域与地区惯例（例如东亚金融“红涨绿跌”与欧美相反），不武断硬编码固定色相语义。
