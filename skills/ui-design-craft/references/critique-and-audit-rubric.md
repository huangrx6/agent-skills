# 设计批评（Critique）、5 维审计（Audit）与上线基线量表

本规范整合两套互补的深度评估体系，以及一套上线工程基线核查表：
- **技术质量审计（Audit）**：面向代码与可测实现缺陷，按 **5 维度 20 分**打分，只诊断不擅自改码；
- **设计总监级批评（Critique）**：面向设计特异度、认知负荷、可用性与用户角色体验，按 **尼尔森 10 项启发式（满分 40 分，支持模式折算）** 打分并输出整改路线；
- **上线基线核查（Foundations）**：上线前 16 项工程与产品基线逐项验收。

---

## 一、独立双视角原则（防锚定铁律）

做深度评审或审计时，必须严格分离**设计体验判断（视角 A）**与**机械/代码扫描证据（视角 B）**：

1. **先做视角 A（纯设计与体验判断）**：阅读源码、观察真实渲染视图与多断点页面，在看到任何自动化告警之前，独立完成设计特异度、层级、认知负荷、启发式评分与角色走查——避免机械报错锚定你的审美直觉。
2. **再做视角 B（代码/浏览器实测核验）**：逐项核查对比度计算值、语义标签、Token 覆盖、焦点环、响应式断点、触控/手势与控制台报错。桌面端应用（Electron / WebView2 等）若接入本地调试端口，须保持窗口可见（最小化窗口会跳过像素对比度测算），并在检后将窗口还原。
3. **综合交叉比对**：合并报告时明确指出「双方共识」「视角 B 抓出而视角 A 漏掉的客观缺陷」「视角 B 中的误报」，禁止简单拼接两段清单。若因环境限制只能在单上下文顺序完成，须在报告首行显式声明降级方式与未测项（如真机手势未测）。

## 二、5 维 20 分技术质量审计量表（Audit）

按以下 5 维度逐项核查并打分（每维 `0–4` 分，总分 `20` 分）：

### 1. 无障碍（Accessibility，0–4）
- **核查点**：正文/占位符对比度 ≥ `4.5:1`、大字/控件/焦点环 ≥ `3:1`；`prefers-reduced-motion` 为有意降级（严查一刀切 `0.01ms` 抹杀反馈）；图标按钮 `aria-label`、表单 `<label>`、异步 `aria-live`；可见 `:focus-visible`、逻辑 Tab 序、无键盘陷阱；语义 HTML（无 `<div onClick>`）；`<h1>`–`<h6>` 阶梯与 Skip Link；图片 `alt`。
- **评分**：`0` 不可用（不达 WCAG A）｜`1` 重大缺口（几乎无 ARIA/键盘支持）｜`2` 部分达标（有明显缺口）｜`3` 良好（基本满足 WCAG AA，少量细节）｜`4` 优秀（全面满足 AA 并逼近 AAA）。

### 2. 性能（Performance，0–4）
- **核查点**：循环内读写交替引发的布局抖动；随手动画化布局属性或无边界大模糊掉帧；图片缺宽高（CLS）、缺懒加载或未压缩；`will-change` 滥用常驻；大列表（>50 项）未虚拟化或未用 `content-visibility: auto`；冗余依赖包与无必要重渲染。
- **评分**：`0` 严重性能事故｜`1` 主要路径明显卡顿/未优化｜`2` 局部优化仍有大缺口｜`3` 整体流畅仅小幅可调｜`4` 轻量迅捷且实测达标。

### 3. 主题化（Theming，0–4）
- **核查点**：散落硬编码色值未走设计 Token；暗色模式缺失、机械反色或对比度崩溃；Token 混用错位；主题切换时部分元素（如原生 `<select>`、滚动条、`theme-color`）未同步更新。
- **评分**：`0` 全硬编码无主题｜`1` 极少 Token｜`2` Token 存在但混用严重｜`3` 规范用 Token 仅个别漏网｜`4` 完整语义 Token，明暗双主题俱佳。

### 4. 响应式设计（Responsive，0–4）
- **核查点**：固定像素宽度在移动端撑破或出现横向滚动；触控热区 < 44px 或不满足 WCAG 2.2 SC 2.5.8 最低 `24×24 CSS px`（含 24px 间距圆例外）；自定义滑块/拖拽控件触控失效或中断卡死；200% 文字缩放断裂；缺少内容驱动断点；**若页面声明 `dir="rtl"`**：核查物理方向属性未换逻辑属性、覆盖未清旧边、方向图标错向（出现普遍渲染性 RTL 故障时该维扣 1 分）。
- **评分**：`0` 仅桌面可用｜`1` 严重断层｜`2` 移动端可用但粗糙｜`3` 响应式良好仅少量热区或溢出｜`4` 全断点流式自然、热区与触控手势俱佳。

### 5. 实现完整性（Implementation Integrity，0–4，关键维）
- **核查点**：是否表达连贯且专属于本产品的设计系统？是否存在 AI 模板脸快捷方式、设计系统漂移、凑数装饰、假数据/误导状态、或换个 Logo 就能套给任何产品的结构同质化。
- **评分**：`0` 系统性漂移与模板堆砌｜`1` 多处重复实现捷径｜`2` 若干经核实的一致性缺陷｜`3` 仅孤立小瑕疵｜`4` 高度连贯、克制且有清晰产品意图。

### 20 分审计评级带
- **`18–20` 优秀**：仅需微调即可发布
- **`14–17` 良好**：补齐薄弱维度后发布
- **`10–13` 可接受**：需一轮针对性整改
- **`6–9` 较差**：需较大规模重构
- **`0–5` 严重**：存在根本性结构与可用性故障

## 三、深度设计批评量表（Critique）

### 1. 设计特异度裁决（必须放在报告首位）
直白回答：**这套界面的构图、交互与视觉语言是专为本产品打造的，还是换个名称就能套给任何竞品？** 用具体区块与元素举证，绝不敷衍。

### 2. 认知负荷评估（3 类型 + 8 项检查）
区分三类负荷：**内在负荷**（任务本身复杂度，靠分步/默认值/渐进披露管理）、**外在负荷**（糟糕设计造成的无谓脑力消耗，必须无情清除）、**相关负荷**（帮助用户建立心智模型的学习投入，应鼓励支持）。

逐项打勾统计失败数（`0–1` 低负荷良好｜`2–3` 中等需优化｜`4+` 高负荷严重阻塞）：
- [ ] **单一焦点**：主任务不受竞争性装饰干扰
- [ ] **合理组块**：单组信息 ≤ 4 项
- [ ] **清晰分组**：靠亲密性或共享表面明确归属
- [ ] **视觉层级**：一眼能分主次，不需阅读全文
- [ ] **一次一决策**：不强迫同时消化多件事
- [ ] **克制选项（工作记忆 ≤ 4 法则）**：任一决策点可见选项 ≤ 4（5–7 项已逼近上限需分组，8+ 项必导致跳读/误点；顶层导航建议 ≤ 5 项，动作栏 1 主 + 1–2 次）
- [ ] **无记忆桥接**：不要求用户背住上一屏信息才能在当前屏操作
- [ ] **渐进披露**：高级选项按需展开

同时排查 8 类常见过载反模式：**选项墙**（10+ 项平铺）、**记忆桥**、**隐藏导航**（不知身在何处）、**行话壁垒**、**视觉噪底**（万物等重）、**模式不统一**、**多任务并发逼迫**、**高频上下文跳切**。

### 3. 尼尔森 10 项可用性启发式评分（0–4 分，满分 40 分）

打分必须诚实：`4` 分代表真正卓越，绝大多数真实上线产品落在 `20–32 / 40`。

| # | 启发式维度 | 核心核查点 | 0 分 vs 4 分标尺 |
| --- | --- | --- | --- |
| 1 | **系统状态可见性** | 加载/保存/多步进度反馈、当前位置高亮、行内实时校验 | `0` 全程盲猜 → `4` 每步动作即时清晰确认 |
| 2 | **贴合真实世界** | 用户语言无内部行话、自然信息顺序、易懂隐喻与图标 | `0` 满屏内部术语 → `4` 表达自然流畅 |
| 3 | **用户控制与自由** | 撤销/重做、取消出口、清除筛选、随时安全退出长流程 | `0` 陷入死胡同需刷新 → `4` 处处可撤可退 |
| 4 | **一致性与标准** | 全站术语、组件、交互手势与平台习惯高度一致 | `0` 像拼装多套产品 → `4` 高度一致可预测 |
| 5 | **防错设计** | 高危操作确认/撤销、输入约束、智能默认值、自动存草稿 | `0` 极易误操作无护栏 → `4` 借约束近乎杜绝误操作 |
| 6 | **识别胜于回忆** | 常用项可见、情境提示、最近记录、图标配文字标签 | `0` 全靠死记路径 → `4` 无需记忆随看随用 |
| 7 | **灵活性与高效性** | 快捷键、批量操作、收藏/常用项、专家加速路径不干扰新手 | `0` 僵化单一路径 → `4` 兼顾新手与高阶加速 |
| 8 | **美学与极简设计** | 仅呈现当下必需信息、清晰视觉重心、零无意义装饰 | `0` 视觉噪音淹没重点 → `4` 每像素皆有职责 |
| 9 | **识别诊断与错误恢复** | 人话报错、精准定位问题、给出恢复步骤、不清空已填输入 | `0` 裸错误码或无提示 → `4` 精准定位+恢复+保数据 |
| 10 | **帮助与文档** | 可检索任务型帮助、关键节点行内提示、不离开当前上下文 | `0` 无任何帮助 → `4` 恰当时机给恰当指引 |

**模式折算规则**：在 Persuade / Experience 型落地页或作品集上，第 7 项（高效快捷键）与第 10 项（帮助文档）或其他确实不适用的项可标为 `n/a` 并附一句理由，**分母按适用项数 × 4 重新计算**（例如 8 项适用则记 `24/32`，绝不把残缺项硬记 `/40`），评级按百分比判定：
- **`≥ 90%`（36–40/40）优秀**｜**`≥ 70%`（28–35/40）良好**｜**`≥ 50%`（20–27/40）可接受**｜**`≥ 30%`（12–19/40）较差**｜**`< 30%`（0–11/40）严重**。

### 4. 五大测试角色走查（选 2–3 个，直指具体元素红旗）

| 角色 | 画像与行为 | 必报红旗示例 |
| --- | --- | --- |
| **Alex（急躁老手）** | 跳过引导、找快捷键、想批量处理、容忍度极低 | 不可跳过引导弹窗、核心操作无快捷键、慢动画锁操作、缺批量能力 |
| **Jordan（迷茫新手）** | 逐字读说明、字面理解每个词、遇行话或无引导即放弃 | 侧栏纯图标无文字、报错含技术术语、完成后无确认与下一步指引 |
| **Sam（无障碍依赖者）** | 纯键盘 Tab + 读屏（VoiceOver/NVDA）+ 200% 缩放 | 仅点击有效无键盘路径、缺焦点环、单靠颜色表状态、异步变更无播报 |
| **Riley（刻意压测者）** | 试 0 项/1000 项、超长词/Emoji、中途刷新、多标签切换 | 静默失败、刷新丢草稿、空态只写“暂无数据”、同类操作行为矛盾 |
| **Casey（分心移动用户）** | 单手拇指操作、常被打断切应用、弱网、懒得打字 | 主按钮挂屏顶够不着、切后台丢进度、热区 <44px 紧挨、大资源未懒加载 |

- **场景选角参考**：落地页/营销（Jordan + Riley + Casey）；后台/工作台（Alex + Sam）；电商/结账（Casey + Riley + Jordan）；首次引导（Jordan + Casey）；重度表单/向导（Jordan + Sam + Casey）。若项目有明确用户画像文档（如 PRODUCT.md），可额外派生 1–2 个项目专属角色。

### 5. 情绪旅程与收尾提问纪律
- 检查**峰终定律**（最高潮与结束收尾是否令人安心清晰）以及支付、删除、权限等高风险时刻是否有稳重安抚；
- **先完整输出全部报告，最后再提 2–4 个带具体选项的决策问题**（优先方向、语气意图、整改范围、禁动区域），每个问题必须引用报告中的真实发现；若 Priority Issues 少于 3 条或属只读/非交互评审，可省略提问并写明原因。

## 四、P0–P3 严重度标准与报告模板

| 级别 | 名称 | 定义 | 处理动作 |
| --- | --- | --- | --- |
| **P0** | **阻断（Blocking）** | 核心任务无法完成、数据丢失、严重误导或无障碍彻底断链 | 立刻修复，阻断发布 |
| **P1** | **严重（Major）** | 造成显著困惑/摩擦、缺关键状态或违反 WCAG AA | 发布前必须修复 |
| **P2** | **一般（Minor）** | 体验瑕疵或设计系统漂移，但存在可用绕行路径 | 下一轮迭代修复 |
| **P3** | **精修（Polish）** | 细微美学/微文案打磨，无实质任务阻碍（保持少量避免淹没重点） | 视时间安排处理 |

> 快速定级口诀：**“真实用户会因为这个问题找客服或放弃吗？”——会，则至少为 P1。**

## 五、上线工程基线清单（Foundations）

项目准备对外发布前，逐项核查以下 16 条非设计替代的基础护栏（不借此顺手重设计界面）：

1. **密钥不出库**：仓库跟踪文件与 env 中无真实私钥、Token、密码或含密码连接串（示例模板文件除外；一旦泄露须轮换密钥而非仅删文件）。
2. **全局对比度合规**：全站无低对比文本，优先调深共享 Token 而非打零散补丁。
3. **清零 AI 模板脸**：消除所有模板装饰件与反模式结构，对齐既定产品设计语言。
4. **定制 404 / 错误页**：按当前框架规范配置 404/错误边界页，用产品语气说明原因并给出回首页路径。
5. **应用图标齐备**：提供正式 Favicon 与大尺寸应用图标（`rel="icon"` / `apple-touch-icon` / manifest），缺品牌标识时向用户索取，绝不擅自捏造 Logo。
6. **社交分享预览图**：配置 `og:image` / `twitter:image`（建议 `1200×630`），不只写空 `twitter:card`。
7. **隐私政策与服务条款**：页脚链接至有效隐私/条款路由（如需起草须标明草稿、不冒充法律意见）。
8. **README 可复现运行**：安装与启动命令真实可用且与包脚本一致。
9. **CI 自动校验**：推送与合并请求触发自动化质量检查与构建流程。
10. **设计 Token 落地**：项目已定义并通过 `var()` 实际消费主题色与间距变量。
11. **减少动态真实生效**：凡含动效均配有真实有效（非注释）的 `prefers-reduced-motion` 守卫。
12. **依赖真实与安全扫描**：确认包名真实存在、定期关注过时依赖，并配置 Dependabot / Renovate。
13. **错误监控初始化**：在应用入口按环境变量 DSN 初始化异常监控（如 Sentry / RUM 等，账号由团队提供）。
14. **数据迁移可逆**：涉及数据库迁移时每条向上迁移配对应回滚步骤。
15. **无千行巨石文件**：手写源码单文件不超过 1000 行，按既有职责边界无损拆分。
16. **部署配置入库**：托管与构建配置（如 Dockerfile、平台部署清单、移动端构建清单）随仓库版本化管理。
