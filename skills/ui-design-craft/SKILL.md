# 界面设计工艺与可用性规范

把真实 Web 与桌面产品界面做到**第一眼看懂怎么用、细节经得起推敲、极端场景不崩塌**。每次动手前先过两道闸门：**先判访客模式定视觉边界，再按任务类型加载对应规范**；严守工艺底线与反 AI 模板红线，按 `P0–P3` 由重到轻推进。

## 1. 第一关：判定访客模式（严禁错配视觉尺度）

同一产品内不同页面可属不同模式（官网属 Persuade，文档属 Read，控制台属 Operate），切忌把展示页的戏剧化照搬进工作台，也不要把品牌页做成平庸表单。

| 访客模式 | 典型界面 | 访客诉求 | 视觉世界边界 | 不可违背的铁律 |
| --- | --- | --- | --- | --- |
| **Operate（工作台/工具）** | 控制台、设置页、编辑器、数据后台 | 高效完成任务、状态一目了然、操作低摩擦 | **仅贡献 4 项**：字体、色板、密度、1 处标志性动作 | 导航与控件严格沿用平台标准；拒绝终端/仪表盘/账本道具戏服；隐去名称仍像本品类一流工具 |
| **Read（阅读/文档）** | 帮助中心、API 文档、长文、更新日志 | 理解概念、长读不累、随时定位上下文 | **掌控外框，让出正文主栏**（报头/侧轨/开篇/代码块） | 正文行宽 `60–75ch`、扎实对比度、文字背后绝不表演；等宽字只给代码与参数 |
| **Persuade / Experience** | 产品官网、落地页、作品展示、互动体验 | 判断价值主张、建立信任、直接完成转化 | **可主导页面骨架与材质，做载体不做静态画报** | 首屏露出**可工作**的核心转化动作（非空泛跳转链接）；单物件单视角；至多 1 处焦点动效 |

- **把大胆花在一处**：无论哪种模式，只让 1 个核心元素承担视觉记忆点，周围全部安静守纪；在「精致圆滑」与「坚定清晰」之间犹豫时，只要底线全绿就坚定表达既定视觉世界。
- **隐去名称自检**：Operate 遮名须一眼像该品类高效工具；Read 遮名须能从外框认出专属品牌且正文舒展好读；Persuade 遮名须能一眼读懂价值主张并直接触发主动作。

## 2. 第二关：按任务类型路由（先立命题，再动代码）

| 任务类型 | 必须遵守的前置闸门与执行顺序 | 对应参考 |
| --- | --- | --- |
| **全新设计 / 视觉定调** | ① 锚定真实题材、受众与访客模式 → ② 写两遍紧凑设计规划（4–6 命名色、1–2 字族、一句话布局+ASCII 线框、唯一性原则）→ ③ 反向对照简报剔除默认模板 → ④ 写代码 | [访客模式与方向](references/visitor-modes-and-direction.md)、[底线与反模板](references/craft-floor-and-anti-slop.md) |
| **排版 / 布局 / 色彩专项** | 保留既定视觉世界，不借专项调整偷换品牌；先声明角色尺度 / 空间命题 / 色彩职责，再执行并在全断点与双主题复核 | [排版系统](references/typography-system.md)、[布局与多端](references/layout-and-responsive.md)、[色彩与主题](references/color-and-theming.md) |
| **文案 / 去噪 / 引导 / 强弱** | 按「此刻事实 → 下一步动作 → 决策上下文 → 匹配语气」改写；删冗余不删功能；空态区分 5 类；局部放大严守作用域不偷加 Token | [文案、去噪与引导](references/copy-distill-and-onboard.md) |
| **动效编排与降级** | 先写四要素动效命题（焦点/连续性/反馈/预算）→ 按语义选材质与时长曲线 → 补齐防抖、可中断性与 `prefers-reduced-motion` 有意降级 → 进退场五帧核查 | [动效编排](references/motion-choreography.md) |
| **既有精修 / 组件与性能评审** | **精修绝不偷偷重设计**。先读现有 Token 与标杆页 → 把漂移归为 4 类（缺 Token / 重复造轮子 / 概念错位 / 局部缺陷）→ 按 5 级分诊顺序在最窄层级修复，并核查组件完备度与 CWV | [精修与组件评审](references/polish-and-component-review.md) |
| **极端数据与生产加固** | 用 0 项/1000+ 项、超长词/CJK/Emoji、30–40% 翻译膨胀、RTL、全状态码（400–500/离线）、并发连点与手势中断逐项压测加固 | [极端场景加固](references/hardening-extremes.md) |
| **5 维审计 / 深度 Critique** | 严格分离「纯设计体验判断（视角 A）」与「代码/实测扫描（视角 B）」防锚定；输出 20 分技术审计或 40 分启发式批评、角色红旗与 P0–P3 整改路线 | [批评、审计与上线基线](references/critique-and-audit-rubric.md) |

### 五条跨任务执行铁律

- **新设计必须过反身自审**：若把规划里的配色、字体或 Hero 骨架换给另一个无关需求也能照套，必须推翻重写该轴，不把自由度浪费在默认模板上。
- **精修严格走 5 级分诊**：先修①阻断与无障碍断裂 → ②缺失核心状态 → ③流程与系统漂移 → ④视觉与动效精修 → ⑤死样式清理；绝不把局部特例硬抽象成全局组件，也不放任复用值继续硬编码。
- **动效服从 4 档时长与降级**：即时反馈 `100–150ms`、常规切换 `150–300ms`、弹层/布局 `300–500ms`、焦点入场 `500–800ms`；退场快于进场（65%–80%）；减少动态时删位移保状态变化。
- **极端压测必查 6 边界**：超长连续无空格词、空值与 1000+ 项、CJK/Emoji/德语膨胀 30–40%、RTL 逻辑属性与方向图标、400–500/超时离线恢复、多指与 `pointercancel`/`lostpointercapture`/`blur` 中断清理。
- **评审必须先体验后扫描**：先基于真实渲染完成设计特异度、认知负荷与启发式判断，再合入代码/机械扫描结果并标注互补项、误报与未测边界（如真机手势）。

## 3. 不可妥协的工艺底线（Craft Floor）

以下 9 项是对**真实渲染结果**的实测底线，不接受纸面承诺；审查或落地时在一次渲染视图中批量核验：

| # | 工艺维度 | 量化与工程底线 | 高频失守反模式 |
| --- | --- | --- | --- |
| 1 | **对比度与有色底面** | 正文与占位符 ≥ `4.5:1`，大号文本、控件描边与焦点环 ≥ `3:1`；有色底面次级文字从底色或前景色派生显式实色 | 浅灰占位符、有色卡片里放中性灰、暗底低亮蓝字 |
| 2 | **景深与层级唯一** | 阴影带方向偏移与柔和模糊；同一容器在「细边框」与「柔和阴影」间**二选一**；嵌套满足外圆角 ≥ 内圆角 + 内边距 | 零偏移彩色光晕、1px 边框叠大阴影（幽灵卡片） |
| 3 | **空间与光学对齐** | `4px` 基础步进，组内紧、组间松，**标题上方留白大于下方**；亲密性优先于套卡片；`text-box` 作用于块级内层 `<span>` | 全页一律 16px、按钮文字视觉偏上偏下 |
| 4 | **排版与暗底补偿** | 正文 `45–75ch`、底线 `16px`、展示字 ≤ `6rem`、字距底线 `-0.04em`；暗底亮字做行高/字距/字重三轴补偿；`balance`/`pretty`/`tabular-nums` | 移动端输入 <16px 触发强放大、动态数字列晃动 |
| 5 | **全状态闭环** | `default` / `hover` / `focus-visible` / `active` / `disabled` / `loading` / `error` / `empty` 完备；交互态对比度高于静息态 | 只画 3 条理想短文案，缺搜索无结果与报错重试 |
| 6 | **浏览器默认表面** | `::selection`、`caret-color`、滚动条、`:focus-visible`、`text-underline-offset`、`color-scheme`、`theme-color` 与原生 `<select>` 全面 Token 化 | 暗色界面选中文字泛默认蓝、Windows 下拉白底白字 |
| 7 | **动效与降级** | 自然减速曲线 `cubic-bezier(0.16, 1, 0.3, 1)`，禁反射性弹跳；Hover 动内层不动外框；`will-change` 仅动画期临时启用；自动播放 >5s 配暂停/停止 | `transition: all`、Hover 边缘抖动、全局 `0.01ms` 砍死降级 |
| 8 | **语义与触控无障碍** | `<button>` 动作、`<a href>` 导航；移动热区 ≥ `44px`、WCAG 底线 `24px`；`touch-action: manipulation`；弹层 `overscroll-behavior: contain` | `<div onClick>`、禁缩放、手势无点击/键盘替代 |
| 9 | **文案与抗压** | 动词+宾语具体化，全链路术语一致，真省略号 `…`、弯引号与 `&nbsp;`；报错含原因+恢复并保输入；Flex/Grid 子项 `min-width: 0` | “提交/确定”、按钮写死固定宽、报错清空表单 |

## 4. 反 AI 模板脸与代码一票否决红线

### 视觉硬禁令（任何场景不可豁免）
- **标题上方加眉标 / Kicker**：删除标签，让标题凭自身措辞与尺度立住。
- **卡片套卡片**：禁止在卡片内再嵌带边框/阴影的子卡片，改用细分割线、缩进或间距层级。
- **圆角框单侧彩色竖条**：无论用单侧边框、内阴影还是伪元素实现均禁用，改用完整细边 + 极淡同色底 + 前置图标。
- **Emoji / Unicode 充当正式图标系统**：统一使用同族同线宽的图标库或自绘几何 SVG。
- **代码硬搓涂鸦伪插画**：禁止粗糙手绘风 SVG 场景与无由来 `feTurbulence` 噪点（精确几何图、架构图、数据图仍是一流媒介）。

### 高频 AI 模板默认（简报未明确指定时禁止在自由轴采用）
- 等大「图标 + 标题 + 两行说明」卡片矩阵；无真实序列逻辑的 `01 / 02 / 03` 伪序号；默认堆砌 Hero 指标卡。
- 渐变文字、装饰性毛玻璃、非新粗野主义的 `4px 4px 0` 硬阴影、把等宽字体当“科技感戏服”、凑数 Sparklines/进度环。
- 暖米白 + 高对比衬线 + 陶土橙套路；近纯黑 + 单一荧光绿/朱红套路；无差别模板件（标题单字斜体变色、全大写标签、`A · B · C` 拼接、按钮末尾机械追加 `→`、全页清一色滚动淡入上移）。

### 代码级一票否决项（评审见到即标红）
- `user-scalable=no` 或 `maximum-scale=1`；`onPaste` 拦截粘贴；裸 `outline: none` 无替代焦点环；`transition: all`。
- `<div onClick>` / `<span onClick>` 充当按钮或跳转；无 `aria-label` 的纯图标按钮；无 `<label>` 的表单控件；无尺寸的 `<img>`；未虚拟化的超大列表；硬编码日期/货币格式；无点击与键盘替代的纯手势操作。

## 5. 评审与修复优先级（P0–P3）

严禁在边角雕花却留着阻断缺陷，所有审计、批评与精修一律按 `P0 → P3` 排序处置：

| 级别 | 名称 | 判定标准 | 处理要求 |
| --- | --- | --- | --- |
| **P0** | **阻断（Blocking）** | 任务无法完成、遮挡不可点、数据丢失、严重状态误导或无障碍断链 | 立刻修复，阻断发布 |
| **P1** | **严重（Major）** | 造成明显理解/操作障碍、缺关键状态（加载/空/错/权限）或违反 WCAG AA | 发布前必须修复 |
| **P2** | **一般（Minor）** | 与邻近页面 Token/组件漂移、高数量未独立滚动、窄窗错位（有绕行路径） | 下一轮集中修复 |
| **P3** | **精修（Polish）** | 光学对齐、留白微调、动效阻尼与微文案润色（控制少量，不淹没主问题） | 视时间安排处理 |

> 快速定级口诀：**“真实用户会为此找客服或放弃吗？”——会，则至少定为 P1。**
> 评估分工：**技术审计（Audit）**评 5 维 20 分（无障碍 / 性能 / 主题化 / 响应式 / 实现完整性）；**深度批评（Critique）**评设计特异度 + 认知负荷（工作记忆 ≤4）+ 尼尔森 10 项（40 分，支持模式折算）+ 5 大测试角色走查。

## 7. 输出交付契约与自检

按任务类型交付对应的结构化产物，不发空泛修辞：

- **新设计 / 改版方案**：输出访客模式判定、四项紧凑视觉规划（色值 Token / 字族角色 / 布局线框 / 唯一性原则）、反模板自审修订点，以及可落地的语义 CSS/组件结构。
- **既有页面精修方案**：列出引用的既有 Token 与标杆页面、4 类系统漂移归因表、按 5 级分诊排序的具体改动点，明确标注不触碰的范围外模块。
- **动效规格方案**：输出四要素动效命题、各交互对应的时长/退场/缓动曲线表、合成层与防抖实现代码、以及 `prefers-reduced-motion` 有意降级规则。
- **极端加固方案**：按「长短空值 / 高数量 / 多语种与 RTL / 表单与状态码 / 并发与中断手势 / 键盘无障碍」逐项输出防护代码与验证点。
- **技术审计 / 深度 Critique**：首行声明评估方式（双视角独立 vs 单上下文降级与未测项），先给健康分表与特异度/完整性裁决，再按 `P0 → P3` 输出带落位与改法的整改清单；若存在 ≥ 3 条高优问题，在完整报告**之后**再提 2–4 个带具体选项的决策问题。

### 交付前必核
- 已明确访客模式并基于真实渲染或现有 Token 输出具体方案，精修未私自偷换视觉世界。
