# 工作管理笔记

用于 Projects、Areas、会议、周计划和周报，以及已有工作记录的内容修订。
从新完成的开发/部署事实生成长期记录，交由 `obsidian-work-log-release-recorder`；
本规则不把普通周报自动转换为发版笔记。

## 按用途选择结构

| 笔记 | 应回答的问题 |
| --- | --- |
| 项目主页 | 目标、当前状态、具体任务、阻塞与依赖、验收标准、相关资料 |
| 领域 MOC | 职责范围、活跃项目、周期性记录入口、标准流程与参考资料 |
| 会议 | 日期、必要的参会人、决定、待办及负责人、受影响项目 |
| 周计划 | 日期范围、任务、优先级、状态、预期产出或验收口径、依赖 |
| 周报 | 本周结果与证据、整体进度、下一步、风险和所需协助 |

工作笔记服务执行和检索。状态、任务、负责人、优先级和排期可以用表格或复选框，
在同一篇内保持一致。未知负责人、日期或完成情况标明待确认，不把计划写成结果。
不附加学习笔记式概念展开、配图提示词或完整研究流程。

## 周期记录

优先读取目标目录现有格式和 `99 System/Templates/模板 - 周计划.md` 或 `模板 - 周报.md`
（存在时）。模板与实际使用不同，沿用本次指定格式或最近有效的本地约定。

默认周计划列可用：完成、日期、项目、任务、优先级、产出。
默认周报可分整体进展、本周进展、下周计划、风险及问题；整体进展概括结果，细节进入本周进展。
只有已确认无风险时才写“暂无”，缺少信息写“未提供”。

领域页链接项目计划，避免两处维护同一任务表。可复用操作知识放 Resources 后回链；
发布记录中的命令仅解释执行需要的参数、环境和验证，不扩写成课程。

## 审阅重点

检查归位、状态与证据是否一致，任务和验收口径是否具体，链接是否有效。
已有待写笔记的链接可以保留并说明，不为通过检查而删除有意保留的导航。
