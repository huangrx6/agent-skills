# 归位规则与目录入口

本文件记录稳定的 PARA 约定，不保存当前项目清单、文件数量或机器状态。
实际目录、索引和用户当前要求优先；名称不同则沿用现有结构，不另建一套。

## 区域判断

| 区域 | 用于 | 常见入口（用前确认存在） |
| --- | --- | --- |
| `00 Inbox` | 尚未归类的捕获和草稿 | `收件箱 - 说明.md` |
| `01 Projects` | 有明确交付结果、可完成或关闭的工作 | `项目区 - 索引.md` |
| `02 Areas` | 长期责任、周期性维护 | `领域区 - 索引.md` |
| `03 Resources` | 可复用知识、学习和技术资料 | `资源区 - 索引.md` |
| `04 Archive` | 不再活跃但需保留的内容 | `归档区 - 说明.md` |
| `90 Assets` | 图片、附件、绘图 | `Attachments/` |
| `99 System` | 模板、工作流、命名等知识库规则 | `首页.md`、`00 MOC - System.md` |

只选一个主家；项目状态不放 Resources，可复用方法可以独立成为资源笔记并回链项目。
归档不等于删除，移动后保留可用入链。

## 区域内组织

- **Projects**：先找已有项目目录和主页。新项目沿用邻近的数字前缀命名；需要持续跟踪时建立
  `项目 - 名称` 主页。会议、实施和交付记录只有直接服务该项目时才放入项目目录。
- **Areas**：领域 MOC 链接活跃项目、周期性记录和运行手册，不复制完整项目计划。
  周计划、周报沿用领域中已有的 `NN 周计划/`、`NN 周报/` 或同等结构。
- **Resources**：按当前资源区索引选择主题。新分组沿用已有编号和命名，不根据预存清单重建历史分组。
- **System**：按需查看 `工作流.md`、`命名规范.md` 和 `Templates/` 中相应模板。
  修改一篇笔记不意味着需要修改系统规则或模板。

## 探查与变更边界

先查看目标目录的直接子项，目录大时用文件名关键词或子目录缩小范围。
找入链时可以全库搜索旧名称和路径，但无需把全库正文读入上下文。

用户给出的确切新目录是落点依据，检查同名冲突后可创建。未给落点时优先已有主家；
临时内容可进 Inbox，无法判定的新项目/领域结构才需要澄清。不要把“目录不存在”误当成一律需要重新授权。

保留未明确要求修改的 `.obsidian/`、隐藏目录、嵌套仓库和附件。
名字奇怪或零字节不能证明无用，例如 macOS 文件夹图标标记 `Icon\r`。
不假定 vault 已用 git 管理、已有备份或已安装 hooks；确需 git 操作时再遵循相应工作流。
普通知识库操作只更新 vault 内相关导航，不自动回写本 skill。
