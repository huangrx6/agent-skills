# 资源笔记

仅用于 `03 Resources` 的可复用知识。按主题决定深度，不把所有笔记写成教程。

## 内容结构

| 类型 | 重点 |
| --- | --- |
| 概念 | 定义、层次与边界、解决的问题、例子、常见误区 |
| 工具 | 适用场景、必要安装配置、关键操作、验证和故障表现 |
| 机制 | 输入、处理流程、输出、状态变化、失败路径 |
| 对比 | 统一比较维度、证据、适用条件和取舍 |
| 实践 | 前提、步骤、预期结果、验证及必要的恢复方法 |

关键术语需要解释，重要判断要有例子或验证路径。直接写机制、字段或动作，
不要用阅读顺序、记忆口号和泛泛评价代替内容。正文应独立可读，MOC 只负责导航。

## 示例与准确性

- 命令和代码说明环境/版本、依赖、输入、关键参数、运行方式和预期结果。
  完整可运行示例须含必要 import、配置和数据；省略的片段明确标为片段。
- 配置说明属于哪一层、字段语义和修改后果，注释不只是换词复述字段名。
- 沿用用户的实际工具和模型，不把某次示例的供应商或模型名固化成通用默认值。
- 脚本里的异步入口与 Notebook 区分；例如脚本用 `asyncio.run()`，支持时 Notebook 可顶层 `await`。
- 涉及当前 SDK/API、协议保证或版本差异时核对一手来源；有本地代码时先确认实际版本。
  语法检查不等于运行验证，未运行或依赖外部服务的部分如实标明。

复杂研究见 [研究与综合](research-and-synthesis.md)，不要在每篇小笔记里复制研究流程。

## 组织与图示

内容可独立解释、验证和复用时再拆分；需要跨篇导航时建 MOC，不按固定篇数建空壳。
已有学习顺序需保持前置关系；拆分和重编号按通用写作规范更新全库受影响入链。

图示只在解释结构、流程、状态、参数关系或故障路径时加入，不按篇幅或固定数量配图。
建议清单只需图要回答的问题、节点/关系、位置和来源。真实截图与机制示意要区分。
风格沿用用户要求和目标笔记约定；需要实际画技术图时使用 `diagram-authoring` 的流程。

移除无用图片引用属于正文编辑；删除源附件需在清理授权范围内并确认无其他引用。
若用户需要自测题，附独立可读的参考答案；开放题给判断维度，不用“见上文”代替答案。
