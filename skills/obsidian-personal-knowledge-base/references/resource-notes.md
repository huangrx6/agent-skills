# 资源笔记

本文件只适用于 `03 Resources`。资源笔记的目标是沉淀可复用知识。

## 适用范围

使用本规则处理：

- 技术概念解释
- 工具、框架、中间件、协议、平台笔记
- 对比、选型、排障方法
- 从资料、文档、源码、文章整理出的长期知识
- 可反复引用的实践经验

## 写作目标

资源笔记应让未来的自己能快速回答三个问题：

| 问题 | 笔记里需要有的内容 |
|---|---|
| 它是什么 | 定义、所处层次、边界 |
| 它解决什么问题 | 使用场景、存在原因、适用条件 |
| 怎么实际使用 | 最小例子、配置、命令、请求路径、故障表现 |

## 笔记类型

先判断笔记类型，再决定结构。

| 类型 | 重点 | 常见结构 |
|---|---|---|
| 概念笔记 | 解释对象、边界、关系 | 定义、问题域、核心模型、例子、误区 |
| 工具笔记 | 说明工具怎么用、怎么验证 | 用途、安装/配置、关键命令、常见错误 |
| 机制笔记 | 解释运行过程 | 输入、处理流程、输出、关键状态、失败路径 |
| 对比笔记 | 帮助做选择 | 对比维度、差异表、适用场景、取舍 |
| 实践笔记 | 可复用操作方法 | 前提、步骤、验证、回滚/排障 |

## 完成标准

基础技术笔记至少满足：

- 读者知道对象是什么、处于哪一层、主要用途是什么。
- 关键术语有解释，不依赖未说明的缩写。
- 至少有一个能固定理解的例子、命令、配置、请求路径或故障场景。
- 命令、配置和字段说明准确，不把字段名换个说法当解释。
- 参考资料与实际使用来源一致。

不达标的典型表现：

- 只有术语列表，没有运行路径或例子。
- 标题很多，但每节只有一句泛泛描述。
- 配置块没有说明字段语义和修改后果。
- 同一段解释在多个笔记里重复出现。

## 表达规则

写资源笔记时，直接写知识本身。

不要写读者状态、学习阶段、记忆建议或教学旁白。把这类内容改成以下信息之一：

| 原问题 | 改写方向 |
|---|---|
| 读者处于什么学习阶段 | 对象的定义、边界、前置概念 |
| 应该怎么记 | 稳定术语、字段语义、可验证事实 |
| 方案可靠性判断 | 具体条件、风险、适用场景、验证方式 |
| 验证实验设计 | 实验目的、输入、步骤、预期结果 |

标题使用“概念名”或“动作名”。章节顺序交给编号和 MOC，不在每篇笔记里重复写学习路径。

好的标题形态：

- `VirtualService 的核心字段`
- `TLS 证书链验证流程`
- `gRPC Metadata 的传递方式`
- `用 curl 验证 SNI`

## 示例和配置

资源笔记里的示例要承担解释作用。

命令示例应包含：

- 运行前提
- 命令用途
- 关键参数说明
- 预期输出或状态变化

配置示例应说明：

- 片段属于哪一层
- 关键字段的真实语义
- 修改字段会影响什么
- 常见错误表现

如果示例只是在页面上“看起来完整”，但不能帮助理解或验证，就删掉或补足说明。

## 技术准确性

涉及命令、YAML、API、字段、版本行为时：

- 优先查官方文档、源码、规范或实际输出。
- 不确定时明确标注不确定点。
- 行为和版本有关时写明版本背景。
- 注释解释语义和影响，不复述字段名。
- 声称“会看到某个输出”时，应确认输出与当前工具行为一致。

## 结构维护

资源主题达到 4 到 6 篇笔记时，创建或维护 MOC。

编号学习集应：

- 使用连续整数编号。
- 前置概念排在下游框架和应用之前。
- 拆分、重命名、重编号时同步更新 MOC。
- 搜索并修正附近失效链接。

如果一篇笔记覆盖过多同层概念且都不深入，拆成多篇；父级保留概览或 MOC。

## 图示和截图

只有图示或截图能降低理解成本时才添加。不要按固定数量配图，也不要因为某篇文章较长就机械增加图。

判断一张图是否保留：

- 它是否解释了文字难以快速讲清的结构、流程、状态变化、张量形状、参数关系或故障路径。
- 它是否能作为复习时的核心心智模型。
- 它是否来自真实配置、运行输出、trace、模型报告或明确的机制示意。
- 如果删掉这张图，理解成本是否明显上升。

如果答案是否定的，删除图示建议；如果图片已经嵌入正文，还要删除图片引用，并在确认没有其他笔记引用后删除源文件。

视觉建议可分为：

- `核心必画`：没有图会明显难懂。
- `可选截图`：有真实配置、运行结果、trace、报告截图时再放。
- `不建议画`：文字已经足够，画出来只是重复或装饰。

视觉建议字段保持紧凑：

- `图`
- `画什么`
- `为什么需要`
- `位置`
- `来源`，仅真实截图需要

默认生成图风格：

- Excalidraw 手绘风格
- 纯白背景
- 白底上很淡的浅灰细网格线
- 浅色系
- 少量手绘 icon

明确排除：灰色底色、深色背景、海报风、3D、商业宣传风、装饰性插画、为了显得丰富而添加的重复图。

## 自测问题

资源学习笔记中的自测题要给参考答案。优先使用 `## 自测问题与参考答案`。

答案写法：

- 简短、明确，可独立复习。
- 覆盖关键判断、边界条件和常见误区。
- 不写“见上文”作为答案。
- 开放题给判断维度，不强行给唯一答案。

需要完整研究流程或详细图示提示词结构时，加载 `research-and-synthesis.md`。
