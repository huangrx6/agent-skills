# 结构检查

vault 里有两类"指向虚空"的引用，都用脚本查，不要手写临时扫描：

| 检查 | 脚本 | 抓什么 |
| --- | --- | --- |
| 链接 | `scripts/check_links.py` | 失效的 wikilink 与嵌入 |
| 配置路径 | `scripts/check_paths.py` | `.obsidian/` 配置里指向不存在位置的绝对路径 |

两者放在一起讲，是因为它们**坏起来的方式一样**：都指向一个不存在的东西，而且都不报错。

## 一、链接检查

PKB 的规则在多处要求"检查明显的失效链接"。用 `scripts/check_links.py` 做，不要手写临时扫描。

### 用法

```sh
python3 scripts/check_links.py                     # 扫默认 vault
python3 scripts/check_links.py --ignore-template   # 跳过模板占位符（日常用这条）
python3 scripts/check_links.py --json              # 机器可读
python3 scripts/check_links.py --quiet             # 只输出计数
python3 scripts/check_links.py --vault PATH        # 扫别的 vault
```

退出码：`0` = 无失效链接，`1` = 有失效链接，`2` = vault 路径不存在。

### 为什么必须用脚本，不能手写临时扫描

2026-09-12 的 vault 修复中，手写扫描器同时产生了假阳性和假阴性：

| 坑 | 后果 | 脚本怎么处理 |
| --- | --- | --- |
| 代码块里的 `[[ ]]` 不是 wikilink | bash 条件判断、Python 注解 `Callable[[P], T]`、TOML 配置片段被误报 | 扫描前剥掉围栏代码块与行内代码 |
| 只索引 `.md` | 所有图片嵌入 `![[x.png]]` 变成假失效 | 索引 vault 内**所有文件**（含附件） |
| 只按 basename 精确匹配 | 漏报改过路径的引用 | 同时试「相对 vault 路径」「相对当前笔记路径」「basename」 |
| 未处理链接修饰 | `[[x\|别名]]`（表格内转义）、`[[x#标题]]`、`[[../相对路径]]` 被判错 | 统一规范化后再解析 |

实测对比：同一次修复中手写版报 9 个失效链接，脚本报 12 个——多出的 3 个是真实丢图（`Pasted image *.png` 全库不存在），手写版漏报。

### 支持的链接形式

| 形式 | 说明 |
| --- | --- |
| `[[笔记名]]` | 按 basename 解析 |
| `[[路径/笔记名]]` | 按相对 vault 的路径解析 |
| `[[笔记名\|别名]]` | 去掉别名；表格内的 `\|` 转义也处理 |
| `[[笔记名#标题]]` | 去掉锚点 |
| `[[../相对/笔记]]` | 相对当前笔记目录解析 |
| `![[图片.png]]` | 嵌入，按附件索引解析 |

### 发现失效链接后怎么处理

| 情况 | 处理 |
| --- | --- |
| 目标存在，只是改名 / 改编号 | 修正链接（不要删除链接） |
| 目标主题已被拆成多篇 | 改为分别链接实际的各篇 |
| 目标不存在（从未写过） | 改纯文本 + `（笔记待补）`，**不要猜一个映射** |
| 模板里的占位符 | 用 `--ignore-template` 跳过，不要"修"——模板要有占位符才能示范结构 |
| 图片丢失 | 改纯文本 + `（图片丢失：<原文件名>）`，保留可检索线索 |

## 二、配置路径检查

`.obsidian/` 下的配置里有绝对路径（插件设置里的 CSS 片段、导出目录、可执行文件路径……）。
vault 搬家之后这些路径会失效，而**插件通常不报错**。

### 用法

```sh
python3 scripts/check_paths.py           # 扫默认 vault
python3 scripts/check_paths.py --json    # 机器可读
python3 scripts/check_paths.py --quiet   # 只输出计数
```

退出码：`0` = 没有失效的**文件**引用，`1` = 有，`2` = vault 路径不存在。

### 真实案例（为什么要有这个检查）

2026-09-12，vault 从 `~/obsidian` 搬到 `~/Documents/obsidian` 之后，
`better-export-pdf/data.json` 的 `cssSnippet` 仍指向旧位置。插件的读取是：

```js
try   { await fs2.readFile(config.cssSnippet, ...); await preview.insertCSS(...); }
catch (e) { console.warn(e); }        // ← 只打 console
```

`ENOENT` 被吞掉，UI 上零提示，**PDF 静默地不带自定义样式**。更糟的是插件每次导出都执行
`settings.prevConfig = this.config`，把错误路径一遍遍重新固化。

而发现它纯属偶然——当时是在查别的问题。这类"配置指向虚空 + 失败静默"没法靠自觉发现。

### 分层判定：文件 vs 目录

| 路径形态 | 判定 | 行为 |
| --- | --- | --- |
| 以扩展名结尾（`.css` / `.json` / `.png`） | 明确在引用一个**文件** | 不存在即失败，退出码 `1` |
| 无扩展名 | 多半是**目录**（导出目录、缓存目录） | 不存在只提示，退出码 `0` |

分层的理由：没法从路径本身区分"待创建的输出目录"和"无扩展名的可执行文件"，而前者很常见。
宁可把无扩展名的归成目录（只提示），也不要因为一个正常的输出目录配置挡住提交——
那会把人逼向 `--no-verify`，hook 就白加了。

**已知盲区**：`/…/bin/lark-cli` 这类无扩展名的可执行文件会被归成目录，只提示不阻塞。

### 扫描范围（刻意排除的）

| 排除 | 原因 |
| --- | --- |
| 笔记正文 | 里面的绝对路径绝大多数是示例。实测 vault 里有 **64 处**，全部纳入会淹没真问题 |
| 插件的打包 JS（`main.js` 等） | 里面的路径是"候选列表"，逐个尝试直到命中。不存在的候选是设计如此 |

### 发现失效路径后怎么处理

| 情况 | 处理 |
| --- | --- |
| vault 搬过家 | 把路径改成新位置（**不要**改成相对路径——见下） |
| 目标是可执行文件 | 尽量改成裸命令名（`lark-cli` 而不是 `/…/node/v24/bin/lark-cli`），让插件走 PATH，免得换 node 版本又失效 |
| 目标确实不该存在 | 把该设置清空 / 恢复默认，而不是留一个坏路径 |
| 目录类提示 | 确认那个目录是否本来就该由插件运行时创建；是就不用管 |

**为什么不能改成相对路径**：这类插件多用 Node 的 `fs`（不是 Obsidian 的 `vault.adapter`），
相对路径会相对**进程 cwd** 解析，在 Electron 里不可预测。绝对路径是硬性要求，
本检查能做的只是把"它失效了"变成可见。

## 什么时候跑

- 重命名 / 移动 / 删除文件或目录之后，批量改编号、拆分合并笔记之后（链接检查）
- vault 搬家 / 改名之后（两者都跑）
- 装了新插件、改了插件设置之后（配置路径检查）
- 换 node 版本之后（`nvm` 的路径里带版本号，会连带失效）
- 定期巡检（例如每月一次全库扫描）
