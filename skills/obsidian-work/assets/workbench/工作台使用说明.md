# 工作台使用说明

[[99 System/工作台/工作台|← 返回工作台]]

## 记录一件工作

1. 在对应项目下新建笔记，标题说明具体事项。
2. 用命令面板的“模板：插入模板”选择需求、缺陷、任务或外部工作项模板。也可以打开模板复制内容，再手动替换标题和日期占位符。
3. 填写实际已知信息。每个需要独立跟踪的事项使用唯一且稳定的 `work_id`，例如 `local-年月日-序号`；先查是否已占用，改名不换编号。

本地模板插入后按类型进入视图；外部工作项模板需先按来源填好 `work_kind`（requirement、bug 或 task）。工作项缺少身份、归属或状态等信息时，也会进入“待整理”。
简单一次性待办仍可留在日常清单，不必全部拆成文件。

## 视图怎么用

| 视图 | 用途 |
| --- | --- |
| 待推进 | 本地尚未明确完成或取消的需求、缺陷与任务 |
| 需求 | 明确目标、范围与验收 |
| 缺陷 | 保存复现、证据和验证结果 |
| 任务分工 | 按负责人查看具体行动和交付 |
| 外部跟踪 | 查看外部平台的状态快照和来源时间 |
| 待整理 | 找到需要补充身份或关键信息的工作项 |
| 已完成 | 回看已确认完成的本地事项 |
| 近期记录 | 回看日常和发布记录，按笔记修改时间排序 |

表格里的本地状态、负责人、优先级与日期来自笔记属性，可以直接编辑，变化会回写原笔记。
“类型”等计算列用于显示，不是输入框。空白负责人表示信息未提供，确认无人负责才填“未分配”。

## 本地与外部状态

本地自管项使用 `authority: local`。外部引用页使用 `authority: external`，并记录真实外部编号、
链接与快照。外部状态写 `external_status`，负责人写 `external_assignee`。
来源更新时间与本次读取时间分别保存；今天读了旧导出，不能当作今天最新状态。

个人跟进可以另建本地任务，用 `related` 链接外部事项。个人任务完成不代表团队缺陷关闭。
编辑外部快照不会自动更新 PingCode 或其他平台，也不会自动通知负责人。

## 视图为空时

视图只收录已明确填写工作类型的笔记，不猜测旧笔记属于需求还是缺陷。
先按需要整理一条真实事项即可；旧笔记保持原位，模板文件本身不会作为工作项显示。
模板不会为你猜测负责人、验收完成或截止日期。
