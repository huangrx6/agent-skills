# Obsidian 工作台

> 用普通 Markdown 管理需求、缺陷、任务、负责人、日常进度、周报与发布记录。

| 适合 | 产物 | 依赖 |
| --- | --- | --- |
| 需求 / 缺陷 / 任务主档 · 周报 · 发布记录 · Bases 视图 | 工作项笔记 · 项目页 · 周报 · 工作台首页 | Obsidian（Bases）· Python 3.10+（标准库） |

复杂工作项拥有自己的主档，简单待办留在清单；项目页和周期汇总通过链接组织内容。
可独立安装，不依赖其他 skill 或外部项目系统。调用名为 `$obsidian-work`，中文展示为“Obsidian 工作台”。
普通记录使用 Markdown；动态视图使用 Obsidian 自带的 Bases。

## 使用场景

- “在 Obsidian 的项目 A 下建一个导出需求，验收是能按当前筛选条件导出。”
- “把这个缺陷记下来：预发环境点击保存后页面报错，刷新后数据又在。”
- “把需求拆成前后端任务，负责人先留未分配，列清交付和验收。”
- “用户列表的后端任务已经按张工给的结果验证通过，更新进度和来源。”
- “根据这周的日常记录生成周报，把未完成事项和阻塞列出来。”
- “把刚才的发布记到已有记录，再把这份外部系统导出作为快照补进去。”

需求关注目标、范围与验收；缺陷关注环境、复现、期望与实际表现；任务关注动作、负责人、交付与验收。
负责人只按已有事实或用户指定填写。建议分工不等于已分派，写到笔记也不等于通知或更新外部系统。
学习笔记可以有普通关联链接，工作台不会因此生成学习页或启动另一套工作流。

## 安装与配置

仓库安装方式见 [根 README](../../README.md)。本目录包含全部运行脚本，可单独复制安装；
脚本仅依赖 Python 标准库。下面命令从仓库根目录执行：

```sh
export OBSIDIAN_VAULT_PATH="/path/to/your/vault"
python3 skills/obsidian-work/scripts/vault_path.py --explain
```

也可在 `~/.agent-skills/config/obsidian-vault-path` 保存一行路径；`AGENT_SKILLS_CONFIG_DIR` 可覆盖配置目录。
解析优先级是显式路径、环境变量、配置文件，旧配置 `~/.config/obsidian-vault-path` 仅作兼容回退。
各检查器可传 `--vault PATH` 指定临时目录或本次知识库；路径解析器本身用位置参数 `PATH`。
这些配置键沿用旧版，但读取配置和运行脚本不依赖任何相邻 skill。

## 记录与外部系统

独立工作项采用 `work_kind` 和持久 `work_id`，其他属性按用途保留，详见
[工作项规则](references/work-items.md)。旧笔记逐次更新，不强制全库补字段或重命名。

默认本地笔记是个人工作主档，可用 `authority: local|external` 标明主档归属。
导出文件、截图、粘贴内容都可以作为外部快照来源；
外部状态与本地个人进度分别记录，观测时间与外部变更时间分别保存。
切换到外部系统为主或请求远端变更时，遵循 [外部协同规则](references/external-collaboration.md)，
不默认后台双向同步，也不绑定特定平台或技能。

## Bases 工作台

包内提供可直接接入的[工作台首页](assets/workbench/工作台.md)、8 个中文视图、5 份新建模板，
以及仅作用于工作台首页的 CSS 样式。首页用分类卡片、待推进表格和近期记录组织日常工作。
数据仍在原笔记中，表格里的本地属性可以直接编辑；不需要 Dataview 或 Templater。

按 [接入说明](references/bases-views.md) 复制到现有知识库并启用核心 Bases 和 CSS 片段。
已有内容先检查和合并；视图空白时从真实事项逐步接入，不批量猜测旧笔记的类型。

## 格式兼容与检查

原八章周发版模板和命令保留为一种可选格式。单次发布、按版本记录和普通日志可直接使用
[轻量事件结构](references/event-records.md)，不默认每次创建周发版。

```sh
python3 skills/obsidian-work/scripts/check_links.py --ignore-template
python3 skills/obsidian-work/scripts/check_release_note.py "<八章周发版笔记路径>" --vault "<知识库路径>"
python3 -m unittest discover -s tests/obsidian-work -v
```

链接检查支持 `--json`、`--quiet`，退出码 `0` 为未发现失效目标，`1` 为发现失效目标，`2` 为输入不可用。
它检查双链/嵌入的目标文件并忽略代码，跳过隐藏目录及固定缓存目录；不验证 Markdown 链接、锚点、
同名短链接语义或嵌套仓库边界。入链与移动结果还需要人工审阅。

周发版检查支持单篇或 `--dir PATH`；单篇也检查同目录重复周。
退出码 `0` 为无失败或仅提示，`1` 为格式/入链/重复周问题，`2` 为输入或包内组件不可用。
显式无效知识库路径会失败；未配置路径时跳过入链检查并明确说明。
校验器从 [周发版模板](references/release-note-template.md) 读取全部字段和章节，不验证正文是否填写完整、
事实真实性、工作项 ID、状态一致性或回滚有效性。入链只认其他笔记里的双链，不能证明它来自有用索引。
明显凭据赋值仅提示并隐藏值，不代表完整密钥扫描。

两个检查器只读。自定义或轻量格式不运行周发版格式检查，不为通过检查改坏本地约定。
`evals/evals.json` 是触发与行为评审用例，没有自动执行或评分器。
