# 工作事件记录与更新

事件记录保存发生过什么、目前处于什么状态及依据。优先更新已有笔记中的一段，只有需要独立检索、
多人交接或持续积累时才单独建页；不要求建立统一的事件目录或给所有旧笔记补属性。

## 找到同一事件

先按项目或系统、变更内容、PR/提交/版本和环境查现有记录。已有稳定标识时复用；没有时用可检索标题
和必要上下文定位，不为了去重强制生成编号。同一版本可能含多次部署，同一变更可能涉及多个环境，
需要保留各次尝试和环境结果，不能只凭版本或标题相同就合并。
若事件成为独立持续跟踪工作项，按 [工作项规则](work-items.md) 分配持久 `work_id`；段落内的日志不必逐条编号。

| 新输入 | 写入方式 |
| --- | --- |
| 与已有内容相同，没有新事实 | 不追加事件、不重复链接、不更新修改日期 |
| 同一事件增加验证或发布结果 | 原位更新对应状态及依据，保留其他维度 |
| 同一变更在新环境执行，或再次尝试发布 | 在原事件下增加该环境或该次尝试的结果；不覆盖之前的结果 |
| 发现原记录错误 | 改正当前表述，保留简短更正说明、依据和时间 |
| 两项材料互相冲突且无法确定 | 记录各自来源和适用条件，明确待确认，不替用户裁定 |

来源优先链接已有 PR、提交、构建产物、测试报告、日志或笔记段落；不为每条命令另建来源页。
只有用户陈述时注明“据用户提供，未独立核验”，这不是否定其事实，而是说明证据来自哪里。
“会话中已运行”只有在当前可见工具结果支持时才能写，不能从任务完成语气推断。

## 分开状态与时间

| 维度 | 需要保留的信息 |
| --- | --- |
| 实现 | 变更范围、提交/产物、是否实际完成；不由测试或发布状态倒推 |
| 验证 | 环境、检查项目、实际结果、证据；未执行项和原因 |
| 发布 | 目标环境、实际版本/产物、每次尝试结果；准备完成不等于已发布 |
| 回滚 | 是否实际执行、回退目标、结果与当前环境状态；预案不算已回滚 |

只写本事件涉及的维度，未知明确标注；不要用一个“已完成”概括全部状态。
发布后回滚可以同时保留“曾发布成功”和“当前已回退”，不删除发生过的发布事实。

事件时间表示操作或结果实际发生的时间，记录时间表示何时写入笔记。历史补录保留两者；
事件时间未知则写未知，不用当前时间补造。用户指定周汇总时遵守该范围；自动归入事件周必须有
实际日期依据。只知道月份或版本时按已知精度记录，不猜具体日期、时区或发布周。

## 轻量结构

已有格式优先。没有格式时可在现有笔记加入以下段落，删除不适用的行；这是写作起点，不是必填表单：

```markdown
## <可检索的变更或事件名称>

- 范围：<项目/系统、变更或 PR/版本、环境>
- 事件时间：<已知时间或未知>；记录时间：<本次实际记录日期>
- 实际变化：<做了什么及产物位置>
- 状态与依据：<按需分写实现、验证、发布、回滚及各自证据>
- 待确认或下一步：<确有缺口时记录>
```

命令只保留后续复现、验证、恢复需要的部分，注明环境、工作目录、前提和实际结果；长脚本引用已有
文件。用户提供了待执行步骤时明确标为待执行，不能将其变成执行日志。敏感值只写变量名和位置。
更正无需保存整篇旧版，例如“原记录将预发验证记成生产验证；依据报告 X 更正，生产验证仍未提供”。

## 汇总与关联

事实只维护一个主家。周报、周发版或项目首页用链接及短摘要展示进展，必要时链接到事件标题或块；
实际修改链接后人工确认锚点，现有链接检查器不验证标题或块锚点。
若现有周发版笔记就是事实主家，直接更新它，不为套新模型把历史记录拆散。

关联需求、缺陷、任务或已有资料时使用普通链接，遵循 [工作项规则](work-items.md)。
工作记录不自动派生学习笔记，不要求另一项 skill，也不把每次工作包装成通用方法。
