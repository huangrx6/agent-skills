# 追问话术与决策

追问只为一件事：拿到会改变邮件结论的信息。能从材料判断的不问，非关键信息用占位。

## 什么时候必须问（C1）

- 类型不明：不知道是通知、申请还是确认。
- 收件人关系不明：上级、同级、外部，称呼和语气不同。
- 期望动作不明：仅知悉、回复、审批、确认、参会。
- 关键事实缺失或矛盾：时间、金额、对象、范围、截止时间。
- 同一材料里两个日期或数字对不上。

## 什么时候用占位

签名、抄送、附件名、图片地址、会议链接等不影响结论的信息，写 `【待填：xxx】`。
注意：占位会让校验产生阻断项，交付前要么补齐、要么按用户要求明确标注为草稿。

## 提问规则

- 一轮最多 4 题；能合并的合并。
- 优先选择题，每题标推荐项；自由文本题只留一题。
- 一题只问一件事，不把「时间、地点、议程」塞进同一题。
- 用户已经说过的不要再问；用户说「你定」时按默认值执行并写进假设。
- 用户说「直接生成」时跳过常规 C1/C2；内容完整时正常渲染，不加 `--draft`。
  仅缺失或矛盾事实保留待填时用 `--draft` 输出，
  列出未确认内容，不补造事实，也不自行选择冲突版本。

## 四个常用问题

按需选用，不必每次都问满四题：

1. **主要目的是？**
   申请审批 / 告知通知 / 确认范围 / 汇报进展 / 其他
   推荐：能从「请审批」「同步给你」这类动词判断时直接判定，不问。

2. **收件人是谁？**
   上级 / 同级同事 / 下级 / 跨部门 / 外部客户
   推荐：材料里有称呼或邮件往来时直接采用，不问。

3. **希望对方做什么？**
   审批 / 回复确认 / 仅知悉 / 参会 / 提供材料
   推荐：与目的最匹配的一项；选「仅知悉」时结尾不要强加回复要求。

4. **有没有图片、附件或表格？**
   几张图 / 表格 / 仅文字 / 附件
   推荐：材料里已经有时直接读取；图片要问 alt 与说明，避免只写「见图」。

## 时间与数字的追问

- 相对日期按当前日期与用户时区换算，交付时注明；有歧义才追问，写成全年月日。
- 「晚上」要确认具体时间与用户时区；发布、会议、截止时间都要。
- 金额要确认币种与是否含税；工时确认单位（人天 / 小时）。
- 百分比要确认基数；「错误率超过 1%」要确认统计口径。
- 多个数字互相矛盾时，把两个版本都摆出来让对方选，不要自行合并。

## 用户不回答时

仅样式与格式按默认值执行；缺失或矛盾事实保留待填，不把未回答视为确认：

- 收件环境：通用兼容，覆盖 Outlook 与主流邮箱。
- 输出格式：HTML + 纯文本 + Markdown。
- 图片：图床 URL 占位，由用户替换。
- 邮箱连接器：不接，只输出文件。
- 语言：中文，专业术语保留英文。

把这些写进交付清单的「假设」，不要藏在正文里。

## C2 按需确认

普通邮件、已有模板和需求清晰的任务直接出稿。仅用户要求预览或复杂版式存在
影响结果的选择时，合并确认结构与样式：

> 结构：主题 + 摘要 + 发布范围（3 条）+ 3 张图 + 工时表（3 行）+ 发布步骤 + 待办（2 项）+ 签名。
> 样式：business 预设，强调色 #1F4E79，宽 640px，标题左侧色条。
> 结构和样式是否接受？接受 / 调整颜色 / 更简洁 / 更正式 / 换预设。

按用户反馈调整，不因达到固定轮数而擅自退回默认预设。
原始 HTML 模板若需 C2，展示「模板版式 + 变量清单」，不展示预设名；已选模板无需重复确认。

## C3 只在可复用时问

内容结构稳定、日期/数字/人名/项目名会换，才问「这套结构要不要存为模板？」。
一次性邮件不问；用户明确说「存为模板」时直接进入模板流程。
模板目录与两种模板类型见 [templates.md](templates.md)。
