# 让知识随证据演进

用于新资料融入已有主题、版本变化、纠错和复核。“更新笔记”允许在所指范围写入；
“看看有没有过时”先报告。以受影响的结论及其解释为修订单位，不把每次更新都变成整篇重写。

## 先确定这次要更新什么

从用户请求、笔记和材料确定目标问题、适用版本及范围。学习当前方案、维护旧项目的操作方法、
保存当时的实验记录，是不同目标。版本已明确就沿用；只有会导致不同结论且无法推断时再问。
用户要“最新”时查当前一手资料；提供一份摘录不等于授权把全专题升级到最新版本。

找到主笔记及直接来源，分别辨认：来源发布/版本时间、本次读取时间、实际验证时间。
同 URL 可能已经改版，旧笔记中的摘录也可能只覆盖部分文档；只对实际读取范围作判断。
旧来源不可访问时保留其记录，说明缺口，不把新页面内容冒充原来的证据。

## 让新证据对应到旧判断

找出新材料涉及的具体断言、条件、例子或操作，定位旧段落。小改动心中对照即可；
多处修改时可临时列“旧判断 → 新证据 → 处理位置”帮助复查，不要求每篇维护结论编号或台账。

| 材料带来的变化 | 写回方式 |
| --- | --- |
| 只是重复 | 不改正文、不刷新日期、不追加日志；若确实重新核验，按核验范围记结果 |
| 补充解释或支持依据 | 融入对应段落，保留原来有用的解释；不是默认追加一节“新资料总结” |
| 条件不同，旧说法仍成立 | 就近说明版本、环境或前提；旧项目仍需的操作保留，不能直接覆盖成新版本 |
| 同一条件下确认旧说法错误 | 更正主段落及相依内容，重要纠错留下简短原因与来源 |
| 证据冲突或不足 | 保留可区分的说法和具体未知项，标明需核实的结论，不强行合成答案 |

材料更新不等于结论一定改变，材料较新也不自动优于直接实验或准确限定条件的旧来源。
用户原有理解即使有误，也应明确解释更正；有学习价值的原推演可保留为“当时的理解”，
不把旧误解继续留成当前推荐，也不把个人观点悄悄改成 AI 的口吻。

## 修订真正受影响的内容

沿着改变的判断查找它在本页的摘要、参数、代码、预期输出、图示与解释，再查直接引用它的页面。
更新同一事实的实际使用位置，避免正文说新接口而示例仍调用旧接口。
知识文章更新后仍要能独立发布：不要把解释挪到另一篇，也不要用“见另一篇”补全；
确实需要的前置知识写回本文；用不到的不补。
更换标题或拆页时核对标题锚点和入链；只因普通“相关阅读”链接相连不算需要重写。

可更新图就同步更新；图暂时无法修正时就近标明哪部分过时，必要时取消误导性嵌入，保留源附件。
已有待生成图时同步修订其提示词、标签和适用版本；需要重生的角色图继续用原身份参考，
按 [个人 IP 与生图交接](personal-ip.md) 留下更新任务，不能让旧提示词生成已被纠正的知识。
依赖新环境的代码未运行时说明只据文档修订及尚待验证的行为；旧实验保留当时版本和结果，
不能将其改写为新版本实验成功。无法安全执行的验证留缺口，不为了凑齐结果制造运行记录。

如果传播影响超出请求范围，列出受影响的具体页面和原因；已获授权的关联修订继续完成，
无依据的全库改写和递归扫链不属于默认动作。独立工作记录只作为来源或普通链接，不同步业务状态。

## 核验范围比“更新于今天”更重要

回读修改后的论证是否自洽：结论、条件、示例和来源是否一致，个人理解及有效旧内容是否还在。
事实核对、语法检查、实际运行和视觉检查各自只证明其覆盖的部分。

仅核对某一节时，在该处简短注明来源、版本和核验范围，不把整页 `review_state` 改成 `current`，
也不刷新表示整页已核验的 `verified_at`。原来的页面级状态若已会误导，应改为待复核并说明已核对/未覆盖的范围。
只有本次确实覆盖笔记的关键结论及所声明条件，才更新页面级核验字段；这些字段仍然是可选的。
来源读取日期不冒充验证日期，排版更新不冒充知识更新。

正文保持可直接阅读的当前解释。只有理解变化需要追溯时才留简短更正记录：
例如“原先将 A 视为所有场景的默认值；按某版本文档，A 只在条件 X 下成立，示例已相应调整，尚未运行”。
旧版本仍有实际用途时用明确的小节或独立旧版笔记承载；无用的旧错误不必永久堆在主文末尾。
不要求统一变更表、全局日志或每次复制完整旧文。

交付说清改变了什么、依据是什么、保留了什么适用条件、哪些地方仍未核实。
发现新来源、用户遇到问题或主动复核时使用此流程；建立定时检查或后台监控需要另有明确请求。
