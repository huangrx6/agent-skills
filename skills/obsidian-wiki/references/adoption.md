# 渐进采用学习 Wiki

用于用户明确要求升级知识库方法或迁移一个主题。普通写笔记不必读取。

## 先适配一个真实主题

1. 查看现有主题入口、代表性笔记与来源位置，选择用户当前确实在学的问题。
2. 复用目录与可用笔记：区分原始材料、知识结论和个人理解，保留已有链接。
3. 用一份资料更新一个实际结论，再根据笔记回答一个有用问题；需要时做解释或应用练习。
4. 核对是否更容易找到依据、重复资料是否没产生副本、新旧结论是否说清适用条件。
5. 按结果决定要不要增加来源卡、主题索引或视图，再逐步用于其他主题。

没有来源的历史笔记先按现有笔记使用；遇到关键结论时补核实，不批量标记为可靠或补造来源。
不为了统一格式改名、搬空目录、将手写笔记全部冻结为原始材料，或替换所有模板。

## 旧习惯如何替换

| 旧习惯 | 新默认 |
| --- | --- |
| 所有内容先进 Inbox | 已知归属直接进入主笔记；Inbox 只收尚未决定的内容 |
| 收一份资料就写一篇摘要 | 先看它解决哪个问题、改变哪条已有知识；只有保存需求时可只收来源 |
| 按固定篇数建 MOC | 需要导航或学习前置关系时建主题入口 |
| 所有属性都补齐 | 按查询和维护需要增加，旧属性保持兼容 |
| 每次聊天都沉淀 | 普通提问与复习在对话中完成，明确要求保存才写回 |
| 整理目录就是维护知识 | 同时关注依据、适用范围、矛盾和可解释性 |
| 每篇填满相同章节、预留固定配图 | 保留命名和属性兼容，文章按真实问题展开；模板只提供必要起点 |
| 收到新资料就在末尾追加总结 | 定位它改变的旧判断，同步修改相关解释、代码、图和引用 |
| 更新过一段就算整篇已核实 | 标明实际核验范围，未检查的部分不盖上新日期 |

采用新方法时可在本次授权范围内更新知识库内的工作流说明；先展示或保留可审阅差异，
保留仍有效的个人偏好。局部任务中发现旧规则冲突时说明影响，不顺带重写系统规则。
用户要求重构写作方式时，也检查实际资源模板和工作流；仅改 skill 而继续优先执行旧正文骨架，
会让问题复发。先用代表性文章验证；全库现有笔记在阅读、补资料或明确整理时逐步修改。

## 工具作为可替换配件

- 文件搜索和主题入口足以找到材料时，继续使用它们。
- 检索确实漏掉材料时，再评估已有全文/语义搜索；索引是可重建的辅助数据，原文件仍是主档。
- 需要阅读清单、待复核或工作项属性视图时，可使用已启用的 Bases；没有插件时普通链接仍可用。
- 本地文件不等于整个 AI 处理链都离线，不能在未确认工具配置时承诺内容不会离开设备。
- 不因为采用学习 Wiki 自动安装服务、修改应用配置、建立后台同步或定时任务。
