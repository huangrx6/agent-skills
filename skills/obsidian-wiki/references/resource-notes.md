# 学习笔记与复习

笔记应帮助这个读者解决一个实际理解问题。先读用户已有的解释，判断缺的是直觉、推导、证据、
操作经验还是取舍，再决定写什么、写多深。短不等于浅，长也不等于完整；需要深入时把关键推理展开。
每篇按可直接发布的标准写：读者不需要读过其他笔记；本文真正依赖的名词、流程和代码要讲清，
用不到的前置知识不必补。

## 详略：简单处省略，难处讲透

文章不按篇幅均匀分配，而按读者的理解难点分配。

- **简单处不铺陈**：安装命令、显而易见的语法、读者已经掌握的背景、重复结论，一句带过或直接省略。
  不要为了显得完整把每一步都写成教程。
- **名词第一次出现要讲清**：它指什么、为什么存在、解决什么问题、和相邻概念的区别、
  在本文链路里的角色。不要用另一个未解释的名词定义它，也不要用“顾名思义”“详见上文”代替解释；
  必要时给最小例子或类比。
- **繁琐流程要拆开**：写清输入、输出、状态变化、失败分支，以及“为什么不能合并/跳过”。
  步骤多时用编号、阶段表或图；不要用一段长句概括。
- **相关代码要讲**：给出文件和函数位置、输入输出、关键行在做什么、默认值与边界；
  只贴代码不解释等于没写。简化片段标明省略了什么，伪代码标明不是可运行代码。
- **纯文字讲不清时换表征**：目录树、时序表、状态表、最小例子、代码走查、图都可以；
  不要反复用更抽象的句子解释同一个难点。
- **判断标准**：读者能否用自己的话复述这个名词、这条流程、这段代码的作用。
  不能，就补例子、图、逐行说明或最小运行方式；不要只加“很简单”“显然”之类的话。
- **讲仔细不等于每处都长**：难点展开，简单处收住。删的是重复和显而易见，
  不是理解所需的中间步骤。

例：讲一次启动链路，不必解释 `cd` 和 JSON 是什么；但 `trusted` 这类名词、
三个阶段的先后、以及决定默认值的表达式，要讲到读者能复述。

## 让内容决定文章结构

先想清读者读完能解释或完成什么，以及哪些材料最能帮助他到达那里。由此选择叙述顺序，
不要先套“概念/机制/工具”分类再填章节。这个判断通常在写作时完成，不必另交提纲、让用户选模板。

例如，纠正误解可以从一个反例开始；排查记录可以跟着现象、假设与证据推进；
理解机制可以追踪一个输入经历的变化；做选择可以先写当前约束，再比较真正会改变决定的差异。
这些是展开内容的可能方式，不是四套固定模板；一篇文章也可以自然组合它们。

章节标题尽量指出本节的问题或判断。若把主题名换掉，整套标题仍适用于任何文章，
检查是否只剩通用外壳。相近内容使用相近结构没有问题，不为追求差异刻意打乱有效顺序。
已有的“概念、例子、步骤、误区、总结、配图”只是候选材料；有助于理解才保留，
不为凑齐栏目扩写。用户指定教程、速查表或固定格式时遵从本次要求。

保留用户自己的解释与例子，指出具体理解缺口，再用来源补充。
有价值的犹豫、失败尝试和不确定性可以留在文中，不把个人学习过程抹平成百科口吻。
只改排版时保留事实和细节；重组长文时先辨认论点、例子和独有信息，删去重复而不是把深度删掉。

## 示例与准确性

- 例子用来验证或解释具体判断，不为每篇强塞代码、命令与 JSON 响应。
  可运行示例交代影响复现的版本、依赖、运行方式和预期现象；局部片段说明省略的上下文。
- 配置解释真正改变行为的字段、所在层与后果；无关参数可链接参考，不逐项铺满正文。
- 当前 SDK/API 和版本差异查一手来源；语法检查不等于运行验证。
- 研究结论、作者主张、个人推断与实际实验结果分开，不把“未运行”写成成功。
- 不把某次示例的供应商、模型名或工具固化成所有主题的默认选型。

源码走读、架构说明和机制型长文另按 [机制与源码解读](source-review.md) 组织：
先给心智模型，再落到源码；动作词、绝对化措辞和跨篇一致性按那篇检查。

正文排版见 [写作规范](writing-conventions.md)；查证见 [研究与综合](research-and-synthesis.md)；
新材料改变旧认识时走 [知识更新](knowledge-updates.md)，不要把补丁一律追加成“补充说明”。

## 复习方式

用户要求自测时，围绕实际目标选择解释、辨别反例、推演或小应用题。
互动复习先出题，等用户回答后再指出缺口；用户要求题单和答案时提供独立可读的答案。
不要默认加题库、记分、定期提醒或完成百分比；要求记录学习进度时才保存实际练习结果。

## 图示与拆分

完整写作或实质性改写时，在安排结构阶段执行 [技术配图](technical-visuals.md) 的判断与落地流程，
正文完成后核对是否落实。数量由各图解决的问题决定，不预设一张就够、每节必配或固定总数。
图放在相关解释附近，正文点明该看哪里。暂时不能生图或由用户自行生成时，按
[个人 IP 与生图交接](personal-ip.md) 留下明确标为待生成的 Callout；它是制作待办，不是已完成的图片。

能独立解释和复用的内容再拆页，保持每篇解释完整；文章间导航按写作规范交给 MOC。
拆分后每篇仍要自包含，不能把前提留在原篇；维护受影响的旧入链，不自动在新文章间添加互链。
删除正文中的图与删除源附件分别处理；源附件清理须在用户要求范围内且确认无其他引用。
