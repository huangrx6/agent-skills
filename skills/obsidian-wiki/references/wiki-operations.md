# 吸收、查询与维护

## 吸收一份材料

1. 确定要补充的学习问题和材料范围。用户只要暂存时保存可检索来源，不强制研究整合。
2. 按标题、原始 URL/文件、主题关键词查已有来源和相关知识页。
   同标题不代表同一份材料；同 URL 也可能内容已更新，核对版本或读取到的差异。
3. 阅读材料及与它直接相关的现有结论，判断是新信息、补充证据、版本变化、分歧，还是重复。
   完全重复且没有新的核对结果就不重写文件、不刷新日期、不追加空操作日志。
4. 保留来源定位；已有知识需要变化时按 [知识更新](knowledge-updates.md) 修订具体结论及相依内容。
   新建或重组文章时按 [学习笔记](resource-notes.md) 选择结构。用户明确要求新建专题时可建最小主题页，
   不先生成一整套目录、摘要、概念、人物与组织页面。
5. 检查新结论是否影响其他已引用它的页面。只更新有明确影响的内容；无法判断则标记待核实。
6. 更新确有必要的主题入口，说明学到了什么、改变了哪些结论、哪些仍未验证。

材料获取失败时可以整理已知题目和待核实问题；不能以搜索摘要、推断或模型记忆假装读取成功。

## 查询和复习

先读相关主题入口、文件名命中或关键词结果，再读匹配正文；问题涉及版本、数值、争议或执行方法时，
回到直接来源核对。找不到时先扩大同义词和相关主题范围，再说明“本次未找到”，不等同于全库不存在。
默认使用现有文件搜索；已有检索工具可辅助召回，但仍回读原文件，不能把搜索结果片段当完整证据。

- 用户问“知识库里怎么说”：优先用现有笔记回答，指出来源范围与未知项。
- 用户问“现在是否还成立”：核对当前一手来源，并说明新旧信息的时间/版本区别。
- 用户要复习：围绕概念解释、具体例子、反例或应用问题出题，先让用户回答，再给反馈。
  不主动记录得分或把知识库标为已掌握；若用户要求记录，再保存其实际回答反映的薄弱点。
- 普通查询、出题和只读检查不写文件或日志。用户要求保存答案时，先匹配现有主题再写入。

答案把“已有笔记记载”“原始材料支持”“本次综合推断”说清楚。
外部补充资料单独标注，不能让用户误以为它原本就在库里。

## 按问题做健康检查

“帮我检查”默认报告，“修复这些问题”才落实修改。检查范围先从指定主题开始：

| 检查 | 判据 |
| --- | --- |
| 依据 | 关键结论能否回到实际读过的材料，是否只是 AI 页面之间循环引用 |
| 适用性 | 版本/环境是否明确，是否已有取代当前结论的新证据 |
| 一致性 | 同一对象和条件下是否存在相互矛盾的描述 |
| 可学习性 | 能否解释核心机制、举例或应用，是否只有术语堆积和摘要拼接 |
| 导航 | 重要知识能否从合理入口找到，是否有重复主笔记与失效链接 |

区分确定问题、需要用户判断的问题和可选改进。只有导航价值才补索引，不为消除所有孤立页制造链接。
结构脚本检查文件存在性；语义审阅检查证据是否支持结论，两者不能互相替代。

根据检查结果修订时，适用版本、关联影响与核验记录统一见 [知识更新](knowledge-updates.md)。
