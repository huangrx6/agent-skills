# 个人 IP 与生图交接

用于 Wiki 配图中的小研究员角色，以及不能直接生图时的交接。与 [技术配图](technical-visuals.md)
一起使用；普通文字修订不读取角色资产、不批量改旧图。

## 用图片固定身份，用文字指定任务

用户提供的 [角色原图](../assets/personal-ip/researcher-v1-reference.png) 是 `researcher-v1` 的身份基准。
这是角色和动作设定板，不是透明贴纸，也不是待复制的知识图。每次制作涉及角色的图时实际查看它，
调用支持参考图的工具时传入图片本身；写一个本地路径或“同上一个人物”不等于模型收到了参考。
无法看图时说明限制，交接原文件，不声称已检查一致性。

当前原图 SHA-256：`361acaed92f668bdc3b4346931c3dd75659f0486f9e85cc8e02b3935ba116560`。

身份特征以图为准，以下文字辅助提醒：

- 灰黑色蓬松短发、侧分弧形刘海和头顶小翘发；圆润脸型、小圆耳，黑色点状眼睛、小鼻嘴和粉色腮红。
- 浅蓝毛衣配露出的白色尖领；头身比例、五官位置和线条保持参考图中的卡通比例。
- 深灰略不规则的手绘轮廓、温和的铅笔/蜡笔质感；神态亲切、专注。

动作、表情、视线、手持道具和人物位置可随知识变化，发型、脸型、服装主色及画法保持一致。
笔记本、笔和指示棒是可选道具，不是每张必备。参考图里的电脑品牌标志、标题和分区文字不属于人物身份。
参考未展示的全身细节不自行定义为新标准；先选已有视角，新角度有必要时注明仍需确认。

默认跟随本 skill 携带该角色；用户明确不用人物、提供新的角色或指定其他风格时尊重本次要求。
只有明确要求更新角色设定才替换身份基准，普通生成结果不能自动成为下一张的新参考。
原图保持原文件；后续用户认可的角色升级另存新版本，旧图及旧任务仍能找到所用版本。

## 选择可执行的路径

| 实际能力或请求 | 执行方式 |
| --- | --- |
| 有生图工具且支持参考图输入 | 传入角色原图和本次完整任务，明确其他参考各自用途；检查产物再插入 |
| 已有用户认可的角色贴纸，且可用排版工具 | 复用贴纸文件，把人物、精确标签和知识结构分别排版；避免每张重新绘制人物 |
| 能生成图但不能输入参考，或本次只有文本能力，或用户自行生成 | 输出待生成块及真实参考附件，不能用纯文字生成人物后称为同一 IP |
| 只需要精确工程结构，人物没有解释作用 | 用当前可用的图形工具完成，不因缺少生图能力就阻塞整篇笔记 |

目前内置的只有角色原图，**尚无已确认的独立透明贴纸包**。未来需要稳定重复的动作时，可从原图制作少量
思考、讲解、记录等角色素材，经用户认可后复用；不要把整张设定板缩小当贴纸，不擅自批量生成姿势库。
同一成图内精确技术结构和标签可由 Mermaid、SVG 或排版工具承担，人物负责解释和引导。
人物也可参与情境、对照实验或操作示意；既不限定为角落装饰，也不替代真实数据与关系。

参考图能约束身份，但不能保证生成模型每次完全一致。固定种子或堆叠负面提示词不能替代带图输入与视觉核对；
工具支持参考强度时按其实际接口设置，未提供该能力就不编造参数。需要完全一致的角色像素时复用已确认素材，
变化发生在结构和排版层。单张失败优先修正具体偏差，连续修正仍不合格则保留为待生成，说明原因。

## 让用户一眼看到该生成什么

使用 [待生成块模板](../assets/templates/image-task.md)，按每张图填入真实内容；最终交接不能残留模板变量。
可参考 [缓存读路径交接示例](../examples/personal-ip-handoff.md)，借鉴交接方式，不把其版面和内容当作所有图的模板。
默认在图应出现的段落后放 `[!todo]+ 配图待生成 · 图号 · 图名`，展开可见，支持 Obsidian 原生样式，
不用自定义 CSS 或插件。任务包含：

- 一个文内稳定图号（如 `fig-01`）、要解释的问题及必要适用条件。
- 要上传的参考文件名与可点击附件，明确“上传图片后再粘贴提示词”；本地链接不会自动上传到外部工具。
- 独立可读的完整提示词：角色身份、内容关系、动作作用、构图、画幅、精确标签和禁止推断的部分。
- 相对于 vault 的最终保存路径、图注，以及补图时要检查的关键点。

首次在一个 vault 中交接时，把原图按原字节复制到该库的附件目录，默认建议
`90 Assets/Attachments/personal-ip/researcher-v1-reference.png`；先读取实际附件约定。
目标已有同名文件时核对内容，相同即复用，不同则保留双方并使用可区分的名称。
不要在笔记里引用聊天临时文件、安装目录绝对路径或其他模型访问不到的隐式历史。
没有可写 vault 时，把交接 Markdown 和参考图放在用户指定的交付目录，用相对 Markdown 链接；
不能复制附件时说明现有可取路径和缺口，不能伪造已复制。

默认直接在待生成块内给完整提示词；图多或提示词较长时，可保存到同附件目录的一个配图任务 `.md`，
正文保留短待生成块链接到具体图号。它是本篇的制作附件，不另建全库台账。用户只要提示词时直接交该文件。
输出路径先用行内代码呈现，文件存在并检查后再改成图片嵌入，避免产生断链。

## 成图、补图与更新

逐张核对人物发型、脸型、领口、毛衣色与质感，再核对标签、关系、方向和可读性；两类检查不能互相替代。
不要以“生成成功”或“文件存在”声称视觉通过；未能查看产物就保留“待检查”状态。
人物不遮挡节点和连线、不把图文挤满；技术内容发生变化时复核对应图和提示词，角色参考无需随知识版本变更。

用户放回文件并要求补图后，按明确图号与路径匹配，不把同一目录的任意新图自动插入。
检查通过后将对应待生成块替换为图片和简短图注，保留原始参考与仍有引用的附件。
为后续重生保留本图提示词及参考版本：已有配图任务文件就更新它；原先内联的提示词移到图片旁的
同名 `.prompt.md` 制作附件，不在成品正文里长期展开。事实改变时同步更新它，不套用旧提示词生成过时图。
不合格的成图留在待检查/待修正状态，说明具体缺口；发布或导出前明确处理尚未完成的任务。
