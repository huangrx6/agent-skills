# 证据规范、严重度与缺陷报告模板

验收报告的唯一价值在于：**让研发不用追问“你是怎么点出来的、算不算严重、哪些其实没测”**，一眼看懂结论、复现路径、客观数值与遗留风险。

---

## 1. 验证前四步门控与零猜测原则

**铁律：没有本轮新鲜验证证据，禁止宣称任何 AC 或维度「通过 / 已修复 / 可发布」。**

在写下任何正向结论之前，必须依次走过四步门控（跳过任意一步等于猜测而非验收）：

1. **识别（IDENTIFY）**：明确要证明的断言需要哪类真实操作、DOM 测量或运行时日志。
2. **执行（RUN）**：在真实渲染页面上新鲜、完整地走完操作与检查，不沿用改代码前的旧截图或旧日志。
3. **阅读（READ）**：读取完整命令退出码、全部 Console/PageError/Network 记录与几何脚本返回，不跳过尾部报错。
4. **核对（VERIFY）**：证据与断言完全匹配才写「通过」；未达标如实写「失败」并附证据；受条件限制未执行则写「未验证（原因）」。

### 严禁出现的自欺红旗措辞

| 禁止表述 | 背后陷阱 | 正确做法 |
| --- | --- | --- |
| 「源码逻辑写对了，应该没问题」 | 静态读码 ≠ 真实渲染交互 | 在真实页面点通并附实测记录；打不开就标「未验证」 |
| 「单元测试全过了，页面肯定通」 | 单测不测 CSS 裁切、焦点环、水合与遮挡 | 运行黑盒页面操作与 DOM 几何巡检 |
| 「刚才已经测过，这次只改了一行」 | 微小改动常引发回归或状态复位断裂 | 针对受影响链路做新鲜复测 |
| 「看截图布局正常，所以触摸拖动没问题」 | 渲染视口只证明布局，不证明手势事件与中断恢复 | 实际执行手势并写清证据来源（合成触摸/真机）与未测项 |
| 「部分场景测过，整体先算通过」 | 局部样本掩盖极端数据与边界崩溃 | 逐项区分「通过 / 失败 / 未验证」，不打包混写 |

## 2. 硬证据采集标准

每条结论（尤其是「失败」缺陷单）必须配齐可回溯的客观证据：

- **运行上下文**：目标 URL / 应用版本、视口尺寸列表（如 `1440×900`、`900×620`、`1280×560`）、缩放倍率、深/浅主题、数据规模（0 / 1 / 30 / 100+）、浏览器引擎与输入方式（鼠标键盘 / 合成触摸 / 真机）。
- **DOM 与几何数值**：涉及溢出、裁切、遮挡或焦点丢失时，附 `scrollWidth vs clientWidth`、`getBoundingClientRect()`、触发元素与 `document.activeElement` 对比、`aria-*` 属性值。
- **Console / PageError / Network 原文**：完整摘录报错类型与首行消息、失败请求的 `METHOD URL -> STATUS` 与触发时机。
- **截图留证卫生**：阻断/高优与视觉布局缺陷保存清晰截图，写明对应步骤与本地临时路径（如 `/tmp/qa-evidence/...`）；**严禁把临时检查截图提交进业务源码库**。

## 3. 缺陷严重度分级量表

| 级别 | 对标 | 判定标准 | 发版影响 |
| --- | --- | --- | --- |
| **阻断（Blocker）** | P0 | 核心主路径不通、白屏/崩溃、数据丢失或写错、核心按钮被遮挡/裁切无法点击、安全或权限越界 | **禁止发版**，必须修复并新鲜复测 |
| **高（High）** | P1 | 切页/关闭状态复位失效、高数量或窄/矮窗严重溢出、纯键盘核心链路断裂或 WCAG AA 明显违规、未捕获 Console Error 或非预期失败请求、5 连击产生重复写入 | **建议发版前修复**；若带病发版须明确降级为「有条件通过」并说明风险 |
| **中（Medium）** | P2 | 边缘校验提示不够清晰、局部主题色漂移、次要视图轻度错位但存在绕行路径、非关键资源告警 | 排期尽快修复 |
| **低（Low）** | P3 | 细微光学对齐、文案标点、动效手感打磨（保持克制，不堆砌琐碎项淹没核心缺陷） | 可随后续迭代优化 |

## 5. 真实缺陷单示范（3 条标杆示例）

### [阻断] #1 矮窗 + 30 条扩展时，底部粘性操作栏遮挡最后一项勾选开关且无法点击
- **页面/区域**：主工作区 → 扩展选择器弹窗（视口 `1280×560`，30 条数据）
- **最小复现步骤**：
  1. 以 30 条扩展数据打开应用，调整视口至 `1280×560`；
  2. 点击「选择扩展」打开弹窗，将列表容器滚动到底部（`scrollTop = scrollHeight`）；
  3. 尝试点击第 30 项右侧的启用开关。
- **实际结果**：第 30 项的下半部分及右侧开关被底部 `position: sticky` 确认栏完全盖住，点击坐标命中确认栏而非开关。
- **预期结果**：列表滚动容器底部预留足够内边距，滚到最底时第 30 项与右侧开关 100% 露出且可直接点击。
- **客观证据**：
  - 几何实测：第 30 项开关 `rect.bottom = 532px`，粘性底栏 `rect.top = 496px`（重叠遮挡 `36px`）；`document.elementFromPoint(cx, cy)` 返回底栏容器 `footer.picker-actions`；
  - Console / Network：无报错；
  - 截图留证：`/tmp/qa-evidence/bug1-sticky-occlusion-1280x560.png`（步骤 3 滚到底部态）。

### [高] #2 切主导航再返回后，扩展选择器残留上次无效搜索词与旧空态
- **页面/区域**：主工作区 → 扩展选择器弹窗（视口 `1440×900`）
- **最小复现步骤**：
  1. 打开扩展选择器，在搜索框输入 `not-exist-qa-999`（列表展示「未找到匹配扩展」空态）；
  2. 不手动清空搜索框，直接点击左侧导航进入「设置」，再切回「主工作区」；
  3. 再次点击「选择扩展」打开弹窗。
- **实际结果**：搜索框仍残留 `not-exist-qa-999`，列表继续停留在「未找到匹配扩展」空态，需用户手动清空才能看到全部扩展。
- **预期结果**：弹窗关闭或主页面切换后，临时搜索词与过滤态干净复位，重新打开展示完整扩展列表。
- **客观证据**：
  - DOM 实测：重开后搜索框 `input.value === "not-exist-qa-999"`，可见列表项计数 `0`（总数据 `12` 条）；
  - Console 告警：`[warning] React key warning` 无新增；
  - 截图留证：`/tmp/qa-evidence/bug2-stale-search-after-nav.png`。

### [高] #3 纯键盘按 `Esc` 关闭扩展选择器后，焦点丢失到 `<body>` 未归还原触发按钮
- **页面/区域**：主工作区 → 扩展选择器弹窗（纯键盘路径）
- **最小复现步骤**：
  1. 使用 `Tab` 将焦点移至「选择扩展」按钮，按 `Enter` 打开弹窗；
  2. 在弹窗内按 `Tab` 两次确认焦点在内部控件上；
  3. 按下 `Esc` 关闭弹窗，立即再按一次 `Tab` 观察焦点位置。
- **实际结果**：弹窗关闭后 `document.activeElement` 退回 `<body>`，再按 `Tab` 焦点跳回页面左上角第一个导航链接，键盘用户被迫从头重新导航。
- **预期结果**：按 `Esc` 关闭弹窗后，焦点准确归还给原「选择扩展」按钮，方便用户继续原有工作流。
- **客观证据**：
  - DOM 实测：`focus_restored = { restored: false, activeTag: "BODY", activeText: "" }`；
  - Console / Network：无报错。
