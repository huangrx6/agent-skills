# Acme Pay 后端编码规范（主规范 · 语言无关）

> 适用范围：Acme Pay 后端各模块。**语言实施细节见 `coding-standards-java.md`**，
> 技术栈与约束见 `project-profile.md`。编码前按序阅读三份。本文件遵循 SKILL 九段结构。

## 1. 目标、适用范围与规范强度

**目标**：模块化、命名与测试一致，规则尽量可自动验证。

| 强度 | 含义 |
| --- | --- |
| 必须 (MUST) | 违反即构建失败或评审不通过 |
| 应 (SHOULD) | 默认遵守，偏离需说明理由 |
| 可 (MAY) | 推荐，按场景取舍 |

机械格式（缩进/空白/导入）由格式化器自动执行，评审不讨论。

## 2. 命名与术语

- 类型=名词短语，函数=动词短语，布尔=可判定命题（is/has/can），集合=复数。
- 同一概念跨代码/API/配置/文档用同一术语。
- 单位、时区在易混淆时体现在名称或类型（如 `timeoutMs`、`createdAtUtc`）。
- 数据库表名单数 snake_case 带模块前缀；布尔列用 `is_`/`has_` 前缀。
- 语言具体命名表见 Java 附录 §1。

## 3. 格式化、文件和目录

- 每种语言指定**唯一**格式化器；输出是机械样式的事实来源，评审不讨论空白。
- 使用 `.editorconfig` 统一编码/换行/缩进/尾随空白。
- 目录按业务能力组织，避免 `common`/`utils` 杂物箱；禁止循环依赖。
- 生成代码与手写代码隔离。
- 具体格式化器与命令见 Java 附录 §2。

## 4. 文件头、许可证和版本信息

- 默认**不**在源文件手工维护个人作者、创建时间、最后修改时间、文件版本——Git 为事实来源。
- 许可证信息优先用 SPDX 短标识（如 `SPDX-License-Identifier: Apache-2.0`）。
- 生成文件头标注生成器版本与来源，且可重复生成。
- 版本信息在包清单/发布标签中维护，不在源文件重复。

## 5. 注释与文档

- 注释解释**为什么**、约束、不变量、风险，不复述代码表面行为。
- TODO/FIXME 关联可追踪事项编号，说明原因或退出条件。
- 公共 API 文档面向调用方，说明参数/返回/失败/副作用/线程安全。
- 代码变更时同步更新相关注释，不留孤儿 Javadoc。

## 6. 设计原则与设计模式

- KISS/YAGNI 优先；模式只在真实变化点、边界或协作问题时使用。
- 优先组合而非继承；优先不可变数据与显式状态转换。
- 引入模式后，职责/生命周期/失败行为必须清晰，并有测试证明收益。
- 治理反模式：God Service、循环依赖、贫血模型、过度通用 utils。

## 7. 实现质量、安全、并发和性能

- 空值语义明确；优先可选类型/结果类型，不捕获后返回默认值掩盖失败。
- 安全：密钥哈希存储禁止明文；信任边界验证输入；数据库用参数化接口。
- 并发：明确所有权与线程安全；异步支持取消与超时；不持锁做不受控 I/O。
- 性能：先保证正确性与可读性，再依据测量优化；缓存/队列设容量上限。

## 8. 测试、评审和自动化

- 测试分层：单元=领域纯逻辑，集成=引导模块集中，E2E=HTTP 纯文本断言。
- 测试隔离：不依赖执行顺序、真实时钟、公共互联网；不用任意 sleep。
- 测试命名表达"条件-行为-结果"。
- CI 质量门禁：格式检查、编译类型检查、静态分析、单元与集成测试、依赖/许可证/安全扫描、生成代码一致性。
- 评审同时检查设计、复杂度、命名、注释、测试与文档。

## 9. 语言实施附录

- 多语言项目区分主规范与语言附录；冲突按优先级裁决（编译器/运行时 > 语言官方工具 > 框架 > 仓库自动化 > 组织偏好）。
- 语言附录只写"用什么注解/什么工具命令"，不重复主规范的原则。
- Acme Pay 当前仅 Java，详见 `coding-standards-java.md`。
