## 通用原则

命名必须优先表达领域含义，而不是实现细节。

- 同一概念在代码、API、配置、数据库和文档中使用同一术语。
- 名称应准确区分“创建、提交、确认、完成、取消、失效”等业务阶段。
- 避免 `data`、`info`、`obj`、`temp`、`manager`、`handler`、`helper` 等无上下文泛化名称。
- 只使用团队已约定或行业通用缩写，例如 HTTP、URL、ID；自定义缩写必须登记。
- 不使用匈牙利命名法或把语言类型重复写进名称。
- 不用看似精确但实际错误的名称，例如把可能为空的结果命名为 `user` 而不是 `userOrNull`、`optionalUser` 或结果类型。
- 名称长度由清晰度决定，不使用人为统一长度。

## 标识符命名

大小写遵循语言官方约定，并在项目内保持一致。

通用语义规则：

| 对象 | 要求 |
| --- | --- |
| 类型 | 使用名词或名词短语，表达稳定职责 |
| 函数 | 使用动词或动词短语，表达动作与结果 |
| 变量 | 表达业务含义、生命周期和单位 |
| 常量 | 表达稳定概念，不把所有局部不可变量都视为全局常量 |
| 异常 | 明确失败原因，通常以语言惯例的 Error/Exception 结尾 |
| 事件 | 使用已发生事实，例如 `OrderPaid`，避免命令式名称 |
| 命令 | 使用动作意图，例如 `CancelOrder` |
| 查询 | 表达读取意图，不暗示副作用 |

避免数字后缀和临时名称，例如 `user1`、`user2`、`newData2`。确有顺序语义时使用 `previous`、`current`、`next`、`primary`、`fallback`。

## 布尔值、集合与单位

布尔名称应构成可判断命题：

```text
isEnabled
hasPermission
canRetry
shouldRefresh
```

避免含义不清的否定叠加，例如 `notDisabled`、`disableFlag`。

集合名称应体现复数或容器语义：

```text
orders
ordersById
pendingOrderIds
```

容易混淆时，名称或类型必须包含单位：

```text
timeoutMs
sizeBytes
amountCents
createdAtUtc
```

更优先使用带单位或领域含义的值对象，避免裸数字。

## 类型与接口

- 类型名应表达职责，不表达技术噪声。
- 接口名描述能力或角色，不强制统一加 `I` 前缀，除非语言和团队约定要求。
- 实现类名不得只是在接口名后加 `Impl`；应表达具体策略、协议或存储方式。
- 枚举成员使用同一语法层级，避免混合状态、动作和错误。
- DTO、Entity、Model 等后缀仅在能清晰区分边界时使用。
- 泛型参数使用语言惯例；复杂泛型使用语义化名称而非连续单字母。

## 函数与方法

- 名称必须与副作用一致。
- 查询函数不得隐藏写入、网络调用或全局状态修改。
- 返回布尔值的方法使用命题式名称。
- 转换函数优先使用 `toX`、`fromX`、`parseX`、`formatX` 等一致术语。
- `get` 不应掩盖昂贵计算或远程调用；名称应提示潜在成本。
- 异步函数是否使用 `Async` 后缀遵循语言和框架惯例，不跨语言强制。
- 避免 `process`、`handle`、`execute` 等泛化动词，除非上下文已明确职责。

## 文件、包与模块

- 文件名遵循语言和构建工具惯例。
- 包或模块名使用稳定领域概念，避免 `common`、`utils` 成为无边界杂物箱。
- 目录优先按业务能力或清晰模块组织，而不是无限按技术层分割。
- 测试文件名应能映射被测行为或模块。
- 迁移、脚本和配置文件使用可排序、可追踪名称。

## 测试命名

测试名应表达：

- 前置条件；
- 被执行行为；
- 预期结果。

可使用语言惯例的形式：

```text
givenExpiredToken_whenRefreshing_thenReject
refresh_rejects_expired_token
TestRefresh_ExpiredToken_ReturnsError
```

禁止 `test1`、`normalCase`、`works` 等无法定位意图的名称。

## 公共 API

- 公共名称是兼容性契约，发布后谨慎修改。
- API 名称使用调用方领域语言，不泄露内部数据库或框架概念。
- 参数名称表达语义和单位。
- 避免多个同类型位置参数；使用命名参数、配置对象或值对象。
- 公共 API 的空值、失败、幂等性、副作用和线程安全必须明确。
- 已发布 API 的重命名必须提供兼容迁移方案。
