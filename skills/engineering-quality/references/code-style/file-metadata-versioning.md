## 默认策略

普通源文件默认不手工维护以下字段：

```text
Author
Created
Last Modified
Version
Change History
```

原因：

- Git 提交历史、作者和 blame 已提供更准确的追踪；
- 手工字段容易过期、冲突或泄露个人信息；
- 文件级版本通常与包、模块或产品版本不一致；
- 修改历史应保存在版本控制和变更记录中，而不是不断增长的文件头。

如法律、监管、客户交付或代码生成流程强制要求，才使用文件头，并保证字段可自动生成和校验。

## 许可证与版权

- 许可证信息必须遵循组织法务和仓库许可策略。
- 开源或多许可证场景优先使用 SPDX 短标识，例如：

```text
SPDX-License-Identifier: Apache-2.0
```

- 不自行改写许可证名称或拼接非标准表达式。
- 版权主体优先写组织，不默认写每位个人贡献者。
- 年份策略由法务确定；不得要求开发者每年手工批量修改所有文件。
- 完整许可证文本应放在仓库许可证文件中，源文件仅保留必要短标识。

## 作者信息

默认禁止把个人姓名、邮箱或工号作为必须文件头字段。

责任归属优先通过：

- 代码所有者配置；
- 模块维护者清单；
- Git 历史；
- 团队或领域 Owner；
- 工单和评审记录。

确需作者字段时，应使用团队或组织角色，而非可能离职或变化的个人：

```text
Owner-Team: Payment Platform
```

不得把文件头作者视为唯一所有者或审批人。

## 时间信息

默认不写 `Created` 和 `Last Modified`。

需要时间字段时：

- 使用 ISO 8601/RFC 3339 格式；
- 明确时区，优先 UTC；
- 由生成器或 CI 自动写入；
- 不手工更新“最后修改时间”；
- 区分源代码创建时间、构建时间和发布版本时间。

示例：

```text
Generated-At: 2026-08-07T03:00:00Z
```

构建产物需要可复现时，不应把每次构建的当前时间无条件写入源码或产物内容。

## 版本信息

版本的事实来源应是：

- 包或模块清单；
- 发布标签；
- 构建系统；
- 制品仓库元数据；
- API 或数据库 Schema 版本。

普通源文件不维护独立 `Version: 1.2.3`。

语义化版本只适用于已定义公共 API 的发布物。公开 API 文档可使用语言支持的 `since` 标记，但不得在每个文件重复整个产品版本。

生成文件可记录生成器版本：

```text
Generator: schema-codegen/2.4.1
```

数据库迁移、协议 Schema 和序列化格式应使用其领域约定的显式版本机制。

## 允许使用文件头的场景

文件头适用于：

- SPDX 许可证标识；
- 法律要求的版权声明；
- 自动生成代码标记；
- 协议或 Schema 生成器版本；
- 安全分类或出口控制声明；
- 客户合同强制的稳定元数据；
- 需要由工具识别的机器标记。

文件头不得用于：

- 记录完整修改历史；
- 替代 Git；
- 重复包版本；
- 保存个人联系方式；
- 记录会频繁过期的说明；
- 放置大段模板化注释降低可读性。

## 推荐模板

最小许可证文件头：

```text
// SPDX-License-Identifier: Apache-2.0
```

生成文件头：

```text
// SPDX-License-Identifier: Apache-2.0
// 由 schema-codegen/2.4.1 自动生成，请勿手工修改。
// Source: schemas/order.proto
```

确有组织元数据要求时：

```text
// SPDX-License-Identifier: Proprietary
// Copyright: Example Corporation
// Owner-Team: Payment Platform
// Classification: Internal
```

不推荐加入个人作者、创建时间、最后修改时间和文件版本。
