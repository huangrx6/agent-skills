## 分层原则

- **主规范**（语言无关）：模块边界、DDD/分层、命名语义、安全/事件/测试原则、质量门禁——任何语言都适用。
- **语言实施附录**：具体大小写、框架注解、格式化器、测试栈、共享工具类名——随语言/框架变化。
- **项目画像**：技术栈、模块清单、依赖 DAG、构建/测试命令——项目特有事实。

三者分离的好处：换语言只改附录，不动主规范；AI/人按任务只读相关文件，不必通读。

## 推荐目录结构

```
docs/standards/
├── README.md                         # 索引 + 按任务导航（见下）
├── <project>-profile.md               # 项目画像：技术栈/模块/依赖/命令
├── coding-standards.md                # 主规范（语言无关）
├── coding-standards-<lang>.md         # 语言实施附录（每语言一份）
│   例：coding-standards-java.md
│       coding-standards-ts.md
├── comment-standards.md               # 注释规范（项目级，可跨语言）
└── frontend/                          # 前端独立子目录（技术栈差异大时）
    └── ...
```

命名约定：
- 主规范固定名 `coding-standards.md`，被画像和索引引用，改名会破坏链接。
- 语言附录用 `coding-standards-<lang>.md` 后缀，便于 grep 和排序。
- 画像、注释、日志等按主题命名，不绑语言（项目级规则跨语言共用）。

## README 索引与按任务导航

README 同时给"按文件浏览"和"按任务导航"两个入口：

```markdown
## 按任务导航

| 任务 | 先读 |
| --- | --- |
| 任何后端编码 | profile → coding-standards（主规范）→ coding-standards-java（附录） |
| 改持久化 | coding-standards-java §持久化 |
| 加日志 | logging-standards.md |
| 前端编码 | frontend/ 下对应文件 |

## 目录索引

| 文件 | 层级 | 内容 |
| --- | --- | --- |
| coding-standards.md | 主规范（语言无关） | 分层/边界/命名语义/原则/门禁 |
| coding-standards-java.md | 语言附录 | 命名表/格式化/持久化/事务/测试 |
```

## 落地步骤

1. 先定**项目画像**（技术栈/模块），再定主规范，最后写语言附录——顺序错了会重复返工。
2. 主规范只写"是什么/为什么"，语言附录写"用什么注解/什么工具命令"。
3. 每条规则标注 `[必须/应/可]` 与"可自动化/需评审/仅合规"。
4. 语言附录开头声明"配合主规范 §x 阅读"，避免重复规则。
5. 产出后用 `standard-completeness-checklist.csv` 自查九段覆盖。

## 单语言仓库的简化

若仓库只有一种语言（如纯 Java 后端），可把主规范与语言附录**合并为一份**，但务必在开头声明"本规范 = 主规范 + X 语言实施附录"，并在文档内用层级标注区分语言无关规则与语言实施细节——为将来引入第二语言留拆分接口，不必提前拆文件。
