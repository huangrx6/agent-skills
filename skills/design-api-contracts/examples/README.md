# 示例：API 契约产出样例（虚构项目）

> 本项目设定：虚构公司 "NovaPay"（与其他 skill 示例同项目），REST + Webhook 接口。
> 演示用本 skill 产出的契约风格选择 → 资源与 Schema → 版本兼容 → 错误响应。
> **本示例不抄用、仅作参照——实际项目以自身交互模型和运维约束为准。**

## 文件

- `contract-brief.example.md` — 风格选择 + 资源建模 + 版本兼容 + 错误契约端到端示范

## 要点

1. **先选协议再写接口**：根据交互模型选 REST/gRPC/GraphQL/Webhook，不默认 REST。
2. **资源建模优先**：URI 表达资源而非动作，特殊动作用命令资源或子资源。
3. **HTTP 状态码 + 业务错误码分离**：状态码表达协议语义，code 表达具体原因。
4. **兼容矩阵驱动变更**：每个变更走"兼容/BREAKING"分类，BREAKING 必须发新版本。
5. **9 风格各有适用场景**：强制选 REST 之前先看场景表。
