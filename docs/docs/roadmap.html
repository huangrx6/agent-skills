ROADMAP.md

优先解决的问题

方向 后续工作的判断依据
产物质量 用实际生成的 deck 和技术图检查层级、留白、文字可读性、连接关系和导出差异；不把静态检查当视觉验收
可移植性 在缺少可选依赖、安装成副本、路径含空格等环境验证；准确区分降级、跳过和失败
外部服务 接口或认证行为变化时补可复现夹具；真实写入验证只在用户授权的目标范围执行
PingCode 周报 用真实项目验证 check/weekly；空项目、缺字段、缺下一迭代和截断必须显式报告，不把空周报当完成
触发边界 根据真实误触发、漏触发案例改进 description，用正例和近似反例评估；不靠关键词数量推断效果
文档一致性 命令和限制以实现为依据，清理被替代的流程；动态数字从运行结果取得
COSMIC 口径 用真实送审项目校准句式、排序与覆盖清单；本地惯例只提示，不反向决定计量

有真实需求再扩展

  • Deck 的新页面类型、图表组合、注释或导出能力，需要同时补输入契约、浏览器产物与导出验证。 现有格式不支持时明确报告，避免静默丢失内容。
  • 技术图的新后端或专用图元，需要明确可编辑程度、样式映射和布局限制。
  • Obsidian 以学习 Wiki 和独立工作台演进：用真实学习效果验证来源整合与知识更新，用实际工作项验证去重、分工和状态。 关联保留在普通笔记链接和外部来源字段中；只有检索或视图成为实际瓶颈时再接入工具，不引入跨 skill 必需依赖。
  • 学习路线：用真实学习目标验证资料质量、路线可执行性和 HTML 的可读性；已加入本机进度、 测验、间隔复习和 Markdown 导出。下一步只在真实使用后扩展团队上手包、云同步或自动知识库写入。
  • 新工具集成先判断现有 skill 能否组合完成；只有独立可复用的流程才增加入口。

完成标准

实现、说明和可用命令相符；对应回归通过；引用与安装状态可核验。 涉及视觉、导出或外部服务时，说明实际验证的环境和仍未覆盖的部分。 已完成且不再影响未来决策的记录留在 Git 历史中，不继续追加到本文件。
