Obsidian 学习 Wiki

以学习为主的知识 Wiki：把资料融入已有知识，按笔记提问、复习，并随新证据更新结论。

SKILL.md·README.md
适合 产物 依赖
新建 Wiki · 吸收文章 / 课程 · 主题更新 · 按笔记问答与复习 可分享的库结构 · 知识笔记 · MOC · 证据链接 Obsidian · Python 3.10+（标准库）

保留原有 PARA 目录，同时区分来源、知识和学习入口；不要求另建 raw/wiki 顶层目录。

这个 skill 可以单独安装运行，不依赖工作记录 skill、PingCode、数据库或插件。 工作笔记可作为学习来源；知识文章按可直接发布到公众号/博客的标准写，正文不依赖其他库内文章，笔记间导航只放 MOC，保留外部证据来源。 不会触发任务同步或自动生成工作记录。

使用场景

  • “把这篇文章融入我的缓存专题，保留原来的个人理解，指出它改变了什么。”
  • “根据已有笔记解释缓存一致性，标出还有哪些地方没证据。”
  • “基于这个主题考我两个应用问题，先别给答案。”
  • “这份新版本说明推翻了旧笔记的一部分，核对并更新。”
  • “检查这些笔记的矛盾和过期结论，先告诉我问题。”
  • “把这篇笔记改名并更新受影响的链接。”
  • “我本地还没有知识库，帮我在这个目录初始化一个可以分享给别人的学习 Wiki。”
  • “这篇像模板拼起来的，围绕真正的问题重组，保留细节和我的解释。”
  • “只更新这份 v2 材料影响的部分；v1 项目仍在使用的操作保留。”
  • “给这篇笔记做知识图解，用我的小研究员 IP；不能生图就把参考图和提示词留在待生成块里。”

资料接收、查询和检查的具体行为见 SKILL.md。查询和复习默认不写入， “保存”“融入”“更新”才在要求范围内修改。需求、缺陷、任务分工不属于本 skill 的业务职责。 整理项目说明、会议材料或润色已有周报时，按 工作材料编辑 处理： 可以保留材料中已有的分工与进展，区分事实、建议和决定；仅编辑文档不会自动变更工作项主档。

配置

安装方式见仓库 README。脚本只依赖 Python 标准库。 下面命令从仓库根运行；安装后可换成对应 skill 的完整脚本路径。

export OBSIDIAN_VAULT_PATH="/path/to/your/vault"
python3 skills/obsidian-wiki/scripts/vault_path.py --explain

也可把路径写为 ~/.agent-skills/config/obsidian-vault-path 的一行文本； AGENT_SKILLS_CONFIG_DIR 可覆盖配置目录，旧文件 ~/.config/obsidian-vault-path 仅兼容回退。 显式路径优先于环境变量，环境变量优先于配置文件；可以单独指定本次库，不要求与其他能力共用库。

如果本机还没有 vault，可以先创建一个可分享的起点：

python3 skills/obsidian-wiki/scripts/init_vault.py "/path/to/your/vault" --git --configure

它会创建最小 PARA 目录、入口页、AGENTS.md、VAULT.md 和 .gitignore，只写缺失文件。 AGENTS.md 约束所有 Agent，VAULT.md 保存库内目录和知识生命周期；已有同名文件不会被覆盖。 --git 初始化 vault 自己的 Git 仓库，--configure 写入当前用户的 vault 路径配置。 skill 代码仓库和 vault 数据仓库分开分享，本机配置不要提交到任一仓库。接收者流程见 初始化与分享知识库。

从旧方式迁移

渐进采用说明如何从一个真实主题开始，不搬空现有目录。 知识模型定义来源、结论、个人理解与可选属性。 已知归属直接更新主笔记；资料先与已有认识比较，再决定是否需要新页面。

文章没有统一章节骨架。学习笔记指导如何从问题选择讲述顺序， 写作规范指导段落、表格、代码、提示块和图的搭配。 沿用的是文件、属性和链接约定，不是旧模板里所有章节。深入解释与简短笔记都可以成立。 每篇以“不需要回看其他库内文章”为标准；本文真正依赖的名词、流程和代码讲清，用不到的前置知识不必补。 详略按理解难点分配：简单处省略，名词、繁琐流程与关键代码讲透。 源码与机制长文按 机制与源码解读 组织：先给可检验的心智模型，再落到源码证据。

知识更新处理“新资料怎样改变旧笔记”：对应到具体结论， 区分补充、修正、版本并存与未决分歧，修订相关示例和图，并说明实际核验范围。 收到新资料、准备应用或用户要求复核时维护；不会自动持续联网、定时改库或要求新建版本数据库。

个人 IP 配图

内置 小研究员角色原图， 配图默认使用与它协调的清爽手绘风格。人物可以讲解、提出问题或参与情境，出现与否由图的解释目的决定。 角色身份以图片为准；构图、知识结构、动作及知识区域的配色随内容变化。

支持参考图输入的生图工具会实际带图生成；没有生图工具、不能输入参考或你要自己生成时， 在笔记对应位置留下展开的 「配图待生成」 Callout，包含参考附件、完整提示词和成图保存路径。 在外部工具中需要同时上传参考图片，只复制提示词或图片路径不能保证同一人物。 补回图片后检查身份和知识准确性，再替换待生成块；提示词作为制作附件保留，便于后续更新。

详见 个人 IP 与生图交接。当前只有角色参考板，还没有确认的独立贴纸包； 要达到人物像素级一致，应复用以后确认的透明素材，不能把参考图生成等同于绝对一致。 此能力不强制安装其他 skill 或插件，也不会自动给旧笔记批量加人物。 可直接查看一份完整的 待生成块示例。

验证与限制

python3 skills/obsidian-wiki/scripts/health_check.py --strict
python3 -m unittest discover -s tests/obsidian-wiki -v

health_check.py 默认检查失效双链和 .obsidian 配置文件路径；--strict 再检查共享前的核心目录与入口， 适合刚初始化的库。单独诊断时再运行 check_links.py 或 check_paths.py。所有检查只读， 支持 --vault PATH、--json 和 --quiet。 退出码为 0 无范围内失败、1 发现问题、2 输入不可用。 链接检查只验证双链/嵌入的文件目标，不覆盖普通 Markdown 链接、标题/块锚点或同名语义歧义。 配置检查只提取常见 POSIX 绝对路径，并启发式区分文件和目录，边界见 结构检查。 这些脚本不证明结论正确；证据、冲突和学习效果需按实际材料审阅。 evals/evals.json 是行为场景，不代表已自动执行全部场景或完成触发基准测试。
