维护与验证

结构检查、回归测试、锁文件与站点构建，各自证明不同的事情。

README.md
结构检查、回归测试与产物质量是三件事。检查通过只说明对应范围，不代表视觉、导出或外部服务已经验收。

维护工具

技能之外的仓库工具放在 tools/，不会被安装到 agent：

工具 作用
skill-builder 编写 / 评审 skill 的指南，以及结构、引用、名称泄露检查器
install_skills.py 把 skills/ 软链或复制到 agent 发现目录
skills_lock.py 记录并校验各个 SKILL.md 的哈希
migrate_skill_home.py 把旧配置 / 缓存迁到 ~/.agent-skills
skill_health.py 仓库体检与维护建议
skill_trigger_log.py 分析本机会话日志，不做触发效果承诺
build_site.py 从 README 与 skill 文档生成项目站点（首页 + docs）

开发与验证

python3 tools/skill-builder/scripts/preflight.py
python3 -m unittest discover -s tools/tests -v
python3 tools/skills_lock.py --check

修改其他 skill 时，把测试目录换成对应名称。preflight.py 只做结构、泄露、指针与文件快照， 不执行回归，也不证明产物质量；Deck 的浏览器与 PDF 测试需要其运行依赖。 tools/skill_health.py 提供维护建议，tools/skill_trigger_log.py 分析本机会话日志。 skill-builder 的写作方法在 GUIDE.md，检查器命令见其 README。

CI 在 .github/workflows/gate.yml：推送与 PR 时跑结构、泄露、 指针、锁文件校验，并按 Python 3.10 / 3.11 跑各 skill 与 tools/ 的回归——版本声明要能被验证。Deck 与 diagram 的重型套件需要 Chrome / LibreOffice，不在 CI 里跑，仍由发布前的人工闸门覆盖：

改动 description 或触发边界后，用 tools/trigger_eval.py 算触发率：数据在 skills/<name>/evals/triggers.json（正例 + 近邻反例），--template 生成待记录结果， --score 算分。方法与判据见 GUIDE。

AGENT_SKILLS_GATE=1 git commit --allow-empty -m "release gate"

提交涉及 skills/、tests/、tools/ 或 .githooks/ 时，可启用仓库 hook：

git config core.hooksPath .githooks
检查 行为
结构、敏感名称、引用目标、文档测试数字 发现错误时阻塞；词表未配置则跳过该扫描
各 skill 与仓库工具回归 默认只提示；AGENT_SKILLS_GATE=1 时阻塞
仓库体检 维护建议，不阻塞
锁文件同步 按暂存区的 SKILL.md 更新锁文件

后续方向见 ROADMAP.md。

仓库结构

agent-skills/
├── skills/        # 10 个可独立安装的 skill
├── tools/         # 安装、锁文件、迁移、体检、skill 编写
├── tests/         # 回归测试，按 skill 分目录
├── docs/          # 生成的项目站点（GitHub Pages 发布）
├── .github/       # CI 与 Pages 发布
├── .githooks/     # 提交检查
└── skills-lock.json
