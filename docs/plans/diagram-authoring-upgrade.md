# diagram-authoring 优化设计与任务

日期：2026-10-16。状态：D01–D05 已验证；D06 已增加矩形内部裁切、文字重叠与遮挡采样，仍部分完成；D09 自由配色阶段已验证、整体部分完成；D07、D08、D10、D11 待实施。

## 问题与目标

当前生成链能把闭合结构规格转换成确定性的可编辑图，但表达目的、图型专属语义、
最终观看尺寸和优质样例尚未形成完整流程。优化目标是提高图的解释力与可读性，
同时保留事实完整性、可编辑性和自动布局的可靠性。

审查参考：cathrynlavery/diagram-design，审查时 main 为
`c417868a79838ce98f37104f51d31b2a9859f317`。
[语义模式](https://github.com/cathrynlavery/diagram-design/blob/c417868a79838ce98f37104f51d31b2a9859f317/skills/diagram-design/references/semantic-patterns.md)、
[观看场景](https://github.com/cathrynlavery/diagram-design/blob/c417868a79838ce98f37104f51d31b2a9859f317/skills/diagram-design/references/output-spec.md)、
[渲染检查](https://github.com/cathrynlavery/diagram-design/blob/c417868a79838ce98f37104f51d31b2a9859f317/scripts/lint-render.py)。
借鉴工作方法，自行实现适配现有后端的代码与示例；不复制其模板、字体或固定审美限制。
后续若直接引入代码/资产，单独记录来源、许可和修改。

## 保留的边界

- `*.diagram.json` 继续表达结构与语义，不接受坐标、像素字号或布局算法参数。
- Excalidraw / draw.io 仍是可编辑交付。默认生成结果不得因新增可选字段改变；已确认的方向、端点和坐标缺陷允许纠正并补回归检查。
- 不强制品牌确认，不为节点数量阈值删除事实，不靠放大 PNG 冒充观看可读性。
- 声明分层：结构有效、语义提示、几何有效、真实导出、目视审查分别记录。
- 本次只改 diagram-authoring、相关测试与本计划；保留其他未提交工作。
- 新专用图型必须有真实图元、布局、验证和两后端能力声明，不能只改白名单。

## 处理流程

用户材料 → 一句话阅读问题 + 受众 → 表达模式（可省略）→ 已支持图型
→ 图型规则 → 结构规格 → 结构/语义检查 → 布局与可编辑输出
→ 观看场景估算 → 官方导出 → 目视审查 → 产物与证据。

表达模式说明必须表达什么；图型决定采用什么布局语法；观看场景决定交付时的阅读条件。
三者独立，不能用“管理层受众”自动删除细节，也不能用“投影场景”自动改业务标签。

## D01：表达意图与路由

新增可选 `intent` 对象：`question`（读者问题）、`audience`（engineer/mixed/executive）、
`pattern`（封闭模式 ID）。允许省略任一项；省略不引发默认生成变化。
它们只供作者、路由与审查使用，不自动修改标签、不选择配色、不调整布局。

模式初始限定于已支持图型：容量与等待、生命周期、主流程与恢复、边界与访问、
主题分解、依赖与影响。每项包含适用触发、必须信息、反例与现有后端限制。
`authoring.py` 是脚本词表的单一来源；正文只保留入口，说明放按需参考。

`guide.py` 维持旧调用兼容，新增 `--pattern`、`--audience`、`--preset`。
自动匹配只供辅助：多模式命中保留候选，显式 pattern 优先；请求时序/泳道/ER 时报告未支持。
不在候选不确定时强制询问；作者能从上下文判断就继续。

## D02：图型语义与提示

`check_semantics.py` 在结构有效后工作，输出 code / subject / evidence / suggestedFixes。
首批只检查可观察事实：判断结果缺失或标签重复、状态转移无事件、孤立节点、
主要强调占比过高、脑图非有向树、模式与图型不一致。

提示不是事实错误证明。孤立节点可能有效、多焦点可能必要，因此默认退出 0；
`--strict` 仅用于受控样例/自动化，存在提示返回 1；坏规格返回 2。
不把这些提示加入布局调参循环：调大间距不能补出缺失的业务条件。

阶段一在技能必经流程中调用检查器；检查器不会产生新图。单独结果可作为审稿附件。
后续语义强约束通过新图型契约引入，不能突然让已有普通规格无法出图。

## D03 / D05：观看场景与真正的排版分开交付

阶段一的 `check_presentation.py` 读取可编辑成品中的尺寸和字号，不修改文件。
支持本工具生成的 Excalidraw 与未压缩 draw.io；draw.io 页签逐页评估。
按目标宽/高扣除边距计算容纳比例，上限为 1；不利用假定放大使小字过关。
`fit` 只测自然尺寸，状态为 not_assessed；其他场景给出低于观看阈值的元素 ID。
阈值是项目初值，需真实样例校准，不宣称 WCAG 认证或普遍视觉下限。

局限：名义字号不等于真实墨迹；draw.io 边标签尺寸、字体替换、手绘笔画均需真实导出复核。
不能将 source-estimate 的 pass 称作 render pass。PNG @2/@3 是采样密度，不是观看尺寸。

D05 已实现：新增不可变 PresentationContext（字体角色、间距、目标画布），显式传入
text_metrics → boxes → layout → backend。禁止靠修改全局 FONT 常量实现预设，防止同进程
多页交叉污染。以 fit 维持当前数值；slide 使用更大的节点/说明/边标签字号，print 使用中间字号。
先布局再判断能否装入目标；装不下返回可读性诊断，不缩字偷偷过关。
最终由 export 层处理固定画框：Excalidraw 可补背景；draw.io 当前仅保证容纳范围，
不得把现有 width+height 说成精确补边成 16:9。

## D04 / D06：样例与真实渲染

每类一个新写的虚构技术案例，避免用客户/生产资料当公开样例。至少包含中文/英文混排、
分支、不同节点间的回边、区域、径向及网络关系。样例给出“应该读到什么”和已知限制。
`examples/manifest.json` 记录 spec、两种源文件、官方 PNG、回执的 SHA-256，
目视审查单独记状态、工具和观察。清单验证不能自动把 pending 改成 reviewed。

阶段二优先依赖已存在的官方导出器，增加实际 SVG 文本/截图边界分析：
测量 font readiness、标签裁切、画布溢出、固定目标尺寸、内容是否完整。
PNG 与 SVG 各有能力边界；不得把无文本信息的 PNG 推断为标签完整。
固定渲染器版本并记录字体环境；浏览器截图需要单独环境权限，不改工作区其他配置。

## D07 / D10：专用图型

状态自环单独设计 loop 路由，绕开节点/标签；label 可以分解 event/guard/action，
迁移期仍支持原字符串。开始/结束为显式语义对象，不靠“最后一个节点”猜终态。
普通图型继续拒绝未实现的自环，不能添加重复状态假装已支持。

时序图需要 participants/messages/fragments，泳道图需要 owners/steps/handoffs，
ER 需要 entities/fields/relations/cardinality；它们不能硬塞到现有通用 nodes/edges 后
假称完整支持。先明确版本化联合 schema 与后端矩阵，再逐种实现，不一次扩展全类型。

## D08：导入与信息变化清单

第一阶段只处理本生成器的输出，优先读取 node_id、edge 端点绑定及分组元数据，
对用户改字保留实际标签。引入中间结构与 import receipt，记录原始/生成数量、
保留/合并/省略/未知对象、每项来源 ID 与原因。不执行外链、不运行嵌入脚本。
输入文件保持不变；输出新 spec，不静默覆盖原图。压缩 draw.io、外部 Excalidraw、
Mermaid 在兼容矩阵中逐步扩展；解析失败不得退回截图猜测并称“无损”。

## D09：品牌与可访问性

配置优先级：显式参数 > 项目配置 > 默认主题。项目配置在项目内，用户共享配置在
安装目录外；使用严格 schema，颜色/字体为数据，不执行其中内容。
不在读配置时改写共享 palette 全局状态；通过渲染上下文隔离多项目/多页。
检查实际文字角色 4.5:1、关键图形 3:1 作为默认质量目标，透明度按实际背景合成；
颜色不是状态唯一标识。SVG 若作为发布产物，增加 title/desc、稳定 ID 和可访问名称。

## D11：评估与后端决策

固定至少六类输入、中文长标签、大量必要关系和品牌要求；同时记录成功与失败。
首轮候选冻结，不提供预期布局；审查关系是否真实完整、最终观看字号、焦点、回路、
可编辑性及修复次数。作者自跑与独立评估分别标记。
只有发布图质量有实证收益时才增加 HTML/SVG 后端；它与可编辑工程图共享语义来源，
能力和交付限制分别说明，不替换现有后端。

### 真实渲染发现并修复的问题

1. **互为反向的两条边被一起反转**：布局临时断环后，原先按节点对猜测是否反转，导致提交和退回的方向可能错误。
   改为逐边保留反转标记，恢复各自方向与标签；含重复正向边的回归检查通过。
2. **draw.io 说明卡片压到节点**：卡片未使用与节点相同的页面平移。统一坐标转换，验证卡片位于节点下方。
3. **非矩形节点端点悬空**：draw.io 使用形状周界，Excalidraw 将端点投影到菱形/椭圆实际轮廓。
   为已有轮廓端点加入舍入容差，避免误选椭圆另一侧交点；两后端实际图片复核通过。

## 第二批：D05 完成，D06 部分完成

### D05 实现

- `presentation.py` 定义不可变的每次生成配置；通过测量、布局参数、区域/卡片、后端序列化与检查传递。
- 两后端新增 `--preset`：fit、doc-inline、doc-wide、slide-16x9、print-a4-landscape。
  默认 fit 与第一批 12 份可编辑样例逐份相等；先生成投影再生成默认模式也不串用设置。
- 投影节点 / 说明 / 标题 / 区域字号为 24 / 20 / 32 / 24；文档为 16 / 12 / 24 / 20。
  投影层间 / 节点间起始距离为 90 / 90，文档为 120 / 120。均为项目设计初值，不是通用标准。
- 显式预设下，draw.io 用不同字号的 HTML span 表达节点说明和卡片标题，避免测量按小字、落笔按大字。
- 生成后按成品实际名义字号复查；装不下给出 `presentation` 提示，不偷偷缩字、删边或修改输入。
  六类测试中的横向四节点架构仍产生投影提示，正确保留为待调整内容，不声称任何图都能自动装进一页。
- 本轮实现重新测量与布局，未自动改方向或拆页。固定 16:9 画框仍由导出器负责。

### D06 已实现范围

`dev-tools/check_render.py` 使用真实 Chrome 测量官方 SVG，核对可编辑源文件，检查：

1. 可见文字及重复标签数量，draw.io 按单元格 ID 对照。
2. 实际箭头/头部路径数量；适配官方 Excalidraw utils 0.1.5 和 draw.io 当前导出结构。
3. 文字及图形是否超出画布、指定画布尺寸是否匹配、目标观看尺寸下文字是否过小。
4. 字体加载状态，以及声明字体的可用性启发式检测（两种回退字体度量比较）。

检查页禁用网络、不跟随超链接；无浏览器记 skipped，格式/能力不支持记 unmeasurable。
结果保存源文件及 SVG 哈希，与样例清单连起来，不能把旧回执套到新文件。

**保留为部分完成的原因**：当前只覆盖单页、无图标的受支持 SVG；尚未检测节点内部裁切、
文字/图形遮挡、每个汉字的实际字体与缺字方框，也未证明箭头方向语义正确、PNG 与 SVG 一致。
多页需逐页提供对应源文件。其余范围继续推进，不能以此次 pass 宣称全面视觉验收。

## 第三批：按用户反馈优先解决配色僵化

用户指出现有样例反复出现棕/蓝，且新增六组固定 profiles 仍然僵化。
本轮改为开放项目配色，不增加封闭的六套颜色菜单。仓库已有的配色网站方法已接入画图技能。
用户随后强调单图多色容易杂乱：默认中性节点与少量重点色，伴随色只作为候选，显式按需要使用；三组样图已按此重做。

### 设计决策

1. 结构 spec 保留节点、关系与语义；配色独立为项目 `*.colors.json`，两后端 `--colors` 读取同一文件。
2. 颜色来源可以是实际查看过的网站/参考图、品牌材料或作者设计。source/rationale 只做来源记录，绝不执行或自动访问。
3. 任意 HEX 和任意命名 swatches，无需注册 profile；by_kind 与 by_node 默认留空，仅按需要显式分配，节点覆盖角色。
   primary 加强所属颜色，critical 保持警示编码，muted 中性。保留文字/形状/线型，不只靠颜色理解。
4. 颜色与画法解耦。四项 strength 自由控制节点/重点/异常/表面的填充强度；背景、文字独立指定。
5. 单主色候选工具允许任意色相角度和数量；这只是起点，不宣称算法审美最优。作者应查看同图实际效果并调整。
6. 保留源色，派生可读边线并记录调整；强填充使用合适的黑/白文字。画布与 ink 不可读时失败，避免悄悄替换品牌。
7. 旧调用保持兼容；有意修正 draw.io 深色节点、边和说明卡片缺少显式文字色的问题。
